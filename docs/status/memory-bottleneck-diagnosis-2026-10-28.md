# 记忆系统**真瓶颈**诊断（2026-10-28）：19.7% 是「候选集/语义」问题，不是排序问题

> 复现：`cargo run -p apeireth-memory --example locomo_bottleneck --locked`
> 杠杆：`cargo run -p apeireth-memory --example locomo_levers --locked`
> 语料：LoCoMo **单证据题 1,122 题**（人工标注 evidence）

---

## 一、诊断：扫 k ⇒ 区分「排序病」与「候选病」

| k | 命中题数 | `recall@k` |
|---|---|---|
| 1 | 354 | 0.3155 |
| 3 | 546 | 0.4866 |
| 5 | 615 | 0.5481 |
| **10** | **698** | **0.6221** |
| 20 | 762 | 0.6791 |
| 50 | 850 | 0.7576 |
| **100** | **901** | **0.8030** |

⇒ ⇒ **「加大 k」只能捞回 +0.1809（18.1%）**
⇒ ⇒ **「候选集里根本没有」= 0.1970（19.7%）** ⇒ ⇒ **加大 k / 重排 / 加信号都救不了这部分**

### 按类别（LoCoMo：1 多跳 · 2 时间 · 3 开放 · 4 单跳）

| 类别 | 题数 | k=10 | k=100 |
|---|---|---|---|
| cat:1 多跳 | 5 | 0.2000 | 0.4000 |
| cat:2 时间 | 280 | 0.6607 | 0.8321 |
| **cat:3 开放** | **42** | **0.4048** | **0.4762** |
| cat:4 单跳 | 795 | 0.6226 | 0.8126 |

⇒ ⇒ **开放类最差（0.40）** ⇒ ⇒ 与「需要推理/语义」一致。

### ⚠️ 我先查了一个**看起来最像**的元凶，结果**不是**它

怀疑：中文被切成**单字** ⇒ BM25 被「一/的/了」淹没。
⇒ ⇒ 查 `hybrid_search::tokenize` ⇒ ⇒ **生产分词器早就是 CJK 二字组**（`tokenizer_splits_ascii_and_cjk_bigrams`）
⇒ ⇒ ⇒ **假设否证**（**幸好先查了再动手**）。

## 二、不需要 owner 拍板的杠杆（**已实测**）

| 臂 | 做法 | `recall@10` | Δ |
|---|---|---|---|
| L1 基线 | 原样 | 0.6221 | — |
| **L2 去疑问词** | 查询侧删 `what/when/did/the/...`（30 个） | **0.6658** | **+0.0437** |
| **L3 时间入索引** | 每条记忆正文前加 `会话日期` | **0.6471** | **+0.0250** |
| **L4 两者叠加** | L2 + L3 | **0.6809** | **+0.0588** |

⇒ ⇒ **叠加 +5.9 个点（相对 +9.5%）**，**零模型、零新依赖、零成本**。

⚠️ **边界**：L3 利用 LoCoMo 的日期字符串格式 ⇒ 有**构造成分**
⇒ 它证明的是「**结构化元数据该不该可检索**」（真实系统里日期本来就该可检索），
**不是**「真实系统一定涨 2.5 个点」。

## 三、真瓶颈与两条路

```
剩余缺口 = 19.7%（候选集里没有）
  ① 检索侧杠杆      已实测能啃下 ~5.9 个点（去疑问词 + 元数据可检索）
  ② 真语义召回      需要**真模型**（哈希伪语义已被否证：−0.15 / −0.32）
                     ⇒ ⇒ 这是**基础设施/产品决策**（模型文件 50~120MB、Rust 推理依赖、
                        离线打包、许可证、内存与延迟）
```

⇒ ⇒ **没有真模型 ⇒ 天花板约 0.68（杠杆全上）~ 0.80（k 放到 100）。**
⇒ ⇒ **有真模型 ⇒ 混合召回（BM25 + 向量）才有机会把那 19.7% 啃掉一大块。**
