# 内部卷首跑结果（2026-10-26）

> **一句话**：内部卷**第一次跑出了真分数** —— 全中率 21.2%（k=5）/ 26.5%（k=10）/ 36.6%（k=20），
> **不是恒等于满分** ⇒ **卷子终于在测东西了**。

## 1. 这次跑的是什么

| 项 | 值 |
|---|---|
| 语料 | 《紅樓夢》**120 回**（88.8 万字），可检索文本 = **回目正文**（不含回目联） |
| 题数 | **476 道**（放宽配置：每记录 6 题） |
| 题型 | conflict 242 / decision 113 / keyword 120 / temporal 1 |
| 检索器 | **生产用的 BM25**（`Bm25LexicalCandidateSource`，确定性 Okapi BM25）⇒ 与生产同口径 |
| 注入口径 | **与生产逐字一致**：每条证据 = 记忆正文**前 120 字**（`EVIDENCE_MAX_CHARS`） |
| 评测 | `golden_set::evaluate`（recall@k / nDCG@k / evidence 族） |

## 3. 怎么读这些数字（**别读错**）

### ✅ 可以下的结论

1. **卷子有效**（最重要）：全中率 21–37% ⇒ 题面**不是**字面命中 ⇒ 它**真的在测检索**。
   修之前（全中率 ≈ 100%）那套卷子**测不出任何东西** ⇒ 这次的数字是**第一组有意义的数字**。
2. **检索侧有明确空间**：`recall@10 = 0.37` ⇒ 十道里找到不到四道。
   这是**基线**，不是判决 —— 后面每次改检索都要跟它比（`check_no_regression`）。

### ⚠️ **不能**下的结论（口径还没到位）

1. **evidence_precision / groundedness 目前**测不出**注入策略**的好坏** —— 根因已定位到两层：
   * **判定层（已修）**：原判定是「注入片段**逐字包含**期望片段」，而期望片段是**句子里的一个切片**
     ⇒ 窗口切过句子就丢 ⇒ **对窗口对齐过敏**。
     ⇒ **已改成「覆盖」判定**（最长公共子串 ≥ 期望片段的 60% 且 ≥ 4 字）；
     ⇒ 并且把 **evidence_precision（片段级）** 与 **groundedness（题级）** 的**分母拆开**
     （此前两者同口径 ⇒ 一个指标测两件事）。
   * **语料层（未修，下一批）**：**期望片段分散在正文各处**（实测 p50 = **第 731 字**，
     只有 **39.4%** 落在正文前 120 字内）⇒ 生产注入（前 120 字）天然只覆盖一小部分；
     而「按查询词选最相关窗口」这个**对照口径本身无效** ——
     **查询词来自回目联，而回目联不在正文里** ⇒ 选出的窗口与答案句无关
     （实测注该口径的 groundedness 反而只有 0.0147）。
   ⇒ **结论**：**注入策略的影响现在无法衡量** ⇒ 要衡量它，必须先解决 §5 的主体来源问题。

2. **「抽掉片段兜底」没有改变分数**（实测 719 个题-记录对**全部**本来就有片段）⇒
   片段**不是**来自「取首句」兜底 ⇒ 兜底去掉是**正确但非关键**的清理。
2. **两本书的题型分布不可直接比**（《紅樓夢》decision 113 vs《水滸傳》7）⇒ 那是**语料性质**
   （前者 515 次决策标记命中，后者只有 8 次），**不是**我们算法的差异。
3. **`temporal ≈ 0` 是语料性质**：小说相邻回是**不同话题** ⇒ temporal 要求「同主题 + 时间相邻」
   ⇒ 天然稀少（git 语料才有 13 条）⇒ **两个语料互补**，不是缺陷。

### ⚠️ 两个**口径陷阱**（已加机器警告/测试）

1. **`k` ≥ 语料条数 ⇒ recall 恒为 1**（全部记录都进 top-k）⇒ 分数**没有信息量**。
   ⇒ `summarize()` 现在会**明说**这一点。
2. **BM25 会按 id 顺序把零分文档填满 limit** ⇒ 「目标恰好排第 1」会**假命中**。
   ⇒ 跑批时**剔除零分结果**（真检索器也会设分数阈值）。

## 4. 本批修掉的三个「会让数字失真」的问题

| 问题 | 后果 | 处置 |
|---|---|---|
| **题面来源被复制进可检索文本** | 检索字面命中 ⇒ recall 恒满分 ⇒ **卷子完全失效** | 原则：题面来源只当「提问的把手」；`scripts/check_golden_no_leak.py` + 两条 Rust 端到端断言守住 |
| **挖出来的题进不了评测** | `MinedCase` 与 `GoldenCase` **不同型** ⇒ 卷子分数一直是空的 | 加 `mined_to_golden()` 转换层 |
| **证据片段没喂进评测** | evidence 族恒为 0（**看着像检索很差，其实是不会喂证据**） | 按**生产口径**（前 120 字）注入，并加「最相关片段」对照 |
| **证据判定要求「逐字包含」** | 窗口切过句子就丢 ⇒ **对窗口对齐过敏** | 改成「覆盖」判定（最长公共子串 ≥ 60% 且 ≥ 4 字） |
| **evidence_precision 与 groundedness 同口径** | 一个指标测两件事 | 拆开：前者**片段级**（精度）、后者**题级**（覆盖） |

## 5. 下一步（按优先级）

0. ⭐ **题面主体应来自「正文里的实体/关键词」，而不是章节标题**（**这是最关键的一条**）。
   * 现状：题目长成「第三十二回　訴肺腑心迷活寶玉后来是怎么改的？」——
     **人不会这样问**（人会问「寶玉和黛玉後來怎麼樣？」）。
   * 后果（三条，都已实测）：① 查询词**不在正文里** ⇒ 检索只能靠 bigram 偶然命中；
     ② 注入按查询选窗口**必然选到无关处** ⇒ 证据族指标**测不出注入好坏**；
     ③ 题面像「检索结果的目录名」，不像「人话」。
   * ⇒ 改法：题面主体 = **正文里真实出现的实体/关键词**（如「寶玉」「黛玉」「限流阈值」）。
     ⚠️ **这不是泄漏**：泄漏指「**题面来源被复制进可检索文本**」；
     而「人话里的实体词**本来就在正文里**」⇒ 检索命中它是**正常的**（正如人问「宝玉怎么了」
     能检索到提到宝玉的章节）⇒ **这才是设计稿说的「像人话的问题」**。
   * ⇒ 顺带：`check_golden_no_leak.py` 的口径**要相应复核**（判「题面来源」而不是「题面里任何词」）。
1. **证据族指标改句子级判定** —— **判定层已改**（覆盖口径 + 两个指标分母拆开）；
   **语料层待上面第 0 条修完**才能真正测出注入好坏。
2. **把检索基线固化**：`recall@10 = 0.3729` ⇒ 写成基线文件 ⇒ 后续每次改检索
   都要过 `check_no_regression`（准确度不许掉）。
3. **外部卷**（PerLTQA）数据到位后跑同一套 ⇒ 证明「不落后公开水平」。
4. **B2 三接口契约**（`MemoryView` / `MemoryAnnotation` / `InjectionRenderer`）
   —— `InjectionRenderer` 正好是第 1 条的落点。
