## 一、目的（两件事，都由 2026-11-10 的实测定案）

1. **摄像头敏感读是死面**：`crates/capabilities/tools/src/device/sense.rs` 的能力声明面只有 3 个字段
   （`action` / `device_ids` / `sensitive_read_authorized`，`additionalProperties: false`）
   ⇒ 模型**无权**提供授权人；而旧的 `DeviceSenseBoundaryGuard::deny()` 要求
   「授权旗 = true **且** `authorized_by` 非空」⇒ **规则永不可满足** ⇒ 摄像头类敏感读无法被合法调用。
   ⇒ 并且 Guard 先于工具面拒 ⇒ **工具面那行审计留痕也被吃掉**。
   ⇒ 裁定：**放行只认宿主决定账**（宿主批准记录），模型给的授权旗只是*请求*。
2. **Windows 侧两笔假债 + 一条既有 clippy 债**：仓级 `cargo fmt --check` 在 Windows 报 os error 206（调用方式坏了，不是格式坏了）；
   7 处脚本路径分隔用反斜杠 ⇒ 两类门禁假红；`crates/capabilities/tools` 16 条 dead_code + 1 条 `needless_pass_by_ref_mut` ⇒ Windows clippy 恒红。

## 三、还差什么（诚实清单）

1. **fuzz 臂未本地实跑**（见上）⇒ 等 CI 的 fuzz job 给出真账。
2. **unix 侧未本地编译验证**（本机装不上 linux target）⇒ `#[cfg(all(test, unix))]` 收口只保证「Windows 上不再编译这些模块」，
   unix 侧行为未改（收口是 `cfg` 门，不是逻辑改写）⇒ 仍以 CI 的 ubuntu/macos job 为准。

4. `Makefile:117` 的 fmt 目标**未改**（Linux CI 仍以 `cargo fmt --all -- --check` 为准，不冲突）。
