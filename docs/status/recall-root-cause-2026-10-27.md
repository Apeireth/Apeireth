# 内部卷召回瓶颈的**根因判定**（2026-10-27）

> **一句话结论**：内部卷《紅樓夢》的 `recall@10 = 0.2983`，
> 瓶颈**不是**「切分粒度」，而是「**查询的判别力**」——
> 题面**只有主体词一个信号**，而主体在 **73%** 的记录里都出现。
> ⇒ **继续在切分粒度上加码是白费**；下一批该攻「**题面增信号**」或「**语义/向量召回**」。

## 这份文件的来历（为什么值得单独写）

⇒ 上一批（W-16）诊断出「切分粒度 = 根因」；
⇒ 下一批（W-20 / W-20R）去**验证**它 ⇒ **被实测否证**；
⇒ 但**否证过程里的机制**比原结论更值钱 ⇒ 写在这里，**免得交接时丢掉**。

## 一、数据（严格 A/B：同一批题，只改切分粒度）

**方法**：③ **映射题** = **同一批题、题面一字不改**，只把「期望记录」从「回」改指
「含答案片段的那个段落」（片段跨段时取重叠最多的那段；映射不上就整题排除
—— 实测**排除 0 道** ⇒ 没有偷偷少算题）⇒ **唯一变量 = 粒度**。

### 三条口径自证

* **基线逐位复现**：0.2983 / nDCG 0.1615 / 476 题、0.6875 / 0.4817 / 248 题
  ⇒ 与 `scripts/golden-baseline.json` 一致 ⇒ **不是**换了口径才「变差」；
* **缺口分类复现**（W-16）：命中 179 / 排在 k 外 297 / **没进候选池 0**
  ⇒ **目标每次都进了候选池** ⇒ **不是索引/分词问题**；
* **同题型对照**（② vs ④）：只留 `keyword`/`decision` 单记录题时，
  紅樓夢 **0.3820 → 0.3282**、水滸傳 **0.8831 → 0.5418**
  ⇒ 连「重挖题」这条端到端口径也**没有净涨**。

## 二、机制（**为什么**切细反而更差）

⚠️ **反直觉点**：切细之后**竞争者的密度比**其实**降了**（73.3% → 12.4%），
**可 recall 反而崩了** ⇒ 所以「密度决定 recall」**不是**完整解释。

**真正的机制是：TF 本身就是判别信号。**

* **整回粒度**下，目标回把主体词说**很多遍** ⇒ BM25 的 tf 项**有区分度**
  ⇒ 在 88 个同主体候选里，目标**还能挤进 top-10**；
* **段落粒度**下，目标段落里主体词只出现一两次 ⇒ **tf 不再判别**
  ⇒ 同主体候选从 88 涨到 360 ⇒ 目标**被挤出** top-10
  （缺口分类：命中 37 / 排在 k 外 436 / **没进候选池 3**；`k=1000` 时 recall 才回 0.89）。

⇒ **推论**：切分粒度是**放大器**，不是**根因**。
⇒ **真根因 = 查询的判别力**：题面只有主体词 ⇒ 主体 saturate ⇒ 排不出差别。

## 三、⚠️ 重挖题有个**坑**（读数字前必须知道）

段落正文只有 ~300 字 ⇒ 挖题器的「实体频次门槛」**自动放宽到 1**
⇒ 题面主体**退化成泛称** ⇒ 实测样本：

> 「**世人**这件事最后是怎么定的？」「**女婿**…」「**金陵**…」

⇒ ⇒ **④ 重挖题的分数是在更简单的题上拿的**
⇒ ⇒ **不能**当成「切分让检索变好」的证据
⇒ ⇒ 这就是为什么必须做**同题型对照**（② vs ④）—— 而 ② vs ④ **两头都掉**。

## 四、**下一批该攻什么**（按数据排序）

1. ⭐ **题面增信号**（让题面带上判别词）—— 直接打「查询判别力」这个真根因
   ⇒ 见 `crates/engine/memory/src/query_signals.rs`（量化各方案的判别力与真实 recall）；
2. **语义/向量召回**（`hybrid_search` 那条路）—— 绕过词面饱和；
3. ❌ **不要**继续切分粒度（**实测有害**）；
4. ❌ **不要**指望「两段式」（先回后段）—— 它**继承**第一级的排序问题（0.0861）。
