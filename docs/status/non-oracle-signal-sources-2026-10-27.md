# 非答案侧信号来源：**5 种全不提升**（2026-10-27）⇒ **D-12 的方案 A 失败**

> **一句话**：W-30 实测「题面加一个判别信号 ⇒ `recall@10` **0.2983 → 0.6113**」，
> **但那信号来自答案片段**（**答案侧**）⇒ 不可上线。
> ⇒ 本轮量化 **5 种非答案侧来源** ⇒ ⇒ **没有一种比基线好**
> ⇒ ⇒ **「信号从哪来」的答案不是「随便找个语料统计」**。

## 一、5 种来源（**顺序固定** ⇒ 报告可比）

| 来源 | 口径 | 用到答案吗 |
|---|---|---|
| **同主题历史** | 与主体同现的记录里的高频词 | ✘ |
| **实体共现** | 与主体共现强度高的词（df 过滤 + 强度下限） | ✘ |
| **时间锚** | 「第N回 / N年前 / 固定时间词」 | ✘ |
| **段落首句** | 含主体的那一段的**首句**实词 | ✘ |
| **原文首句** | top-1 记录的**首句**实词（伪相关反馈） | ✘ |

## 二、结果（**两部语料** · k=10 · 生产 BM25 ⇒ **独立复现**）

### 《紅樓夢》（476 题）

| 来源 | `recall@10` | 相对基线 | 出词题数 |
|---|---|---|---|
| **基线**（原题面逐字未改） | **0.2983** | — | 0 |
| 同主题历史 | 0.2752 | **−0.0231** | 474/476 |
| 实体共现 | 0.2794 | **−0.0189** | 469/476 |
| 时间锚 | 0.2983 | +0.0000 | **0/476 ⇒ 实测无效（没出手）** |
| 段落首句 | 0.2542 | **−0.0441** | 476/476 |
| 原文首句 | 0.2468 | **−0.0515** | 476/476 |

### 《水滸傳》（248 题）

| 来源 | `recall@10` | 相对基线 | 出词题数 |
|---|---|---|---|
| **基线**（原题面逐字未改） | **0.6875** | — | 0 |
| 同主题历史 | 0.5141 | **−0.1734** | 248/248 |
| 实体共现 | 0.4073 | **−0.2802** | 245/248 |
| 时间锚 | 0.6875 | +0.0000 | **0/248 ⇒ 实测无效（没出手）** |
| 段落首句 | 0.6371 | **−0.0504** | 248/248 |
| 原文首句 | 0.6492 | **−0.0383** | 248/248 |

⇒ ⇒ **两部语料独立复现同一结论：没有一种非答案侧来源真提升 recall**
⇒ ⇒ 且《紅樓夢》的跌幅**普遍更小**（−0.02 ~ −0.05）
⇒ ⇒ **因为它的基线本来就低（0.2983）⇒ 掉分空间也更小**
⇒ ⇒ ⇒ **不是「某本书的巧合」**。

## 三、这条负面结果**为什么重要**（**它改写了我自己的建议**）

| 信号来源 | `recall@10` | 相对基线 |
|---|---|---|
| **答案侧**（W-30 oracle：答案片段里的词） | **0.6113**（紅樓夢） | **+0.3130** |
| **非答案侧**（本轮 5 种） | 0.4073 ~ 0.6875 | **−0.28 ~ +0.00** |

⇒ ⇒ **两者差距巨大** ⇒ ⇒ **答案侧信息携带了非答案侧统计携带不了的东西**
⇒ ⇒ ⇒ **「随便找个语料统计当信号」这条路走不通**（**实测**）
⇒ ⇒ ⇒ **D-12 的方案 A（非答案侧信号）实测失败** ⇒ **推荐要改**（见决策书）。

⚠️ **机制猜测（**未验证**，只作方向）**：非答案侧信号是「**主体相关的泛词**」
（如「話說」「宋江」「楊志」）⇒ ⇒ 它们**已经在题面里**（主体就是其中之一）
⇒ ⇒ 追加它们**不增加判别力**，反而**稀释**了原题面的 TF 信号
⇒ ⇒ **掉分**（−0.17 ~ −0.28）⇒ ⇒ **与 W-20R 的机制（TF 本身是判别信号）一致**。

## 四、⚠️ 诚实边界（**必须先看**）

1. **时间锚 = 0/476（紅樓夢）、0/248（水滸傳）出词** ⇒ 它**没被真正测到**（不是「持平」，是「**没出手**」）
   ⇒ 词表没覆盖真实题面（真实题面是「XX后来是怎么改的？」）⇒ **这条待修**
   ⇒ ⚠️ **不许**把「+0.0000」当成「时间锚无效」的证据；
2. **数据集构造红利**：本批题是**从记录里挖出来的**（主体 = 该记录的最高频实体）
   ⇒ 「原文首句 / 段落首句」两行的数字含**构造红利**
   ⇒ ⇒ **不等于**真实用户提问的收益（真实提问的措辞分布不同）；
3. 与 W-30 的 oracle 上界**不可直接比**（一个含答案侧信息、一个不含）；
4. 只有**两部古典小说** ⇒ **机制可迁移、数字不可迁移**。

## 五、🐛 交付过程中我修的两个**真问题**（子代理中途失败 ⇒ 我接手收尾）

### ① 死循环 bug（`time_anchor_terms`）

```rust
if index != cursor { continue; }   // ← 没匹配上后缀时 index 根本没被改
```
⇒ `index != cursor` **恒真** ⇒ `continue` ⇒ **游标不前进** ⇒ **无限循环**
⇒ ⇒ 真实语料里有「3個 / 5年」这类**数字后不接后缀**的题面
⇒ ⇒ **报告永远跑不完**（交付物不可用）⇒ 现已**推进游标**修好。

### ② 性能（报告 10 分钟出不来）

* `subject_fragments` 要扫**整篇正文**（《紅樓夢》一回 **7401 字**）
  × 每道题 × 每条提到主体的记录 ⇒ **上亿次**字符比较；
* ⇒ 已加 **(主体, 记录下标) 缓存**（`CorpusIndex.fragment_cache`）；
* ⇒ 且把**信号缓存提到来源循环外**（原来每换一个来源就新建缓存 ⇒ 同一主体被重算多次）；
* ⇒ 实测：逐来源对照 **从「跑不完」到 4.2 s/语料**（單来源 ~250 ms）⇒ **报告可用了**。

## 七、下一步（**由这条负面结果推出**）

* ⛔ **不要再投**「语料统计类信号」（共现/历史/首句）⇒ **已实测无效**；
* ✅ **要投**的是**「让信号本身更准」**的方向 ⇒ 两条候选：
  * **(i) 用户/模型多给一个信号**（D-12 方案 B）⇒ 信号**最准**，代价 = **用户负担**；
  * **(ii) 让检索器用上题面**之外的结构（**时间/位置/链**）⇒ 与 B4 的时间锚能力接上
    ⇒ ⚠️ 但时间锚这条**还没被真正测到** ⇒ ⇒ **先修时间锚的取词**（0/248 出词）再测。
* ⇒ ⇒ **下一步的**第一步**不是**做新实验，而是**把「时间锚没出手」这件事查清楚**
  （它现在是**唯一一个没被测到**的来源）。
