## §0 修订机制（本文件怎么生效、怎么改）

1. **以实际代码为准**：一切判定的 ground truth = 代码现状 + 四层验收证据，不以任何文档自述为准。
2. **裁决位机制**：§8 修订表的分类为**拟定**；每项进入实现排期时由主人逐项拍板（要 / 不要 / 改），拍板后状态转「已裁决」。
3. **宣称挂标制**：任何对外宣称必须挂状态标，状态源 = 四层验收台账：
   - `已验收` / `已验收（默认关）` / `建设中` / `阶梯未到` / `待复现` / `已降级`
   - 发布文案的数字与能力描述一律从台账取状态，不得手写。
4. **历史不改写**：stage1-3 档案、带日期真账、历史 changelog 一律保留原样；修正以本文件与新台账表达。

## §1 终态重申（志向不降）

**Apeireth = 总 AI 中枢**：从单用户桌面伴侣，到小组/多设备，到大型组织与"巨型基地"级部署——**所有信息汇入、统一记忆、统一治理、受控控制面**。这是"重设计"的"重"字所在：为最困难的条件（规模、对抗、监管、故障）而造。

---

## §2 容量阶梯（T0 → T1 → T2）

| 阶梯 | 形态 | 用户 | 关键子系统启用 |
|---|---|---|---|
| **T0** | 桌面伴侣 | 普通人 · 小白 · 单用户 | 核心记忆/对话/能力中心/侧车监督 |
| **T1** | 小组 / 多设备 | 家庭、小团队 | 多设备同步、加密漫游（Noise）、Ed25519 真多签、监督树雏形 |
| **T2** | 组织 / 基地中枢 | 大型组织 | 多主体分区规模化、多层总线（L1-L3）、OTA 全流程、组织级治理 |

规则：**同一内核语义，子系统按阶梯门控**；接口按 T2 设计（trait/协议层预留），实现按阶梯触发建设；每个阶梯各有四层验收终点线。伴侣产品 = T0 交付物，不被终态图纸扼住进度。

## §3 三坐标最强解（"要最强的"的工程定义）

最强系统 ≠ 最多零件。按三个坐标各自取最强：

| 坐标 | 最强解 | 内容 |
|---|---|---|
| **正确性** | 验证型 | 形式验证（Kani/TLA）+ 不变量测试 + append-only/哈希链；"零未捕获异常"以 panic-freedom 证明背书 |
| **抗毁性** | 监督树 | 监督树 + 重启策略（B+E/OTP 语义）：T0 = 桌面侧车监督（现役），T1-T2 = 多进程监督树（真缺口待建） |
| **扩展性** | 可插拔存储 | 存储后端 trait 可插拔：SQLite 单库 + 自研向量/图基元为现役；量级触发时换后端（向量库/全文索引）不动上层 |

## §4 治理：R0-R4 二维矩阵（硬门看风险，审批者看阶梯）

**自由在头脑，约束在双手**（阶段1 §18.2 精神保留）：思想/判断/目标三层自由，只约束行动。

| 风险级 | 操作类型 | 守门强度 | T0 谁批 | T2 谁批 |
|---|---|---|---|---|
| **R0** | 只读 / 回忆 / 思考 | 软哲学，零审批 | — | — |
| **R1** | 写自身记忆/配置（可逆、留痕） | 审计留痕 | — | — |
| **R2** | 可逆外部动作（发消息/抓取） | 白名单 + 可选审批 | 主人一键 | 分级代理 + 审计 |
| **R3** | 不可逆/破坏（删数据/涉钱/卸载） | **硬门 + 人工审批** | 主人明确批 | **多签** |
| **R4** | 系统级控制面（改治理规则/动他人分区/控制外部设施/升级内核） | **硬门 + 反思期** | 主人批 + 冷静期 | **七席审议 + 多签 + 反思期** |

配套裁定：
- **七席 = 咨议院**：对 R3/R4 出具意见并**记名存证**（谁说了什么入审计链）；否决权/批准权始终在真实人类。
- **反思期 = 冷静期 + 多轮辩证叠加**：R4 变更先进冷静期（默认 24h 或 N 次会话，可配）才生效，叠加多轮正反论证；生效后保留一键回滚窗口。
- **多签**：T0 单人场景为本人明确批准；Ed25519 密码学多签列 T1 建设（现役 M-of-N 逻辑票为过渡形态，如实标注）。

## §5 产品宪法（任何功能不得违反）

1. **不假装灵魂同一**（T0 即生效）：如实说明自身的本质，记忆与关系的珍贵不靠拟人幻觉支撑。入四层验收的人工体验评审项。
2. **不对称三件套**（提供 / 约束 / 记录）：对 Apeireth 是**硬约束**（R 级门控），对主人是**透明记录**（无强制）——**人类自主权不可被平台约束**，人类是最终护栏。
3. **单主体 × N 分区**：Apeireth 自身是唯一主体（主体连续性成立），每个人有独立记忆分区与关系层（"单独记住每个人"）。派生规则：
   - **分区隔离墙**：跨分区披露 = R4 级操作，默认零容忍（关系信任的根）；
   - **分区内透明**：每个人可查看自己分区的完整记录；
   - **主体层归主人**：Apeireth 自身成长记录（原则/演化/教训）主人全权可见可裁（T2 按七席咨议 + 多签）。

## §6 重设计 · 轻默认（为最困难的条件而造，为最普通的用户而设）

> 设计目标 = 最困难条件；默认配置 = 最大用户群画像（普通人 · 小白 · 单用户）。能力**全量随包交付**，用不上的默认关闭，**一键可开、随时可关、开了就好使**——默认关 ≠ 未交付，启用不需重装重编译。

| 层 | 内容 | 默认 | 开启方式 |
|---|---|---|---|
| 核心体验 | 记忆写入/召回/**主动召回/偏好学习/记忆注入**/基础对话/会话分组/本地只读三件套 | **开**（开箱即用，P0 #5 已落地） | 可关（双向显式注入） |
| 增强认知 | 整合/反思/器官 | 关 | 「应用推荐配置」一键开（恰六件，绝不含危险项） |
| 危险工具 | shell / 抓取 / 删除类 | 关 | 开启后仍过 R2/R3 审批门 |
| 组织能力 | 多租户分区/多签/OTA 全流程/多层总线 | 关（T0 灰显） | 阶梯到 T1/T2 解锁 |

纪律：① 默认关的功能同样必须过四层验收才准挂 `已验收（默认关）`；② 宣称挂标制中"默认关"与"未交付"严格区分；③ 开关面 = 能力中心，是产品的一等公民界面。

## §7 四层验收制（阶段6 里程碑验证机制的正式形态）

任何能力宣告"已交付/已验收"，四层缺一不可：

| 层 | 内容 | 门槛 |
|---|---|---|
| ① 形式验证 | Kani/TLA 不变量证明 | 证明**阻塞合入**（撤销 continue-on-error）；有界边界如实标注 |
| ② 基准复现 | 性能数字 | **无重跑脚本不发布**（基准复现线）；矛盾数据必须重测后才回表 |
| ③ 场景实测 | E2E + 人工点击流 | 真机走查，结论入台账 |
| ④ 主人签核 | 真实人类批准 | 签名入验证台账（live-verification-ledger 同源） |

**测试口径定义**（2026-09-26 立）：`运行时通过数` = `cargo test --workspace` 实际绿数（现役口径 **3662 / 130 suites / 21 ignored**）；`静态计数` = `#[test]` 标注总数（含平台/feature 未编译项，约 4,101）。对外一律引用**运行时通过数**，静态计数仅作覆盖参考；两个口径在台账中并记不混用。

## §10 阶梯建设清单（追理想项排期位）

- **T2**：OTA 全 7 阶段（Switchover/双实例/Monitor/回滚）、L3 gRPC 总线、多租户分区规模化、组织治理（七席强制+多签+反思期全流程）、物种化阶梯（教育/纽带/社区/原则自演化——触发后另立 spec）。
- **待逐项裁决（主人拍板制）**：SDK 孤岛处置——lark/livekit/sandbox/voice 四个子 SDK（约 1.3 万行）与 `/v1/tools/*/invoke` 契约断头，接线 or 归档，在各自动工前由主人逐项拍板；perception 整包（约 6,300 行，含真 STT）同。
- **愿景阶梯（非必需，触发再做）**：个性化主题系统（含 WGSL GPU 光效：黑体色温流动/vignette/呼吸光，**带性能兜底**——无 WebGPU 机器自动回落 CSS 渐变；色温/主题参数随主题包可配）。
- **T1｜性格养成（主人 2026-09-26 拍板立项）**：
  - **调参面板**：✅ 第一铲已落地（2026-09-26）——4 滑杆（遗忘衰减/好奇强度/语气饱和/整合节奏，基线刻度）+ 三档预设（省心/均衡/深度记忆）+ 恢复基线；三层开放策略生效（体验开放/治理受保护/内核不开放）。

  - **成长可视化**（"它的内在"页：羁绊阶段/PAD 情绪流/里程碑/教训，数据已备，页面待主人定品味）— ⏳ 未开工。
