## 2. 设计原则（七条失效模式 → 七条原则）

| # | 百年内几乎必然发生 | 原则 |
|---|---|---|
| P1 | 模型/供应商换代 | **数据保真优先**：原始证据（原文+结构+时间+出处+关系+上下文+访问史）永久保留；向量等只是派生 |
| P2 | 我们自己的程序消失 | **自描述归档**：manifest + schema 说明 + 哈希清单 + 纯文本，脱机可读 |
| P3 | 磁盘静默损坏 | **权威层带哈希链** + 定期 scrub + 能定位到具体记录 |
| P4 | 格式演进 | schema 版本化 + **未知版本显式拒**（不猜着读） |
| P5 | 密钥丢失 | 加密归档必须有**受控明文旁路**，否则密钥一丢=数据永久死 |
| P6 | 法律/意愿要求删除 | 删除必须**删透（含派生索引）**，只留墓碑（§4 第三级，且仅授权触发） |
| P7 | 组织中断/人员交接 | handover 清单：数据 + 说明 + 迁移脚本 + 校验工具 + **恢复演练** |

**三条铁律**

1. **只有 D0 是真相**；D1–D5 全部可删可重建。
2. **越深越可丢、越深越可重算、越深越依赖上层**；D4/D5 **永不回写** D0–D3。
3. **默认永不销毁**；降权/归档都不丢内容（owner 裁定 D-9）。

### 3.5 D4 的地位（「今人的智慧」住在哪里）

D4 是**唯一允许"想法多、实现杂"的一层**，因为它与主线只通过一个窄接口相连：

* **输入**：只读 D0–D3（经 `MemoryView`）；
* **输出**：只产 `MemoryAnnotation`（关联/标签/分数），写入 **D4 标注区**（派生数据，可全量重算）；
* **纪律**：默认关；每个算法一个开关；**不接线也能离线评估**（用 §7 的卷子量"如果开启会怎样"）。

⇒ 于是"36 个NOT IMPLEMENTED模块"从**债务**变成**候选池**：每个都能被回答「开了涨几分、多花多少 token、值不值」。

## 4. 「遗忘」的语义：三级处置（owner 裁定 D-9）

> 裁定原文：「选择性遗忘……应该被描述为一个**权重机制**，而不是真的忘掉……
> **我们不要忘掉，相反，我们要所有东西都记得牢靠、管的靠谱**。」

### 4.1 三级（只有第三级会掉数据）

| 级 | 动作 | 数据还在吗 | 触发 | 可逆 |
|---|---|---|---|---|
| **① 降权**（= 本产品的「遗忘」） | 只改**排序权重**；旧/低重要/已失效/重复的**往后排**，默认不进上下文预算 | 在，**永远可按需检索到** | 自动（D5 权重模型） | ✅ 换权重即恢复 |
| **② 归档** | 移冷存储（压缩/加密/离线），降常驻成本 | 在，**无损保真** | 自动（容量策略） | ✅ 换回热层 |
| **③ 销毁** | 从所有层与派生索引移除，只留**墓碑** | **不在** | **仅**：被遗忘权 / 用户明确请求 / 法定义务 | ❌ 不可逆（有审计） |

### 4.2 降权模型（D5）

```
weight = f(时间新旧, 重要性, 时效性(valid_until), 访问史, 与更新条目的重复度, 出处权威性)
```

三条约束（缺一条就成黑箱）：

1. **只影响排序与预算取舍**，不影响存储、不影响能否检索到；
2. 权重是**派生数据**，换算法/换参数**可全量重算**；
3. **可解释**：一条记忆为什么排到后面，必须能说出是哪个因子导致的。

### 4.3 可审计（「管的靠谱」的具体含义）

三类动作**全部写入处置日志**（谁、何时、因为什么、作用于哪条），与 provenance 同源；
**销毁**额外要求：授权凭据 + 墓碑 + `verify` 证明（内容消失、索引已清）。

## 5. 三个接口契约（让未来算法插得上）

设计取向：**接口要比今天的检索窄，比今天的模型宽。**

```rust
// ① 读契约：算法只能通过它读，不许直接碰库
pub trait MemoryView {
    fn record(&self, id: &RecordId) -> Option<&Record>;
    fn by_time(&self, from_ms: i64, to_ms: i64) -> Vec<&Record>;
    fn related(&self, id: &RecordId) -> Vec<&Record>;
    fn provenance(&self, id: &RecordId) -> ProvenanceChain;
    fn visible_to(&self, scope: &Scope) -> bool;   // 权限在契约里，不在算法里
}

// ② 写契约：算法只能产「标注」，永不回写原始层
pub struct MemoryAnnotation {
    pub kind: AnnotationKind,        // 关联 / 标签 / 分数 / 建议权重
    pub target: RecordId,
    pub payload: AnnotationPayload,
    pub algo: AlgoStamp,             // 哪套算法、哪个版本（百年后要能重算/追责）
}

// ③ 注入契约：检索语义不变，输出形态可换
pub trait InjectionRenderer {
    fn render(&self, evidence: &[Evidence], budget: Budget) -> Injection;
}
```

**现状对照**：`MemoryCandidateSource` / `EmbeddingProvider` / `context_compiler` 的两条渲染路径
已经是"可插"的**雏形**，但都绑在具体形态上（能换实现，换不了动作本身）⇒ 本设计把它们**上提为契约**。

## 6. 质量度量体系（「好用」的裁判）

### 6.1 五层 20 项（前次讨论定稿）

| 层 | 指标 |
|---|---|
| **L1 定位** | `Recall@k` · `nDCG@k` · **时间正确率**（返回的是否已失效） · **矛盾检出率** |
| **L2 注入** | `Evidence Precision` · `Token 效率` · `Groundedness`(幻觉率) · `Citation coverage` |
| **L3 鲁棒/成长** | **规模延展斜率** · 噪声鲁棒 · 确定性（逐字节） · 越权命中率（**恒 0**） |
| **L4 可塑性** | **`Swap cost`** · 影子胜率 · 回退时间 |
| **L5 可继承** | 脱机可读 · schema 自说明覆盖 · handover 演练通过 |

### 6.2 「遗忘」相关（D-9 改写，替换原"遗忘正确率"）

| 指标 | 定义 |
|---|---|
| **降权正确率** | 该往后排的是否真往后排 |
| ⭐ **保真可达率** | 被降权/归档的记忆，明确需要时**仍能检索到**（「不丢」的机器证明） |
| **销毁合规率** | 所有销毁有授权+墓碑；**越权销毁恒 0** |
| **秩位位移** | 降权后条目下移多少位（纯排序层，数据不动） |

### 6.3 外部对照口径（诚实要求）

引用公开基准的 *selective forgetting* 分数时**必须注明**：我们的口径是「降权 + 仍可检索」，
**不是删除式遗忘**，**不得与拟人系统分数直接比较**。

### 6.4 阈值政策（owner 已认「你的想法没问题」）

* **准确度一分不许掉**（错误代价不对称：记错 > 记不住）；
* 比「稳定分」不比「单次分」（确定性优先；必要时多次取中位数）；
* 最差情况不劣化 > 1%；
* **唯一的交换许可**：准确度不变的前提下，允许以更少 token 完成（纯赚）；
* 规矩**写进 CI**，不写在人自觉里。

## 7. 考卷体系（golden set）

### 7.1 卷子清单（已核实资料，2026-10-25）

| 卷 | 规模与结构（已核实） | 许可 | 我们怎么用 |
|---|---|---|---|
| ⭐ **PerLTQA**（[arXiv 2402.16288](https://ar5iv.labs.arxiv.org/html/2402.16288)，SIGHAN-2024，**中文**） | 记忆库：141 角色 / 1,339 语义关系 / 4,501 事件 / 3,409 段对话（25,256 轮）；**8,593 条 QA**，**23,697 个 memory anchor**（均 2.8/题）；每条 QA 是四元组 **(question, reference memory, memory anchor, answer)**；官方划分 train 5155 / val 1719 / **test 1719**；检索指标本来就是 **Recall@K**，基线 DPR / BM25 / Contriever | 论文 CC-BY-4.0；数据见 GitHub `Elvin-Yiming-Du/PerLTQA`（**下载前核仓库 LICENSE**） | **中文主卷**。`reference memory` ⇒ Recall@k 的标准答案；`memory anchor` ⇒ **Evidence Precision / Groundedness** 的直接标注 ⇒ 我们的 L1+L2 指标可**无缝对接** |
| **MemoryAgentBench**（[arXiv 2507.05257](https://browse-export.arxiv.org/abs/2507.05257)，ICLR 2026） | 把长上下文数据集改造成**多轮增量**形式；提出记忆智能体**四能力**：准确检索 / 测试时学习 / 长程理解 / **选择性遗忘** | **MIT**（两个独立 HF 镜像元数据均标 mit） | **能力框架来源**（我们的五层标准与之对齐）；其"选择性遗忘"子任务必须**按 D-9 口径改造**（降权+仍可检索，**不是删除**）并明确标注，不得直接比分数 |
| **LoCoMo**（Maharana et al.） | 公开资料显示**仅 10 段对话**；且有研究指出「开发期已见过全部 10 段」⇒ 分数更多反映**稳定性**而非泛化 | 待核 | **只作对照，不作主卷**（体量太小，易被过拟合） |
| **内部卷** | 从本仓日记/记忆挖 2000 条候选 → 精标 300 条 | 自有 | 证明**我们自己的场景**好用（中文 + 长期工程记忆 + 出处要求） |

> ⚠️ **执行时仍需核实**：各仓库 LICENSE 原文、数据文件字段名、以及是否需要注册/申请。
> 本机 **TLS 到 github / huggingface 被阻断**（直连与经代理均失败）⇒ **数据下载不能作为 B0 的前置**；
> 因此施工顺序改为 **「适配器先行」**（见 §8 与 §10 R4）：先把 PerLTQA 四元组 → golden set 的转换器与指标写出来
> （纯代码、不需要网络），数据到位即可跑。数据一律**不入库**，只提交下载脚本 + 适配器 + 分数。

### 7.2 复用方式（关键）

外部卷的**使用点不是它们的 LLM 判分**，而是它们的 **evidence 标注**：
「问题 → 哪几段对话/记录是答案依据」⇒ 直接映射成 `Recall@k` 的标注
⇒ 我们**不吃它们的判分器**，只吃标签 ⇒ 省钱、可复现。

### 7.3 产出物 = 「祖传考卷 v1」

数据集下载脚本 + **适配器**（外部 → golden set 格式）+ 标注文件 + 基线分数 + `reproduce.sh`
⇒ 一百年后的人 `bash reproduce.sh` 能重跑同一份卷子。
