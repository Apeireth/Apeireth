## 一、数据出境如何控制

云端模型会接收为其准备的请求上下文。产品按对象、用途和授权状态控制已接入治理的流转路径。

| 边界 | 谁在管 | 现在什么状态 |
|---|---|---|
| 工具出网（fetch 等） | 出网控制：域名/地址许可 + 策略档 | **PRODUCTION WIRED**（`sec.egress_control`） |
| 对象级越界（shell 读工作区外的对象） | 对象级判定：按对象域 × 主体判，越界即帧 | **PRODUCTION WIRED**（`sec.object_access`） |
| **模型上下文出境** | **出网闸**：检查消息文本以及历史工具参数中的字符串值，检出的敏感值替换为占位符。拒绝无法检查的图像请求。 | **PRODUCTION WIRED，默认脱敏**（`sec.egress_gate`） |

CLI 出网脱敏已接线（**PRODUCTION WIRED**）。未设置或留空 `APEIRETH_ENABLE_EGRESS_GATE` 时默认脱敏，且不写出网、影响和后果账本。
设为 `1` 会启用脱敏和账本。填写授权策略 JSON 可进一步限制出网，策略读取失败时拒绝出网。
图像请求需要显式配置兼容模式（`0` 或 `false`），该模式同时关闭文本脱敏和模型出网授权闸。
脱敏只覆盖已实现的识别规则，模型供应商仍会收到处理后的上下文。

每次模型请求使用独立的占位登记簿。最终回复仅可还原这一次请求发出的占位符。
检测范围以已接入的内容类型与识别规则为准。模型供应商收到的内容可能受其留存策略约束。

## 二、我们保证什么 / 不保证什么

按 **R1–R4** 分级（你在我们的能力声明与承诺里都会看到这套编号）：

| | 承诺 | 状态 |
|---|---|---|
| **R1** | **停止未来外流** —— 你撤回授权后，之后不再出去 | ✅ **保证**（在自己控制范围内的部分） |
| **R2** | 撤回**已导出副本** | ❌ **不保证**（已经交出去的副本不在我们手里） |
| **R3** | **撤回本系统内派生结论** —— 基于旧事实得出的结论作废并可追溯 | ✅ **保证** |
| **R4** | 抹除**模型侧残留** | ❌ **不保证**（provider 侧行为不由我们决定） |

### 正确的说法是这一句

项目对受自身控制的路径执行停止与撤回。以下义务的实现取决于实际启用的治理与记录范围。

1. **记录流向**。显式启用模型出网账本时，记录目的地、用途、对象类型和脱敏判定。记录不包含对话原文。
2. **提供请求路径**。外部副本需要通过持有方的渠道提交删除请求。
3. **发现影响时通知**。启用的问责面可追踪已登记的行动和事实之间的关系。通知取决于实际存在的关联记录。

### 我们根本管不了的（如实说管不了）

- 你自己已经复制、转发出去的内容；
- 第三方系统的内部留存；
- 你根据建议**已经完成**的外部决策（买过、签过、发过、投过）—— 但我们会告诉你
  哪条建议被推翻了、影响过哪些行动，并给出补救路径。

## 三、provider 侧：我们不替别人承诺

发送到模型服务商的内容受实际使用的账户、API 条款、区域和留存设置约束。向相应服务商核实留存、训练及删除条件。

## 四、怎么查账（不只信我们）

| 想查什么 | 去哪查 |
|---|---|
| 某个能力到底接了没、默认开还是关 | [`docs/status/claims.yaml`](../status/claims.yaml)（唯一真源，26+ 条，每条带 `sources` / `tests` / `verify_cmd`） |
| 系统此刻自报什么 | 自述面（21 节冻结合同，**拿不到就写 `null` + 原因**，不编） |
| 发生过什么 | 审计哈希链（append-only，坏行读作不存在） |
| 有没有「实现了但没接电」的 | [未接线台账](../status/unwired-ledger.md) + `scripts/audit_unwired.py` |
| 出网记录 | 出域账本（只记指涉与用途，**零真值**） |

> **重要**：`claims.yaml` 是唯一真源，但**用户不会去读它**。
> 所以承诺的落点不止文档 —— 还要进自述面、进拒绝时的可读原因。

## 五、拒绝时你会看到什么

我们的一条硬纪律：**拒绝必须可读**。

不好：
```
error: denied
```

应该：
```
这次没有把内容发出去：检测到「个人身份信息」，而「发送给外部模型」
这一用途你还没授权。
下一步：在设置里对该用途授权，或改问不涉及这些内容的问题。
```

（这是我们要建的方向。**当前状态**：出网闸 **PRODUCTION WIRED**（默认脱敏），可读拒绝原因的
统一形态仍在实施中 —— 未完成的按「0 装诚实」如实标注，不假装已有。）

## 六、一句话版本

生产 CLI 的模型请求默认脱敏，云端模型仍接收处理后的上下文。已启用的权限、出域和问责账本按各自记录范围提供核对依据，外部副本由持有方处理。

## 七、会话库的本机保护

显式启用 `APEIRETH_ENABLE_SESSION_SEAL=1` 并配置 `APEIRETH_SESSION_SEAL_KEY_FILE` 后，首次成功启动会在事务中升级会话与已提交操作证据。升级后的库需要正确密钥才能打开，写入受保护的表需要新版格式。部署前保留可恢复的密钥和迁移前备份。旧二进制无法读取升级后的会话，回退需要使用迁移前备份。

升级保护的是 SQLite 当前逻辑行。旧页、WAL、历史备份和外部副本仍可能留存明文。记忆库、桌面 IndexedDB 与缓存需要各自的保护和保留策略。会话加密默认关闭，Windows 的解锁密钥文件依赖目标目录的权限配置。
