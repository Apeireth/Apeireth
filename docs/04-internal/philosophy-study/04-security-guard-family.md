## 1. Sandboxie — Windows 对象级沙箱隔离（sandboxie-plus/Sandboxie）

- **①对象级隔离域（重定向+独立令牌）** ②宿主的文件系统/注册表面不被沙箱内程序永久改动，沙箱之间互不串扰 ③"沙箱=隔离域"：程序的写入被重定向进虚拟化层，落不到真实磁盘与注册表；每域可独跑/并跑，同域内多进程共处一盒、跨域互不可见；后期引入**全新令牌创建机制**让每个沙箱在系统里的身份独立度大增（不再共享宿主安全上下文）；快照管理器给整盒做可回退副本 ④隔离的单位是"域"而非"进程"——写入被改道而不是被监控后告警 ⑤弃完全透明的兼容性（个别程序需浏览器兼容向导/模板）换"改动永不落宿主"的结构性保证 ⑥对照：我们的沙箱是 AppContainer+作业对象的进程面收口→进步空间：文件/注册表写面也做对象级重定向，隔离从"限权"升级为"改道"。
- **②隐私模式沙箱（数据面防护+防指纹）** ②用户数据（文档/剪贴板/截图/设备指纹）不被沙箱内程序越权读取或外带 ③隐私模式专挡"对用户数据的不正当访问"：UI 级开关可掐断打印机后台/剪贴板等 Windows 组件访问；**防截屏保护**让沙箱内程序抓不到宿主画面；**抑制唯一标识符生成**——阻止程序按常规途径造设备指纹；加密沙箱以 AES 落盘存储，静止数据也在加密边界内 ④隐私守望的第一问不是"它做了什么"而是"它根本碰不到什么" ⑤弃程序兼容性（剪贴板/打印常被误伤）换敏感面默认不可达；防指纹是"让它拿不到"而非"事后追查" ⑥对照：脱敏 input_security 管出口文本、威胁模型 G3 对象级判定在建→进步空间：敏感对象（截图/剪贴板/标识符）显式建"不可达清单"，判定粒度落对象而非 API 名。
- **③隔离域网络/系统面收口 + 生命周期触发器** ②沙箱内程序不该有任意网络出口、任意系统端点、无限资源 ③每沙箱一张 WFP 网络防火墙（含 DNS 阻断/重定向、强制走指定 SOCKS5 代理出口）；Start/Run 与 Internet 访问双重限制清单；安全增强模式**收缩系统调用与端点可用性**；内存/进程数配额（单进程上限+整盒总量+进程数上限）；**触发系统**在初始化/启动/终止/文件恢复等阶段自动执行动作，配合轨迹工具把关键 Windows API 调用写进追踪日志 ④出口与资源也是防护面——默认收口，放行要显式 ⑤弃"网络透明"体验（代理强制/DNS 管控常致兼容问题）换外带通道收窄+失控进程资源上限；按生命周期挂钩子是留痕与自动处置的统一入口 ⑥对照：写总闸+令牌门管住写面/身份面→进步空间：网络出口独立成面（代理强制+DNS 管控），资源配额进作业对象，生命周期钩子承载审计留痕。

## 2. Vaultwarden / KeePassXC — 密钥保管边界（dani-garcia/vaultwarden · keepassxreboot/keepassxc）

- **①加密保管库边界（KDBX 静止加密+硬件因子解锁）** ②用户凭据在落盘/云同步任何形态下都不以明文存在 ③KDBX 文件=唯一持久形态，全部条目字段静止加密（KDBX4/3，可选 Twofish/ChaCha20）；解锁=主密钥组合（口令×钥匙文件×YubiKey/OnlyKey 挑战-应答硬件因子），任一因子不满足即整库不可解；明文只在程序进程内短暂驻留（README 自述"永不出程序边界"）；条目历史+数据恢复记录每次改动 ④保管库是一个"加密边界内的文件"——边界之外（备份/云盘/同步通道）只见密文 ⑤弃"忘口令可找回"的便利换静止态零明文；硬件因子加解锁摩擦换口令单点被离线猜解的防护 ⑥对照：凭据钥匙串管我们自己的凭据面→进步空间：钥匙串静止态加密+解锁多因子化（口令+硬件/设备因子），条目改动留历史可回溯。
- **②凭据出库窄通道（Auto-Type/浏览器桥/Secret Service 白名单）** ②凭据"使用环节"被旁路截获（剪贴板残留、输入监听、越权进程索取） ③出库只走显式白名单通道：Auto-Type 直注目标应用窗口、浏览器集成经扩展桥逐站授权、FreeDesktop Secret Service 面向本地会话受托应用；TOTP 在库内生成、种子不出库；条目间字段引用（field references）让复用不落第二份副本；口令健康报告+HIBP 泄漏比对让用户自查"哪些凭据已暴露" ④存储安全不等于使用安全——出库口越少越窄越好 ⑤弃"随处可粘贴"的顺手（通道各有兼容成本）换凭据明文暴露面最小化 ⑥对照：令牌门管调用面凭据→进步空间：凭据注入走定向通道不经通用剪贴面，泄漏自查（已泄露口令库比对）进隐私守望。
- **③零知识服务端+组织审计链（Vaultwarden）** ②服务端失陷不泄密、组织内共享可追责 ③加解密在客户端 Web Crypto 安全上下文内完成（HTTPS 强制=加密边界前置），服务端只承担 API 与密文存储；组织面分层授权（Collections/角色/Groups/密码共享）+Event Logs 事件留痕+Policies 策略下发；MFA 多形态（TOTP/邮件/FIDO2 WebAuthn/YubiKey/Duo）；Emergency Access 紧急访问与 Admin Password Reset 托管恢复=恢复通道也有授权与记录 ④服务端按"不可信"设计，密钥永远在客户端；恢复能力必须带授权链而非旁门 ⑤弃"服务端可代解密"的运维便利（忘口令即数据不可恢复）换密文失陷不泄密，再以紧急访问/托管恢复补人因缺口 ⑥对照：三洋葱把判定权留在我们手里、凭据钥匙串集中托管→进步空间：用户敏感数据采用客户端加密、服务端零知识，恢复通道（紧急接管）显式授权+全程留痕。

## 3. opencode-vibeguard — 出境脱敏规则引擎（inkdust2021/opencode-vibeguard）

- **①出境脱敏边界（占位符替换+会话内不可逆指纹）** ②配置清单内的敏感字符串随请求流向 LLM 供应商（明文离开本机） ③请求发出前把敏感值替换为 `__VG_<类别>_<hash12>__` 占位符：hash12=HMAC-SHA256(会话随机密钥, 原值) 前 12 位十六进制——同一会话内稳定（模型可跨轮关联同一实体）、对供应商不可逆；类别标签给模型语义上下文而不给值；本地展示/持久化在输出结束后还原原文 ④脱敏边界钉在"出境"这一刻——供应商侧只见带类别的稳定别名 ⑤弃跨会话关联性（会话随机密钥，换会话即换别名）换取不可逆性；类别标签牺牲少量信息量换模型可用性 ⑥对照：脱敏 input_security 管出口文本→进步空间：脱敏占位符带"类别+会话内稳定指纹"，脱敏后仍可推理、但值不可复原。
- **②还原双闸+历史面回扫** ②脱敏值在"真正要用的地方"必须还原，而历史上下文里的明文不能随下一轮请求回流 ③还原发生在两个闸口：模型输出结束后的本地落地（显示/持久化拿原文）、工具执行前（bash/write/edit 拿真实值跑）；更关键的是**历史面回扫**——工具调用参数/输出以真实值存 DB，故每次请求前对历史工具输入输出再跑一遍脱敏，防明文在后续轮次搭车上游 ④脱敏不是一次性预处理，是"出境必扫、落地才还原"的双向闸；泄漏路径包括历史回放 ⑤弃少量每轮重复扫描开销换"存储层真实值"与"出境层脱敏值"两个世界的隔离 ⑥对照：input_security 主要闸当前出口→进步空间：历史消息/工具轨迹每次出境前回扫脱敏，堵住"历史搭车"泄漏面。
- **③失配安全默认+零明文留痕** ②配置缺失时插件不能乱动数据，调试日志不能成为新的泄漏口 ③配置按"环境变量→项目根→.opencode 目录→全局目录"序查找，缺失或 enabled=false 即 no-op（行为安全默认）；调试日志只记配置路径与替换计数，永不打印明文；流式输出期间占位符可能短暂可见、text-end 还原（已知时序缺口明示） ④防护组件的失败模式必须可预期：宁可不动也不误伤，且自观测面不泄密 ⑤弃"缺配置也强拦"的激进（no-op=缺配置时防护缺位）换零误修改；流式时序缺口明示而非掩盖 ⑥对照：写总闸"宁误拒不漏放"是另一极→进步空间：脱敏面区分"防护缺位"与"误伤"两种失败并显式上报，日志/审计面立"永不落明文"硬规矩。

## 4. Briar / Session — 加密通讯与元数据最小化（briar/briar · session-foundation/session-android）

- **①元数据最小化投递面（去中心化存储+洋葱路由）** ②"谁和谁通信、何时、从哪"的关系图与位置（IP）被集中收集 ③Briar 不设中心服务器，消息在用户设备间直接同步：断网走蓝牙/Wi-Fi 局域直连、联网走 Tor 网络保护用户及其关系网；Session 由分布式、去中心化、抗合谋（Sybil resistant）的 Service Node 群做消息离线存储，另设洋葱路由节点层混淆用户 IP，口号"Send Messages, Not Metadata"④内容加密相对容易、元数据难——最可靠的守望是根本不产生可集中收集的元数据 ⑤弃中心服务器的可达性/多端同步便利（离线投递靠节点群或邻近直连）换取"没有单点持有通讯图" ⑥对照：我们的事件溯源日志集中留痕（恰恰是元数据富集面）→进步空间：用户侧遥测/日志做元数据最小化分级（必需留痕 vs 可省收集），关系图类数据默认不落中心。
- **②端侧加密边界（中转者永远不可信）** ②传输途中/中转节点上的内容与身份被读取 ③加密边界钉在两端设备之间：无论蓝牙直连、Wi-Fi 直连还是 Tor/Service Node 中转，通道只搬运密文与路由信息；节点群分担存储与转发，任何单一节点既无完整内容也无完整路由图 ④传输多样性是防护层不是备份层——每条通道都在同一加密边界之下 ⑤弃"服务端代投递+账号找回"的便利（丢设备即丢身份）换中转面零信任 ⑥对照：令牌门管调用身份、加密边界主要在传输层 TLS→进步空间：用户敏感数据的加密边界前推到端侧，服务端/中转层只处理密文。
- **③可验证分发链（可复现构建+签名哈希）** ②安装包被替换/供应链污染后用户无从察觉 ③Briar 提供 Docker 化可复现构建环境，任何人可验证发布 APK 只含公开源码；Session 发布物配 GPG 签名的哈希清单+公开 SHA-256 证书指纹，验证流程明文成文（签名→哈希→文件逐一比对） ④隐私工具的可信度来自"可被独立验证"，不是"请信任我们" ⑤弃"一键安装"的顺滑（验证要跑多步比对）换发布面零信任 ⑥对照：git 三级+审计配对管仓库面→进步空间：对外发布物（安装包/模型文件）附签名哈希与可复现校验路径，交付物可离线自证。

## 5. Sherlock / Maigret — 公开足迹自查（暴露面守望视角）（sherlock-project/sherlock · soxoj/maigret）

> 视角声明：本节只取"帮用户知道自己暴露了什么"的防御用途——数据源组织与报告留痕机制；对他人做信息归集的用途一律不写。

- **①暴露面清单化（站点规则库+统一调度）** ②用户不知道同一个用户名在多少站点留下了可关联的公开足迹 ③站点清单即规则库：每个站点一条声明式条目（查询入口、"存在/不存在"的页面判定信号、类别标签），Sherlock 覆盖 400+ 社交网络且站点清单独立维护可贡献；引擎本体只做并发调度（超时/重试/--site 限定范围）与结果判定 ④暴露面管理的前提是"可枚举"——先把散落的足迹变成一张清单 ⑤弃判定精确性（站点改版即规则老化，需社区持续维护）换覆盖广度与零配置自查 ⑥对照：威胁模型 G1-G10 是我们的面清单→进步空间：给用户产出"个人暴露面清单"（账号关联面/公开数据面），清单化后才谈收口。
- **②用户名变体归并+结构化核查报告** ②换标点的同名变体也在暴露，且核查结果不留档就无法复查 ③变体展开（`{?}` 把分隔符展开为 `_`/`-`/`.`）+多用户名批量核查；结果按用户名落独立文件，另出 CSV/XLSX/JSON 结构化报告——每次核查产出可归档、可 diff 的暴露清单证据 ④隐私自查的产出必须是"可留档的暴露报告"，不是一次性终端输出 ⑤弃"只报确定命中"的洁癖（宁全列待人工复核，误报=同名撞车）换取不漏报自己的变体足迹 ⑥对照：审计留痕管我们的动作面→进步空间：暴露面核查结果进"用户隐私档案"，前后两次报告可 diff（暴露面收敛可度量）。
- **③公开信息聚合的警示镜（Maigret 档案视角）** ②用户感受不到"零散公开信息拼起来有多完整" ③Maigret 按用户名在大量站点核查账号并从公开页面聚合可见信息、拼成一份档案（dossier），无需 API key 全走公开面，并有 AI 画像演示——防御用途：让用户亲眼看到"仅凭一个用户名能被拼出什么"，即暴露面教育镜 ④最好的隐私警示是让用户看到自己的暴露面有多完整 ⑤弃聚合完整度（宁多聚合以强化警示）换教育力度；代价是同名误聚合需用户自行甄别 ⑥对照：G3 对象级判定在建→进步空间：把"能被公开拼出的画像"做成用户的暴露面体检报告，配合脱敏/收口建议闭环。

## 6. ghidra — 大型分析平台的插件/脚本化架构（NationalSecurityAgency/ghidra）

> 视角声明：本节只取架构哲学——分析平台如何组织扩展、协作与自身安全治理；分析对象是恶意样本与缺陷理解（防御评估用途）。

- **①分析核心与扩展面分层（插件+脚本双轨）** ②分析能力要随处理器指令集/可执行格式/分析任务不断扩展，又不能让核心被扩展拖垮 ③核心框架提供反汇编/反编译/图示/脚本化基础能力；指令集与格式支持走扩展点接入；用户可开发扩展组件（Java）或脚本（Python，另有 PyGhidra 一体化入口）；交互式与自动化两种运行模式共用同一能力面 ④平台的寿命取决于扩展点设计，不是内置功能清单 ⑤弃"核心即全部"的封闭性（须维护扩展 API 兼容承诺）换生态扩展；脚本执行面开给分析员换效率，代价是脚本面也得纳入治理 ⑥对照：器官 9 件是固定内置件、CapabilityRegistry 面在建→进步空间：能力以扩展点组织（加载器/分析器/输出面可插），交互与自动化共用一套能力契约。
- **②规模化协作分析（scaling+teaming 优先）** ②复杂程序的分析知识集中在单个分析员头脑里，无法协作、无法复核 ③为"规模化与团队协作"而设计：程序分析工程可承载共享知识、自动化模式支撑批量分析、反编译把二进制提升为可读形态使分析结论可共享可复查；定位是"可定制可扩展的研究平台"而非单人工具 ④分析工具要解决"人和知识怎么协作"，不只是"怎么读代码" ⑤弃单人工具的轻量（工程文件/共享库复杂）换分析结论可传承、可团队复核 ⑥对照：事件溯源日志+教训回路已有记录面→进步空间：分析类能力的中间结论结构化沉淀（可共享的"发现对象"而非散文），支持多人复核与增量续查。
- **③自身安全通告面（工具也要被治理）** ②分析平台自身携带的缺陷会成为防护链的入口 ③README 首屏挂安全警示、Security Advisories 独立成页按版本通告已知问题；发布物命名有严格规范并明示哪些文件不是发布物（防拿错包）；构建依赖显式拉取清单（fetchDependencies） ④分析器也要被分析——工具的安全姿态必须公开可查、按版本可追 ⑤弃"无通告即无问题"的形象（公开通告=承认缺陷存在）换用户可评估自身暴露并按版本升级 ⑥对照：威胁模型 G1-G10 是我们的自省面→进步空间：对外工具/插件立安全通告机制（版本级已知问题清单+升级指引），防护工具自身进守望范围。

## 7. VulnClaw / DeepSec — 安全评估工作流编排（Netw0rkNoob/VulnClaw · vercel-labs/deepsec）

> 视角声明：VulnClaw README 的操作性进攻段落全部跳过，只取"任务编排/证据/报告/留痕"机制；DeepSec 为面向自有代码库的评估 harness，防御用途直取。

- **①证据链优先的评估记忆（evidence 归档+反幻觉闸门）** ②评估结论凭空生成（幻觉）、或结论无法回查复核 ③工具结果统一写入 evidence 记忆、raw 原文完整保留，active context 只注入高信号预览、`evidence_search/view` 按需回查原文；**证据级采信闸门**：声称的结论必须在真实工具输出里逐字出现才被采信；纠偏层记录重复调用/失败降级/空转信号，重复读取抑制、连续空转触发 stall guard；流量证据按追加式 JSONL 索引+原始报文归档 ④评估报告的可信度=证据链完备度，结论必须指向证据 ⑤弃上下文经济性（原文归档+回查有存储/检索开销）换零编造、可复核 ⑥对照：事件溯源日志+审计配对留痕已有→进步空间：判定/结论对象绑定证据引用（claim→evidence 引用链），无证据引用的结论标记为不可采信。
- **②分层漏斗评估流水线（廉价筛查→精查→复核→报告）** ②大规模代码面全量精查成本失控、误报淹没真问题 ③漏斗分层：pattern scan 免费快筛候选→AI review 只精查新候选→revalidate 复核砍误报→export 导出结构化报告；`process --diff` 做增量评估进 CI 门禁；中断后重跑同一命令**断点续查**（跳过已分析文件、只查余下）；`--max-cost-usd / --max-duration` 成本与工期硬上限 ④贵的智能只花在便宜层筛出的候选上，且任何长跑都可断点续作 ⑤弃漏斗盲区（模式层看不见的问题会漏，须靠加深推理档位补）换成本可预算、误报可收敛 ⑥对照：三维预算有超限帧→进步空间：威胁感知巡检按"筛查→精查→复核→报告"漏斗编排，配成本/工期闸+增量 diff 门禁。
- **③评估工作区单目录化+授权范围声明** ②评估状态散落不可审计、评估动作越过授权边界 ③全部状态与发现集中 `.deepsec/` 单目录（state+findings 即审计对象，可整体审计/移交/清理）；运行范围先声明（Authorized Only 范围限定随项目成文）；检测插件低耦合接入、结果自动汇入报告链路；知识/Skill 以索引暴露、按需显式加载而非全量注入 ④评估工作区本身就是审计对象，范围声明先于一切动作 ⑤弃工作区灵活性（状态集中=目录约定刚性）换可审计、可移交、越权可判定 ⑥对照：审批四态+写总闸管动作面→进步空间：安全评估任务绑定"授权范围对象"（对象级判定 G3 落地场景），评估产物单目录归档成留痕包。

## 「Apeireth 安全守望能力」建设清单 TOP5

1. **隐私守望 · 用户暴露面清单与体检报告**：把"用户知道自己暴露了什么"产品化——账号关联面/公开数据面清单化（400+ 站点清单即规则库的组织法），用户名变体归并自查，核查结果结构化留档、两次报告可 diff（暴露面收敛可度量），再配"公开信息拼图警示镜"做暴露面教育。落点：隐私守望的第一张产品面。
2. **隐私守望 · 出境脱敏边界**：脱敏从"出口文本过滤"升级为双向闸——出境前敏感值换成"类别+会话内稳定不可逆指纹"占位符（脱敏后仍可推理、值不可复原），落地/执行前才还原，历史工具轨迹每次出境回扫防搭车；日志/审计面立"永不落明文"硬规矩。落点：input_security 的下一形态。
3. **隔离防护 · 改道式对象隔离纵深**：沙箱从"进程限权"（AppContainer+作业对象）走向"写面改道"（文件/注册表对象级重定向）+敏感对象不可达清单（截图/剪贴板/标识符）+每隔离域网络出口收口（代理强制/DNS 管控）+资源配额；生命周期钩子统一承载审计留痕。落点：G3 对象级判定的天然承载面。
4. **密钥边界 · 零知识存储与恢复授权链**：用户敏感数据客户端加密、服务端只见密文；解锁多因子化（口令+设备/硬件因子）；凭据出库走窄通道（定向注入不经通用剪贴面）；恢复/紧急接管是显式授权+全程留痕的通道而非旁门；凭据泄漏自查（已泄露口令比对）进守望面。落点：凭据钥匙串面向用户的延伸。
5. **审计留痕+威胁感知 · 证据链结论与守望巡检**：守望的每条判定绑定证据引用（claim→evidence 引用链），审计面哈希串链可离线自证；威胁感知按"筛查→精查→复核→报告"漏斗巡检（成本/工期闸+增量 diff 门禁+断点续查）；用户侧遥测走元数据最小化分级；对外工具立版本级安全通告。落点：安全守望的"可信度基础设施"。
