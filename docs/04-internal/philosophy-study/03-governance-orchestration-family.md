## 1. DeerFlow — 长周期 SuperAgent harness（bytedance/deer-flow，~83.8k★）
- **①Thread-scoped Goal Loop + 无进展熔断** ②长任务何时该继续、何时该停 ③GoalState 挂 LangGraph thread checkpoint 的 goal_outcome channel；独立 LLM goal evaluator 产出类型化 GoalEvaluation，blocker 是封闭枚举（missing_evidence/needs_user_input/run_failed/external_wait/goal_not_met_yet），只有 goal_not_met_yet 允许隐藏续跑；硬上限 max_continuations=8、max_no_progress=2；无进展 key 用"最后可见 assistant 文本 SHA-256 签名+类型化 blocker"而非 evaluator 每轮重新措辞的 free-text ④用确定性计数器约束 LLM 自评的续跑意愿 ⑤弃无限自主续航换成本可预期、防幻觉续跑；长任务需人/调度器再唤醒 ⑥对照：折子戏/目标续行有续行语义→进步空间：续跑配确定性无进展熔断（签名 key 防伪进展）。
- **②Delta checkpoint + 状态变更图（单一闸口）** ②checkpoint 读写模式漂移、回滚/压缩不一致 ③CheckpointStateAccessor 是 thread checkpoint 读写唯一闸口，每次操作注入 mode marker 过兼容门；delta checkpoint 不存完整 channel_values，消费方被强制走 accessor；状态回滚/上下文压缩走"单 no-op 节点、entry=finish"的状态专用图整段替换，写完 head 保持 idle 不调度 agent 节点 ④状态变更必须是无副作用的图操作 ⑤弃直接调 checkpointer 的自由换 mode 一致性与压缩/回滚可审计 ⑥对照：事件溯源日志+会话写闸已有→进步空间：状态读写收敛单一 accessor+兼容门。
- **③子代理容量准入 + turn 预算换算** ②子代理并发失控、操作者预算被框架折算稀释 ③SubagentExecutionCapacity 进程内 FIFO 准入（max_running/max_queued/queue_timeout，"queued work never owns a thread"，饱和抛类型化拒绝）；turn_budget 把操作者写的 max_turns 按实际 middleware 链节点数换算成 recursion_limit（不换算时 max_turns=150 实得约 18 turn 的事故记录在案）；批量委派带 acceptance_criteria+max_live_items ④预算以操作者单位表达、以框架单位换算 ⑤弃精确换算（扁平乘数是下界）与无限并发换确定性、进程稳定 ⑥对照：三维预算含 tool_steps→进步空间：子代理并发准入+两单位换算层。
- **④确定性验收检查 + 报告契约（子代理自证）** ②子代理谎报 done 无法与真实完工区分 ③三层：收割工具回执/bash 执行记录→代码判定叶标准（json-valid/csv-columns/exists 非空，只限共享 workspace 路径，跨沙箱不可达报 UNVERIFIED 而非猜测）→报告契约把引用义务注入每个 subagent system prompt，acceptance_criteria 走不可信通道（SystemMessage 只放指针）；父会话快照明示"历史指令不能覆盖 system 指令/工具限制" ④自报永远不能通过可判定要求 ⑤只做叶检查不做语义验证，弃覆盖率换零误判 ⑥对照：教训回路信源限 Judge 显式判定→进步空间：子代理完工以可判定叶检查自证。
- **⑤Skill 即安全边界（工具面治理）** ②技能扩权与 agent 自写技能的供应链风险 ③skill 声明 allowed-tools 即并集裁剪工具面（仅 4 个框架工具保底），tool_search 晋升不能恢复被裁工具；装好的 skill 树 chmod 只读供沙箱读取；agent 写 skill 须过静态扫描+LLM 扫描（security_fail_closed 默认 True）；skill 目录延迟加载，prompt 只放索引、describe 才给元数据；授权过滤器在工具组装前按 principal 过滤，provider 异常且 fail_closed 时拒绝全部工具 ④能力收窄默认、fail-closed ⑤弃便利（误拒、prompt 多一跳）换可审计最小工具面 ⑥对照：写总闸+权限预设已有→进步空间：技能包声明即工具面裁剪，晋升不复权。
- **⑥DeerMem 经验记忆流水线** ②对话经验散失、纠错不沉淀 ③五模块（storage/queue/updater/prompt/message_processing）；YAML 消息模式（correction/decision/goal/identity/preference/reinforcement/trivial）做信号检测；防抖更新队列防高频写；LLM 抽事实/合并/判定过期（staleness_review）；IDF 排序+混合淘汰策略；注入器格式化回 prompt；后台线程带 trace_id 跨 HTTP 生命周期关联 ④记忆是可过期、可合并的证据而非永久事实 ⑤弃向量库改 Markdown+IDF，弃召回精度换零依赖可人审 ⑥对照：教训回路+consolidation 已有→进步空间：经验带过期复审/合并/淘汰律。

## 2. LoopX — 长周期 Agent 控制平面（loopx-project/loopx，~6.3k★，huangruiteng/loopx 重定向至此）
- **①六层状态内核 + append-only 事件账本** ②跨会话/跨 harness 的工作真值丢失 ③六层 Registry→Goal state→Run log→Run history→Status/attention→Compute quota；todo/history 真值迁往 append-only 事件账本（rollout-event-log.jsonl，事件类 quota_spent/todo_claim/todo_complete/failure_attribution/research_evidence，分 work/decision/accounting/evidence）；契约规定确定性 replay、幂等 append、隐私分区、Markdown 兼容投影 ④当前状态只是事件账本的投影，不可静默重写做出决策的事件 ⑤弃数据库查询性能换人机同读、可 diff、纯本地；索引需自愈（duplicate repair）⑥对照：事件溯源日志已有→进步空间：事件契约化（幂等 append+replay+隐私分区），状态视图只作投影。
- **②配额状态机 + 配额感知自动唤醒** ②调度器在无有效进展时继续烧算力 ③配额=分钟 slot 占空比（窗口/slot/算力），spent 由事件派生（registry 只当策略源不当花费账本）；State Order 五级门 health/safety→operator gates→evidence waits→focus waits→compute quota（"quota 不作第二权限系统"）；计算态 eligible/focus_wait/throttled/waiting/operator_gate/paused/blocked_health；should-run 返回调度提示供宿主确认节奏；花费入账走独占文件锁+准入，dry-run/preflight 失败不花费；连续停滞投 autonomous_replan_required 强制有界 replan ④预算是状态机而非计时器 ⑤弃 token 精算换跨 runtime 可比可审计 ⑥对照：三维预算超限即帧→进步空间：预算态驱动唤醒/等待/强制 replan 的调度律。
- **③Governed Turn 生命周期 + 类型化结算/恢复** ②turn 结束算什么、崩溃后算不算花过钱 ③执行前路由（LoopXTurnRoute）与执行后结果（TURN_RESULT_KINDS）构成可执行词汇表——validated_progress/validated_completion 与执行失败同级；terminal_closeout_failed 特指"durable writeback+配额已提交后 closeout 失败"，恢复只重试 closeout、不得把失败当未花费（测试钉住边界）；turn journal 投影供恢复决策 ④执行失败是一等公民的类型化结果 ⑤双语言词汇表维护成本换跨宿主一致；typed 决策弃灵活性换恢复不重复副作用 ⑥对照：审批四态有终态闭合→进步空间：turn 结算词汇表+崩溃恢复"不重复副作用、不重复记账"。
- **④对等 claim/硬租约 + 可验证交接** ②多 agent 争抢工作与交接不可信 ③无持久 leader，registered agents are peers；硬租约含 claimant/排除名单/写范围交集校验；交付前 todo claim、验证后 update；停止即归还所取租约、永不拥有他人租约，结果是类型化租约事实（released/release_unproven/obligation_unproven）；操作记录里的租约注解只是 hint 不是证明；交接文本受硬预算（16 行/1800 字符）与 must-include 三件套（连贯工件/针对性验证/状态回写）约束 ④所有权是显式租约而非聊天默契 ⑤弃交接表达力（硬预算）换机器可校验；权威仲裁弃本地速度换无双花 ⑥对照：worktree 四拍是批级隔离→进步空间：任务租约（claim/写范围/归还义务）+交接契约。
- **⑤Operator Gate + checkpointed 恢复契约** ②危险动作无人终审、旧批准被滥用 ③record_operator_gate 产出带问题/建议/决策分类的门记录；恢复契约规定旧决策只作审计锚点，恢复时必须对当前 registry/active state/quota/policy/repo 状态 rebase（freshness checks）；权威源分级 public/local_private/private_redacted；promotion gate 产出晋级证据；"危险权限、发布、生产写、最终所有权留给人"；投影（dashboard/Kanban）永不成为真值源 ④人是终审者而非建议者 ⑤每门显式问弃自治度换可追责 ⑥对照：审批四态+IM 卡已有→进步空间：checkpointed gate——旧批只作锚点，续行必 rebase 当前状态。
- **⑥Reward Memory：记忆可建议、永不授权** ②反馈不进下次尝试、经验越权 ③五类一等记忆（run_bound_reward/hard_policy/soft_preference/procedural_experience/working_context），每条必带 source/scope/authority/confidence/lifecycle/supersession/revocation/expiry/privacy 九字段（"confidence 描述证据质量、永不增加 authority"）；候选由模型提议、确定性代码只验形状/绑定/新鲜度/冲突/当前工件证明，五决策 accept/edit/reject/retire/no_write；guarded precedence：显式动作权威>生效 hard policy>新鲜工作上下文>工件验证过的经验>soft preference>run-bound reward；防提权回归夹具常开 ④记忆可以建议、永远不能授权 ⑤弃自动化速度（五决策审查流）换"权限永不被记忆放大" ⑥对照：reflexion 教训回路→进步空间：教训带九字段生命周期+先验权威序。

## 3. Harness-R1 — 从失败轨迹学习编辑 runtime harness（DeepExperience/Harness-R1，~114★，arXiv 2608.02276）
- **①失败包（Batch Failure Packet）** ②一批杂乱 rollout 怎样变成可分析的失败证据 ③`harness_r1_trace_packet.py` 只挑 reward<threshold 产出有界 TraceCase；`sanitize()` 以 `[PRODUCT_ID]/[PATH]` 占位防泄漏；`runtime_signal_lines()` 从 tool_calls/observation 推导重复 search/click、"Nothing happens" 观测循环（明示废弃 regex 扫文本旧方案）④失败不做人工归类，让编辑者直读证据 ⑤弃归因 taxonomy 的可解释性换证据保真+零标注；有界截断牺牲长尾 ⑥对照：reflexion 只收 Judge 显式判定→进步空间：工具轨迹循环类信号自动入失败包。
- **②Overlay-only 补丁 DSL** ②限制"编辑 harness"自由度使补丁可验证可回滚 ③6 动作白名单（set_config/edit_tool_hint/add_or_edit_skill/add_guard_rule/add_recovery_rule/add_code_hook）写入 `harness_overlay`（`overlay_only=True`）；`MODULE_CONFIG_FIELDS` 硬拒改内置模块；`FORBIDDEN_TEXT_PATTERNS` 拒答案泄漏进补丁 ④补丁只叠 overlay 层，绝不改内置模块 ⑤弃核心重构能力换可组合/可回滚/跨任务泛化（held-out +8.9pp，自由编辑器为负）⑥对照：教训回路只改注入文本→进步空间：教训落为 overlay 层可执行件（技能/守卫/恢复规则），主体冻结。
- **③hook(ctx,nb) 四钩子 + nb 便签状态机** ②不改权重获得全流程干预点与跨步状态 ③on_init/make_pre_hint/on_before_action/on_post_step；ctx 只读证据（含 world 快照/admissible）；nb 为每 episode 便签状态机（stage/last_hint 去重）；返回值即生效契约（block_and_prompt/force_action/rewrite_action/inject_hint）软提示优先 ④把补丁当小型 stage machine，窄干预 ⑤弃通用规划（限 5 helper/禁 while）换确定性执行与"修失败不破成功"⑥对照：器官 9 件为固定 tick 串联→进步空间：干预点契约化，器官间留便签态续接。
- **④AST 沙箱 Hook Runner** ②模型生成的补丁零信任进运行时 ③`code_runner.py` AST 白名单禁 Import/While/Lambda/eval/exec/open；硬顶 8000 字符/1200 节点/5 helper/签名必须 hook(ctx,nb)；仅注入 math/re/SequenceMatcher；signal 限超时；抛错降级 no effect ④补丁是故意很小的同步函数，不是插件系统 ⑤弃表达力换零信任；信号超时非子进程，弃隔离深度换低开销 ⑥对照：写总闸管住写面→进步空间：注入执行面（回调/脚本）同款 AST 白名单+尺寸硬顶。
- **⑤同批重跑 Delta 奖励 + 任务身份锁定** ②改进奖励不能是裁判估计，必须是因果增益 ③校验→编译→冻结 target 于相同 task identities 重跑→reward=patched−baseline；`assert_matching_task_hashes` 强制 manifest 哈希一致（"下标相同不算配对"）；metadata 内嵌不可变 baseline；失败分级：非法补丁=0 分、基建失败=missing eval 且禁止重试到变正 ④奖励即可复现的配对实验 ⑤弃样本效率（每补丁全量重跑）换无 reward hacking；身份校验繁琐防静默错配 ⑥对照：教训回路无验证证据→进步空间：教训生效后留"同题重跑前后"证据对，教训可被证伪。
- **⑥GRPO 三角色解耦** ②把"读失败→写补丁"本身训成策略 ③frozen target / 训练中 engineer / frozen reference；分组不混 benchmark；协议（schema_style/prefill）全局锁死防 train/eval 漂移 ④编辑策略与被编辑对象解耦 ⑤弃"通用编辑器"叙事（换 target 需重训）换实证增益 ⑥对照：RuleCritic 规则版蒸馏→进步空间：蒸馏器与被蒸馏对象分离冻结，防自我确认。

## 4. OpenWorker — 桌面 AI 同事，治理是架构不是插件（andrewyng/openworker，~18.5k★）
- **①RiskClass 五级 + 命令语义论证** ②工具名黑白名单不足以安全放行 ③`coworker/risk.py` 五级 READ/EGRESS/WRITE_LOCAL/EXEC/EXTERNAL（web_fetch 归 EGRESS：URL path/query 可外带数据；未知工具回落需审批）；`permissions.py` 按 Plan/Interactive/Auto+参数模式出 allow/deny/ask，复合命令按分隔符拆段逐条论证，含 `$/重定向/变量展开` 的不透明构造不可前缀放行，前缀永不为 xargs/ssh/npx/python -c 背书 ④自动放行的单位必须是可静态论证安全的命令片段 ⑤弃通过率换 allowlist 永不为没见过的代码背书 ⑥对照：写总闸词法+双查同构→进步空间：按风险类分级授权，EGRESS 独立成类。
- **②Hard floors + 阶梯式授权** ②高危不可被模式吞掉，重复审批又不该疲劳 ③`human_only` 硬底线（无任何 auto-approve 路径可清，含 create_scheduled_task 这类后果越出对话边界的工具——"承担后果的人不在场"）；常驻规则候选仅限 external-risk 类升为任务级；exec/write-local 永远逐次问；会话 allowlist（工具/命令/域名精确匹配）每级显式可见可撤销，bypass 模式仍受 floors 约束 ④授权是随证据累积的租赁，不是开关 ⑤弃全自动体验换任何模型/注入都夺不走人对高危的审批权 ⑥对照：审批四态+IM 卡闭合已有、权限档是全局档→进步空间：分层可撤销授权+硬底线"人类专属"清单。

- **②集中式调用缓存 + SQLite 持久化** ②增量执行与跨进程重启存活 ③`dagql/cache.go` 的 GetOrInitCall 是唯一查/插口（in-flight 共享同一次求值），结果带 HitCache/DoNotCache/内容摘要；缓存元数据进 SQLite，BootRestoredResults 支持引擎重启恢复；CachePrunePolicy（保留时长/预留空间/最大占用/最小空闲）结构化回收；session 绑定资源+释放屏障是清理完成契约 ④缓存即数据库，不是旁路 ⑤弃 buildkit 自带层缓存的简单性换 call 级跨 run 复用与可审计占用 ⑥对照：事件溯源日志有持久层→进步空间：缓存作一等持久资产（回收策略+跨重启恢复+占用可审计）。
- **③Lazy parts + 跨 session 接算** ②大工件不阻塞 DAG 求值 ③结果拆 parts 按需物化；producer session 死亡时 foreign-session takeover，重试有界（ErrLazySessionRetryExhausted）配套 offer/restore/renewal 恢复契约 ④只算被观察到的部分 ⑤弃"一次求值全确定"的简单模型换大工件不阻塞（代价是恢复契约代码量）⑥对照：worktree 验证拍全有或全无→进步空间：大件按需物化+宿主死亡可接管，长任务不整体报废。
- **④模块注册=装进动态 schema + 显式能力面** ②跨语言可复用的类型化扩展 ③模块自身带 CallDigest、Ref+Pin 锁版本保复现；Server.InstallObject/Interface/Scalar/Directive 动态扩 schema、Fork 派生子 server，8 语言 SDK 由 schema 生成；自主性边界=全容器沙箱、host/secret 显式授予、secret 从日志洗除、git push 需审批 ④一切扩展都是同一张类型图上的安装；确定性计算无自主决策，只有显式能力面 ⑤弃静态插件 ABI 的简单性换跨语言类型组合 ⑥对照：MCP 接入是外部工具面→进步空间：扩展注册即 schema 安装（发现面同源）+危险外发动作单独设审批。

### 9.2 PraisonAI（MervinPraison/PraisonAI，~9.2k★）— 范式：agent-as-worker 多智能体框架
- **①显式刹车的 Agent 循环** ②自主循环必须可停 ③ExecutionConfig(max_iter/max_budget/on_budget_exceeded) 超限抛 BudgetExceededError 收敛为 completion_reason=error；终止原因枚举 goal/no_tool_calls/max_iterations/timeout/doom_loop/needs_help/error；hierarchical 过程由 manager 校验每步输出并硬停 ④每个刹车都显式且成为可观测输出 ⑤弃隐藏式自动（暴露大量旋钮）换可预测性 ⑥对照：三维预算有 BudgetExhausted 帧→进步空间：终止原因升为一等可观测枚举（含 doom_loop/needs_help）。
- **②Doom-loop 检测（默认开）** ②工具调用死循环/振荡 ③`escalation/doom_loop.py` 六型（REPEATED_ACTION/FAILURE/NO_PROGRESS/CIRCULAR_PLAN/RESOURCE_EXHAUSTION/REPEATED_OUTPUT）+阈值配置（同动作 3 次/滑窗内容复读/300s 上限）；RecoveryAction 五档 CONTINUE/RETRY_DIFFERENT/ESCALATE_MODEL/REQUEST_HELP/ABORT；result-aware 检测按 name+args+result-hash 抓 A→B→A→B 振荡、放过输出持续变化的轮询 ④按"证据"而非"相似度"判卡死 ⑤弃误伤率（阈值启发式）换默认开启 ⑥对照：reflexion 是事后教训沉淀→进步空间：环内实时卡死检测+五档恢复动作。
- **③审批后端可插拔** ②高危工具需人工放行 ③`approval/backends.py` 四后端：Auto（无人值守）/Console（once/session/always 三档+可复用放行规则建议）/AgentApproval（另一 LLM 当审查者）/Callback；verdict 解析映射 APPROVE/DENY/ESCALATE 且 fail-closed；防注入：拆参数标签、剥 shell 注释 ④审批是一等可插拔后端而非 UI 附庸 ⑤弃通过率换安全默认+防御性解析 ⑥对照：审批四态是内建单闸→进步空间：审批后端可插拔、"once/session/always"常驻规则分级。
- **④AgentFlow 拓扑即数据 + 默认关的 Step Cache** ②超越顺序链的编排与确定性步骤重复付费 ③组合原语 Route/Parallel/Loop/Repeat(until=)/Discussion/Include(recipe=)/If，Parallel 有 partial_ok/fail_fast/fail_all 三失败语义+超时抛错永不挂死，同一图可 YAML 表达；step cache key=sha256(步骤身份+输入+前步输出+带类型标签变量)，有界 LRU+存取 deepcopy 防污染、Include 独立命名空间，docstring 原话"Nothing caches unless asked" ④图是可版本化产物，控制流是库而非引擎 ⑤弃图执行器的静态分析/缓存能力换 5 行可写；弃命中率换"预期会再跑一次就真的再跑" ⑥对照：任务编排未建→进步空间：编排拓扑作可版本化数据+步骤缓存默认关。

### 9.3 Langflow（langflow-ai/langflow，~155.7k★）— 范式：视觉节点图编排（flow JSON→DAG 运行时）
- **①就绪度调度的图运行时** ②前端 JSON 变可执行顺序 ③`lfx/graph` 分层拓扑排序后由 RunnableVerticesManager 维护 predecessor fulfilled 集、每 vertex 完成后动态取下一批并发跑；环靠 CycleEdge 显式容纳（Loop 组件）④DAG 为主、环为受控例外 ⑤弃纯拓扑确定顺序/静态分析换并行与环支持 ⑥对照：器官 9 件 tick 串联固定序→进步空间：就绪度驱动并行调度+环显式登记。
- **②主体隔离的结果缓存（命中前重新授权）** ②重复运行成本与多租户缓存串读 ③frozen vertex 经注入 get_cache/set_cache 复用旧结果；缓存键按 principal 命名空间（user:…:end-user:…，租户串读事故后加）；读缓存前先重新过 provider 策略授权，被撤销的 provider 不能复用旧输出 ④缓存命中也必须过授权 ⑤弃全局复用率（按主体分键）换隔离 ⑥对照：会话写闸管并发写者→进步空间：缓存键按主体分区+撤销后旧产物不复活。
- **③分支失活即控制流** ②DAG 里的条件/迭代 ③If-Else 输出名触发 mark_branch 把可达下游置 inactive（只剪该输出的分支、可按条件剪）；Loop 组件每轮重新激活状态节点 ④控制流=运行时顶点激活状态的变异 ⑤弃独立控制流 IR 的静态可判定性换可视化直觉 ⑥对照：决策流三相是语义层→进步空间：条件分支的语义落为"激活状态"数据。
- **④暂停/检查点（中段人审）** ②长流程中段需要人审 ③pause 信号轮询生效后产出 GraphCheckpoint（图序列化+各 vertex built 状态）落 CheckpointStore，每个 vertex 的构建结果/工件独立持久化为 vertex_builds 行，可从中段恢复 ④流程状态必须可快照、可从中间恢复 ⑤弃快照序列化开销换半自动逐节点控制 ⑥对照：审批四态+IM 卡有人审→进步空间：长流程快照/中段恢复（人审在流程中途落锚点）。
- **⑤组件即工具的同一注册面** ②组件复用为 agent 工具 ③ComponentToolkit 把任意组件输出方法包装成结构化工具，工具名派生+同名消歧；每次调用在组件副本上解析输出方法；flow 本身可导出为 API 工具/MCP server ④视觉组件与 agent 工具是同一注册表 ⑤弃静态类型检查强度换"画出来的图直接变工具" ⑥对照：工具注册有 CapabilityRegistry→进步空间：编排产物直接升格为工具面（发现面同源）。
- **范式对照一句话**：Dagger 把自主性消灭在内容寻址里（纯函数求值，自由度只剩显式能力面）；PraisonAI 把自主性关在 worker 内靠刹车+审批收束；Langflow 用图拓扑收束自主性（分支失活/缓存授权/pause 把决策留给结构和人）。

## 10. Omnigent — 元 harness（omnigent-ai/omnigent，~10.8k★，Databricks）
- **①三层策略栈 PolicyEngine** ②跨管理员/开发者/用户的统一授权 ③PolicyEngine 每 workflow 构造一次、显式传四个 enforcement sites（无 ContextVar）；按声明序求值，DENY 短路、ASK 累积、ALLOW 继续；三层 Session→Agent spec→Server，越靠近用户越先短路更严；LabelDef 热缓存写穿 conversation_store（含 monotonic 约束）；ASK 走超时审批，agent 可 sys_add_policy 自加策略 ④策略是声明式闸门而非 prompt 恳求，越靠近用户的规则越优先 ⑤弃中心化单点审计简单性换"每角色管自己的风险面" ⑥对照：审批四态是单层判定→进步空间：策略分层求值序+label 状态单调约束。
- **②预算降级门 + 子树记账** ②控制花费且不误杀长任务 ③cost_budget 在 request（纯文本轮也计费）+tool-call 双闸；软阈值越过 ASK，硬上限是"降级门"：仅在昂贵模型上 DENY、/model 换便宜后放行；_root_conversation_id 把预算审批路由到 spawn 树根——一次审批覆盖整棵子 agent 树；用量持久化于 conversation_store，子树记账默认懒加载零开销 ④预算是引导行为的软约束，不是硬墙 ⑤弃绝对花费上限的严格性（降级而非停止）避免腰斩长会话 ⑥对照：三维预算超限即熔断→进步空间：硬限=降级门不腰斩+子树预算一票审批。
- **③爆炸半径策略 + 沙箱/环境默认拒绝** ②防一击毁机/偷渡密钥 ③三级分类：_DENY_PATTERNS（git reset --hard <remote>/）永拒、_ASK_PATTERNS（gh pr merge、terraform apply/destroy）先问人、rm -rf 危险目标识别；shlex 切语句逐条判（docstring 自认"安全网而非安全边界"）；真边界是 bwrap/seatbelt 沙箱+deny-by-default 环境（跨厂商密钥不继承，需显式 env_passthrough）④启发式防呆与 OS 沙箱分层——前者宽容、后者兜底 ⑤弃启发式的安全性声称（可被子 shell 绕）换明显误操作零延迟拦截 ⑥对照：写总闸"保守扫描宁误拒不漏放"同思想→进步空间：明示"防呆层/边界层"分层职责，防误拒被误当安全缺陷。
- **④Harness 适配层（bridge/forwarder/hook + ACP）** ②不改各家 harness 就能统一驱动/审批/透传 UI ③每 harness 一包：bridge（会话桥）、forwarder（transcript 增量转发/compaction 恢复/子 agent 投递）、hook（PermissionRequest 镜像成 web 审批卡）；第三方走 ACP over stdio，凭证留 vendor 自管、--model 拒绝而非静默丢弃；launch.json 存"如何启动→如何 resume"契约；进程树 zygote/process_manager 管 ④适配而非重写——每个 harness 保留原生身份与登录 ⑤弃跨 harness 行为一致性（能力矩阵靠实测）换第三方即时兼容 ⑥对照：apeireth-acp 远程宿主已有→进步空间：resume 契约落盘（启动→恢复同一张单）。
- **⑤Polly 编排器：分工/仲裁/预检** ②多 agent 分工的调度与独立仲裁 ③spawn:true 注册 sys_session_create 拉子会话；七 worker 挂不同厂商 harness，编排者本人禁写代码（按"种类"而非大小切分）；首轮 roster preflight 读就绪图（binary-missing/needs-auth 即不派发，fail-loud 不盲重试）；实现者各开 PR、diff 交**不同厂商** reviewer 交叉审，人类合并、编排者永不 merge ④编排者是 tech lead 而非全能 agent——用厂商多样性换独立复核 ⑤弃速度与 token（每 diff 跑两遍）换去偏审查 ⑥对照：议会 council 是同模型多顾问→进步空间：仲裁用异构评审源+人保留合并权。
- **⑥会话持久化 + 跨端协作** ②长任务跨设备/跨进程/跨人存活 ③server 持 conversation_store（labels/usage/cost）会话跟人走；harness 状态按 conversation-id digest 存 launch.json，另有 process-registry(+lock) 追踪进程；缓存用 .staging+backup rename 原子替换、回滚失败保留 backup 不自动清理（人工恢复流程成文）；协作原语：Share 共看、attach co-drive（消息在 owner 机器执行）、run --fork 分叉 ④状态归 server/harness 所有、UI 只是视图——恢复优先于重建 ⑤弃全状态单文件可迁移换与原生 resume 格式零摩擦共存 ⑥对照：SQLite WAL 单库已有→进步空间：staging/backup 原子替换+残骸不自动清的可人工恢复纪律。

## 11. Self-Improving 合集 — 自改进模式分类学（selfimproving-agent/Awesome-Self-Improving-Agents，~557★，arXiv 2607.13104）
- **①A_t=(θ,Σ) 改进分界律** ②"自我改进"一词被滥用 ③形式化：agent 配置 A_t=(θ_t, Σ_t)，Σ=(p prompts, m memory, T tools, g control logic)；瞬态执行状态 X_t（对话历史/KV cache）**不算**自我改进；改进必须是持久的、自诱发的组件更新 ④把自我改进收窄为"可指认哪一组件被改"的持久更新 ⑤弃"会反思=自我改进"的宽定义换可测量性 ⑥对照：reflexion 教训持久化已合规→进步空间：每项自改进声明须指名改动的 p/m/T/g 组件。
- **②两轴解耦 + skill 正交定义** ②参数学习与脚手架学习混为一谈 ③Axis1 参数慢环（θ 更新，信号三型：生成示范/评估反馈/探索经验）vs Axis2 脚手架快环（Σ 更新，θ 冻结，按 p/m/T/g 分）；skill="自诱发更新算子 U 的可复用实例"，可序列化进任一 substrate，与 substrate 轴正交 ④快慢两环分开治理，skill 跨基质复用 ⑤弃统一学习框架叙事换两环各自的门控/回滚纪律 ⑥对照：教训回路在快环（p/m）→进步空间：skill 化沉淀（可序列化、可跨器官复用的更新产物）。
- **③评估器独立性 + 校准门控** ②自评自我确认偏差 ③evaluator 与生成器必须分离（"evaluator independence"）；校准研究进必读清单；评估轨迹决定是否接受更新 ④agent 可当自己的 critic，但 critic 是被治理的独立基础设施 ⑤弃单模型闭环的便宜换无 reward hacking 的更新门 ⑥对照：Judge 显式判定已是外部信号源→进步空间：教训蒸馏接受前过独立校准评估。
- **④防回退三件套** ②自我更新会遗忘/回退 ③replay/正则/LoRA 抗灾难遗忘；显式版本化+checkpoint 回滚（reverting to a prior checkpoint）；prompt 侧 best-so-far 保留、旧版本不删 ④每次更新都可撤销是自我改进的安全底线 ⑤弃激进更新速度换可回退性 ⑥对照：教训回路无回滚→进步空间：教训库版本化+回滚锚点。
- **⑤Full Scaffolding 自编辑的门控栈** ②让改进本身可被改进（自指闭环）③目标=Σ 整体（控制逻辑/工具/技能库），持久化为自身源码/配置/skill library；门控=benchmark 评估+人工审阅（Reviewed Core Evolution）+独立 verifier+沙箱；DGM 归档父代 agent 供回滚；README_AGENT 明示"gate persistent updates through layered validation, permission boundaries, regression testing, and rollback" ④改进器与被改进物同体演化，但更新必须过层层验证 ⑤弃最大可塑性的安逸换最大风险面下的验证栈 ⑥对照：写总闸+审批四态管外部写→进步空间：自我改写面（若建）须过独立验证+回归+回滚栈。

## TOP5 机制排名（本族）
1. **失败→补丁→同批重跑验证闭环**（Harness-R1：overlay-only DSL + delta 奖励 + 任务身份哈希锁）——理由：教训从"文本"升级为"可执行且可证伪"，补丁面冻结主体代码保回归安全，奖励=同题重跑的真实增益；是我们教训回路的下一级形态。
2. **六层状态内核 + Governed Turn 类型化结算**（LoopX：append-only 事件账本 + TURN_RESULT_KINDS + 恢复不重复记账）——理由：长周期耐久性的账本级答案，"turn 结束算什么、崩溃后算不算花过钱"有确定性词汇表；断点/恢复/预算三题一解。
3. **持久任务队列 + assign 即唤醒 + 幂等去重**（agent-teams `tasks_db`：认领授权、failed 只能人判、redelivered 重投递）——理由：跨重启的多 agent 交接耐久性一次解决，正对"任务编排未建"的空位，且状态推进显式与我们审批哲学同向。
4. **Action-bound 审批 + 委派信任收窄**（AGT `ActionBinding` JCS digest + `min(parent,requested)`）——理由：把审批绑定到字节级动作，堵"批准后改参数"的静默越权（正对我们威胁模型 G2 自认的族等价绕过）；信任随深度单调收窄，正合星群多户分权。
5. **预算降级门 + 子树记账**（Omnigent `cost_budget`：软阈值 ASK、硬限只降级不停、一次审批覆盖 spawn 树）——理由：预算从硬墙变引导，长任务不被腰斩；子树一票审批直接升级三维预算的粒度。
