## 2. 关键架构决策（rc 阶段必须锁）

### 2.1 LLM Factory 抽象

**问题**：v2 governance / council / orchestrator / perception 都需要调 LLM，但：
- 5 个 hook 都已经有 trait，impl 集中好
- 不同模块需要的 model 不一样（per scene-d §5 决策 1：reviewer 用不同 model 隔离）
- 凭证（API key）必须走 `CredentialResolver`（不是 `String`）

**rc 决策**：在 `apeireth-plugin` 新增 **`LlmFactory` trait**（与 `CredentialResolver` 同位）：

```rust
pub trait LlmFactory: Send + Sync {
    /// 起一个独立 LLM 实例 (scene-d §3 多 instance 隔离)
    fn spawn(&self, role: SubagentRole, model: &str) -> Result<Box<dyn LlmInstance>, LlmError>;
}

pub trait LlmInstance: Send {
    async fn complete(&self, req: CompletionRequest) -> Result<CompletionResponse, LlmError>;
    async fn stream(&self, req: CompletionRequest) -> Result<Pin<Box<dyn Stream<...>>>, LlmError>;
}
```

**约束**：
- `LlmInstance` 必须是 **独立**的 LLM 调用上下文（独立 temperature / 独立 system prompt / 独立 tool config），不共享
- 凭证走 `ctx.credentials.resolve("provider.<vendor>.api_key")`
- 所有 governance/council/orchestrator 通过 `LlmFactory` 调 LLM，**不直接**知道 provider 细节

### 2.2 SQLite migration 策略

`StorageError` / `MemoryBackend` 当前走 `SqliteConnectionPool`（writer + reader pool）。rc 阶段需要：
- `MemoryBackend` trait impl 把所有 Episode / Note / Session / IdentityCard 操作映射到 SQLite 表
- **不引入 ORM**（per master 偏好）
- migrations 走现有 `migrations.rs` 机制（已有 5 个迁移）
- 索引：`(session_id, timestamp)` / `(subject_id, created_at)` / `(stream_kind, session_id, created_at)`

### 2.3 Keyring 接入策略

`KeyringCredentialResolver` (alpha) 是 trait wrapper。rc 阶段：
- 添加 `EncryptedFileBackend` 真实 AES-GCM 加密（alpha 只是 trait 定义）
- 凭证默认走 `KeyringSelector::select()`（按 `APEIRETH_KEYRING_BACKEND` env 选 backend）
- CLI bootstrap (`build_canonical_runtime_from_env`) 真正用 keyring 拿 API key，不再 `std::env::var`
- master token 仍走 `GatedCredentialsStore` + `DenyAllGate`（fail-closed）

### 2.4 Council 的真实 60s timeout

rc 阶段：
- `Council::decide()` 用 `tokio::time::timeout(Duration::from_secs(60), futures::future::join_all(7 LLM calls))` 包住
- 任一 advisor 失败 → 该 advisor 视为 Abstain（不算 30% 阈值）
- 60s 触发 → CouncilVerdict::DeferToHuman（不是 Vetoed，runtime 转 RequireApproval）
- governance 已有 RequireApproval 决策路径（per upstream `8732857` wiring），直接复用

### 2.5 SelfAssessmentCache 触发策略

`SelfAssessmentCache` trait 已有（alpha 0 装）。rc 触发：
- **时间驱动 fallback**：每 100 turn 强制一次（`crates/engine/runtime/src/canonical/execute.rs::execute_outcome` 加 `if self.turn_counter % 100 == 0`）
- **事件驱动**：每次 tool 失败 → 触发 + 写缓存
- 多 instance：评估用 `model: "anthropic/claude-3-5"`，主对话用 `"MiniMax-M3"`（per scene-d §5 决策 1）
- 缓存读：runtime 在每 turn 开始前查 `SelfAssessmentCache::recent_for_task(task_id, 5)`，如果最近一次 alignment < 0.6 → 触发 `DeviationReport` 给主人

## 3. 详细工作分解（每项含 acceptance criteria）

### RC-1: MemoryBackend trait → SQLite impl

**位置**：`crates/engine/memory/src/backend/sqlite.rs` 已有 trait impl `SqliteBackend` 是 0 装薄包装（写 `append_stream` 用 `StreamHandle` 但 Episode/Note 直接走 `EpisodeStore::put_episode`）。

**rc 任务**：
- 把所有 `MemoryBackend` 方法在 `SqliteBackend` 用**纯 SQL**实现（绕开 `SqliteMemoryStore` 的 mutex，因为 trait 要求 `Send + Sync`）：
  - `put_episode` → `INSERT INTO episodes (...) VALUES (...)` 含 append-only trigger
  - `get_episode` → `SELECT ... WHERE id = ?1`
  - `recent_episodes` → `SELECT ... WHERE session_id = ?1 ORDER BY timestamp DESC LIMIT ?2`
  - `append_stream` → 6 个流表（thought_stream / proposal_stream / ...），触发器拒 UPDATE/DELETE
  - `list_stream` → 跨表 dispatch by `StreamKind`
- 添加 `episode_index` 表（performance，per session_id 快速查）
- 添加 unit test（每方法 3 测试）

**Acceptance**：
- `cargo test -p apeireth-memory --lib backend::` 全绿
- 性能：1000 episode 写入 < 1s（in-memory sqlite）
- 现有 `SqliteMemoryStore` 不破（向后兼容）

### RC-2: Experience trait → SQLite impl

**位置**：新 `crates/engine/memory/src/experience_store.rs`。

**任务**：
- `WikiEntryStore::put_wiki` / `list_wiki` / `wiki_for_episode` → 新表 `wiki_entries`
- `KnowledgeGraphStore::put_fact` / `put_link` / `facts_from` / `links_from` / `forget_subject` → 新表 `kg_facts` / `kg_links`
- `AssociationStore::record_cooccurrence` / `top_associations` → 新表 `association_edges` (entity_pair PK, weight 字段)
- 全部 migrations 加到 `MIGRATIONS` 数组（v6 → v7+）
- schema 索引：`(session_id, extracted_at)` for wiki；`(subject_id)` for kg；`(entity_pair)` PK for assoc
- `extract_experience_from_episode` 从 0 装占位升级到：调 LLM（scene-d 例 1 SingleInstance）跑 `extract_wiki_and_kg_from_episode` prompt 解析 → 写存储

**Acceptance**：
- 12+ 测试（每个 trait 方法 2-3 个）
- 与 `SqliteMemoryStore` 同 SQLite 连接，复用 migrations
- 0 装部分保留 trait 默认 impl 走 0 装占位（向后兼容）

### RC-3: PreferenceStore trait → memory impl

**位置**：`crates/engine/memory/src/preference_store.rs` (新文件)

**任务**：
- trait `PreferenceStore`：`record(stance, evidence)` / `recall_for_context(session_id, current_topic) -> Vec<UserPreference>`
- `UserPreference { topic, stance, evidence_refs, created_at, confidence }`
- 新表 `user_preferences` (session_id, topic, stance TEXT, confidence, evidence_refs TEXT (JSON array), created_at)
- `recall_for_context` 简化为：session_id 下 top-N by confidence + topic LIKE
- `extract_preference_from_turn` 调 LLM 1x per turn（scene-d §1 preferencd），low cost
- 检索时按 `confidence DESC LIMIT 3` 注入 transcript

**Acceptance**：
- 5 测试（record / recall / context-aware ranking）
- transcript 注入与现有 `MemoryBackend` 集成

### RC-4: SelfAssessmentCache → SQLite

**位置**：`crates/engine/memory/src/self_assessment_store.rs` (新)

**任务**：
- trait `SelfAssessmentStore`: `record(sa)` / `recent_for_task(task_id, n)`
- 新表 `self_assessments` (task_id, round, alignment, quality, deviations JSON, assessed_at, reviewer_id)
- integration: `Runtime::execute_outcome` 在每 100 turn 触发 `SelfAssessor::assess(turn_context)` → 调 LLM (multi-instance per §5 决策 1) → 写 `SelfAssessment`
- 启动时 (turn 0) 读 `recent_for_task(session.task_id(), 5)`，如果 alignment < 0.6 → 触发 `DeviationReport` → runtime 报告给主人

**Acceptance**：
- 4 测试 (record / query / integration with runtime)
- 与 RC-3 同 SQLite 路径
- 0 触碰 13 键 verdict cache (key 独立, 物理隔离 per scene-d §3)

### RC-5: Orchestrator → runtime LLM harness

**位置**：`crates/engine/runtime/src/llm_orchestrator.rs` (新)

**任务**：
- struct `LlmOrchestrator` 实现 `apeireth_orchestration::Orchestrator` trait
- 持有 `Arc<dyn LlmFactory>` + `Arc<dyn CredentialResolver>`
- `start/stop` 初始化 LLM factory
- `dispatch(spec)` 走流程：
  1. 调 `governance.evaluate(...)` 拦截（runtime 的 `arc_dyn_governance_hook`）
  2. 如 Deny → 返 `GovernanceDenied`
  3. 如 RequireApproval → 暂存 + 通知主人（runtime 持久化 PendingApproval）
  4. 通过 → `LlmFactory::spawn(spec.role, spec.model)` 拿独立 LLM instance
  5. 调 `llm.complete(complete_with_tools(spec))` → 拿 output
  6. 写 `subagent_outcome` 持久化
- `orchestrate(title, payload)` 走默认三步：Planner → Implementer → Reviewer
- 集成 `SelfAssessor` （RC-4）做每 100 turn 自评估

**Acceptance**：
- 6 测试 (governance 拦截 / LLM spawn isolation / 3 步 orchestrate / 凭证不暴露)
- `cargo test -p apeireth-runtime --lib` 全绿

### RC-6: Council → multi-LLM 并行

**位置**：`crates/engine/runtime/src/llm_council.rs` (新)

**任务**：
- struct `LlmCouncil` 实现 `apeireth_orchestration::Council`
- 持有 7 个 `LlmAdvisor`（每个是独立 `LlmInstance`，7 LLM 并行调用）
- `decide(proposal)`：
  1. `tokio::time::timeout(Duration::from_secs(60), futures::future::join_all(7 LLM calls))`
  2. 任一 advisor 失败 → 视为 Abstain（不算阈值）
  3. 任一 advisor Deny → `Vetoed { by, reason }`
  4. 全 Allow/Abstain → `Approved`
  5. 60s 超时 → `DeferToHuman { reason: "60s no consensus" }`
- 7 个 advisor system prompt 模板：safety / performance / philosophy / history / strategy / ethics / legal

**Acceptance**：
- 5 测试（7 advisor 并行 / 60s timeout / 任一 Deny 即 Vetoed / 失败即 Abstain / DeferToHuman 路径）
- integration with runtime：runtime 在关键决策点（hook Action 风险等级 ≥ medium）触发 Council

### RC-7: Perception 真实 modality

**位置**：`crates/engine/perception/src/`

**任务**：

**Acceptance**：
- 6 测试（whisper API 客户端 / xcap capture / config switch）
- 真实 mod 仍归 0 装（用户不开启就返 NotImplemented）
- LLM 调用走 `LlmFactory`

### RC-8: SubSupervisor → tokio::process

**位置**：`crates/capabilities/tools/src/supervisor_runtime.rs` (新)

## 5. 风险与缓解

| 风险 | 影响 | 缓解 |
|---|---|---|
| LLM 调成本（每 turn 1-7 LLM call） | token 费用 | `LlmFactory` 默认 model 是 cheap model；advisor sub-agent 才能用贵 model；PerSpec 缓存相同 prompt |
| 5 个新 trait + 10 个新 impl 改 API 表面 | 12 个 v1 consumer 破 | additive-only 设计（alpha 已验证）；v2.0.0-rc 锁 API 后才允许改 |
| SQLite migration 失败 | 现有 memory data 损坏 | migrations 走 `MIGRATIONS` 数组顺序执行；每次 migration 写 idempotent SQL；新增表 `IF NOT EXISTS` |
| keyring 不可用 (CI 环境) | 凭证解析失败 | `KeyringSelector` 自动降级到 `InMemoryKeyring`（test only）+ 0 装错误信息 |
| Council 60s timeout 频繁触发 | 长程任务响应差 | advisor 数量可配（v1 5 个 → v2 3 个 core + on-demand）；per-advisor timeout 10s（不是 60s 总） |
