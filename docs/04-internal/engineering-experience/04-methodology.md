## 一、已验证配方

### 配方 1 · 剥装饰取材

【情境】外部 README/巨文件的装饰层（徽章/横幅/徽标表格）先霸屏，读入量大半是装饰、有效信息不到一成；整读 = 上下文读爆（02 矿死法 3）。

【配方】①**剥装饰**：取有效正文（剥徽章/横幅）；若前 N 行是徽标/表格等纯装饰标记层，取**有界等价窗口**——剔除装饰行后的前 N 行实质内容；②**限读**：每源读取量封顶（先例口径：README 前 80 行 / 单项目累计 ~160 行以内），超限截断并注明，不硬读；③截断/等价窗口在条目处逐一注明。

【验收形状】取材文档抬头带「取材口径」注（剥装饰/限读/截断范围）；每个条目能指回"取的是哪段"。

> 出处：★[philosophy-study/02-memory-family.md](../philosophy-study/02-memory-family.md) 抬头「取材方法说明（如实记录）」（限读口径 + 有界等价窗口 + 单项目 ~160 行）；★[philosophy-study/01-companion-family.md](../philosophy-study/01-companion-family.md) 抬头研究引注（剥徽章/横幅）；★[02-failure-anatomy.md](02-failure-anatomy.md) 死法 3 药方（同款三联，此处只记配方、案例与死因见 02 矿）。

### 配方 2 · 渐进落盘三律

【情境】批不可能一次做完：中道猝死、上下文预算烧穿、跨批接续都会丢成果；把全量挂在上下文里既易爆又无法断点续作。

【配方】宪章 §六.1 三律：①**做一段落一段**——每个处理单元完成即落盘（小文件族/骨架先行），中道猝死不丢成果、可续作；②**限读取材**——读前先定读取预算，装饰层剥除后取有界等价窗口，单源超限即截断不硬读；③**外部素材先净化后入上下文**（触发词替换为占位），取材口径（净化/限读/剥装饰）在产出抬头如实注明。配套收益：渐进式披露一处 35k→920 token（-97%）。

【验收形状】任何"批开工"动作先产出骨架文件再展开内容；产出按小文件族组织、每单元完成即落盘（断点可续）；交付文档能指回「已完成/未完清单」。

> 出处：★[CONSTRUCTION-DISCIPLINE.md](../backend-enhancement/CONSTRUCTION-DISCIPLINE.md) §六.1（渐进落盘三律，2026-10-15 批 L1 实战回写）；★[next-team-handbook.md](../backend-enhancement/00-backlog.md) §1 渐进式披露条（35k→920 token 对照）；★[philosophy-study/02-memory-family.md](../philosophy-study/02-memory-family.md) 抬头「产出纪律（渐进式落盘）」。

### 配方 3 · 单项目粒度

【情境】多项目批量调研里，一个处理单元横跨多项目 = 读入量膨胀 + 中途死亡丢全部 + 落盘粒度无法断点续作。

【配方】**一项目一处理单元**：逐项目序贯处理、每项目即时落盘；单项目读取量有界（实质内容 ≤80 行、累计 ~160 行以内）；吸收裁定走「一项目一小节、机制假说+实证+吸收裁定三段式」——粒度小到"死亡只损失一个项目"。

【验收形状】调研/取材文件每项目一节独立成段、每节自带三段式；项目间零混读；任意时点截断，已完成项目节即成品。

> 出处：★[philosophy-study/02-memory-family.md](../philosophy-study/02-memory-family.md)（"逐项目序贯处理、每项目即时落盘；单项目读取量有界"）+ 逐项目 README 限读口径；★[absorption-candidates-2026-10.md](../03-audits/absorption-candidates-2026-10.md)（"一项目一小节、机制假说+实证+吸收裁定三段式"调研纪律）。

### 配方 4 · 源头净化防过滤

【情境】外部素材自带触发物（擦边营销词/安全词），研究取材批连续多次会话被上游内容过滤器拦杀——毒在素材本身，换措辞重试无效。

【配方】**净化是工序，不是补救**：脚本先行剔除触发词（替换为 `[滤]` 占位）、只留工程骨架后才进分析与产出；引注走净化后的有效正文（研究的天职是引注，但引注不搬触发物）；取材口径（净化已发生、截断范围）在产出抬头如实注明；禁逐字搬运未净化原文。

【验收形状】外部素材的取材管线先过净化再入上下文；研究文档抬头必有「取材口径」注；产出零逐字触发物。

> 出处：★[philosophy-study/01-companion-family.md](../philosophy-study/01-companion-family.md) 抬头研究引注（"…会触发上游内容过滤器"→本轮起采用「源头净化取材」：脚本先行剔除触发词替换为 [滤]、仅留工程骨架）；★[02-failure-anatomy.md](02-failure-anatomy.md) 死法 2（四连猝案例与防复发断言）；☆会话记录（四连猝现场，未落仓）。

### 配方 5 · 沙箱预验

【情境】破坏性/不可逆动作（多文件大改、落盘）直接上真面，一旦验证失败真面已损；"先改完再验"的顺序本身就是风险。

【配方】**先在隔离面预验，验证绿才落真面**：①四拍受控写「计划→改→验证→落」——计划拍零落盘，改拍/验证拍全在暂存面（真面零写入），验证拍 = 纯结构校验恒有 + 可挂校验命令（受控通道：结构化 argv、无 shell 解析、工作目录限域暂存面、超时归一），任一不过 = 整批未落地；落拍**全有或全无**（预演 + 版本 CAS + 原子写 + 失败回滚）；②事务补丁同款两阶段：内存预演→落盘，任意异常自动回滚；③**预检与落地 Guard 同一判定函数**（不各说各话——预检放行而 Guard 拒、或反过来，都是裂缝）。

【验收形状】任一拍失败后工作区与调用前逐字节一致（测试钉死）；验证拍失败在落盘前中止；预检与 Guard 判定一致性有专测。

> 出处：★[worktree-apply-delivery.md](../backend-enhancement/worktree-apply-delivery.md) §一 四拍表 + §二 关键性质（落盘前真面零写入/全有或全无/改单是合同）+ §四 测试表（原子回滚、验证拍失败即回滚、预检与 Guard 同判定三行）；★[worktree_apply.rs](../../../crates/capabilities/tools/src/worktree_apply.rs) 头注与边界预检注（"同一判定函数，预检与 Guard 不各说各话"）；★[capabilities-matrix.md](../../03-reference/capabilities-matrix.md)（受控补丁：内存预演→磁盘写入，任意异常自动回滚）。

### 配方 6 · 隔离复跑定性 flake vs 真 flake 定根

【情境】共树并行的"瞬时红"（一次退出码 101、一次格式不净、一次编译中断，复跑即绿）与真缺陷混在一张门禁表里；粗暴归因冤枉好人，"复跑绿了"放走真凶。

【配方】**先定性再定罪**：①瞬时红先隔离复跑——隔离复跑即绿、且期间有并行扰动证据（同 build 目录出现并行抢锁 "Blocking waiting for file lock"）→ 按 flake 口径定性「并行在途扰动」非本批引入，报告固定三件：如实标红 + 明确归属线 + 定性理由；②负载敏感的 flake **不许用"复跑绿了"收账**——必须定根：file_lock 案（标记瞬时失败被误判持有者已死 → 误删活跃锁，改为"接管只认确证"）才算治根，定根后以测试/提交钉住。

【验收形状】门禁报告红就是红（零假绿）；flake 定性行必带扰动证据与归属线；真 flake 有定根提交与防复发断言，不是复跑掩盖。

## 二、接棒遗嘱格式

【情境】批不可能一次做完，中道停机与跨批接续是常态（宪章 §二.3「半成品不弃尸」）——没有遗嘱的半成品就是弃尸。

【格式】交付文档固定一节「接棒清单（未完）」，每条写清**四件**：①**落点文件**（真实路径）②**注册条件**（开关/依赖/同源要求）③**现成零件**（已备好的构造器/挂载点）④**验收形状**（测试名/断言形状）。完成后**就地标 ✅** 并注明收口批 + 兑现的注册条件 + 新增测试名，不留悬空的"未完"。

【模板（直接套）】

```markdown
N. **<接棒项名>**（<落点文件>，<并发注意事项>）：<注册条件>；
   现成零件 = <构造器/挂载点>；验收形状 = <测试名/断言>。
   → ✅ 已收口（<日期> <收口批名>）：<注册条件兑现说明>；测试 `<测试名>` <例数>。
```

【验收形状】接棒清单是活文档：任一时刻「未完」列表反映真实残余；每条 ✅ 都能指回兑现证据（实形先例：组装根注册由总装批按清单原样收口，附注册条件兑现与新增测试名）。

> 出处：★[worktree-apply-delivery.md](../backend-enhancement/worktree-apply-delivery.md) §六「接棒清单（未完）」（四要素实形 + ✅ 就地收口注）；★[CONSTRUCTION-DISCIPLINE.md](../backend-enhancement/CONSTRUCTION-DISCIPLINE.md) §二.3；★[01-collaboration-patterns.md](01-collaboration-patterns.md) 模式 8（遗嘱+就地收口）。

## 三、门禁分层（本批 / 全量 / 权威 三级）

【情境】一张门禁表混跑三级口径会两头误事：只跑全量则迭代太慢、只跑本批则共树回归看不见、数字随手对外则口径漂移。

【分级】

| 级 | 跑什么 | 何时 | 产出什么 |
|---|---|---|---|
| **本批门禁** | 本批增量面：本批新增/触碰的测试目标 + 相关 crate 定向测试 | 施工中随时（快速出口） | 本批增量事实（如"本批新增 N 例"），只对本批负责 |
| **全量门禁** | 宪章 §四全量命令：`cargo test --workspace --all-targets --locked --no-fail-fast -j 2` + clippy `-D warnings` + `cargo fmt --all -- --check` + 前端 `pnpm check`/`pnpm test` + 中性表述扫描 + secret-scan | 每批交付出口必跑 | 全量实测数字（命令+日期+工具链随行，log 留档可复算）；出红走配方 6 定性 |
| **权威门禁** | 口径权威对照：测试数字对 [test-baseline.md](../../03-reference/test-baseline.md)（单一真源，只引用不抄写）；「已验证」对 [live-verification-ledger.md](../live-verification-ledger.md)（验收权威，写"已验证"前先查） | 数字/结论**对外发布前** | 可对外的口径；不一致如实报「本批实测值 + 日期」，不代改真源 |

【要点】①隔离复跑是**全量门禁出红时的定性手段**（配方 6），不是第四级；②三级各有产出物：本批增量行 → 交付文档测试表；全量实测 → 门禁表（命令+日期）；权威对照 → 数字口径注（链路自洽对账）；③本批门禁的绿**不能**当交付门禁用（共树在途回归只有全量看得见）。

## 四、「无脚本不发布数字」执行细则（复测注记写法）

【铁律】无脚本不发布数字（宪章 §三.1）；每个数字必须可复核（命令 + 日期 + 工具链），无脚本不写数字（AGENTS.md §1）；未达标标红，未实测写「未实测」。

【细则】

1. **数字随行三件 + 落档**：命令原样（含 `-j 2` 等口径差异）+ 日期 + 工具链；长输出落档 log（数字可复算），成败判定基于落盘输出文件（防管道截断假绿，02 矿死法 7）；
2. **复测注记写法**（在单一真源内追加注记，**不改基线行**）：

   ```markdown
   > **复测注记（<日期>，<批次名>校验）**：同命令（<口径差异，如加 -j 2>）在当前工作树
   > 复测 = <实数>，exit <码>。与上表差异来自 <归因：树间在途批次增量，逐列对账>；
   > 上表为 <基线口径名>，对外引用保持上表，现场以复测类实数为准。
   ```

   ——实形先例见 [test-baseline.md](../../03-reference/test-baseline.md) §1「复测注记（2026-10-16）」（本矿不抄写数字，只引用写法）；
3. **批文档侧数字口径注**：本批实测与真源做**链路自洽对账**（真源复测值 + 本批增量 = 本批表值，逐列可加）；他口径差异（审计者自计/静态计数）如实注明定义不同，按「不一致如实报本批实测值 + 日期，不代改真源」处理；
4. **边界四不**：不把 ignored 计入 passed；不拿本批门禁数当全量数；不代改真源；不写"应该有 N 个"这类无脚本推算数。

【验收形状】任何对外数字都能三步复核：命令可重跑、log 可对数、真源可对照；差异有归因行。

> 出处：★[CONSTRUCTION-DISCIPLINE.md](../backend-enhancement/CONSTRUCTION-DISCIPLINE.md) §三.1；★[AGENTS.md](../../../AGENTS.md) §1（每个数字必须可复核：命令+日期+工具链）/§3（测试数字单一真源）/§5（数字对外引用对照现行口径，不一致如实报）；★[test-baseline.md](../../03-reference/test-baseline.md) §1 复测注记 + §2 口径定义（套件/例/ignored 三分）；★[audit-gap-behavior-fixes-2026-10-16.md](../backend-enhancement/audit-gap-behavior-fixes-2026-10-16.md) §5「数字口径注」（链路自洽对账 + 他口径定义差异如实注明实形）；★[J-life-integration.md](../backend-enhancement/02-axes/J-life-integration.md) 数字口径注（"未实跑不发布数字"）。
