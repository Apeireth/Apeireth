## 死法 1 · 启动猝死（上下文/额度类）

【症状】新会话/新子代理刚启动或读完第一屏就无声死亡——无报错帧、无产出、无遗言；批量派工时表现为同批多个子代理接连夭折；或启动动作本身"接不上话"。

【死因】启动即超载：一次性读入巨文件/徽章墙把上下文预算烧穿（见死法 3），或首个重动作撞上额度/预算上限——预算顶满的同族机制在产品面早有实证（认知深度档 judge+council 8 次模块调用恰好顶满旧预算 8，第 9 次 `BudgetExceeded` 直接炸毁整个回合）。死亡发生在任何错误通道/遗嘱机制建立之前，所以零遗言、零可接棒产物。

【药方】启动三件套：① 启动前先立**读取预算**（限读口径，见死法 3 药方），不裸读巨物；② **骨架先行**——先落盘骨架/清单再填内容（渐进落盘三律，宪章 §六.1），猝死也留下可续作的骨架；③ 批量派工**分波次、单波小批**，一波夭折不至全军覆没；预算类故障一律走优雅降级（该模块跳过 + 留痕），不枪毙主任务。

【防复发断言】任何"批开工"动作先产出骨架文件再展开内容；交付文档必须能指回「已完成/未完清单」（中道死亡可续作的构造性证据）；预算耗尽路径有降级出口且留痕 `module_budget_degraded` 一类事件。

## 死法 2 · 内容过滤误伤（安全词/擦边词；伴侣族四连猝）

【症状】研究取材批（伴侣族项目 README 取材）**连续四次会话**在读入/复述原文时被上游内容过滤器拦杀；死亡与工程质量无关，纯粹由素材里的擦边营销词触发。换了措辞重试也没用——毒在素材本身。

【死因】原文未经净化直接进上下文与产出：README 的擦边营销词命中过滤面（安全词/擦边词触发），逐字引用、翻译、摘要都可能二次触发；取材流程里没有"净化"这一工序，等于把触发物原样端上桌。

【药方】**源头净化取材**：脚本先行剔除触发词（替换为 `[滤]` 占位）、只留工程骨架后才进分析；叠加剥装饰取材（见死法 3）；取材口径（净化已发生、截断范围）在产出文档抬头**如实注明**——研究的天职是引注，但引注走净化后的有效正文。

【防复发断言】对外部素材的取材管线必须先过净化脚本再入上下文（净化是工序不是补救）；研究文档抬头必须有「取材口径」注（净化/限读/剥装饰声明）；禁逐字搬运未净化原文。

> 出处：★[philosophy-study/01-companion-family.md](../philosophy-study/01-companion-family.md) 抬头研究引注（"伴侣族 README 含大量擦边营销词会触发上游内容过滤器"→本轮起采用「源头净化取材」）；采矿图 §二.2（内容过滤误伤名目）；☆会话记录（四连猝案例）。

## 死法 3 · 上下文读爆（README 徽章墙/巨文件）

【症状】读一个 README/巨文件后会话直接超限死亡，或之后每一步都因上下文逼近上限而变笨、输出截断；徽章墙/横幅/表格等装饰层占了大半读入量，有效信息不到一成（对照数据：全量注入仅约 6% 相关）。

【死因】无预算的全文读入——装饰层（徽章/横幅/徽标表格）先行霸屏；巨文件整读不设限；读完不落盘，全量常驻上下文直到爆。

【药方】三联配方（已在研究线验证）：
1. **剥装饰**：取有效正文（剥徽章/横幅）；若前 N 行是徽标/表格等纯装饰标记层，取**有界等价窗口**——剔除装饰行后的前 N 行实质内容，并在条目注明；
2. **限读**：每源读取量封顶（先例口径：README 前 80 行 / 单项目累计 ~160 行以内），超限截断并注明，不硬读；
3. **渐进落盘**：每处理完一个单元**立即落盘**（渐进式），后续按需展开，不把全量挂在上下文里（渐进式披露的同构收益：一处 35k→920 token，-97%）。

【防复发断言】取材文档带限读口径注；产出按小文件族组织、每单元完成即落盘（断点可续）；巨物读取前先声明预算上限。

> 出处：★[philosophy-study/02-memory-family.md](../philosophy-study/02-memory-family.md) 抬头「产出纪律（渐进式落盘）/ 限读口径（剥装饰 + 有界等价窗口 + ~160 行）」；★[philosophy-study/01-companion-family.md](../philosophy-study/01-companion-family.md) 抬头（剥徽章/横幅）；★[next-team-handbook.md](../backend-enhancement/00-backlog.md) §1 渐进式披露条（35k→920 token 对照）；采矿图 §二.2（上下文读爆名目）。

## 死法 4 · 工具链陷阱族

### 4a. 路径拼接双前缀 / canonical 键分叉

【症状】路径拼接后出现 `\\?\` 双前缀或解析到错误位置；写后回填"查无此人"（同一文件落两个键）；Windows 上 cwd 意外掉到 `%WINDIR%`；本地永不复现、CI 必现。

【死因】`\\?\` verbatim 前缀参与二次拼接与 cwd 解析（`lpCurrentDirectory` 收到扩展前缀就掉 `%WINDIR%`）；`fs::canonicalize` 返回**真实大小写 + symlink 解析后**的拼写，归一化键不展开 symlink/不折大小写时同一文件落两个键——apply_patch 版本 CAS 三连败案的真根因就是 canonical 拼写 vs 裸拼写的键分叉（示踪招供：`target_key=/var/...` vs `gate_keys=[/private/var/...]`）。

【药方】路径归一**只认一把尺**（`path_key` 单一来源复用，不复制第二份词法归一）；拼接/cwd 前剥 verbatim 前缀；路径键按目标平台语义折叠 + 查询方用 canonical 拼写命中；分叉悬案走**示踪三选一**（失败点埋双方键/分支标记，让现场自己招供），不靠理论猜。

【防复发断言】路径归一函数全仓唯一（复用面 `pub(crate)`）；测试含平台语义的断言一律 cfg 守卫；三轮理论不破即转示踪，一轮示踪定案。

> 出处：★[E-object-level-contract.md](../backend-enhancement/02-axes/E-object-level-contract.md) §6（`path_key` 复用报备）；★[live-verification-ledger.md](../live-verification-ledger.md) #49 ④（`\\?\` 扩展前缀 cwd 掉 `%WINDIR%` → 剥前缀）；★[handoff-w1-w5-closure-2026-10-10.md](../01-handoffs/handoff-w1-w5-closure-2026-10-10.md) §89 行；★[ops-network-playbook.md](../00-governance/ops-network-playbook.md) §6.2 键规范化面 + 示踪三选一（含 git log `faad54d7` 破案提交主题）。

### 4b. CRLF 吃替换

【症状】批量文本替换"成功"执行但 0 处生效（或只换一半），后续断言/渲染随之出错；换机器/换编辑器才复现；hash 对账显示"同一文件两种形态"。

【死因】行尾形态参与匹配：CRLF 文件里按 `$`/`\n` 锚定的模式匹配落空，替换被**静默吞掉**（0 次命中不报错）；反过来 LF 假设的补丁落到 CRLF 文件上会吃掉内容。git 的行尾归一/`clean filter` 让同一文件出现两种字节形态，取证会被误判成源码漂移。

【药方】替换正则显式容行尾（`\r?$` 或先归一化）；**替换后断言命中数**（0 次命中 = 失败，不是成功）；批量替换后做配平/结构校验（花括号配平 73/73 式的计数核对）；行尾敏感的取证用无过滤 hash 复核（`git hash-object --no-filters` 口径）。

【防复发断言】任何批量替换脚本带"预期替换次数"断言；批量文本手术后必做结构配平校验；机械空白（fmt）与语义改动分开声明。

> 出处：采矿图 §二.2（CRLF 吃替换名目）；★[live-verification-ledger.md](../live-verification-ledger.md) #37 ⑤（批量 sed 手术事故——选择器断行致整页白屏，还原后逐行重做 + 花括号配平 73/73 校验）；★[research-vcp-rerun-2026-07-31.md](../../archive/research/research-vcp-rerun-2026-07-31.md)（CRLF/clean filter 取证口径：无过滤 hash 复核）；☆会话记录（CRLF 吃替换案例）。

### 4c. PowerShell/shell 语法坑（`@{u}` / 引号 / `-i` 歧义 / Regex 第四参）

【症状】命令"只回显不执行"；`git status -sb` 里的 `@{u}` 段报解析错；`-i` 参数没生效或打到别的参数上；正则替换"忽略大小写"没生效反而把别处参数吃掉。

【死因】① `powershell -Command "..."` 经 cmd `/S` 引号规则 × argv 转义叠加，**双引号被吃**（只回显不执行）；② `@{` 是 PowerShell 哈希表/splatting 语法起手，`@{u}` 不加引号会被 PS 先行解析；③ `-i` 在参数前缀缩写下有歧义（可撞 `-InformationVariable` 族），不同命令族又各有一套 `-i` 语义，缩写落到别的参数上；④ .NET `Regex::Replace` **第四参是 `RegexOptions` 不是 count**——想传"只换一处"会传错位，忽略大小写等选项随之失效。

【药方】cmd 桥接走 **`raw_arg` 直传**（`/D /S /C "<cmd>"` 原样进命令行，双引号全保真）+ 真实执行回归测试；含 `@{`/`$`/引号的命令片段单引号包死或转义，不裸放；参数一律**写全称禁缩写**；`Regex::Replace` 用 options 显式形态 + 替换后断言命中数（同 4b）；bash 嵌套引号/here-doc 重灾区按 ops 手册走 UNC 直改文件 + 单条纯命令。

【防复发断言】shell 面回归测试必须含**真实执行**断言（非 dry-run）；命令文本进文档/测试前在目标 shell 实跑一次。

> 出处：★[engineering-log-2026-10-06.md](../04-logs/engineering-log-2026-10-06.md) §1 #11（引号被吃 → `raw_arg` 直传 + 真实执行回归测试）；★[ops-network-playbook.md](../00-governance/ops-network-playbook.md) §5（bash 嵌套引号/here-doc 一日三踩）；采矿图 §二.2（`@{u}`/引号/`-i` 歧义名目）；☆会话记录（`@{u}`、`-i`、Regex 第四参案例）。

## 死法 5 · 多帧 zstd 解包

【症状】压缩包"解包成功"但内容只剩开头一段；换工具/重下后正常；校验缺位时坏产物直接流进后续工序。

【死因】zstd 流可由**多帧首尾相接**构成，单发解压接口只吐第一帧就报成功；叠加分块下载拼接场景（忽略 Range 的节点回整文件、分块拼接必坏）时更容易出现"能解但不全"。

【药方】解包后按**总尺寸/清单校验**（每块字节数 == 区间长度、拼接后 == Content-Length 的同源纪律）；用显式循环解到流尾（多帧全部展开）再验内容；宁可"解不出即帧"，不接受"解出一半"。

【防复发断言】解包产物带完整性校验（尺寸/条目数/哈希之一），校验不过不算交付；下载分块拼接必过尺寸校验关。

> 出处：采矿图 §二.2（多帧 zstd 解包名目）；★[ops-network-playbook.md](../00-governance/ops-network-playbook.md) §2（分块下载的尺寸校验纪律：逐块尺寸 == 区间长度、总尺寸 == Content-Length）；☆会话记录（案例）。

## 死法 6 · 扫描器豁免表滥用边界

【症状】中性表述扫描命中后，第一反应是往豁免表加一行让红变绿；豁免计数悄悄上涨，"扫描零命中"变成"零命中（因为都豁免了）"；叠加扫描器盲区后出现假绿。

【死因】豁免表的正当用途是**结构性豁免**（真实路径/真实文件名/本表自身/研究引注特权文件，"路径保持准确"原则）；滥用它就把门禁第四条（扫描零命中）变成自我安慰。扫描器自身也有过盲区（未跟踪新文件不扫、单行文件标量索引漏行）——豁免滥用 × 盲区 = 假绿双重奏。

【药方】命中先**改表述/归置素材**，不先改豁免表：外部源码/抽取暂存物**出库**（移出扫描面并出索引），而不是给它豁免位；豁免仅限真实字符串且豁免计数随输出公开可审计；扫描器盲区用补扫补掉（未跟踪新文件全文扫描、单行文件索引修复）而不是接受。

【防复发断言】门禁报告里豁免计数可见；豁免表新增行必须带"真实字符串"理由；"扫描零命中"语义 = 0 命中 **且** 豁免仅限结构性（新增豁免行 = 评审事件）。

> 出处：★[scripts/check-neutral-terms.ps1](../../../scripts/check-neutral-terms.ps1) 头注与 `$exemptRe`/`$exemptFiles`（结构性豁免口径 + 豁免计数输出）；★[W3-2-user-identity-roles.md](../backend-enhancement/04-delivery/home-W-axis-delivery.md) §6 中性表述行（外部暂存命中 → 归置后复扫全绿）；★git log `2c701d0a`（外部源码出库——抽取暂存与嵌入仓库移出索引）、`1593a0d4`（扫描器补盲区——未跟踪新文件全文扫描 + 单行文件标量索引修复）。

## 死法 7 · 管道截断假绿（三次假绿事故的根源）

【症状】验证/构建命令"通过"但实际失败；退出码 0 归了截断者，真失败被静默掩盖。

【死因】`... | head -N` / `Select-Object -First N` 提前关管道，SIGPIPE 杀掉上游，`$LASTEXITCODE`/`exit 0` 是截断者的——门禁看到的绿是截断者的绿。

【药方】验证/构建输出**一律落文件再 grep**；成败判定基于落盘输出文件，不是管道末端。

【防复发断言】门禁命令的判定输入是落盘输出文件；发现"管道直判"写法即整改。

> 出处：★[ops-network-playbook.md](../00-governance/ops-network-playbook.md) §5 管道截断条（明记"三次假绿事故的根源"）；★[kani-verification-playbook.md](../kani-verification-playbook.md) K9。
