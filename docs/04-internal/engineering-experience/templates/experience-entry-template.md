## A. 条目骨架（`## 条目 N · <一句话主张>`）

```markdown
## 条目 N · <一句话主张（读者能直接照做的那种）>

【情境】<什么时候会撞上这件事：具体到「谁在什么状态下要做什么」>

【做法】<怎么做：分条、每条可执行；写明**拒了什么**与**为什么拒**>

【效果】<照做之后买到什么：可判定的结果，不是「更规范了」>

【锚点】<仓内可点击复核的位置：文件路径 + 小节/函数名；数字带日期与出处>

【守卫】<退出码可判的命令；没有守卫的经验不许进矿>

> 出处：★[<文件路径>](<相对链接>)（<小节/函数名>）· ★`<commit sha>`（<提交正文里的哪一段>）
```

## B. 各矿型的**必填段**（守卫按此判，缺一即红）

| 矿型 | 文件前缀 | 必填段 |
|---|---|---|
| 协同模式 | `01-` | 【情境】【做法】【效果】 |
| 死亡解剖 | `02-` | 【症状】【死因】【药方】【防复发断言】 |
| 设计裁定 | `03-` | 【裁定】【被拒案】【理由链】 |
| 方法论配方 | `04-` | 【情境】【配方】【验收形状】 |
| 产品洞察 | `05-` | 【洞察】【制度化落点】【可复用判据】 |
| 真源 | `06-` | 【情境】【做法】【效果】【锚点】【守卫】 |
| 工作线 | `07-` | 【情境】【做法】【效果】【锚点】【守卫】 |

## C. 纪律（六条）

1. **锚点必须能点开**：相对链接指向**现存**文件；文件被搬家 ⇒ 改链接，**不许**留陈旧副本；
2. **出处行至少一个链接**（`> 出处：` 行里要有仓内链接）⇒ 只写 commit sha 不算（提交会沉进历史）；
3. **数字必须可复核**：命令 + 日期 + 工具链；口径与真源不一致 ⇒ 如实报「本批实测值 + 日期」，不代改真源；
4. **一条经验对应机器层失败模式** ⇒ 在条目里写 `FP:<id>`，并在
   [`.harness/knowledge/failure-patterns.yaml`](../../../../.harness/knowledge/failure-patterns.yaml) 登记该 id
   （守卫判**双向**：yaml 的每个 id 必须被矿引用，矿引用的 id 必须存在）；
5. **不写「未实测」的东西**（推断就写「推断」，未验就写「未验」）；
6. **一篇一矿**：新矿另开文件（`NN-<name>.md`），并在 [族内 README](../README.md) 的表里**加一行**
   （索引覆盖 ⇒ 接手者查得到）。
