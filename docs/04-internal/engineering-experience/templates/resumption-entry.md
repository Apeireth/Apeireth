## A. 接棒清单条目（放交付文档「接棒清单（未完）」节，四要素缺一不可）

```markdown
N. **<接棒项名>**（<落点文件真实路径>，<并发注意事项/归口线>）：<注册条件：开关/依赖/同源要求>；
   现成零件 = <已备好的构造器/挂载点>；验收形状 = <测试名/断言形状>。
   → ✅ 已收口（<日期> <收口批名>）：<注册条件兑现说明>；测试 `<测试名>` <例数>。
```

纪律：无未完写「无」；收口后**就地标 ✅**，接棒清单是活文档，任一时刻反映真实残余。

## B. 复测注记（追加在 test-baseline.md 真源内，**不改基线行**）

```markdown
> **复测注记（<日期>，<批次名>校验）**：同命令（<口径差异，如加 -j 2>）在当前工作树
> 复测 = <实数：套件/例/ignored>，exit <码>。与上表差异来自 <归因：树间在途批次增量，逐列对账>；
> 上表为 <基线口径名>，对外引用保持上表，现场以复测类实数为准。
```

纪律：数字随行三件（命令原样 + 日期 + 工具链）；不把 ignored 计入 passed；不代改真源；
不写「应该有 N 个」这类无脚本推算数。

## C. 中道停机遗嘱（猝死场景，最小 viable）

```markdown
## 已完成 / 未完清单（<日期> <停机原因>）
- 已完成：<文件清单 + 各自状态（骨架/成品）>
- 未完：<下一步动作 + 落点 + 现成零件>
- 验证状态：<最后跑过的命令 + 结果 + log 路径>
```
