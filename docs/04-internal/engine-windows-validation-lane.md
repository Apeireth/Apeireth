## 0. 现状实测（本仓 `crates-ui` CI，2026-11-04 读 workflow 得出）

| 门禁 job | 跑在哪 | 覆盖 |
|---|---|---|
| check / clippy / fmt / test | ubuntu-latest | native 逻辑层 |
| **wasm** | ubuntu-latest | wasm32 编译 + **wasm32 clippy**（`--all-targets`） |
| cargo_deny | ubuntu-latest | 依赖治理四类 |
| pilot-compare / production-compare | ubuntu-latest | 浏览器内像素/逐帧/DOM 全等对照 |
| **WebView2 能力探针（C2）** | **windows-latest** | Edge(=WebView2 内核) headless 跑五段探针：DOM 能力 / 纹理上传 / 产品宿主 / 双向绑定 / 组合集成 |

**已有的 Windows 车道是有价值的**，但**它不是真机验收**。诚实差距（workflow 原文已自注"这不是 Tauri 应用内嵌 WebView2"）：

| 差距 | 后果 |
|---|---|
| 探针跑在 **Edge headless**，不是 **Tauri 内嵌 WebView2** | 宿主差异（窗口、文件、剪贴板、权限）未覆盖 |
| hosted runner **DPI 固定 100%** | **125 / 150 未验**（Windows 缩放在 hosted runner 不可设） |
| runner **无真实 GPU**（软件渲染） | 帧率/显存结论不可信；GPU 后端差异不暴露 |
| **无帧率/内存基准** | "能不能 60Hz"至今无证据 |
| **无中文 IME 组合输入**验收 | 输入法是最容易在真机炸的一环 |
| **无垂直切片端到端** | 现在验证的是"能力探针"，不是"一条真链路" |

⇒ 结论：**CI 车道继续保留并加一条 Windows 原生观察车道；真机车道必须另立**（下面的 §2）。

---

## 1. 车道分两层

| 层 | 跑在哪 | 谁跑 | 阻塞性 |
|---|---|---|---|
| **A. CI 观察车道** | GitHub Actions `windows-latest` | 自动 | **不阻塞**（`continue-on-error`），只用于发现 Windows 特有的编译/测试问题；连续绿后再提为阻塞 |
| **B. 真机车道** | **一台登记过的真实 Windows 机器**（有真实 GPU、可设缩放、可装 Tauri） | 引擎线（+ 验证线） | **阻塞 W1 前置门**中标注为"真机必测"的项 |

---

## 2. 真机车道验收矩阵

判据栏里 **"未实测"是合法结论**；写"通过"必须有证据路径。

| # | 项 | 环境 | 采集方式 | 判据 | 证据 | 阻塞 W1？ |
|---|---|---|---|---|---|---|
| 1 | Tauri 内嵌 WebView2 启动与首屏 | 真机 Windows 11 + 目标 Edge/WebView2 运行时版本 | 启动录制 + 首屏截图 | 无白屏；无控制台致命错；首屏可交互 | 录屏 + 截图 + 版本号 | ✅ 必测 |
| 2 | **DPI 100 / 125 / 150** | 系统显示缩放三档 × 设备像素比记录 | 三档各跑同一屏 | 布局不塌、不糊、不错位；CSS px→设备 px 一致；命中测试不错位 | 每档截图 + 缩放设置截图 | ✅ 必测 |
| 3 | **真实 GPU 与后端** | 真机 GPU（禁软件渲染） | 记录后端（WebGPU / WebGL2）与设备名 | 画面正确；**context lost → restored 能恢复**（旧线遗留缺口） | 后端日志 + 恢复前后截图 | ✅ 必测 |
| 4 | **中文 IME 组合输入** | 真机 + 中文输入法 | 输入拼音组字、候选切换、焦点切换、撤销 | 组合期不丢字；候选窗不遮挡输入框；焦点切换不串字 | 录屏 + 输入轨迹日志 | ✅ 必测 |
| 5 | **帧率** | 真机 + 目标分辨率与缩放 | 引擎内探针或宿主性能面板 | 正常交互 60fps（可核对的采样口径） | 采样原始数据 + 口径说明 | ✅ 必测 |
| 6 | **内存** | 真机，长跑（≥30 分钟） | 宿主内存采样 | 无持续增长；长跑后回落 | 采样曲线 | ✅ 必测 |
| 7 | 失焦 / 最小化 / 恢复 | 真机 | 切换窗口状态 | 失焦时暂停渲染；恢复后不闪、不重复事件 | 录屏 + 事件日志 | ⭕ 建议 |
| 8 | 减弱动效偏好 | 真机 + 系统偏好 | 开 `prefers-reduced-motion` | 旋转/视差停用；状态语义不变 | 录屏 | ⭕ 建议 |
| 9 | 打包与安装 | 真机 | Tauri bundle 安装/升级/卸载 | 安装可用；升级不丢配置；卸载不残留 | 安装日志 | ⭕ 建议 |

**矩阵登记要求**：引擎线回填的能力矩阵里，每一项原语都要附一行"在 Windows 真机上验过没有、DPI 几档、真实 GPU 还是软件渲染"。**没验的写"未实测"**。

---

## 3. 证据格式（与 `EVIDENCE.md` 对齐）

每项至少写：

```text
artifact_id / 机器标识 / Windows 版本 / Edge-WebView2 运行时版本 / DPI / 分辨率 /
theme / state_id / source / 复现步骤 / 录屏或截图路径 / 实际结果 / 未验证项
```

- 录屏与截图落盘，路径写进证据；
- **未测项写"未实测"**，禁止写"通过"；
- 数字必须可复核（命令 + 日期 + 工具链）。

---

## 4. 机器与责任

| 角色 | 内容 | 归属 |
|---|---|---|
| **机器** | 一台真实 Windows 机器（真实 GPU、可设 100/125/150 缩放、可装 Tauri）；登记机器标识与运行时版本 | 待认领 |
| **执行** | 按 §2 矩阵逐项跑，产出证据 | 引擎线 |
| **复核** | 证据是否齐全、数字是否可复核、"未实测"是否诚实 | 验证线 + 总工 |
| **消费** | 作为 **W1 前置门**的判定输入（§2 中"阻塞 W1 = 必测"的 6 项全绿才开 W1 实现） | 本线 |

**没有登记的真机 ⇒ §2 的必测项一律记"未实测"**，W1 前置门不因此自动放行（可由 owner 显式豁免并登记理由）。

---

## 5. 与既有门禁的关系

- CI 观察车道（windows-native job，2026-11-04 加）：只跑 `cargo test --workspace --locked` 于 windows-latest，
  **不阻塞**；目的是把"Windows 下就编译不过/测不过"这类问题**提前暴露**，而不是等真机才发现。
- 现有 WebView2 探针 job（C2）：保留；它是**能力探针**，不替代真机矩阵。
- wasm 编译门禁：保留（ubuntu 上的 wasm32 build + clippy 已覆盖 wasm 分支的编译与 lint）。
