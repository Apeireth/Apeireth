你是一位顶级的产品设计师 + 前端工程师，擅长把"科幻感"做成真正可用、可读、可维护的产品界面。请为一个 AI 工作系统设计并实现一套**高保真、可交互的前端视觉原型**。

# 一、项目背景

Apeireth 是一个 AI 工作系统（可以理解为一个"AI 操作系统"）。旧前端被判定"整体不行"，现在要**推倒重建全部视觉方案**。当前阶段不做后端、不做生产代码，只交付**设计原型与设计规范**——目标是让 owner 第一眼说"行"，并为后续实现提供可执行的设计源。

# 二、界面范式（必须体现）

- **系统状态是中枢**：首页第一现场是"系统正在发生什么"（agent、任务、队列、工具、资源、治理、事件流），不是聊天窗口。
- **不预设"他"**：产品没有自带的中央 AI 人格；agent 是用户带入的"单位"，界面把它们当系统单位呈现。
- **「特别关注」双模式**：① 视觉高亮（pin 住一个 agent，界面跟随它）；② 指挥授权（被关注的 agent 成为团队 leader）。两种模式必须视觉可辨认。
- **能力可授予**：关系/情绪/记忆/在场类能力是 per-agent 的能力开关，可随时赋予/剥夺（体现在 agent 设置面里）。
- **明暗全双模式**：所有界面都支持明暗两套，两套各自完整、独立成立（不是暗色反相）。暗 = 值班指挥（黑/深蓝、发光量感、实时遥测）；亮 = 图纸工作台（纸白/米白、黑线稿、工程标注）。
- **金色 = 系统信号/能量**：不再专属某个角色；只用于系统活动/信号/能量/告警语义，不做装饰。
- **游戏化只到视觉层**：要"游戏界面般的信息密度与动态感"，不要等级/成就/任务系统。
- **三副面孔（同一套语法，不是三套设计）**：
  1. **指挥仪表盘**（中枢/实时，默认暗）：发丝网格、等宽遥测微标签、中央空间面（agent 编队/系统图）、右侧检查器、时间轴 + 事件日志、回放；
  2. **技术图纸**（工作/配置，默认亮）：纸白/米白、黑线稿、工程标注、剖面/图层、单点信号色；
  3. **编辑终端**（阅读/详情，默认亮）：强排版（大标题 + 等宽元信息 + 细说明）、高对比、留白节奏。

# 三、试金石

任意一屏，3 秒内回答三问：**系统在做什么？我能做什么？下一步点哪里？** 并且"看一眼就像在操作一台强大的机器"。

# 四、参考（研究语言，不复制素材）

参考页（截图由 owner 提供）：全球运营指挥中心、发射任务控制中心、智能体编队、工程示意仪表盘、车间设备运维台、爆炸图工作台、3D 空间叙事页、3D 建模任务工作台、双机械臂工作室、知识星图、开源科幻终端控制台等。

它们的共同语法：
1. 近单色底 + **唯一饱和信号色**；
2. 微型等宽标签（大写、字距、中英并置、编号分节）；
3. **发丝网格面板，不是卡片堆**（方角/2px 小圆角、细分隔线、紧凑内边距）；
4. **中央空间面 + 四周数据面**；
5. **右侧固定检查器 + 聚焦/关注**；
6. **时间维是一等公民**（事件日志/回放/倍速/里程碑）；
7. **动态全部是诊断性的**（每个动效都能回答"系统现在在干什么"）。

参考里的"3D 立体感"来自：中央面是真 3D/高仿 3D + 其余 2D 精密面板——不是全局 3D UI。中央面用什么技术（CSS 2.5D / Canvas / WebGL / 混合）由你判断，选效果最好的。

# 五、要交付的界面

**屏 1 · 系统中枢（首页）**：中央 agent 编队/系统图；四周遥测区（agent 状态/任务与队列/工具与资源/治理与告警）；右侧检查器（被关注 agent 的「此刻/在做什么/排队/利用率/状态/动作」）；时间维（事件日志当前行高亮、回放入口、状态时间轴）。交互：pin 一个 agent → 检查器切换；明暗切换；一个"指挥授权"入口。

**屏 2 · Agent 编队 + 特别关注**：编队视图（分组/站位/连线/状态）；pin（高亮）与指挥授权（leader）两种模式视觉可辨；检查器 + 动作（打断/重派/下线等，语义自拟）；能看出"谁在干活、谁在排队、瓶颈在哪"。

**屏 3 · 会话 / 工作流视图**：即时通讯的熟悉模型（会话列表/消息流/通知/群组/红点）；工具过程、审批卡、任务状态作为系统事件延伸出现；会话是中枢的一种视图，不是全部。

每屏覆盖状态：默认 / 选中 / 告警 / 空态 / 加载 / 错误 / 权限不足（至少前 5 种）；mock 数据必须显式标注。

# 六、交付物（先读 D1/D2/D3 的关系，再动手）

这三件都是 **HTML/CSS/JS 产物**，区别只在粒度与用途：

- **D1 = 设计标准（配方）**：色号、字阶、间距、网格、材质、动效规则、图标规范、明暗两套值。**D1 不是草稿**——后面所有零件与页面都要从它派生；它决定"为什么整套界面像同一个世界"。
- **D3 = 零件图纸 + 状态样件**：把整页拆成**单个组件**，每个组件给出**全部状态**的可运行样件（见下）。
- **D2 = 成品**：把零件组装成三屏整页，各明暗两版。

**逻辑顺序：D1（标准）→ D3（零件）→ D2（成品）**；交付给 owner 时按同样顺序展示。

| # | 交付物 | 内容与要求 |
|---|---|---|
| **D1** | **设计标准 v0.1** | 令牌（颜色/字阶/间距/圆角/层级/动效/材质）明暗两套；网格；图标规则；一页可读规范 + 可复制的 token 清单 |
| **D2** | **三屏 × 明暗 = 6 张成品** | 基准 1440×900，考虑 1280/1920 自适应；每屏可截图当作品；覆盖默认/选中/告警/空/加载等主要状态 |

# 七、硬约束（底线，不是上限）

1. 无预设"他"（不得出现系统自带中央 AI 人格）；
2. 明暗两套都精细，独立成立——"暗色精细、浅色糊弄"直接不算完成；
3. 0 装：mock 数据显式标注；动效必须有状态来源；空态写数据契约；
4. 不做游戏机制（等级/成就/积分），只做视觉层密度与动态；
5. 不做营销落地页/单页概念站——这是产品界面，不是作品集主页；
6. 可读性优先于炫技；高密度但不拥挤，扫读顺畅；
7. 无障碍：对比度、键盘可达、`prefers-reduced-motion`；
8. 版权：参考页只取语言，不复制素材/Logo/品牌字体；自产或可商用素材并署名；
9. 性能：交互流畅（目标 60fps），重效果要有降级；
10. 不接后端、不写生产仓库代码；交付物交给 owner。

# 八、自由条款（请读三遍）

**以上全是方向与底线，不是能力上限。**

- 在不违反第七节硬约束的前提下，**大胆给出你认为更好的设计决定**（版式/材质/动效/3D 语言/交互方式），并在设计说明里解释"为什么更好"。
- 如果某条约束与你的设计判断冲突，优先保证三条：**系统可读、状态可追、明暗对等**；其余可提出替代方案。
- **不要为了"稳"做成普通 SaaS**（那就没有存在意义）；**也不要为了"炫"牺牲可读性**（那就不可用）。
- 中央空间面是这套设计的"脸"：用你认为效果最好的方案（CSS 2.5D / Canvas / WebGL / 混合），写清依赖与降级即可。
- **交付优先级**（额度有限时按此裁）：**首轮 D1 设计标准 → D2 三屏成品（明暗双份）→ D3 组件状态矩阵**；D3 若首轮做不完可放第二轮，D4/D5/D6/D7 放第二轮打磨。
- 信息不足时，按最合理判断先做，**不要停下来提问**；把你的假设写进设计说明。
