# 一、项目背景

Apeireth 是一个 AI 工作系统（可以理解为一个"AI 操作系统"）。旧前端被判定"整体不行"，现在要**推倒重建全部视觉方案**。当前阶段不做后端、不做生产代码，只交付**设计原型与设计规范**——目标是让 owner 第一眼说"行"，并为后续实现提供可执行的设计源。

# 二、界面范式（必须体现）

- **系统状态是中枢**：首页第一现场是"系统正在发生什么"（agent、任务、队列、工具、资源、治理、事件流），不是聊天窗口。
- **中央 = 全息基地投影**：把 Apeireth 系统具象化为一座 **城式 3D 基地**（初始形态），外圈套 **三层轨道环**（记忆/编排/能力）+ 治理闸门环；以全息投影方式呈现实时状态；**基地本身基本不转，旋转交给环**；可交互（详见 §三）。**基地形象层可替换**（城市 → 航母 → 空间站…），语义槽与状态映射不变。
- **不预设"他"**：产品没有自带的中央 AI 人格；agent 是用户带入的"单位"，界面把它们当系统单位呈现。
- **「特别关注」双模式**：① 视觉高亮（pin 住一个 agent，界面跟随它）；② 指挥授权（被关注的 agent 成为团队 leader）。两种模式必须视觉可辨认。
- **能力可授予**：关系/情绪/记忆/在场类能力是 per-agent 的能力开关，可随时赋予/剥夺（体现在 agent 设置面里）。
- **明暗全双模式**：所有界面都支持明暗两套，两套各自完整、独立成立（不是暗色反相）。暗 = 黑色机库里的全息投影；亮 = 白纸上的工程模型。
- **金色 = 系统信号/能量**：唯一饱和色；只用于系统活动/信号/能量/告警语义，不做装饰。
- **游戏化只到视觉层**：要"游戏界面般的信息密度与动态感"，不要等级/成就/任务系统。
- **三副面孔（同一套语法，不是三套设计）**：
  1. **指挥仪表盘**（中枢/实时，默认暗）：全息基地 + 发丝网格遥测 + 右侧检查器 + 时间轴/事件日志/回放；
  2. **技术图纸**（工作/配置，默认亮）：纸白/米白、黑线稿、工程标注、剖面/图层、单点信号色；
  3. **编辑终端**（阅读/详情，默认亮）：强排版（大标题 + 等宽元信息 + 细说明）、高对比、留白节奏。

# 三、目标画面（翔实锚点；允许更好，但必须同样可描述）

## 3.1 中央面：Apeireth 全息基地投影（本设计的"脸"）

**它是什么**：把 Apeireth 系统具象化为一座**悬浮在黑色机库/空旷空间里的 3D 基地**，以**全息投影**的方式显示其**实时状态**。不是装饰性星球，也不是雷达屏；要让人一眼看出"这是一台正在运行的系统"。

**形态定稿（owner 2026-10-30）**：**D 混合——城式基地 + 三层轨道环**。
- **骨 = 城式基地**（初始形态）：可见街区、楼群、道路、灯火；远看是"一座在运转的城市基地"，近看有楼层/窗口/读数。
- **轴 = 三层轨道环**：内环（记忆/经验）· 中环（编排/任务/队列）· 外环（能力/工具/适配器），不同倾角套在基地外；最外一圈是**治理闸门环**（分段，需要你签时亮金边并"开门"）。
- **旋转**：**基地本身基本不转**（转起来会晕、看不清结构）；**旋转交给轨道环**——不均匀地停顿/短冲刺/漂移。这就是"实时旋转"的来源。
- **基地形象层可替换**（owner 要求记录）：城市只是**第一副壳**；换航母/空间站/堡垒时，**语义槽不变**（见下"形象可替换性"）。

**基地解剖（建议；可改，但必须在 T0 里讲清）**：

| 部位 | 对应系统语义 | 视觉 |
|---|---|---|
| **中央光核塔** | 内核 / 调度核心 | 城市中心最高的一束光/塔，呼吸脉冲 = 回合活动；画面最亮处 |
| **内区街区** | 记忆 / 经验层 | 一圈低层街区/院落，屋顶与窗格可贴微面板读数 |
| **中区街区** | 编排 / 任务 / 队列 | 楼群高度/密度 = 负载；街道上排队的光点 = 排队 |
| **外区街区** | 能力 / 工具 / 适配器 | 厂房/坞站式体块；被调用时亮起并拉出流光 |
| **街道 / 高架** | 事件 / 数据流 | 城市道路与高架上的流光；方向 = 数据流向；粗细/亮度 = 吞吐 |
| **泊位 / 坞** | agent 接入 | 边缘的泊位，agent 光点在此进出；pin 时泊位亮起并拉牵引线 |
| **三层轨道环** | 系统分层 | 环段 = 子系统；环带表面贴微面板；环的旋转 = 系统心跳 |
| **外缘闸门环** | 治理 / 审批 | 分段闸门；需要你签时亮金边并"开门" |
| **外围微面板** | 遥测 | 不是 3D，是页面 UI 的薄面板（见 §三 屏 1） |

**状态映射（必须在 T0 里写成表）**：负载 = 街区亮度/楼群密度；健康 = 颜色（金=活跃/信号，灰=静默，特定脉冲=告警）；队列 = 街道排队光点/延迟；吞吐 = 道路流光速度/密度；治理 = 闸门环/光墙；异常 = 局部脉冲 + 事件日志行。

**旋转与镜头（"实时旋转那种"）**：
- **基地本身基本静止**（只做极慢的呼吸/微浮动，不整体旋转）；**旋转交给三层轨道环**——不均匀地停顿、短促冲刺、缓慢漂移（像被系统状态推动，不是匀速转盘）。
- 事件（回合开始/结束、审批、告警）触发**环的脉冲与短加速**；静止段同样重要——静止让爆发成立。
- 自动镜头（可选）：在几个"镜头"间缓慢推近/拉远（远景看全基地+环 → 中景看街区/环段 → 近景看节点）；用户拖拽/滚轮后可接管。
- **缩放层级**：远景 = 全基地 + 环 + 外围遥测；中景 = 街区/环段与微面板；近景 = 单个节点 + 检查器。

**交互**：拖拽旋转（轨道相机）/ 滚轮缩放；悬停节点出标签；点击/ pin 节点 → 右侧检查器 + 牵引线；切"指挥授权"→ leader 徽记 + 指挥链路从它发散；点击街区/环段 → 该区展开或检查器切换。

**明暗两版**：
- 暗：黑色机库、体积光、扫描线、颗粒、泛光；信号色唯一亮色；暗部保留细节（不发灰）。
- 亮：白纸/米白上的工程模型——墨线 + 剖面线 + 标注引线 + 少量实色块；信号色仍是唯一亮色，像纸上的红笔。

**降级（必须给）**：低性能 / `prefers-reduced-motion` → 静态 2.5D 基地侧视图（城市轮廓 + 三层轨道环，环不转），保留状态色、选中、检查器；再低 → 纯平面分区图。降级不是"删功能"，是保留状态可读。

**实现提示**：这是一个 **Canvas/WebGL 场景层**（页面里的一块画布），不是全局 3D UI；页面其余部分仍是普通 DOM/CSS。原型阶段技术自由（Canvas 2D / WebGL / 混合）；写清依赖与降级。

**形象可替换性（owner 2026-10-30 要求记录）**：
- 城市只是**第一副壳**；后续可换航母/空间站/堡垒等，**不得重做语义**。
- **固定语义槽**（换壳只换这些槽的造型，不换含义）：`core`（光核塔）· `districts[3]`（内/中/外区）· `rings[3]`（记忆/编排/能力）· `gate_ring`（治理）· `docks[]`（agent 泊位）· `channels[]`（数据流通道）· `units[]`（agent 光点）。
- **换壳规则**：状态映射、交互（pin/指挥授权/检查器）、明暗两版、降级路径**全部不变**；只换几何、材质、灯光与命名文案。
- 设计时把「壳」与「语义层」分开画/分开写；D6 可用第二种壳证明可替换。

## 3.2 屏 1 · 系统中枢（首屏）

**区域划分（1440×900 基准）**：

| 区域 | 宽度/高度 | 放什么 |
|---|---|---|
| 顶部状态带 | 全宽 × 44px | 左：系统名 + 版本；中：连接状态点 + 预算/上下文小条 + 时钟；右：明暗切换 / 密度 / 命令入口 |
| 左列 | 240–280px | 阶段分组列表（规划/检索/编码/审查/交付），每阶段 2–5 行 agent：名字 · 状态词 · 一条短进度 |
| 中央 | 剩余宽 × 剩余高 | **全息基地投影**（城式基地 + 三层轨道环），占中央约 90% 面积；底部浮一条时间轴 |
| 右列 | 340–380px | 上：检查器（被 pin agent 的名字/职责/状态程序箭头/利用率条/动作按钮）；下：告警卡（2–3 条，含严重度） |
| 底部条带 | 全宽 × 90px | 事件日志（等宽、当前行高亮）+ 回放控制（暂停/倍速/跳转） |

**视线路径（3 秒）**：中央光核 → 右侧大数字/告警 → 左列某条高亮 → 底部日志当前行。

**关键状态**：默认（基地缓慢自转）；pin（节点放大 + 牵引线 + 检查器）；告警（某区脉冲 + 告警卡 + 日志行）；空态（基地暗，中央一行"等待接入 agent"的契约文案）；加载（环段依次点亮）；错误（某区红色脉冲 + 可读错误行）；权限不足（某区锁定：虚线 + 锁标 + 说明）。

**动效**：核心脉冲（回合活动）；环段点亮（任务落到某区）；流光（数据/事件）；pin 牵引线；leader 徽记扩散。全部由真实状态驱动。

## 3.3 屏 2 · Agent 编队 + 特别关注

- 基地放大到**中景**，agent 节点分布在环段与面上；节点旁有编号/职责短标签。
- **pin**：节点放大、光环、牵引线连右侧检查器；其他节点降亮。
- **指挥授权**：leader 节点多一圈**指挥徽记**（直角十字/旗标），**指挥链路**从它发散到同组节点（细线 + 方向）；右侧检查器出现"指挥权限"区。
- 底部读数：吞吐 / 前置时间 / 在制品 / 各阶段百分比 / 瓶颈提示（一句干话）。
- 状态：忙碌/空闲/告警/下线；空态（没有 agent）；权限不足（不可指挥）。

## 3.4 屏 3 · 会话 / 工作流

- 三栏：左 260px 会话列表（名字/未读点/最后一句）；中 1fr 消息流；右 360px 检查器（当前会话的 agent/任务/预算）。
- 消息流：气泡窄而紧凑；系统事件以**细行**插入（等宽、带时间戳）；工具过程折叠成一条等宽小行，可展开；审批卡浮起为一张**金边"待签文书"**。
- 顶部一条细状态带；亮色版像一叠工程纸上的对话记录：墨线 + 纸白，金只用于"需要你签"的瞬间。
- 状态：默认/选中/告警/空/加载/错误/权限不足；动效：新消息从底部滑入、流式光标、审批卡浮起（有因有果）。

## 3.5 贯穿母题（每屏至少复用 3 个）

① **系统信号线**（只在有活动处流动）；② **点云/光点节点**（agent 单位）；③ **等宽微标签**（编号/遥测/HUD）；④ **发丝网格**（模块边界）；⑤ **事件行高亮**（时间维）；⑥ **扫描线/颗粒**（全息投影的材质，克制使用）。

# 四、试金石 + 焦点纪律

- 任意一屏，3 秒内回答三问：**系统在做什么？我能做什么？下一步点哪里？** 并且"看一眼就像在操作一台强大的机器"。
- **一眼一个落点**：中央全息基地是首屏的落点；其余元素不能与它抢戏（大小/亮度/密度至少两项让位）。三四个等重卡片横排 = 打回。

# 五、风格圣经（style bible；T0 里写你自己的版本）

## 5.1 色彩与发光

- 底色**墨**、面板**墨2**、辅助灰**石墨/骨白**、正文**骨白**；**信号色（金橙）是唯一饱和色**。
- **只有"系统在活动/需要你注意"的元素允许发光**；静止/说明性元素不发光；正文与纸面**永不发光**；发光不是装饰。
- 亮色模式：**纸白 + 墨线**，信号色仍是唯一亮色；禁止把暗色反相当亮色。
- 禁：紫青霓虹赛博、彩虹渐变、多彩图表调色盘、彩色光晕汤。

## 5.2 字体三系（不引入第四种）

- **显示字**：大、紧、自信；可变宽度/字重表达"压力/拉伸"。
- **等宽字**：遥测、编号、HUD、数据、表格数字；小号标签用于元信息。
- **正文字**：长文可读；"编辑终端"面可用衬线增阅读感。
- 数字统一等宽/表格数字；不描边、不做发光字、不居中排一切。

## 5.3 布局与材质

- 网格纪律 + 非对称构图 + 发丝分隔线；**小号等宽标签紧挨大号显示字**。
- 暗 = 石墨/玻璃/微光；亮 = 纸/墨线/少量实色块；禁止重阴影堆叠、禁止大圆角卡片堆。

## 5.4 母题

从 §3.5 选 3–5 个，定义出现位置、形态与变化；它们让三屏像"同一个世界"。

## 5.5 语气（tone）

- **impressive, not cute**：精密、克制、有力量；不卖萌、不解释、不堆装饰。
- **deadpan**：文案短促、动词前置；不写"赋能/无缝/释放"类营销词；每屏至多一处冷幽默。

## 5.6 原创性与反 AI 感

- **不抄**：参考页只取语言；不复制素材/Logo/品牌 UI/梗图构图。
- 禁"AI slop"图库：发光大脑、代码雨、镜头光晕汤、粒子星云、通用 AI 插画、机器人脸、emoji 当图标。
- 允许"人工痕迹"：手绘标线/批注/图钉，但必须少而真。

## 5.7 修订记录

owner 驳回的项，记下"改了什么、为什么"；后续不再犯。

## 5.8 全息投影的材质语言（本设计的签名）

- **微面板库**：全息面上可贴小型数据面板（如 10–14 类：代码/键值/走势/条形/进度/网格/仪表/波形/密集文字/条码/矩阵/编号），每类有确定画法；远看是光，近看是读数。
- **层深**：远景（虚化+压暗）/ 中景（主体）/ 近景（光斑、浮尘）；视差 + 景深让画面有纵深；近景元素可越过 UI 边界，但不得遮挡关键读数。
- **标注引线**：少数关键点用细引线拉出小标注（等宽小字 + 公式/状态），像工程图批注；每屏 1–3 条。
- **扫描线/颗粒/暗角**：克制使用，像投影介质，不像滤镜；亮度不可压过数据。
- **调参台（可选，强烈建议）**：给 owner 一个隐藏面板调 20–30 个参数（旋转速度/停顿时长/辉光/扫描线/层深/母题密度），可导出 JSON；大幅降低审美沟通成本。
- **基地形象可替换**：壳与语义层分开；第一副壳 = 城市，后续可换航母/空间站；语义槽（core/districts/rings/gate_ring/docks/channels/units）不变。

# 六、参考（研究语言，不复制素材）

参考页（截图由 owner 提供）：全球运营指挥中心、发射任务控制中心、智能体编队、工程示意仪表盘、车间设备运维台、爆炸图工作台、3D 空间叙事页、3D 建模任务工作台、双机械臂工作室、知识星图、开源科幻终端控制台等。

共同语法：① 近单色底 + 唯一饱和信号色；② 微型等宽标签；③ 发丝网格面板不是卡片堆；④ 中央空间面 + 四周数据面；⑤ 右侧检查器 + 聚焦；⑥ 时间维一等公民；⑦ 动态全部是诊断性的。

参考里的"3D 立体感"来自：中央面是真 3D/高仿 3D + 其余 2D 精密面板——不是全局 3D UI。中央面用什么技术（CSS 2.5D / Canvas / WebGL / 混合）由你判断，选效果最好的。

# 七、要交付的界面

# 八、动效纪律（每条都来自一次"被打回"）

1. **动效必须有因有果**：观众要看到"原因"（点击/状态变化/数据到达），不能只看到结果。
2. **连续，不替换**：状态 A→B 之间必须有元素存活并移动/形变到 B；全部元素各自淡出淡入 = 幻灯片。刻意硬切要说明理由。
3. **不要节拍器**：不要匀速旋转/匀速呼吸；有停顿、冲刺、漂移；静止段让爆发成立。
4. **无源装饰动效 = 模板感**：粒子/彩带/光斑爆发只在有真实状态语义时允许。
5. **动效 token 化**：时长/缓动来自令牌，不写死毫秒与曲线；`prefers-reduced-motion` 有完整降级路径。
6. **可追责**：D5 里列**动效清单**——谁触发、从什么状态到什么状态、时长/缓动 token、降级方案。

# 十二、硬约束（底线，不是上限）

1. 无预设"他"；
2. 明暗两套都精细，独立成立；

6. 可读性优先于炫技；高密度但不拥挤；
7. 无障碍：对比度、键盘可达、`prefers-reduced-motion`；
8. 版权：参考页只取语言，不复制素材/Logo/品牌字体；
9. 性能：交互流畅（目标 60fps），重效果要有降级；
10. 不接后端、不写生产仓库代码；
11. **令牌按语义**；
12. **一个主题一个真源**（禁止硬编码 hex/px/ms）；
13. **交互件八状态**；
14. **全界面唯一饱和信号色**；

17. **决策层级**：用户需求 > 无障碍 > 一致性 > 美学 > 开发体验。
