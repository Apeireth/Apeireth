# 一、项目背景

Apeireth 是一个 AI 工作系统（AI 操作系统）。旧前端被判定"整体不行"，现在要**推倒重建全部视觉方案**。当前阶段不做后端、不做生产代码，只交付**设计原型与设计规范**——目标是让 owner 第一眼说"行"，并为后续实现提供可执行的设计源。

**关键教训（Astra 评审，2026-10-31）**：上一版把"系统状态中枢"放在第一屏，结果像一块漂亮的监控大屏——擅长表达"系统是什么、怎么运行"，不擅长表达"我在做什么工作、我在编辑什么"。**这两件事必须分开。**

# 二、空间模型（必须体现；三空间 + 环境层）

## 2.1 工作空间（默认首屏）

- 用户每天真正干活的地方；**核心对象从"聊天"升级为"工作"**。
- 左：工作 / 项目 / 文件 / 应用入口；中：**可变工作画布**（对话/文档/图像/数据/代码/任务流）；右：**AI 协作栏**；底部：命令输入条 + 轻量状态。
- 首屏必须能**开始工作**：新建工作、打开最近工作、拖入文件、发任务。

## 2.2 应用空间（能力展开）

- 承载 Word / Photoshop / 浏览器 / 终端等**工作内应用**；它们**共享同一个工作上下文**（当前文件、选区、版本、任务）。
- Starport 从"应用启动器"升级为**工作内应用空间**（注册/打开/聚焦/关闭/钉住）。
- 应用空间不承担系统监控。

## 2.3 控制塔（系统状态；主动进入）

- **不是首屏**。用户**主动进入**（一次交互 + 转场）来理解/审计/控制系统。
- 内容：Agent/模型/Provider、CPU/GPU/内存、工具调用与 Trace、审批队列、权限与治理、后台任务、错误恢复、
  文件锁/协作冲突、系统事件与日志、**轨迹视图**、**全息基地（单独一页）**。
- **全息基地**：保留全部设计（城式基地 + 三层轨道环；环境由施工方创造）；进入控制塔需要一次用户交互。

## 2.4 视觉身份退居环境层（只约束功能，不预写画面）

- 视觉不是删除，而是降级为**环境与身份背景**：
  - 空屏/首启/控制塔：可展示环境；
  - 工作空间：**低对比背景**，不抢工作画布；
  - 文档/图像编辑时：自动降低存在感；
  - 任务运行时：用光/呼吸/微动表达状态，而不是持续占屏的场景动画。
- **不预写具体视觉元素**：旧范式的具象视觉元素**不进入新范式**；环境的具体语言（光、雾、材质、地面、纵深手法）由施工方创造，这里只给功能约束：低对比、有纵深、不抢内容。
- 核心原则：**空间化视觉负责让 Apeireth 有灵魂，工作画布负责让用户完成事情。**

# 三、目标画面（翔实锚点；允许更好，但必须同样可描述）

## 3.1 首屏 · 工作空间

**区域划分（1440×900 基准）**：

| 区域 | 宽度/高度 | 放什么 |
|---|---|---|
| 顶部条 | 全宽 × 44px | 左：工作空间标识 + 当前工作名；中：保存状态 / 连接 / 任务状态；右：明暗切换 / 密度 / 命令入口 |
| 左栏 | 240–280px | 新建工作 / 最近工作 / 文件 / 项目 / 应用空间入口 / 收藏；每项一行，带类型小标 |
| 中央工作画布 | 剩余宽 × 剩余高 | **可变画布**：对话 / 文档 / 图像 / 数据 / 代码 / 任务流；默认空态 = 开始一个工作 |
| 右栏 AI 协作栏 | 320–360px | 当前目标 / 正在处理的文件 / AI 正在做什么 / AI 建议 / 待确认操作 / 已完成 / 版本与差异 / 撤销回退 / 权限范围 |
| 底部命令条 | 全宽 × 48px | 输入任务 / 拖入文件 / 选择工作画布类型；Send 快捷键 |

**首屏空态（必须设计）**：中央是"**开始一个工作**——我可以帮你完成什么？[输入任务 / 拖入文件]"，左栏给最近工作，右栏给"无进行中工作"的数据契约与接入入口；不铺假数据。

**工作画布的形态（首轮交付 3 种：对话 + 文档 + 图像；数据/代码/任务流给结构说明，第二轮再做）**：

- **对话画布**：消息流 + 工具过程折叠 + 审批卡；像熟悉的即时通讯，但每条都能"落到文件/任务"。
- **文档画布**：单源文档 + 预览/源码切换；**单人和他的 agent 一起改一份工作**——AI 修改时显示"正在修改哪个文件/哪一节"，给出变更列表（重写/删除/插入）、差异视图、[接受][拒绝][回退]；建议**锚定到选区/段落**（选中一段 → "把这段改得更像投资人说明" → 建议绑定该段，而不是另起聊天）；版本节点可见。首轮不做多人协作/编辑锁（后续轮次）。
- **图像画布**：画布 + 图层 + 选区；AI 建议说明"改了哪层、影响哪、用了什么工具、什么没变、要不要批准"；操作差异与版本节点；同样由单人 + 他的 agent 协作，不做多人。
- **数据画布**：表格 + 图表，AI 建议以"将新增/修改的行列"预览。
- **代码画布**：编辑器 + 终端，AI 建议以 diff 块出现。
- **任务流画布**：多步骤任务的过程/状态/产物；可展开为任务树。

**视线路径（3 秒）**：中央工作画布 → 右栏"AI 正在做什么/待确认" → 左栏当前工作 → 底部命令条。

**关键状态**：默认（空态/最近工作）；选中（文件/画布项）；AI 运行中（画布顶部细状态条 + 右栏活动）；建议待确认（右栏高亮 + 画布锚点）；告警（顶部条 + 相关对象）；空/加载/错误/权限不足；保存中/冲突（文件锁）。

## 3.2 应用空间

- 结构：左侧应用/工作资产树 + 中央应用视图（Word/PS/浏览器/终端之一）+ 右栏沿用 AI 协作栏；顶部一条工作上下文（当前工作/文件/版本）。
- **共享上下文**：在 Word 里选中的段落，右栏 AI 协作栏立刻知道；从 PS 里导出的图可以直接落到当前工作的"图片素材"里；浏览器资料可被"引用到当前工作"。
- Starport：应用注册/打开/聚焦/关闭/钉住的交互一览（不必做全应用，做骨架 + 一个文档编辑示例）。
- **首轮深度 = C（完整应用工作流；owner 2026-10-31 拍板）**：Starport 应用条（文档/图像/浏览器/终端）+ **四个工作流的界面形状都完整**——
  - 文档：工具栏/样式/表格/版本节点 + AI 修改→差异→[接受][拒绝][回退]；
  - 图像：画布/图层/选区/画笔/调色/滤镜 + AI 建议卡 + before/after + 版本节点；
  - 浏览器：页面视图 + 引用到当前工作 + 资料夹；
  - 终端：命令输入 + 输出流 + 多标签。
  - **边界**：这是**界面与交互形状**的完整设计（状态齐全、可演示），**不是真实文件引擎**；工具行为可用 mock 并显式标注（0 装），D5 写清哪些是 mock。
- 视觉：应用 chrome 极简、工具栏克制；环境层降到最低（不抢应用内容）。

## 3.3 控制塔（主动进入）

- **进入**：从工作空间顶部/命令面触发"进入控制塔"——**一次用户交互 + 转场**（不是常驻首屏的一部分）；退出回到工作空间。
  - 首轮进入交互 = **A+B（owner 2026-10-31 拍板）**：右上角低存在感入口（有告警时金点亮）+ **0.6s 转场** + `Esc` 返回 + 快捷键 `Ctrl/Cmd+Shift+T` + 首次进入一次性引导；转场克制、不中断正在运行的 AI。
- 结构：中央 = 全息基地（单独一页/子视图）；左 = Agent/任务列表；右 = agent 检查器 + 告警；底部 = 事件日志 + 轨迹入口 + LIVE；顶部 = 系统遥测（连接/预算/资源）。
- 轨迹视图：事件账本 + 时间概览 + 记录检查器（见 §3.5）。
- 审批：金色闸门 + 待签文书卡，就地批/驳/转交。

## 3.4 全息基地规格（控制塔独有；保留此前全部定稿）

**形态 D**：城式基地 + 三层轨道环（记忆/编排/能力）+ 治理闸门环；**基地本身基本不转，旋转交给环**（不均匀停顿/冲刺/漂移）；**形象层可替换**（城市 → 航母 → 空间站…，语义槽不变）。

**基地解剖（T0 里写成你的版本）**：

| 部位 | 语义 | 视觉 |
|---|---|---|
| 中央光核塔 | 内核/调度 | 城市中心最高光塔，呼吸脉冲 = 回合活动 |
| 内区街区 / 中区街区 / 外区街区 | 记忆 / 编排·任务·队列 / 能力·工具 | 低层院落 / 高楼群（高度=负载）/ 厂房坞站；窗灯亮灭 = 活动 |
| 街道/高架 | 事件/数据流 | 流动光带；方向=流向，粗细=吞吐 |
| 泊位/坞 | agent 接入 | 边缘泊位，pin 时亮起 + 牵引线 |
| 三层轨道环 | 系统分层 | 环段=子系统，表面贴微面板；环旋转=系统心跳 |
| 外缘闸门环 | 治理/审批 | 分段闸门，需要你签时亮金边并"开门" |
| 外围微面板 | 遥测 | 页面 UI 薄面板 |

**状态映射**：负载=街区亮度/楼群密度；健康=颜色（金=活跃，灰=静默，脉冲=告警）；队列=街道排队光点；吞吐=流光速度；治理=闸门环；异常=局部脉冲 + 日志行。

**环境**：由施工方创造——暗色/亮色两套，低对比、有纵深，**基地是画面唯一亮物**；不沿用旧范式具象元素。具体语言（光/雾/材质/地面/景深）不做规定。

**交互**：只"看 + 选"——点选/双击聚焦/拖视角/滚轮缩放/右键菜单（特别关注/指挥授权/查看）；**不通过 3D 拖拽做写操作**；写操作走控制塔命令条/检查器/待签卡。

**降级**：低性能 / `prefers-reduced-motion` → 静态 2.5D 基地侧视图（城市轮廓 + 环，环不转），保留状态色/选中/检查器；再低 → 纯平面分区图。

**实现**：Canvas/WebGL 场景层（页面里一块画布），其余 UI 仍是 DOM/CSS；技术自选，写清依赖与降级。

## 3.6 贯穿母题（每屏至少复用 3 个）

① 系统信号线（只在有活动处流动）；② 点云/光点节点（agent 单位）；③ 等宽微标签（编号/遥测/HUD）；④ 发丝网格（模块边界）；⑤ 事件行高亮（时间维）；⑥ 扫描线/颗粒（环境材质，克制使用）。

## 3.7 交互设计（用户能做什么）

**总原则：观察与操作分离；工作画布是操作面，控制塔是观察/审批面。**

| 层 | 用户想干什么 | 交互 | 落在哪 |
|---|---|---|---|
| ① 工作空间 | 开始工作/编辑文件/看 AI 建议/接受或拒绝 | 新建/打开/拖入；画布内编辑；AI 协作栏批注与差异；命令条 | 工作画布 + AI 协作栏 + 命令条 |
| ② 应用空间 | 用 Word/PS/浏览器/终端干活 | 应用内操作；共享上下文（选区/文件/版本）；Starport 切换 | 应用视图 + AI 协作栏 |
| ③ 控制塔 | 理解/审计/控制系统 | 进入（一次交互+转场）；看基地（只选）；轨迹；审批；检查器 | 全息基地/轨迹/待签卡/检查器 |
| ④ 全局 | 换主题、切密度、搜索、帮助 | 快捷键/命令面 | 顶部条 + Cmd/Ctrl+K |

**可发现性**：可点元素必须有 hover 光标/描边、focus ring、按下态；动作后 200–300ms 内可见反馈；危险动作二次确认；所有操作进审计。空态不写"暂无数据"，写入口与数据契约。

**权限与接入（owner 2026-10-31 定）**：
- **指挥授权**：leader 默认具备**全部权限**（改任务 / 代批 / 治理链），但**权限可在设置里预设/收回**；检查器里要能看到"当前权限范围"。
- **接入模板**：覆盖**当前运行环境自带的 provider 目录**（官方直连 + 主流第三方 + 任意 OpenAI 兼容端点，如 Ollama / vLLM / LM Studio；**具体清单以设置页为准**）；设计上 = 提供商行 + API Key + 模型列表。

# 四、试金石 + 焦点纪律

- **首屏落点是工作画布**；空间化视觉不抢戏（大小/亮度/密度至少两项让位）。
- **控制塔落点是全息基地**；但它不承担"开始工作"。
- 三四个等重卡片横排 = 没有落点 = 打回。

# 五、风格圣经（style bible；T0 里写你自己的版本）

## 5.1 色彩与发光

- 底色**墨**、面板**墨2**、辅助灰**石墨/骨白**、正文**骨白**；**信号色（金橙）是唯一饱和色**；**具体色值由施工方决定**（验收看对比度与"唯一饱和色"纪律，不锁定 hex）。
- **只有"系统在活动/需要你注意"的元素允许发光**；静止/说明性元素不发光；正文与纸面**永不发光**。
- 亮色模式：**纸白 + 墨线**，信号色仍是唯一亮色；禁止把暗色反相当亮色。
- 禁：紫青霓虹赛博、彩虹渐变、多彩图表调色盘、彩色光晕汤。

## 5.2 字体三系（不引入第四种）

- **显示字**：大、紧、自信；可变宽度/字重表达"压力/拉伸"。
- **等宽字**：遥测、编号、HUD、数据、表格数字；小号标签用于元信息。
- **正文字**：长文可读；"编辑终端"面可用衬线增阅读感。
- 数字统一等宽/表格数字；不描边、不做发光字、不居中排一切。

## 5.3 布局与材质

- 网格纪律 + 非对称构图 + 发丝分隔线；**小号等宽标签紧挨大号显示字**。
- 暗 = 石墨/玻璃/微光；亮 = 纸/墨线/少量实色块；禁止重阴影堆叠、禁止大圆角卡片堆。

## 5.4 母题

从 §3.6 选 3–5 个，定义出现位置、形态与变化；它们让三空间像"同一个世界"。

## 5.5 语气（tone）

- **impressive, not cute**：精密、克制、有力量；不卖萌、不解释、不堆装饰。
- **deadpan**：文案短促、动词前置；不写"赋能/无缝/释放"类营销词；每屏至多一处冷幽默。

## 5.6 原创性与反 AI 感

- **不抄**：参考页只取语言；不复制素材/Logo/品牌 UI/梗图构图。
- 禁"AI slop"图库：发光大脑、代码雨、镜头光晕汤、粒子星云、通用 AI 插画、机器人脸、emoji 当图标。
- 允许"人工痕迹"：手绘标线/批注/图钉，但必须少而真。

## 5.7 修订记录

owner 驳回的项，记下"改了什么、为什么"；后续不再犯。

## 5.8 投影/环境材质语言

- **微面板库**：全息面上可贴小型数据面板（10–14 类：代码/键值/走势/条形/进度/网格/仪表/波形/密文/条码/矩阵/编号）；远看是光，近看是读数。
- **层深**：远景（虚化+压暗）/ 中景（主体）/ 近景（光斑/浮尘）；视差 + 景深。
- **标注引线**：关键点细引线拉出小标注；每屏 1–3 条。
- **环境纪律**：环境层只约束功能（低对比、有纵深、不抢内容、明暗两套），具体视觉语言由施工方创造；旧范式具象元素不进入新范式。
- **扫描线/颗粒/暗角**：克制，像投影介质，不像滤镜。
- **调参台（可选，强烈建议）**：给 owner 一个隐藏面板调 20–30 个参数（环境强度/辉光/扫描线/密度），可导出 JSON。

# 六、参考（研究语言，不复制素材）

参考页（截图由 owner 提供）：全球运营指挥中心、发射任务控制中心、智能体编队、工程示意仪表盘、车间设备运维台、爆炸图工作台、3D 空间叙事页、3D 建模任务工作台、双机械臂工作室、知识星图、开源科幻终端控制台等。

# 八、动效纪律（每条都来自一次"被打回"）

1. **动效必须有因有果**：观众要看到"原因"（点击/状态变化/数据到达），不能只看到结果。
2. **连续，不替换**：状态 A→B 之间必须有元素存活并移动/形变到 B；全部元素各自淡出淡入 = 幻灯片。
3. **不要节拍器**：不要匀速旋转/匀速呼吸；有停顿、冲刺、漂移；静止段让爆发成立。
4. **环境层的动效是底噪**：只在任务运行/状态变化时被"点亮"，平时让位给工作画布。
5. **动效 token 化**：时长/缓动来自令牌；`prefers-reduced-motion` 有完整降级路径。
6. **可追责**：D5 里列**动效清单**——谁触发、从什么状态到什么状态、时长/缓动 token、降级方案。

# 十二、硬约束（底线，不是上限）

1. 首屏 = 工作空间；控制塔不是首屏，必须一次用户交互进入；
2. 无预设"他"；明暗两套都精细，独立成立；
3. 0 装：mock 数据显式标注；动效必须有状态来源；空态写数据契约；AI 建议必须可追溯（锚点/差异）；
4. 不做游戏机制，只做视觉层密度与动态；
5. 不做营销落地页/单页概念站；
6. 可读性优先于炫技；工作画布是焦点，环境层不抢戏；
7. 无障碍：对比度、键盘可达、`prefers-reduced-motion`；
8. 版权：参考页只取语言，不复制素材/Logo/品牌字体；
9. 性能：交互流畅（目标 60fps），重效果要有降级；
10. 不接后端、不写生产仓库代码；
11. **令牌按语义**；**一个主题一个真源**（禁止硬编码 hex/px/ms）；**交互件八状态**；
12. **全界面唯一饱和信号色**；
13. **反 slop 清单**：等重卡片横排/全居中/重复左文右图；标题只是加粗正文；每个盒子都投影；纯黑 on 纯白；emoji 当图标；单侧彩色边框；营销填充词与假标签；lorem/Placeholder/"No data" 空态；
14. **内容经得起压力**：长字符串、空列表、一条、四十条、九位数、缺图；错误态给修复；
15. **决策层级**：用户需求 > 无障碍 > 一致性 > 美学 > 开发体验；
16. **观察与操作分离**：控制塔基地只看 + 选，不是编辑器；工作空间操作落在工作画布与 AI 协作栏；
17. **底栏（控制塔）不常驻时间轴**：底栏 = 事件日志 + 轨迹入口 + LIVE。
