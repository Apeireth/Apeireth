## §0 实现基线与边界

- 最终实现 = **自研 UI 引擎**（Rust → wasm）+ Tauri WebView（Windows 首发）。
- 引擎提供基础原语（响应式、DOM 绑定、事件、布局测量、焦点/IME、滚动与虚拟化、主题通道），**没有现成组件库**。
- 交付的是设计原型（HTML/CSS/JS），不写生产代码；D5 需标注：哪些效果用 DOM/CSS、哪些依赖 Canvas/WebGL、哪些需要引擎补齐，并给出降级方案。
- 效果优先：不确定引擎能否支持的效果，标"需引擎支持"，不要自我阉割。

## §1 三空间骨架（布局参考区间）

### 1.1 工作空间（默认首屏）

**分区尺寸与比例不预设**：由你按内容与气质决定。只约束"有哪些区、各自负责什么、中央是主落点"。

| 区域 | 放什么 | 约束 |
|---|---|---|
| 顶部条 | 左：工作空间标识 + 当前工作名；中：保存/连接/任务状态；右：明暗切换 / 密度 / 命令入口 | 常驻、可一眼找到命令入口 |
| 左栏 | 新建工作 / 最近工作 / 文件 / 项目 / 应用空间入口 / 收藏 | 可折叠；窄窗时可收纳 |
| 中央工作画布 | 对话 / 文档 / 图像（首轮 3 种）；数据/代码/任务流给结构说明 | **主落点**：视觉权重最大；AI 协作栏不得压缩到不可用 |
| 右栏 AI 协作栏 | 当前目标 / 正在处理的文件 / AI 正在做什么 / 建议 / 待确认 / 已完成 / 版本与差异 / 撤销回退 / 权限范围 | 可折叠；内容多时自身可滚动 |
| 底部命令条 | 输入任务 / 拖入文件 / 选择画布类型；发送快捷键 | 常驻、随手可达 |

**交付画布**：按 1440×900 基准设计（交付格式要求），同时保证 1280 宽可用、1920 下不松散；窄窗重排、不横向溢出。

首屏空态：中央"开始一个工作——我可以帮你完成什么？[输入任务 / 拖入文件]"，左栏给最近工作，右栏给"无进行中工作"的数据契约与接入入口；不铺假数据。

### 1.2 应用空间

外壳：顶部工作上下文条（当前工作/文件/版本/Agent 状态）→ 左侧 Starport（文档/图像/浏览器/终端）→ 中央应用视图 → 右侧 AI 协作栏（可折叠）。

### 1.3 控制塔

**分区尺寸与比例不预设**（同 §1.1：由你决定，只约束职责与主落点）。

| 区域 | 放什么 | 约束 |
|---|---|---|
| 顶部遥测 | 连接/预算/资源（CPU/GPU/内存）/当前模型 | 常驻、轻量 |
| 左列 | Agent / 任务列表（状态/阶段/队列） | 可折叠 |
| 中央 | 全息基地（单独一页/子视图）；顶部小 tab「基地 ｜ 轨迹」 | **主落点**：基地是画面焦点 |
| 右列 | agent 检查器（此刻/在做/排队/利用率/状态程序/动作）+ 告警卡 | 可折叠 |
| 底部条带 | 事件日志（当前行高亮、可点击定位基地）+「轨迹」入口 + LIVE | 常驻、可扫读 |

进入：工作空间右上角常驻低存在感入口（有告警时金点亮）+ 快捷键 `Ctrl/Cmd+Shift+T` → 转场进入；`Esc`/返回退出，回到原视图位置；首次进入一次性引导。
**转场由施工方设计**：漂亮、流畅、真动效不是 PPT；时长/曲线自定，写进动效清单。

## §2 工作画布

### 2.1 首轮 3 种

**对话画布**：消息流 + 工具过程折叠 + 审批卡；每条都能"落到文件/任务"；流式光标；新消息从底部滑入。

**文档画布**：
- 单源文档 + 预览/源码切换；
- AI 修改时显示"正在修改哪个文件/哪一节"，给出变更列表（重写/删除/插入）、差异视图、[接受][拒绝][回退]；
- 建议锚定到选区/段落（选中一段 → 建议绑定该段，不另起聊天）；
- 版本节点可见；不做多人协作/编辑锁。

**图像画布**：
- 画布 + 图层 + 选区（矩形/套索）；
- AI 建议卡说明：改了哪层、影响哪、用了什么工具、什么没变、是否需要批准；
- before/after 差异 + 版本节点；不做多人协作。

### 2.2 后续形态（结构说明即可）

数据画布（表格+图表，AI 建议以"将新增/修改的行列"预览）；代码画布（编辑器+终端，AI 建议以 diff 块出现）；任务流画布（多步骤任务树/过程/产物）。

## §3 AI 协作栏

字段：当前目标 / 正在处理的文件 / AI 正在做什么 / AI 建议 / 待确认操作 / 已完成操作 / 版本与差异 / 撤销回退 / 权限范围。

- 实时修改文档/图像/数据时，必须显示"改了什么"：文件、章节/图层、变更列表、差异入口、接受/拒绝/回退。
- 建议必须可追溯到锚点（选区/段落/图层），不得另起孤立聊天。
- 空态写数据契约（"当 X 发生时这里出现 Y"），不写"暂无数据"。
- 权限范围可见（当前 agent 能做什么、不能做什么）。

## §5 控制塔与全息基地

### 5.1 基地形态

**城式基地 + 三层轨道环**：
- 骨 = 城式基地：中央光核塔；内区（记忆/经验）/ 中区（编排/任务/队列）/ 外区（能力/工具/适配器）街区；街道/高架（数据流）；边缘泊位/坞（agent 接入）。
- 轴 = 三层轨道环：内环（记忆）/ 中环（编排）/ 外环（能力），不同倾角；最外治理闸门环（分段，需要签时亮金边并"开门"）。
- 基地本身基本静止（只做极慢呼吸/微浮动）；**旋转交给环**：不均匀地停顿、短促冲刺、缓慢漂移，事件触发脉冲。
- **形象层可替换**：语义槽 `core` / `districts[3]` / `rings[3]` / `gate_ring` / `docks[]` / `channels[]` / `units[]` 固定；城市是 owner 已选的初始载体，可在城市内部自由创造；换载体需在 T0 提出并由 owner 决定；换壳只换造型，状态映射/交互/明暗/降级不变。

### 5.2 解剖与状态映射

| 部位 | 语义 | 视觉 |
|---|---|---|
| 中央光核塔 | 内核/调度 | 城市中心最高光塔，呼吸脉冲 = 回合活动 |
| 内区街区 | 记忆/经验 | 低层院落/仓储体块，窗灯亮灭 = 记忆活动 |
| 中区街区 | 编排/任务/队列 | 高楼群（高度 = 负载），街道排队光点 = 队列 |
| 外区街区 | 能力/工具 | 厂房/坞站体块；被调用时整块亮起 + 拉出流光 |
| 街道/高架 | 事件/数据流 | 流动光带；方向 = 流向，粗细 = 吞吐 |
| 泊位/坞 | agent 接入 | 边缘泊位，pin 时亮起 + 牵引线 |
| 三层轨道环 | 系统分层 | 环段 = 子系统，表面贴微面板；环旋转 = 系统心跳 |
| 外缘闸门环 | 治理/审批 | 分段闸门，需要你签时亮金边并"开门" |
| 外围微面板 | 遥测 | 页面 UI 薄面板（不是 3D） |

状态映射：负载 = 街区亮度/楼群密度；健康 = 颜色（金 = 活跃，灰 = 静默，脉冲 = 告警）；队列 = 街道排队光点/延迟；吞吐 = 流光速度/密度；治理 = 闸门环；异常 = 局部脉冲 + 事件日志行。

### 5.3 环境、视角、降级

- 环境：低对比、有纵深、不抢基地；具体视觉语言（光/雾/材质/地面/景深）由施工方创造；基地是画面唯一亮物。
- 视角：远景（全基地+遥测）/ 中景（街区与环段）/ 近景（节点+检查器）；可拖拽/滚轮，自动镜头可选。
- 交互：只"看 + 选"——点选/双击聚焦/拖视角/滚轮缩放/右键菜单（特别关注/指挥授权/查看）；不通过 3D 拖拽做写操作。
- 降级：低性能 / `prefers-reduced-motion` → 静态 2.5D 基地侧视图（不旋转，保留状态色/选中/检查器）；再低 → 平面分区图。

### 5.4 轨迹视图

| 区域 | 内容 | 交互 |
|---|---|---|
| 事件账本 | 按轮次分组：用户/助手/工具/嵌套/压缩；工具名/摘要/状态（等待/流式/完成/失败/中断） | 点击行 → 记录检查器；长历史虚拟化；流式跟随尾部，向上滚暂停 |
| 时间概览 | 真实开始时间×耗时投影；助手条区分 TTFT/解码；悬停出精确时刻 | 拖选过滤；滚轮缩放；右键清除/平移 |
| 记录检查器 | token/耗时/输入/输出/计时/图片摘要；失败显示错误名与代码；进行中只显示开始 | 局部检查器；代码页可换行/原始 JSON/复制 |

### 5.5 审批与遥测

- 审批：金色闸门 + 待签文书卡，就地批/驳/转交；可超时提醒、可打断（barge in）。
- 遥测：连接/预算/资源（CPU/GPU/内存）/当前模型/后台任务/错误恢复/文件锁。
- 底部：事件日志（当前行高亮、点击定位基地）+ 轨迹入口 + LIVE。

## §9 验证门明细

- 首屏是工作空间；3 秒三问可答；控制塔一次交互进入/退出。
- 明暗双渲染、都完整；正文 ≥4.5:1、大字 ≥3:1、图形控件 ≥3:1。
- 键盘：Tab 顺序合理，Enter/Esc/方向键可用，focus 可见。
- `prefers-reduced-motion`：环境安静、基地不旋转但保留状态色/选中；其余动效降级。
- 响应式：1280/1440/1920 三档 + 窄窗重排；无横向溢出/截断。
- 状态覆盖：默认/选中/告警/空/加载/错误/权限不足。
- 工作画布：AI 建议有锚点/差异/接受拒绝回退。
- 应用空间：四工作流形状完整；mock 已标注。
- 基地：唯一亮物、只看+选、降级可用、换壳不变语义；性能达标或已降级并写明。
- mock 标注：所有固定数据显式标注。
- 不声称未测的数字。

## §12 交付目录与检查点

### 12.1 目录结构

```
deliverables/
├── PROGRESS.md              # 当前进度（每个检查点更新）
├── MANIFEST.md              # 文件清单：文件 → 对应 D / 屏 / 组件 / 状态
├── tokens/                  # D1 设计标准
├── components/              # D3 组件与状态样件（按组件类分文件）
├── screens/                 # D2 成品（每屏一个文件/目录，含明暗）
├── prototype/               # D4 可交互原型
├── docs/                    # D5 设计说明
└── checkpoints/             # v0.1.zip / v0.2.zip …（只增不改）
```

### 12.2 检查点粒度

T0 完成 / D1 完成 / 每组组件完成 / 每张屏（含明暗）完成 / 每条可交互流程完成。

### 12.3 PROGRESS.md 模板

```
# PROGRESS
最后更新: <时间>
总体状态: T0 完成 / D1 进行中
已完成: <列表 + 文件路径>
进行中: <文件 + 完成度>
未开始: <列表>
下一步: <具体动作 + 目标文件 + 判断标准>
不确定/待 owner: <...>
检查点: <vN / 时间 / 路径>
```

### 12.4 规则

- 每个检查点：当前文件写完且可打开/可渲染；更新 PROGRESS/MANIFEST；打快照；不覆盖旧快照。
- 断点恢复：先读 PROGRESS + MANIFEST，从"下一步"继续；不重做已完成项；不改已封存快照。
- 额度将尽：停在完整检查点；宁可少做一张屏，不留半张屏/半套组件；下一步写清路径与待定项。
- 文件级：每个屏/每类组件独立文件；待做内容用显式 `TODO` 标注并写入 MANIFEST，不交空文件/占位符。
- 失败/被打回：保留旧检查点，修完再覆盖工作副本；不在失败版本上继续堆。

## §13 数据与交互契约

### 13.1 数据来源标签

```text
LIVE        当前由真实 API / 事件流提供，并显示来源与时间
MOCK        为演示设计而生成，显示 scenario_id
STALE       最近一次真实值，显示最后更新时间
UNAVAILABLE 能力存在但当前不可取值
NOT_WIRED   设计形状已存在，尚未接入后端
```

任何遥测、Agent 状态、工具结果、AI 建议、文件版本、审批都必须属于其中一种；禁止无标签填充。

### 13.2 AI 建议生命周期与记录

```text
idle → proposing → preview → awaiting-approval → applying
→ applied | rejected | failed | reverted
```

每条建议至少记录：`suggestion_id / work_id / artifact_id / anchor_type(selection|paragraph|layer|row|code-range) / anchor_id / before_version / after_version / trace_id / permission_scope / source`。
接受必须产生新版本或明确失败态；回退指向版本节点；局部接受说明剩余差异如何处理。

### 13.3 WorkspaceContext 与演示路径

```text
WorkspaceContext {
  work_id, artifact_id, artifact_type, selection, version_id,
  active_app, focused_agent_id, permission_scope, trace_id,
  return_route, return_focus
}
```

首轮演示路径：工作空间选择锚点 → 打开应用空间 → AI 协作栏识别同一锚点 → 查看差异 → 接受/拒绝 → 返回原工作并恢复焦点。

### 13.4 控制塔进入/退出

```text
进入：保存 route + work_id + artifact_id + selection + focused_agent + 滚动位置。
退出：恢复进入前的工作画布、协作栏展开状态、滚动位置、键盘焦点。
首次引导：非阻塞 coachmark，不增加第二次确认，不改变一次交互进入的规则。
```

基地右键菜单只能打开检查器、待签卡或命令面；写操作不得在基地本体提交。

## §14 证据与交付协议

每个检查点更新：`PROGRESS.md`、`MANIFEST.md`、`EVIDENCE.md`、`DECISIONS.md`、`checkpoints/vN/`（只增不改）。

`EVIDENCE.md` 每项至少写：`artifact_id / viewport / DPI / theme / state_id / source / 复现步骤 / 截图或录屏路径 / 实际结果 / 未验证项`。

开工前先交 `SOURCE-OF-TRUTH.md`（读取的文件与版本、冲突与采用规则、当前模式、待 owner 决定项）；没有它不开始 T0。

未测写"未验证"，不得写"通过"；额度将尽时停在完整检查点并写明下一步与唯一阻塞原因。
