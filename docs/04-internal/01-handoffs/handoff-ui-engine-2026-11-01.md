## §2 本线最重要的「认知更新」（**别踩回去**）

1. ⭐ **瓶颈不在 wasm⇄JS 边界**。浏览器 84 ms / native **143~150 ms**（同一棵树）
   ⇒ ⇒ **native 反而更慢** ⇒ ⇒ 成本在 **Rust 侧 / 后端实现**。
   ⇒ ⇒ 别再按「减少跨界」的思路优化。
   （探针：`cargo run --release -p apeireth-ui-dom --example patch_cost_probe`）

2. ⭐ **跨构建路径 / 跨时段的计时不可比**。曾差点把「vite 路径 82 ms vs 早先 95 ms」
   当成 **-14% 收益**，同口径重测后基线也是 84 ms ⇒ ⇒ **收益不存在**。
   ⇒ ⇒ 判定纪律：**同路径 + 同时段 + 多次取中位数 + 丢首次**（抖动可达 10 倍）。
3. ⭐⭐ **标尺要贴近真实负载**（E-155/E-158，最重要的一条）。
   合成压测树（37,476 节点）曾被当成「首屏」，得出「≈11 fps」的**假结论**。
   真实首屏是**虚拟列表窗口化**（DOM 里只有 7 行）⇒ ⇒
   **首屏挂载 58 ms / 输入重渲染 0.11 ms / 滚动重渲染 0.055 ms**
   ⇒ ⇒ **交互完全无卡点**（约 9,000~18,000 fps）。
   ⇒ ⇒ **性能不是上屏的阻塞项**；真正要定的是「**大列表/长文档**」的目标。

4. ⭐⭐⭐ **「整树重建」与「虚拟列表」曾经不兼容**（E-161 / E-164）——
   ⇒ ⇒ 整树 `patch` 会把列表区域按新树内容替换 ⇒ ⇒ 树里放「占位行」⇒ ⇒ 窗口**被覆盖**；
   ⇒ ⇒ 树里放「空」⇒ ⇒ 列表**被清空** ⇒ ⇒ 内容高度塌陷 ⇒ ⇒ **浏览器把 `scrollTop` 夹回 0**
   ⇒ ⇒ ⇒ **用户的滚动位置丢失**（虚拟列表的滚动**根本没生效**）。
   ⇒ ⇒ ⇒ **正解（E-165）**：引擎给虚拟化子树打 `virtualized` 标记
   ⇒ ⇒ ⇒ 整树 `patch` **自动跳过**它 ⇒ ⇒ ⇒ **调用方零感知**。
   ⇒ ⇒ ⇒⇒ ⇒ **结构性防御的完整含义 =「让补丁不再需要」，不是「让调用方更小心」**。
5. ⭐ **每次「异常」都要先怀疑自己的测量**（E-162 / E-164 各踩了 3 次）。
   ⇒ ⇒ 假象来源实测过这些：①**重复挂载**（探针自己又调一次 ⇒ 换了状态槽）；
   ②**选择器未收窄**（页面上有两个同 id 容器 ⇒ 计数混算）；
   ③**坐标系混用**（文档坐标 vs 视口坐标 ⇒ 误判「找错节点」）；
   ④**浏览器记住滚动位置**（⇒ 「首行没变」是假的）；
   ⑤**测量环境被污染**（l1 页面已有 37,476 个节点 ⇒ 首次 layout 成本被算到我们头上）。

## §3 性能相关的四件事（**全部已完成**；唯一剩余的待决项见 ④）

### ✅ 已完成（2026-11-02）：段级计时插桩 —— E-154

**结论**：`patch_children` **自身逻辑占 75.4%**，直接段合计仅 24.6%
（⚠️ `children` 段含递归 ⇒ 84.1% **不可直接读**，正确读法见探针输出与 E-154）。

### ✅ 已完成（2026-11-02/03）：性能归因 ⇒ **结论是「首屏无卡点」**

- E-154：段级计时落地 ⇒ `patch_children` 自身占 75.4%（**在 37,476 节点树上**）。
- E-155：⭐ **发现标尺错了** ⇒ 真实首屏是虚拟列表窗口化（几十节点）
  ⇒ ⇒ **首屏交互无卡点**（native 49~90 µs）。
- E-156/E-158：浏览器侧确认 ⇒ **挂载 58 ms / 输入 0.11 ms / 滚动 0.055 ms**。
- E-157：harness 的 wasm32 clippy 清零。

⇒ ⇒ **性能不再是上屏的阻塞项**；「优化 `patch_children` 75%」对首屏收益 ≈ 0
⇒ ⇒ ⇒ **不要再去优化它**（那是对错误标尺的忠实执行）。

### ✅ 已完成（2026-11-03）：拆「首屏挂载 58 ms」—— E-159/E-160/E-162

- **E-159 分段**：挂载 111 ms 拆成「构造行数据 1 ms / 首次挂载 0 ms /
  **窗口计算冷 88~110 ms** / 窗口写入 1 ms」⇒ ⇒ **99% 在窗口计算**；
- ⭐ **冷 88 ms / 热 0 ms** ⇒ ⇒ **不是每帧都慢的算法成本**
  ⇒ ⇒ 而是**浏览器首次 layout**（读 `scrollTop`/`clientHeight` ⇒ **强制回流**）；
- ⭐⭐ **E-162 撤回 E-160 的结论**：那 58~88 ms 是**测量环境污染**
  （l1 页面已有其它探针留下的 37,476 个节点）⇒ ⇒ **污染实验**：干净页 **15.7 ms** /
  同页加 20,000 节点 **140.2 ms** ⇒ ⇒ **那不是我们列表的成本**；
- ⭐⇒ **首屏应「立即窗口化」**（延迟反而晚 20~35 ms，且无正确性收益）
  ⇒ ⇒ 已落地 + 用 A/B 驱动 `drive_w0.py` 固化为判据。
