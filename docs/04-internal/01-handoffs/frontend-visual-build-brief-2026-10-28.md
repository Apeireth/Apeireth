## §1 一页目标

Apeireth 是一个 AI 工作系统（**首发平台：Windows 桌面，Tauri + WebView2**）。请设计一套全新的界面：**三个空间**——工作空间（默认首屏）/ 应用空间 / 控制塔（含全息基地）。目标是让 owner 第一眼说"行"，并让后续实现有据可依。

- 首屏是**工作空间**：让人开始工作、完成工作；
- **应用空间**：文档/图像/浏览器/终端共享同一工作上下文；
- **控制塔**：系统状态中枢，主动进入；全息基地是"脸"，单独一页。

## §2 读什么、按什么顺序

1. **交接入口**（`frontend-visual-build-kickoff-2026-10-31.md`，先读）：施工模式、真源优先级、数据契约、证据协议。
2. **创作简报**（`frontend-visual-build-prompt-2026-10-28.md`）：目标 / 三空间 / 画面 / 硬底线 / 动效 / T0 / 交付物 / 验收门 / 自由条款。
3. **施工规格**（`frontend-visual-build-spec-2026-10-31.md`）：布局参考、组件与八状态、基地解剖、轨迹字段、交互清单、验证明细、契约明细。
4. **参考截图**（owner 提供）：只研究语言，不复制素材/构图。

> 硬门以创作简报 §三/§七 为准；规格附录是参考，不是逐条验收清单。

## §3 流程（T0 前置门）

0. 开工前先交 **SOURCE-OF-TRUTH.md**（读取的文件/版本、冲突与采用规则、当前施工模式；没有它不开始 T0）；当前模式 = **DESIGN_ONLY**；
1. 先交 **T0 处理稿**（不写 HTML/CSS）：一句话构想 + 3 概念方向 + 风格圣经 + 三空间 IA + 工作画布 + AI 协作栏 + 控制塔/基地 + 轨迹 + 交互清单 + 不确定项；
2. **owner 审 T0**，说"行"之后才进入生产；
3. 生产顺序：**D1 设计标准 → D3 零件与状态 → D2 成品**；交付时按同样顺序展示。
4. owner 读 T0 若说不出画面 = T0 不够具体，重写，不许开始生产。

### §3.1 进度保存（必须：每完成一个小阶段就存检查点）

额度可能在任意时刻用完。**每完成一个小阶段就保存一次检查点**，保证任何时刻停下来都不丢工作、不留烂摊子：

- **小阶段**：T0 写完 / D1 写完 / 每组组件 / 每张屏（含明暗）/ 每条可交互流程；
- **每个检查点**：写完当前文件（可打开、无半成品）→ 更新 `PROGRESS.md`（已完成/进行中/未开始/下一步/待 owner）→ 更新 `MANIFEST.md`（文件对应关系）→ 打快照到 `checkpoints/vN/`（只增不改）；
- **断点恢复**：新会话先读 `PROGRESS.md` + `MANIFEST.md`，从"下一步"继续，不重做已完成项；
- **额度将尽**：停在完整检查点，宁可少做一张屏，不留半张屏/半套组件；
- **文件级**：每个屏/每类组件独立文件；待做内容用显式 `TODO` 写进 MANIFEST，不交空文件/占位符。

目录与模板见施工规格 §12。

## §5 验收（owner + 总工程师）

- **owner 审美**：对三空间 × 明暗（+ 全息基地）显式说"行"——唯一主观门；
- **客观门**：首屏是工作空间、控制塔一次交互进入、明暗双套、对比度、键盘、reduced-motion、响应式、状态覆盖、AI 建议可追溯、基地只看+选、0 装标注；**Windows Edge/Chrome（WebView2）+ DPI 100/125/150 验收基线**；Linux 仅兼容目标；
- **交付前评审 pass**：自我否定模板（判定/三条打回理由/证据/最多两条真好/未能判断项），判定"可交"后再交。

## §6 边界与自由

- 不接后端、不写生产仓库代码；交付物（文件/链接）交 owner。
- **实现基底**：自研 UI 引擎（Rust→wasm）+ Tauri WebView；D5 标注 DOM/CSS vs Canvas/WebGL vs 需引擎补齐，并给降级。
- 以上是方向与底线，不是能力上限：**大胆给出更好的设计决定**并说明理由；冲突时优先保证"工作可完成、状态可追溯、明暗对等"。
- 不要为了"稳"做成普通 SaaS；也不要为了"炫"牺牲可读性。
- 3D 质感浓度打样后评估；首轮按你能拿到的最好效果做。
