## §1 项目一句话

**Apeireth 是一个 AI 工作系统（操作系统式产品）。旧前端被 owner 判定「整体不行」，现在要推倒重建全部视觉方案。**

本阶段的施工目标不是"先接后端跑起来"，而是：

1. **把新视觉语言做出来**（一套可复用的设计系统）；
2. **用高保真、可交互的原型证明它**（三屏 × 明暗双主题）；
3. **让 owner 第一眼说"行"**，并让后续引擎实现有据可依。

> 交付物是**设计原型与规范**：真数据/后端/引擎实现是后续另一条线的事。请不要接后端、不要动生产仓库。

## §2 已定决策（不要重新发明，但可以在其之上做得更好）

| # | 决策 | 含义 |
|---|---|---|
| 1 | **不再以「他」为中心** | 产品不再预设一个中央 AI 人格；界面不围绕"一个伙伴"做情感中心 |
| 2 | **系统状态是中枢** | 首页第一现场是"系统正在发生什么"，不是聊天窗口 |
| 3 | **Agent 是单位** | 用户自带 agent（BYO）；界面把 agent 当作系统里的"单位"呈现 |
| 4 | **「特别关注」双模式** | ① 视觉高亮（pin 一个 agent，界面跟随）；② **指挥授权**（被关注 agent 成为团队 leader） |
| 5 | **能力可授予** | 旧的关系/情绪/记忆/在场类能力 → 变成 per-agent 的能力开关，可随时赋予/剥夺（在 agent 设置面里） |

| 10 | **业务界面先行，3D 另立项** | 本阶段做的是业务界面；3D 形象/场景/桌宠等不在本次范围 |
| 11 | **中央 = 全息基地投影** | 把 Apeireth 系统具象化为一座 **3D 基地**，以全息投影显示其实时状态、可交互（详见提示词 §3.1）；它是本设计的"脸" |

| 13 | **环境：暗场 + 地平网格 / 明色图纸桌面** | 暗 = **无边暗场**（无墙/无舱门/无设备；极淡地平网格 + 光雾/浮尘 + 体积光斜切）；**基地是唯一亮物**；亮 = **米白工程纸/制图桌面**（不是白机库、不是暗色反相） |

## §3 试金石（owner 会拿这句验收）

> **任意一屏，3 秒内回答三问**：系统在做什么？我能做什么？下一步点哪里？
>
> **看一眼就像在操作一台强大的机器**——而不是在浏览一个网页。

## §3.5 施工顺序：T0 处理稿先行（owner 说"行"才生产）

owner 2026-10-30 定的施工法：**先把文字磨到"读得出画面"，再让施工方下手**。

1. **T0 处理稿**（不写 HTML/CSS）：一句话构想 + 3 个概念方向 + 风格圣经 + **基地解剖** + 三屏 plate 处理稿 + 屏×状态×母题映射 + 不确定项 → **owner 审**；
2. owner 说"行" → 才进入 D1/D3/D2 生产；
3. owner 读完 T0 说不出画面 = T0 不够具体，重写，不许开始生产。

提示词 §三 里有**目标画面速写**（三屏各一段，owner 可读的"画面承诺"）；T0 至少要到同样具体的程度。写作方法参考（treatment / plate-by-plate 写法）见 [methodology 研究稿](../02-research/ui-motion-prompt-research-2026-10-30.md) §2 第 11 条。

## §4 视觉方向（给感觉，不给死规格）

**像什么**：操作系统 / 驾驶舱 / 指挥室 / 游戏界面 / 黑客的电脑屏幕；现代 SaaS 的清晰纪律 + 科幻、高科技、高信息密度、动态、3D 立体感、高级感。

**三副面孔**（同一套语法，不是三套设计）：

| 面孔 | 用在哪 | 默认模式 | 语言要点 |
|---|---|---|---|
| **指挥仪表盘** | 中枢 / 实时值班 / 监控 | 暗 | 发丝网格面板、等宽遥测微标签、中央空间面（**Apeireth 全息基地投影**）、右侧检查器、时间轴 + 事件日志、回放 |
| **技术图纸** | 工作 / 配置 / 数据审视 | 亮 | 纸白/米白底、黑线稿、工程标注、剖面/图层、单点信号色 |
| **编辑终端** | 阅读 / 长文 / 详情 / 复盘 | 亮 | 强排版（大标题 + 等宽元信息 + 细说明）、高对比、留白节奏 |

**明暗两种气质**（不是反相皮肤）：
- **暗 = 值班指挥**：黑/深蓝底、发光量感、实时遥测——适合"正在发生"。
- **亮 = 图纸工作台**：纸白/米白、黑线稿、工程标注——适合"审视/规划/复盘"。

**参考**：owner 会给/给过一组外部参考页（运营指挥中心、任务控制中心、智能体编队、工程仪表盘、爆炸图工作台、3D 空间叙事等）与开源科幻终端控制台。请**研究其语言，不复制素材/品牌/单页构图**。共同语法见 [参考分析](../../design/reference-language-analysis-2026-10-28.md) 摘要：

1. 近单色底 + **唯一饱和信号色**；
2. 微型等宽标签（大写、字距、中英并置、编号分节）；
3. **发丝网格面板，不是卡片堆**（方角/2px 小圆角、分隔线、紧凑内边距）；
4. **中央空间面 + 四周数据面**；
5. **右侧固定检查器 + 聚焦/关注**；
6. **时间维是一等公民**（日志/回放/倍速/里程碑）；
7. **动态全部是诊断性的**（每个动效都能回答"系统现在在干什么"）。

**反范式（明确不要）**：劣质卡网（大圆角卡片堆、无主次、无真实状态）／纯装饰科幻／低密度大留白／"他"中心显影／静态仪表盘／营销落地页。

### §4.5 动效纪律（六条；每条都来自一次"被打回"）

1. **动效必须有因有果**：观众要看到"原因"（点击/状态变化/数据到达），不能只看到结果。
2. **连续，不替换**：状态 A→B 之间必须有元素存活并移动/形变到 B；全部元素各自淡出淡入 = 幻灯片；刻意硬切要说明理由。
3. **不要节拍器**：相邻节拍时长至少 4× 差异；必须有静止段——静止让爆发成立；不要"永远在动"。
4. **无源装饰动效 = 模板感**：粒子/彩带/光斑爆发只在有真实状态语义时允许。
5. **动效 token 化**：时长/缓动来自令牌，不写死毫秒与曲线；`prefers-reduced-motion` 要有完整降级路径。
6. **可追责**：D5 里列动效清单——谁触发、从什么状态到什么状态、时长/缓动 token、降级方案。

### §4.6 中央面的签名：Apeireth 全息基地投影

- **是什么**：一座悬浮在**无边暗场**里的 **城式 3D 基地**（可见街区/楼群/道路/灯火），外圈套三层轨道环；全息投影显示实时状态；不是装饰星球/雷达屏，要让人看出"这是一台正在运行的系统"。
- **环境（2026-10-30 定稿）**：暗 = 无边暗场 + 极淡地平网格 + 光雾/浮尘 + 几道体积光；**不画机库**（无墙/无舱门/无设备）；基地是画面唯一亮物。亮 = 米白工程纸/制图桌面（纸纹 + 极淡网格 + 圆规轨道线 + 标注引线），不是"白机库"。
- **解剖（提示词 §3.1 有完整表）**：中央光核塔（内核/调度）· 内区街区（记忆/经验）· 中区街区（编排/任务/队列）· 外区街区（能力/工具/适配器）· 街道/高架（事件/数据流）· 泊位/坞（agent 接入）· 三层轨道环（记忆/编排/能力）· 外缘闸门环（治理/审批）· 外围微面板（遥测）。
- **状态映射**：负载=街区亮度/楼群密度；健康=颜色；队列=街道排队光点/延迟；吞吐=道路流光速度/密度；治理=闸门环；异常=局部脉冲 + 日志行。
- **旋转**：**基地基本静止**（只做极慢呼吸/微浮动）；**旋转交给轨道环**——不均匀地停顿/短冲刺/漂移（不许匀速转盘）；事件触发脉冲；可拖拽/缩放；镜头可在远景/中景/近景间推拉。
- **形象可替换**：城市只是**第一副壳**；固定语义槽 `core/districts[3]/rings[3]/gate_ring/docks/channels/units`；换壳只换造型，状态映射/交互/明暗/降级不变。
- **技术边界**：它是页面中的 **Canvas/WebGL 场景层**，其余 UI 仍是 DOM/CSS；技术自选，必须写清降级（低性能/reduced-motion → 静态 2.5D 基地侧视图，保留状态色与选中）。

## §5 要做的界面（核心三屏 × 明暗 = 6 张）

### 屏 1 · 系统中枢（首页）

- 中央：**Apeireth 全息基地投影**（**城式基地 + 三层轨道环**；基地不转、环不均匀旋转；Canvas/WebGL 场景层，见 §4.6 与提示词 §3.1）。
- 四周：系统遥测（agent 状态 / 任务与队列 / 工具与资源 / 治理与告警）。
- 右侧：**检查器**——被关注 agent 的「此刻 / 正在做什么 / 排队 / 利用率 / 状态 / 可用动作」。
- 时间维：事件日志（当前行高亮）、回放入口、状态时间轴。
- 交互：点击/pin 一个 agent → 检查器切换 + 高亮；明暗切换；至少一个"指挥授权"入口（leader 切换的视觉表达）。

### 屏 2 · Agent 编队 + 特别关注

- 编队视图：agent 分组/站位/连线/状态；每个 agent 有身份、职责、当前状态。
- **特别关注**：pin（视觉高亮）与**指挥授权**（leader）两种模式的视觉差异必须可辨认。
- 检查器 + 动作（打断/重派/下线等——语义按本产品，动作名可自拟）。
- 要能看出"谁在干活、谁在排队、瓶颈在哪"。

### 屏 3 · 会话 / 工作流视图

- 即时通讯的熟悉模型（会话列表 / 消息流 / 通知 / 群组 / 红点）——降低学习成本。
- 工具过程、审批卡、任务状态等作为系统事件的延伸出现。
- 与中枢的关系：会话是中枢的一种视图，不是全部。

### 每屏必须包含的状态

默认 / 选中 / 告警 / 空态 / 加载 / 错误 / 权限不足（至少覆盖前 5 种）；有 mock 数据必须显式标注。

## §7 硬约束（是底线，不是能力上限）

1. **无预设"他"**：界面里不能出现"系统自带的中央 AI/人格"；agent 是用户带入的单位。
2. **明暗两套都精细**：每屏两种模式都要独立成立；"暗色精细、浅色糊弄"直接不算完成。
3. **0 装**：原型可用固定数据，但必须显式标注 mock；动效必须有状态来源（不能为动而动）；空态写数据契约（"当 X 发生时这里会出现 Y"）。
4. **不做游戏机制**（等级/成就/积分），只做视觉层的密度与动态。
5. **不做营销落地页 / 单页概念站**：这是产品界面，不是作品集主页。
6. **可读性优先于炫技**：高密度但不拥挤；层次清楚、扫读顺畅。
7. **无障碍基线**：明暗对比度、键盘可达、`prefers-reduced-motion`。
8. **版权**：参考页只取语言；不复制素材、Logo、品牌字体；自产或使用可商用素材并署名。
9. **性能**：交互流畅（目标 60fps）；重效果要有降级；首屏可交互时间合理。
10. **范围**：不接后端、不接生产仓库；交付物交给 owner，由我们后续与引擎线对接。
11. **令牌按语义**：危险动作在触发器与确认框都用 destructive 语义；不允许把品牌色当删除色。
12. **一个主题一个真源**：所有颜色/间距/圆角/层级/时长来自同一套 token；禁止硬编码 hex/px/ms；明暗两套从同一 token 层派生。
13. **每个可交互元素八状态**：default / hover / focus / active / disabled / loading（异步）/ error（输入）/ selected（可选——能选就必须有）。
14. **全界面唯一饱和信号色**（金 = 系统信号/能量），其余靠中性色与明度层级。
15. **反 slop 清单**（评审逐条打回）：等重卡片横排 / 全部居中 / 重复左文右图；标题只是加粗正文；每个盒子都投影、同一圆角套全部；纯黑 on 纯白；emoji 当图标/项目符号/状态点；单侧彩色边框；营销填充词与假标签；lorem/Placeholder/Item 1/"No data" 空态。
16. **内容经得起压力**：长字符串、空列表、一条、四十条、九位数、缺图都要有设计；错误态给修复。
17. **决策层级**：用户需求 > 无障碍 > 一致性 > 美学 > 开发体验；不得为低层牺牲高层（"好看但不可用" = 废）。
18. **发光纪律**：只有"系统在活动 / 需要你注意"的元素允许发光；静止/说明性元素不发光；纸面与正文永不发光；发光不是装饰。
19. **字体三系**（显示字 / 等宽 / 正文字，不引入第四种）；数字用等宽或表格数字；不描边、不做发光字。
20. **母题 3–5 个**（系统信号线 / 点云节点 / 等宽微标签 / 发丝网格 / 事件行高亮）；每屏至少复用 3 个，让三屏像同一个世界。
21. **语气**：impressive, not cute；deadpan（短促、动词前置）；允许每屏至多一处冷幽默；禁"赋能/无缝/释放"类营销词。
22. **原创性与反 AI 感**：不抄参考页/梗图/Logo/品牌 UI；禁发光大脑、代码雨、镜头光晕汤、粒子星云、通用 AI 插画、机器人脸、emoji 当图标。
23. **修订记录**：owner 驳回的项记"改了什么、为什么"；修订记录是资产，不是羞耻。
24. **全息基地不均匀旋转**：禁止匀速转盘/匀速呼吸；必须有停顿、短冲刺、漂移；事件驱动脉冲；静止段让爆发成立。
25. **全息基地必须有降级**：低性能 / `prefers-reduced-motion` → 静态 2.5D 环形图（保留状态色、选中、检查器）；降级不删功能只降表现。
26. **场景层边界**：全息基地是页面中的一块 Canvas/WebGL 画布，不是全局 3D UI；页面其余部分是普通 DOM/CSS——这条同时保护后续引擎实现（引擎管 DOM/UI，画布当场景层）。
27. **基地形象层可替换**：固定语义槽 `core/districts[3]/rings[3]/gate_ring/docks/channels/units`；换壳（城市→航母→空间站）只换造型，**状态映射、交互、明暗、降级全部不变**；D6 用第二副壳证明。
28. **环境纪律**：暗场不画机库（无墙壁/舱门/设备）；地平网格极淡；体积光/光雾/浮尘克制；**基地是画面唯一亮物**；明色版是米白工程纸/制图桌面——不是白机库、不是暗色反相。

- [ ] 反范式逐条不出现（见 §4 末）；无 slop 清单命中（见 §7.15）。

## §9 自由条款（要求施工方读三遍）

> **以上全部是方向与底线，不是能力上限。**
>
> - 在不违反 §7 硬约束的前提下，**请大胆给出你认为更好的设计决定**（版式、材质、动效、3D 语言、交互方式），并在设计说明里解释"为什么更好"。
> - 如果某条约束与你的设计判断冲突，优先保证三条：**系统可读、状态可追、明暗对等**；其余可以提出替代方案。
> - **不要为了"稳"做成普通 SaaS**（那就没有存在意义）；**也不要为了"炫"牺牲可读性**（那就不可用）。
> - 全息基地是这套设计的"脸"：用你认为效果最好的方案（HTML/CSS 2.5D、Canvas、WebGL 或混合）——**按你认为最好的效果做**；只需在设计说明里写清依赖与降级。
> - 如果一次交付做不完，**首轮优先 D1 设计标准 → D2 三屏成品（明暗双份）→ D3 组件状态矩阵**（D3 若首轮做不完可放第二轮）；D4/D5/D6/D7 放第二轮打磨。
