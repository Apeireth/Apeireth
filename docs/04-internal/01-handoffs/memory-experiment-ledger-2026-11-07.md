## 二、本次新跑通的 8 个实验：关键数字、能回答什么、边界

### 2.1 `granularity_delivery_curve`（ec=0，78 s）

* **关键数字**：红楼梦整回 7,401 字 recall@10 **0.4548**、送达率 **0.3926**；
  段落 800 送达率 0.3932、段落 400 0.7434、段落 200 0.9111、段落 120 **1.0909**；
  水浒传整回 7,600 字 0.7157 / 0.7380，段落 120 送达率 **1.8947**。
* **能回答什么**：**送达率是不是由「单元能不能放进 120 字注入窗口」决定的**。
  答：是。单元越大送达率越低，5 档全部同向；段落 120 的送达率 1.0909 与「装得下就接近 1.0」的预测吻合。
* **边界**：① 红楼梦 5 档全同向，**水浒传有 1 处反向**（段落 400 的送达率 2.0000 高过段落 200 的 1.5000），
  单调性**不是普适**；② 送达率 = groundedness 除以 recall，**只在「每题 1 条答案」的口径下有意义**；
  ③ 段落 120 的 recall 只有 0.0578，送达率高**不等于**好用。

### 2.2 `d4_fusion_probe`（ec=0）

* **关键数字**：LoCoMo 单证据 1,122 题，基线 **0.6221**。
  coverage ×0.1 **+0.0045**、×0.5 **+0.0053**、×1 **+0.0125**（过预注册门槛 Δ 大于 +0.005）；
  recency ×0.1 **−0.0080**、×0.5 −0.0793、×1 **−0.5000**；
  dedup 降权 ×0.1 −0.0036、×0.5 −0.1390、×1 **−0.5125**。
* **能回答什么**：**「不接线也能量出某个信号值不值得开」**这个测法成不成立。答：成立。
  分数融合能捞到正收益（coverage），也能量出强负收益（recency ×1、dedup ×1 把 recall 打到 0.12 上下）。
* **边界**：① `importance` 恒默认 5、`group_bonus` 恒 0，**本卷无信息**；
  ② coverage 是**本探针引入的新特征**，不是既有 D4 模块，它证明的是「融合接口能捞到东西」；
  ③ 权重只扫 {0.1, 0.5, 1.0}，**没调参到最优**（这是刻意的，为了避免过拟合报告）。

### 2.3 `injection_chunk_ab`（ec=0，75 s）

* **关键数字**：红楼梦整回 recall@10 **0.4548** / nDCG 0.2821 / evidence_prec 0.0187 / grounded 0.1786；
  段落 300 **0.1019** / 0.0628 / 0.0071 / 0.0714，**L1 −0.3529、L2 −0.0116、L2 题级 −0.1071**。
  水浒传整回 0.7157，段落 300 **0.0242**，**L1 −0.6915、L2 −0.0602、L2 题级 −0.4798**。
* **能回答什么**：**段落化能不能治 L2（送不对证据）**。答：不能，而且**两头都伤**。
  这是 L1 与 L2 的取舍第一次被放在同一张表上。
* **边界**：段落那两行的**期望片段口径被改过**（改成段落里的重叠文本），与整回那两行**不是完全同题**；
  题面一字未改，改的是「答案片段」口径。

## 四、最重要的发现：**公共结构体加字段 = 破坏性变更**（实测影响面）

### 4.1 先纠正一个错判

上一个跑批的诊断是「`Bm25Config` 加了 `strip_cn_stopwords` 字段，用结构体字面量构造它的
6 个实验例子缺字段，编译不过」。**本机实测推翻了这条诊断**：

| 断言 | 实测 | 结论 |
|---|---|---|
| 「有 6 个例子用 `Bm25Config { ... }` 字面量」 | **0 个**。32 个例子**全部**用 `Bm25Config::default()` | ❌ 不成立 |
| 「仓内字面量只有例子里有」 | 全仓 `Bm25Config { ... }` 字面量**只有 2 处**，都在 `crates/engine/memory/src/hybrid_search.rs` 的单测里（**624 行**与 **801 行**），**同一个 commit 里已经补好** | 仓内 **0 处遗漏** |

也就是说：**加字段这件事本身，没有弄坏任何一个例子**。

### 4.2 真正炸掉 32 个例子的是什么

2026-11-07 中午，`crates/engine/memory/src/golden_run.rs` 被改成新增一个
「带 BM25 配置的源构造」，其中调用了 `Bm25LexicalCandidateSource::with_config(documents, config)`，
但 `crates/engine/memory/src/retrieval_pipeline.rs` 里的 `Bm25LexicalCandidateSource`
**只有 `new`、没有 `with_config`**，于是库编不过：

```
error[E0599]: no associated function or constant named `with_config`
   found for struct `Bm25LexicalCandidateSource` in the current scope
  --> crates/engine/memory/src/golden_run.rs:179:53
error: could not compile `apeireth-memory` (lib) due to 1 previous error
```

**lib 编不过，所有例子就都编不过**。实测：

| 命令 | 退出码 |
|---|---|
| `cargo build -p apeireth-memory --examples` | **101**（32 个例子一起挂） |
| `cargo build -p apeireth-memory --lib` | **101** |
| 补上 `with_config` 后 `cargo build -p apeireth-memory --examples` | **0** |

### 4.3 影响面：**比预估大 5 倍**

| 传播环节 | 炸掉的东西 | 实测 |
|---|---|---|
| 公共结构体 `Bm25Config` 加字段 | 仓内字面量 2 处（已同 commit 补好） | **0 处遗漏** |
| 新构造函数 `with_config` 没同步 | `golden_run.rs:179` E0599 | **lib 编不过** |
| lib 编不过 | **33 个例子文件里 25 个直接依赖 `golden_run`**（公共跑批骨架） | **32 个实验例子全挂**（实测 `cargo build --examples` ec=101） |
| lib 编不过 | **全部单测** | `cargo test -p apeireth-memory --lib` 编不过 |

上一次估的「影响 6 个例子」**低估了 5 倍**。
**影响面必须实测，不许估**：机制是「公共结构体加字段，顺着构造函数一路传导，炸在最底下」。

### 4.4 修法（三条，按优先级；**本次一条都没做**，见第六章）

| # | 修法 | 具体做法 | 为什么有效（实测） |
|---|---|---|---|
| **A** | 公共配置结构体加 `#[non_exhaustive]` 加 builder | `Bm25Config` 至今**没有** `#[non_exhaustive]`（实测 `grep -n non_exhaustive crates/engine/memory/src/hybrid_search.rs` 无输出），外部 crate 的调用方一加字段就破 | `#[non_exhaustive]` 只能挡**跨 crate** 的结构体字面量，**同 crate 内**仍然会破，必须配 B |
| **B** | 仓内公共配置结构的构造点**一律用 `..Default::default()` 展开** | `MiningConfig` 全仓 23 个字面量点里**22 个**已经这么写；`Bm25Config` 的 2 个字面量点是单测里的显式全字段（建议也改展开） | 实测：正因为 32 个例子**全部**用 `Bm25Config::default()`，加字段**一个例子都没弄坏**，这条纪律就是防炸的那道墙 |
| **C** | 加字段的 commit 必须把 `examples/` 编进闸门 | `cargo build -p apeireth-memory`（**不带** `--examples`）**不会**编例子，闸门必须显式写 `--all-targets` 或 `--examples` | 实测：这次炸的是 **lib**，但被感知到的是「32 个例子全挂」，闸门要覆盖 lib 加 examples 加 tests 三层 |

## 八、给下一个人的三条操作纪律（都带实测依据）

1. **跑批先把环境写死再动手**：语料根 加 `HOME` 加 `TMPDIR` 加 `RUSTC_WRAPPER` 四项写进命令，
   否则**差在哪看不见**（第 5.1 节：同一份 `robustness_report`，`HOME` 不同，一套语料变两套）。
2. **加字段 = 破坏性变更**：公共结构体加字段，顺着构造函数一路传导，炸在**公共骨架**上
   （第 4.3 节：预估 6 个、实测 32 个例子加 lib 加全部单测，**低估 5 倍**）。
   加完字段**必须**跑 `cargo build -p <crate> --all-targets` 加 `cargo test -p <crate>`，
   而**不是**只跑 `cargo build -p <crate>`（它**不编例子**）。
3. **构造点用 `..Default::default()` 展开**：这是 32 个例子在加字段时**一个都没坏**的唯一原因
   （第 4.4 节 B 条：`MiningConfig` 全仓 23 个字面量点里 22 个已经这么写）。
