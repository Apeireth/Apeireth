## 三、⭐ 带走的三条「尺子纪律」（比任何单点优化都值钱）

1. **闸门量的 ≠ 生产做的** ⇒ ⇒ 凡是把闸门数字当生产结论引用，必须先回答
   「**闸门量的是不是生产那条路径**」。本轮已踩中**三次**（coverage 融合掉出生产、
   `first_pos` 混口径减法、送达口径错）。
2. **跨臂相减必须同口径、必须用生产分词器** ⇒ 否则 +0.1227 这类数字**无效**。
3. **两把尺子不许退步**：内部卷（模板题，守「不许退步」）+ 真人查询卷（393 条真人问句，
   守「不许自欺」）⇒ ⇒ **两尺冲突 ⇒ 不并入**（不许重盖基线给自己放行）。

## 五、边界 / 没测什么（如实清单）

1. **无真机、无真模型 E2E** ⇒ 本轮全部是**库级离线度量**。
2. **生产真实数据分布未知**：内部卷是**模板题**（偏乐观），真人卷语料池是**采样**（22,862 段 vs 真实全库 5.9M ⇒ 绝对值不可外推）。
3. **闸门只覆盖 k=10**（见上表 P0）。
4. **`shadow`/`swap` 没有治理链 ⇒ 切换必被拒**（失败闭合，刻意）⇒ 要真放行需要装配根有治理链句柄。
5. **B3 无「换召回算法」**（只覆盖「重排旋钮」这一类变体）。
6. **`rebuild` 未接 CLI 出口**，且生产向量是**按需现算**（无常驻派生索引文件）⇒ 运维入口面向文件形态。
7. **固定 Hook 的「坏配置 ⇒ 拒开」做不了**：装配面没有错误通道 ⇒ 现在**坏配置按关处理**（失败闭合到默认态）。

## 六、搬�� Windows 时会踩的坑（这边踩过的）

| 坑 | 说明 |
|---|---|
| **语料位置** | 两个语料闸门要 `$HOME/.apeireth/novels/` 与 `$HOME/.apeireth/miracl-exam/`；跑闸门**必须带 HOME**，否则会走「缺语料 ⇒ 跳过」路径（**跳过 ≠ 通过**） |
| **`--offline`** | 本仓惯用 `cargo --offline` ⇒ Windows 上首次需要**预热 cargo 缓存**（或允许一次联网） |
| **`RUSTC_WRAPPER`** | Linux 这边 `RUSTC_WRAPPER`（sccache）以 root 跑会产出 root 拥有的文件 ⇒ bai 用户读不了 ⇒ **必须留空**；Windows 无此问题 |
| **中文文件名/路径** | 本仓文档与语料都是中文名 ⇒ Windows 下注意**编码与路径**（仓库已有 `doc-paths` 门禁） |
| **别用 `git add -A`** | 共享工作树里常有**别的线**的在途文件 ⇒ 一律**按文件白名单**暂存 |
