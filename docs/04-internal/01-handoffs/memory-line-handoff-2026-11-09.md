## 一、⭐⭐ 第 1 件：内部卷标注缺陷 `mine_conflict`（**决定内部卷上限**）

### 1.1 问题
`golden_mining::mine_conflict` 的 `fragment_for` 在**找不到「主体」**时**退而找「锚点」**
，于是「前一条记录**从未提到主体**」也能通过，被写进 `expect_ids`。

### 1.2 实测影响（这就是为什么它必须拍板）
| 卷 | 「主体一次都没出现」的金标占比 |
|---|---|
| redchamber | **4.0%** |
| watershed | **11.0%** |

这些金标**任何检索器都找不到**：不是排序问题，是**题面与金标自相矛盾**
，所以内部卷的绝对值**从头就带着一层无法解释的折扣**。

### 1.3 选项
* **A（收窄金标，不动题面）**：`expect_ids` 只保留**真提到主体**的记录；一条都不剩则**剔除该题**。
  ，题面不变、金标变正确；**基线必须重盖**（题型集合变了）。
* **B（改题面，不动金标）**：把问题改成问**锚点**，让题面与金标一致。
  ，金标不变，但**查询变了会改变检索结果**，**基线同样要重盖**
  （注意：这不是「不改基线」的选项，别被「金标没动」误导）。
* **C（不改，只记账）**：保留现状，把「不可检索到的金标」写进**基线版本号**当已知上限。
  ，零改动、零重盖；但内部卷永远是一把**被拖低的尺子**，后面每次「涨了/跌了」都要先扣解释。

### 1.4 建议：**A**
理由：A 和 B 都要重盖基线（B 并非零成本），那就选**语义最干净**的那个
，A 只修**标注事实**（记录到底有没有提主体是可判定的客观事实），不动题面语义。
C 最省事，但它把矛盾**固化进基线名字里**，代价是之后所有人对内部卷的绝对值都失去解释力。

### 1.5 ⚠️ 拍板时必须**一起**定的三件事（否则重盖会变成「洗数据」）
1. 重盖后的**基线版本号**怎么命名（必须能一眼看出「这一版换过尺子」）；
2. **旧基线留档**，不许原地覆盖（否则「涨了」无法归因是改进还是换尺子）；
3. 重盖**不是给回归放行**：重盖前后**各跑一次两把尺子**，把差值写进证据页。

## 二、⭐⭐ 第 2 件：`tool.mcp_bridge` 的 `verify_cmd`（**绿但量不到东西**）

### 2.1 问题
声明里的 `verify_cmd` 是：

```
cargo test -p apeireth-tools-canonical mcp_bridge
```

该 crate 是 **lib** 目标，`mcp_bridge` 这个过滤词**匹配不到集成测试**
，于是 **0 个测试匹配、退出码 0**，声明显示「通过」，但**它量的是一团空气**。

### 2.2 实测
加上 `--lib` 之后得到 **26 passed**。

### 2.3 选项
* **A**：`verify_cmd` 补 `--lib`，复跑 26 passed 后重盖 `verified_at`
  （**最小改动，立刻让声明变真**）。
* **B**：另写一个真正走桥的集成测试当 `verify_cmd`（更贴「端到端」，工作量更大）。

### 2.4 建议：**A**
理由：`--lib` 是**这个 crate 的唯一正确入口**，补上是**补齐事实**，不是换尺子；
B 的价值要等真的需要「端到端证明」时再投，现在补 `--lib` 已经能把「绿但量不到」变成「真绿」。

## 四、本线的**边界补充**（并行线交接页 §五 之外的）

1. **协同器那半没有专门的集成用例**：装配整套协同器成本高
   ，正确性靠「与选择侧**共用同一个函数**」+ 算术（7,400 字 × 2 条 vs 4,000 预算）保证。
   **真正的解法是换可达型考卷后端到端量**，而不是补一个假装在测协同器的单测。
2. **CPU 成本没测**：长记录现在会真正进入候选集，打分候选数变多
   ，多出的成本在**候选生成侧**（`select` 本来就把全部候选算过一遍分），未实测。
3. **没测「锚定找不到主体」的退化路径**：`find_subject_window` 找不到时保留原文
   ，此时送达量 = 原文长度，方向**保守**（不会超额送达）。

## 七、搬机器专属的**四个坑**（并行线交接页 §六 没提的，本机今天全踩过）

并行线那封的 §六 已列：语料位置 / `--offline` 预热 / `RUSTC_WRAPPER` / 中文路径 / 别用 `git add -A`。
**下面是它没提、但今天实打实浪费了时间的四条**：

### 7.1 🚨 **推送只有一条通道：`apipush2.py`；绝对不要用 `apialign.py`**

```bash
python3 apipush2.py debt-round8 <仓库路径> \
  --remote-base <远端完整40位sha> --local-base <本地基点完整40位sha>
```

* 两个 base 都必须**完整 40 位**（短 sha 会挂）；
* 脚本会校验**两个基点的 tree 逐字相同**，才能保证推出去的 diff **只含自己的改动**；
* 一个提交一次 ref 更新，**一次 CI**。

**`apialign.py` 是 HARD align，会丢掉未推的本地提交**（本线已经因此丢过东西）。

⚠️ 今天还踩了一次**半截操作**：`--local-base` 我错传成了**远端**基点的 sha（本地其实还没 rebase 到那），
脚本照样建了提交，最后 tree 校验失败。**正确顺序永远是：先 `git rebase origin/debt-round8`，
再用 `git rev-parse origin/debt-round8` 取 base，**本地 HEAD 必须真的以它为父**。

### 7.2 🚨 **`gates.sh` 必须把 worktree 路径作为第 1 个参数传进去**

```bash
bash gates.sh <你的仓库路径>
```

不传的话它默认跑 `/home/bai/Projects/apeireth-consolidate-wt`（**另一个 worktree**）
，于是 **9 个步骤报 `can't open file .../scripts/xxx.py`**，看起来像「脚本全没了」，
其实**全是假红**。

**分辨方法**：报错里出现**别的仓库路径**，就是路径错了，不是代码坏了。

### 7.3 **`cargo test --workspace` 要单放后台**

全门禁 40–60 分钟，其中这一步就 **30 分钟以上**；本机两次都是在它上面被关机打断的。
，建议：**先跑其余 32 步**（大多几秒到几十秒），把它单独丢后台。

### 7.4 **`redchamber.txt` 必须用 UTF-8 那一份**

* `/home/bai/.apeireth/novels/redchamber.txt` => **UTF-8**（约 2,601KB / 954,114 字）**用这份**
* `/root/.apeireth/novels/redchamber.txt` => **不是 UTF-8**，别拷错

`watershed.txt` 约 1,593KB / 581,003 字；MIRACL 考试缓存是
`miracl-exam/corpus.jsonl`（22,862 docs）+ `miracl-exam/exam.jsonl`（393 问，字段 `id` / `query` / `gold[]`）。

### 7.5 一条**我今天违反了**的纪律
我用了 `git add -A`，把**并行线在途的 fmt 改动**一起暂存了（发现后已 `git checkout --` 还原）
