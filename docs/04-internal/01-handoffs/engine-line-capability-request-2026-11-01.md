## 0. 背景（为什么现在要这个）

- K3.1 的**设计原型**已开工（模式 `DESIGN_ONLY`），交付物是网页形态的设计原型 + 令牌 + 屏幕 + 组件状态说明。
- 生产前端最终跑在**自研 UI 引擎**上；ADR-0018 已 Accepted（基底 = 引擎；设计原型载体 = K3.1 网页；旧前端工程仅旧线基线）。
- 外部评审已指出：**产品仓的引擎当前只是响应式内核切片**（状态图 + 调度），**没有 DOM/渲染/焦点/IME 的生产消费者**，也**没有真实 WebView2 验证**。
- 作战计划因此设了 **W1 硬前置门**：引擎产品仓的最小垂直切片未验证前，W1 只做设计对照，不启引擎实现。

**本件要引擎线回答两件事**：① 能力矩阵（现在到底有什么）② 最小垂直切片（什么时候能有）。

---

## 1. 要交付的东西

### ① 能力矩阵（一份表，先交）

逐项原语标注**现状与证据**。字段规范：

| 字段 | 含义 |
|---|---|
| 原语 | 能力名（见 §2 清单） |
| 现状 | 四级口径之一：`IMPLEMENTED` / `PRODUCTION WIRED` / `DEFAULT ENABLED` / `HARDWARE VALIDATED` |
| 平台 | `native` / `wasm32` / `WebView2 实机` / 未覆盖 |
| 证据 | 可复核路径（代码位置 + 测试名 + 证据产物） |
| 缺口 | 还差什么、预计哪一批 |
| 备注 | 限制条件（如仅 native 可测、仅单测覆盖） |

**硬要求**：每个"已实现"都要有可复核证据；**没测过就写"未实测"**，不许用"应该可以"。

### ② 最小垂直切片（一条能跑通的链路 + 验证）

链路（缺一不可）：

```text
Signal → VNode/RenderPlan → DOM mount/update/unmount → event → focus/IME → dispose
```

切片验收门（全部要**可复核数字**，命令 + 日期 + 工具链）：

- [ ] wasm32 构建通过；
- [ ] 在**真实 WebView2 窗口**里跑通整条链路（不是浏览器 devtools 模拟）；
- [ ] 事件回传、焦点切换、输入法输入、销毁后不再响应，均有断言；
- [ ] 真实窗口的**帧率与内存**有测量结果（测不到写"未实测"，不许估算）；
- [ ] 证据产物落盘（截图/录屏/日志）并登记路径。

## 3. 待复核缺陷清单

来自外部评审的一批生命周期与调度问题。**本线只转办，不代修**；请引擎线逐条回现状：

| # | 现象 | 优先级 | 请回 |
|---|---|---|---|
| 1 | 派生节点句柄丢失后，图里的死节点与边仍残留（无自动析构） | P1 | 已修 / 待修 / 不适用（附证据） |
| 2 | 效果句柄丢弃后仍留在表里继续响应（无自动析构） | P1 | 同上 |
| 3 | 多层跟进刷新：只有首轮会继续请求下一轮 | P1 | 同上 |
| 4 | 切换宿主调度器后旧票据未失效，可能丢刷新 | P1 | 同上 |
| 5 | 用户效果抛异常后依赖不恢复，后续更新不再触发 | P1 | 同上 |
| 6 | 跨运行时读取派生值会静默失去订阅 | P1 | 同上 |
| 7 | 清理回调只在销毁时执行，重复注册累积 | P2 | 同上 |
| 8 | 已销毁作用域上的 API 直接抛异常，缺安全入口 | P2 | 同上 |
| 9 | 图结构用有序容器 + 强制拷贝，未证明适合 60Hz 大规模界面 | P2 | 同上 |

## 6. 边界

- 本线（视觉总攻线）**不代修引擎代码**，也不替引擎线承诺日期；
- 矩阵是**单一真源**：设计包、施工规格、组件契约里凡是提到引擎现状的，一律以矩阵为准；
- 矩阵未回填之前，任何文档**不得声称引擎已具备某原语**（当前口径："以矩阵为准，未列入即视为未就绪"）；
- K3.1 的设计施工**不受本件阻塞**（模式 DESIGN_ONLY）；被阻塞的是引擎实现与 W1。
