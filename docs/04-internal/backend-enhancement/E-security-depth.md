# E. 安全纵深

> `Status: 📋 想法细节（隶属 00-backlog #E）`

## 现状
- 三洋葱、R0-R4、审批四态、审计配对原子、不变量在线守卫、写总闸（词法扫描+双查）；
- 已知残留（在案）：①沙箱本体进程拦截层的反向不对称（Remove-Item 拦、静态调用穿——本仓外）——**本仓面已由对象级判定闭环（E-P3，见下）**，仓外形态不对称如实留残余 ②命令级审批名单——**已族归一（E-P2，见下）**，残余=族集授权不绑目标与词法外形态（对象级判定兜底）③多用户/权限模型无（单机单主）。

## 想法
1. **沙箱对象级判定**：API 形态无关的访问判定（对象级 ACL/token 约束），消除"换 API 换权力"面 —— **已交付（E-P3）**：`crates/capabilities/tools/src/object_access.rs` 对象级判定层（对象域 × 四动作词表、执行前后状态对比事实判定、越界即帧 + `sandbox.object_violation` 审计、`ObjectAccessPolicy` 挂载点），沙箱执行面接线 + 星港线接入契约见 [E-object-level-contract.md](E-object-level-contract.md)；残余（事后判定/域界/枚举零痕迹/元数据指纹/仓外拦截层）如实列该文件 §1；
2. **审批族归一**：命令级名单按语义族匹配（删除族/写入族/网络族），孪生 API 形态同权 —— **已交付（E-P2）**：族词表+族归一函数进治理层单一来源（`governance/src/approval_family.rs`，写意图族词表同源引用），审批/授权记录的对象 = 族（批"删除族"=该族所有形态生效、同族换形不重批、跨族仍逐族审批），存量逐字记录迁移生效，审批卡族标注全链；星港线接入契约见 [E-approval-family-contract.md](E-approval-family-contract.md)；残余（族集授权不绑目标/归属面段首口径/词法外形态）如实列该文件 §10；
3. **多用户**：T2 中枢的多客户端权限（主人/访客/只读角色、每客户端授权范围）；
4. **证明面互弹药**：Kani/TLA 覆盖率向审批/配额语义扩展（与验证面硬化线合力）。
