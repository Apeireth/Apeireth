# E. 安全纵深

> `Status: 📋 想法细节（隶属 00-backlog #E）`

## 现状
- 三洋葱、R0-R4、审批四态、审计配对原子、不变量在线守卫、写总闸（词法扫描+双查）；
- 已知残留（在案）：①沙箱本体进程拦截层的反向不对称（Remove-Item 拦、静态调用穿——本仓外，需对象级判定）②命令级审批名单逐字精确匹配（族归一是治理语义变更）③多用户/权限模型无（单机单主）。

## 想法
1. **沙箱对象级判定**：API 形态无关的访问判定（对象级 ACL/token 约束），消除"换 API 换权力"面；
2. **审批族归一**：命令级名单按语义族匹配（删除族/写入族/网络族），孪生 API 形态同权；
3. **多用户**：T2 中枢的多客户端权限（主人/访客/只读角色、每客户端授权范围）；
4. **证明面互弹药**：Kani/TLA 覆盖率向审批/配额语义扩展（与验证面硬化线合力）。

## 缺口
- 威胁模型文档化（trust boundary 图）——纵深设计先要有敌人画像。

## 分期
P1 威胁模型文档 → P2 审批族归一 → P3 沙箱对象级 → P4 多用户。

## 验收
每层纵深带对抗测试（绕过尝试用例集）；残留风险继续如实入档。
