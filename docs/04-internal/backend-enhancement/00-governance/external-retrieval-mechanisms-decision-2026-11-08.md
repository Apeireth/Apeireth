# 外部检索质量机制的**吸收台账与裁决**（2026-11-08）

> **四级口径**：本文是**决策记录**，不是能力声明页。
> 每条能力的等级与证据以 `docs/status/claims.yaml`（唯一真源）为准。
> 本文**不**宣称任何 **HARDWARE VALIDATED**（无真机、无真模型 E2E）。
>
> ⚠️ **中性表述**：本文只描述**机制**（相关性-多样性折中 / 锚点重塑 / 参数配置面 / 词面覆盖率融合），
> **不出现任何外部产品名、仓库名、文档名**；引用数字一律指向**本仓自己的实测**。

## 〇、为什么有这份文件

外部生态里有一套「检索质量工程」的做法（标签引力重塑 + 能量残差分解 + 结果多样性重排 + 参数热调参）。
owner 指令：**「对我们有好处的全部吸收借鉴，但是注意工程纪律，中性表述」**。

⇒ 「全部吸收」**不等于**「全部照抄」。本文把每一条机制**逐一裁决**：
**吸收 / 已有（并修正）/ 量了但据证据不接 / 明确不做**，每条都给**理由**与**证据指针**。

**纪律**：本文任何一条都**不许**写成「以后再说」——要么吸收，要么**带理由**地不做。

## 二、逐条裁决（含数字）

### ① 残差式多样性重排 —— **已有，且默认档是净损失 ⇒ 默认改正**

机制：逐轮按 `(1-λ)·相关度 + λ·新颖度` 贪心挑选；新颖度 = `1 − 与已选项的最大词面相似度`。

**本仓早已有**（`MemoryRankingConfig::diversity_lambda`，默认原为 **0.20**）。实测（内部两卷，同语料/同挖题/同生产管线）：

| 语料 | λ=0.0 | λ=0.2（原默认） | λ=0.5 | λ=1.0 |
|---|---|---|---|---|
| redchamber recall@10 | **0.4010** | 0.3802（**−5.19%**） | 0.3646 | 0.1615 |
| watershed recall@10 | **0.7240** | 0.7031（**−2.89%**） | 0.6719 | 0.1979 |

⇒ **默认 0.20 是净损失** ⇒ 改为 **0.0（关）**，需要「去冗余展示」的调用方**显式**给 λ。
（λ=0 仍保留**正文完全相同的去重**——去重 ≠ 折中，两件事分开钉。）

**两侧口径（真人卷，393 条真人问句）**：
λ=0 recall **0.8372** / 近似重复对 **0.1094**；λ=0.2 recall **0.8295（−0.92%）** / 近似重复对 **0.0636（−41.9%）**。
⇒ **内部卷测不出去冗余收益**（章节彼此足够不同 ⇒ 近似重复对恒为 0）⇒ **只看一面会误判**。

**覆盖**：`crates/engine/memory/tests/retrieval_diversity_lambda.rs`（5 条 λ 语义；反证：把 λ 短路成 0.0 ⇒ λ=1 用例红）。

### ② 标签/锚点引力重塑 —— **量了 ⇒ 不接生产**

机制：先从查询抽「锚点词」，再给**锚点命中更强者**加成（本仓量测口径：池内 IDF 加权 + 按题归一化到 (0,1]）。

| 尺子 | Δrecall@10 | ΔnDCG@10 | 近似重复对 |
|---|---|---|---|
| 内部卷 redchamber（96 题） | **0.0000** | **−0.0104 / −0.0219（反向变差）** | 0 |
| 内部卷 watershed | **0.0000** | 0.0000 | 0 |
| 真实查询卷（393 题） | **+1.36%**（α=0.2） | +0.0068 | 44 → 43 |

⇒ **两把尺子方向不一致**（与 `first_pos` 同类问题：仪器差异）⇒ **不许默认开**；
且强度与同类的 `first_pos` **同一量级**（真人卷 +1.36% vs +0.0192；模板卷两者都掉）、
**没换来去冗余**（44→43）⇒ 「相关度 vs 去冗余」的权衡不成立。

> ⚠️ **口径更正（2026-11-08 并行线实测）**：此前记录的「`first_pos` 真人卷 **+0.1227 / +16.9%**」
> 是**混口径减法**（基线是「逐题命中比例的平均」，实验臂是「二值任一命中」）⇒ **该数字无效、已撤回**；
> **同口径真值 = +0.0192**（0.7246 → 0.7438），且模板卷是 **−0.0431 / −0.0282**。
> ⇒ **本条的「跨臂相减必须同口径」纪律由此再加一条实证**（见 `retrieval_pipeline/first_pos.rs` 文件头）。

**为什么不算「漏掉的收益」**：这条机制**已经留下可复现的测量入口**（`anchor_gravity_ab.rs`）⇒
将来若换了语料/换了改写方式，**一条命令就能重测**，而不是重新实现一遍。

**顺带发现（推测，未证明）**：它与融合里已有的 **coverage 项**（权重 0.5）**高度共线** ⇒ 内部卷上它主要在**重排**。

### ③ 参数配置面 —— **吸收形态，不做热重载**

**选项**：
- **选项 A（不做）**：旋钮只走 env ⇒ env 名额已 **150/154** 顶格 ⇒ 下一个旋钮必须先删一个；
- **选项 B（吸收形态）**：新增 **Host 配置面**（数据根下的 `retrieval.json`）⇒ 不占 env 名额、支持**按部署**取值；
- **选项 C（照抄热重载）**：文件监听 ⇒ 运行中改排序权重。

### ⑤ BM25 长度归一 `b`：**量了 ⇒ 默认不改**（但记下「按部署可改」）

长度归一越强（b 越接近 1）⇒ 长文档被压得越狠 ⇒ b 变小 ⇒ 长文档更容易进 top-10。
两把尺子实测（唯一变量 = b）：

| 尺子 | 指标 | b=0.75 → 0.3 的变化 | 裁决 |
|---|---|---|---|
| **真实查询卷**（393 条真人问句） | recall@10 | **+4.25%**（相对） | 方向尺说：**涨** |
| | nDCG@10 | 同步涨 | |
| **内部卷** redchamber（模板题） | recall@10 | **−0.79%** | 不许退步尺说：**掉** |
| | **nDCG@10** | **−1.8%**（超 1% 容差 ⇒ **闸门红**） | |
| | 送达率 | −0.49% | |
| **内部卷** watershed | recall@10 | ±0 | |
| | nDCG@10 | −0.75% | |

⇒ ⇒ **两把尺子冲突** ⇒ ⇒ **默认不改**：内部基线闸门是**阻塞**门禁，
⇒ ⇒ **不许用「重盖基线」给自己放行**（那是放宽尺子，不是进步）。
⇒ ⇒ **要 b=0.3 的正确姿势**：**按部署**在 Host 配置面显式给值（自己先量过），不改全局默认。

**裁决：选 B，明确不做 C。**

**建议（给 owner 的拍板建议）**：采纳**选项 B**（配置面 + 启动时读一次 + 失败闭合），
**明确否决选项 C**（运行中热重载）；选项 A（继续只走 env）**不推荐**（env 额度已顶格，且不支持按部署取值）。
理由：
1. env 是**进程级全局**的 ⇒ 不适合「按部署给不同取值」；配置面是**每部署一份文件** ⇒ 更贴运维现实；
2. 仓里已有**配置面先例**（`mesh.json`：StoredDoc 拒开、失败闭合、缺省不注册）⇒ 形态一致、评审有参照；
3. **不做热重载**：热重载 = 会话中途**静默**改排序权重 ⇒ 与治理链/审计口径冲突（行为变更不可解释）；
   而我们已有**受治理的运行时调权**（证据驱动、会话维度、有账）⇒ 两套调权面并存会**互相打架**。

**只放「已量过、默认零变化」的旋钮**（`first_pos_alpha`、`diversity_lambda`），**不放**整个权重向量
——权重归**调权引擎**管（那是受治理的那条路）。

**口径（失败闭合）**：文件缺失 ⇒ 不施加任何旋钮（**逐字节零行为变化**）；文件存在但坏（畸形/串档/未来版本/未知字段/越界）
⇒ **装配失败**（坏配置不许被当成「没配置」）；合法 ⇒ 只施加**文件里显式写了**的旋钮。
**只在启动时读一次**。

### ④ 词面覆盖率融合 —— **我们已有，但生产没吃到 ⇒ 已修**

**缺陷**：词法源自己排序用 `lexical + 0.5×coverage`；而生产的多路管线为对齐量纲会**重算**分数
（`score_components.weighted(...)`）⇒ 那次重算**只带分量、不带 coverage**（coverage 不是分量字段）
⇒ ⇒ **coverage 被丢掉** ⇒ ⇒ 后果是「**闸门量的 ≠ 生产做的**」：
内部卷基线闸门与真人卷闸门量的是**源自己的分数**（含 coverage），生产用的是**不含 coverage** 的分量分
⇒ ⇒ 2026-10-28 实测到的 coverage 正收益（recall +0.0125 / +0.0266）**从未到达生产排序**。

**实测（真人卷 393 题）**：修复前管线臂 0.7233 vs 单路词面臂 0.7246 ⇒ 低 **0.0013**；
修复后管线臂 **0.7246 / nDCG 0.4804**，与单路词面臂（0.7246 / 0.4803）**同到小数点后 4 位**。

**修法**：`retrieval_pipeline/scoring.rs::route_relevance` 补回同一项，并按**管线分量口径**缩放
（`COVERAGE_WEIGHT × lexical_weight × coverage`，且**只在 `lexical > 0` 时加**，与源里同一条件）
⇒ ⇒ 单词法通道时**管线排序与源排序逐条同序** ⇒ 「闸门量的就是生产做的」。

**证据**：新增 `crates/engine/memory/tests/retrieval_caliber_parity.rs`（同序断言；反证：把两处调用点退回
`weighted()` ⇒ 顺序分岔 ⇒ 变红）；三门禁数字**逐字不变**（内部卷基线 Δ +0.0000 · 融合通道 Δ +0.0000 ·
真人卷 Δ +0.0000%）；内部卷两卷**完全不变** ⇒ **不牺牲内部卷**。

## 三、这次裁决带出的**纪律**（要写进合同，不只是写在这里）

1. **「吸收」= 吸收机制 + 裁决口径**，不是复制代码：**每条外部机制都要有「吸收 / 已有 / 量了不接 / 明确不做」四选一的结论 + 理由 + 证据指针**。
2. **两把尺子必须都报**：内部卷（模板题）守「不许退步」，真实查询卷（真人问句）守「不许自欺」；
   **结论相反也必须照报**，并且**默认必须关**。
3. **凡「测出来的收益」都要问一句「生产真的吃到吗」**——④ 就是这么问出来的。
4. **配置面 ≠ 热重载**：行为旋钮只在**启动时**读一次，失败闭合，不静默回落默认值。
5. **env 额度只减不增**（150/154）：下一个旋钮默认走**配置项**，不走 env。
