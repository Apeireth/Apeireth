# 尺寸棘轮政策修正提案 —— 停止「为过门而拆墙」

> 日期：2026-10-23 · 状态：**提案（待 owner / 架构线裁决）** · 归属：架构线（`arch_guard.py` 是其资产，本页不改脚本）
> 触发：副总指挥指出「为过尺寸棘轮把 `cli/src/lib.rs` 从 3878 拆到 3877、`panels.rs` 从 1641 拆到 1633，
> 动机是过门不是内聚」。本页把这件事摆开，给出口。

## 1. 棘轮在防什么（先说它对的部分）

`docs/architecture/contract.toml` 的 `[budgets] max_file_loc` + `scripts/arch-baseline.txt`
对**已存在**文件行数做「只减不增」的棘轮，防的是 god-file：单文件几千行、职责混杂、
review 无从下手。这个目的今天依然成立，不该取消。

## 2. 但它现在的失效模式

规则只认「行数不涨」，于是任何需要在该文件加 1 行的真实改动，都只能靠两条路：

1. **真拆分**（把一块职责搬成独立模块）——好，但成本高，且不是每次改动都恰好可拆；
2. **凑行数**（合并注释、删空行、把两行压成一行）——纯税，零工程价值。

2026-10-22/23 的接线批两种都发生了，如实记账：

| 动作 | 性质 | 评价 |
|---|---|---|
| `memory_ledger_view.rs`（视图层出 `self_status.rs`，4193→4122） | 真拆分 | ✅ 保留 |
| `self_status_probe.rs`（探针出 `cli/src/lib.rs`，3878→3822） | 真拆分 | ✅ 保留 |
| `panel_memory_update.rs` / `panel_governance_port.rs`（HTTP 面 / 端口实现出 panels） | 真拆分 | ✅ 保留 |
| `cli/src/lib.rs` 3878→3877：一行注释压成行尾注释 | **凑行数** | ❌ 待偿债 |
| `self_status_source.rs` 2064：合并两行文件头注释 | **凑行数** | ❌ 待偿债 |

两处「凑行数」没有伤到功能（注释而已），但**风气一开**，下次就会有人为了让门变绿去删测试、
合并 match 分支、甚至拆承重墙。这正是提案要拦的东西。

## 3. 提案（四条，按优先级）

### 3.1 禁止 cosmetic 抵扣

不得以「合并注释 / 删除空行 / 压行尾注释 / 重排格式」作为尺寸违规的抵扣。
违规形态好识别：diff 里被删的行**没有承载逻辑**，而文件只是恰好回到基线。

### 3.2 新增「有理增长」通道

照 `env-registry` 的做法，加一张**受复核的允许表** `scripts/size-justified.txt`：

```text
# <相对路径>  <允许上限行数>  # 理由 / owner / 到期波次
crates/adapters/cli/src/lib.rs  3900  # 组装根天然聚合：新增接线点必须在同一处可见 (owner, wave 6)
```

规则：

- 表内条目的文件，允许长到「允许上限」为止；超出仍红；
- 每条必须写**为什么这个文件必须长**（聚合点 / 跨层装配 / 常量表）与 owner；
- 到期波次复核：到期未收敛 = 退回基线，强制作出取舍；
- 表本身**只减不增**（条目数棘轮），防止变成"什么都能进"的后门。

### 3.3 测试代码不计入尺寸

`#[cfg(test)]` 块与 `tests/` 目录下的文件不计入 `max_file_loc` 与基线。
测试变长不是设计问题；现在这条正在逼着人压缩测试注释与夹具（本批已出现）。
实现代价很小：arch_guard 的 `scan_sizes` 已经按文件切分，只需在统计前剔除 `#[cfg(test)]` 之后的部分。

### 3.4 时间表：先落 3.2，再转真拦截

`arch_guard` 计划 2026-11-03 从 report-only 转真拦截。建议：

- **结构性 / 方向性违规**（W10）照常按期转拦截——那些是真架构问题；
- **尺寸类（W1）**等 3.2 的通道落地后再转拦截，否则等于要求每条线「要么别改，要么拆墙」。

## 4. 不做（明确拒绝的路）

- **取消棘轮**：会放出 god-file，且已有 11 个文件在 4000+ 行；
- **把 baseline 直接上调**：等于把棘轮变成摆设，比 cosmetic 抵扣更糟；
- **一刀切豁免组装根**：`cli/src/lib.rs` 这类文件确实该长，但必须**逐条登记理由**，不能整类放行。

## 5. 待偿债清单（本提案落地后修）

1. `crates/adapters/cli/src/lib.rs`：恢复被压成行尾的那行注释（+1 行，走 3.2 登记）；
2. `crates/engine/runtime-assembly/src/canonical/self_status_source.rs`：恢复被合并的文件头注释（+1 行，同上）。

两处都是 1 行量级，本身无害；列出来是为了**不假装没发生**。
