# 施工纪律（多 AI 共同施工宪章）

> `Status: 🔒 生效中（2026-10-02 立，适用于后端增强全部工程）`
> 这份文件是给**每一位进场施工者**（含外部协作 AI）的第一课。目标：活儿干漂亮，**零技术债**。

## 〇、设计第一律：AI 先用、人后用（2026-10-13 立）

**Apeireth 是给 AI 用的。** 一切工具性能力的第一用户是 agent 自己（它先能用），
同一内核再外接人类界面做第二出口（用户玩一玩）。裁定顺序：
1. 能力先做成**工具**（模型可调用、过治理、入名册）；
2. 人类界面是同内核的**包装出口**（不另起炉灶、不两套逻辑）；
3. 判据：删掉人类界面后，该能力对 agent 仍然完整可用。

## 〇之二、许可搬运线（2026-10-18 立，owner 裁定）

**宽松协议（Apache-2.0/MIT 等）项目=放行搬运**（省工作量），但过四关质检，绝不无脑搬：
1. **许可关**：核实协议与版权主体（NOTICE 落档、版权头原样保留、改动声明、商标不用）；
2. **质量关**：代码质量检查（测试覆盖/unsafe 面/依赖健康/维护活跃度）——不达标不搬；
3. **安全关**：secret-scan+已知漏洞面+恶意行为审查（构建脚本/网络面）；
4. **集成关**：构建可复现/体积可控/依赖树不炸/平台兼容。

中性表述豁免表新增「许可署名头」类（法律义务>行文风格）；copyleft/未知协议=不搬（只研机制）。

## 一、不许留债（零债纪律）

1. **不新造债**：不写"临时实现"、不留 TODO 无主、不注释掉代码当备忘（要么删要么完成）；
2. **见债必还**：碰到既有债（编译警告/陈旧断言/孤儿代码）顺手清或明确登记到 `00-backlog.md` 的债栏，不许"路过就算"；
3. **命名即承诺**：符号/开关/字段的名 = 它的全部权力（名实相符，见 capability-switch-power-audit 先例）；
4. **测试即证据**：没有测试钉住的实现等于没做；测试要钉**行为**不钉字面（演进断言时注明理由）。

## 二、叠加不覆盖（多人并发纪律）

1. **edit 前先读后改**；文件冲突时后到者 rebase，不覆盖他人在途工作；
2. **战场不重叠**：批与批的文件范围预先声明（write_scope），同文件区施工必须排队；
3. **半成品不弃尸**：中道停机必须回报"已完成/未完清单"（接棒制的遗嘱）；
4. **他人文件不乱动**：跨范围的顺手修 = 报备 + 最小改动 + 说明。
5. **⚠️ 自动合并（0 冲突）≠ 合并结果正确**（2026-11-03 实测加）：
   * **形态**：两条线**各自**给**同一个 YAML step** 加了**同一类键**（两处 `if: always()`）
     ⇒ 各自 push ⇒ 互相覆盖 ⇒ 合并时 **git 报 0 冲突**（两处**位置不同** ⇒ 自动合并把两行都留下）
     ⇒ ⇒ 结果：**YAML 同层重复键** ⇒ GitHub **拒解析整个文件** ⇒ **该 workflow 静默失效（0 job）**；
   * ⇒ **git 看不见的冲突**（同键不同位置）**只能靠机器守卫**抓 ⇒ 故本仓已加
     `scripts/check_yaml_duplicate_keys.py`（**严格 loader**；`yaml.safe_load` 与 Ruby YAML
     都**静默取最后一个键** ⇒ 常规自检查不出来 ⇒ 该病已复发三轮）；
   * ⇒ **纪律**：合并后**必须逐项复核**合并结果（谁更全取谁 + **跑一遍新守卫**）
     ⇒ **不许**因为「0 冲突」就当合并正确；
   * ⇒ **同批文件**（同一 workflow / 同一契约 / 同一守卫脚本）⇒ **必须排队**，
     或至少在合并后**逐文件 diff 复核** ⇒ ⇒ **同文件同位置之外**也要防「同键不同位置」。

## 三、口径与诚实（不假装纪律）

1. **无脚本不发布数字**；未达标标红；"暂无接口"就写"暂无接口"（零假旋钮）；
2. **口径唯一**：crate 数/测试数/版本轴/术语全库一致（口径统一批先例）；带日期的历史档案不动；
3. **错误即帧**：失败走正式通道报真因，不静默降级、不"applied 0"式谎帧；
4. **中性表述**：代码/注释/commit 零第三方产品名、零"移植/借鉴"措辞（真实路径与研究引注走豁免表）。

## 四、工程门禁（每批交付的出口）

1. `cargo test --workspace --locked -j 2` 全绿（链接器内存口径；负载 flake 隔离复跑定性）；
2. `cargo clippy --workspace --all-targets --locked -j 2 -- -D warnings` 零警告；
3. `cargo fmt --all -- --check` 干净；前端 `pnpm check` + `pnpm test` 全绿；
4. `scripts/check-neutral-terms.ps1` 零命中；secret-scan 过；
5. 文档随行：影响口径/接口/行为的改动同步文档（含审计表/契约文档）。

## 五、验证与证明（与验证面硬化线合力）

1. 治理/安全语义改动 → 补对抗测试（绕过尝试用例）；核心不变量尽量上证明面（Kani/TLA 口径）；
2. 破坏性/不可逆语义 → 默认拒绝，人工审批链兜底；
3. 性能改动 → 基准前后对比（脚本可复跑），不许改口径粉饰。

## 六、会话生存与协同增补条款（2026-10-15 批 L1 实战回写）

> 依据：`docs/04-internal/engineering-experience/` 两矿（协同模式矿 / 死亡解剖矿）的实战提炼。

1. **渐进落盘三律**：①做一段落一段——每个处理单元完成即落盘（小文件族/骨架先行），中道猝死不丢成果、可续作；
   ②限读取材——读前先定读取预算，装饰层（徽章/横幅）剥除后取有界等价窗口，单源超限即截断不硬读；
   ③外部素材先净化后入上下文（触发词替换为占位），取材口径（净化/限读/剥装饰）在产出抬头如实注明。
2. **占位必报、补位必注**：为他人在途面落占位（`None`/接口桩）必须带报备注释、且占位可被识别并喊破（配测试自报未接线，不做假旋钮）；真接线归口原线。跨线补位（如编译断点）按**对方自己的口径**补最小面，机械空白与语义改动分开声明。
3. **顺手修三判**：确证级小债（挂名不跑/静默失效）顺手清；验收必经但不在战场内的面 = 最小改动 + 报备 + 理由；超范围的顺手重构**登记不实施**；他人在途红**标红不代改**，报备待归口线自检收口。

## 七、机器化纪律（2026-11-08 批 L4 实战回写）

> 依据：[docs/04-internal/engineering-experience/](../engineering-experience/) 06 矿（真源与守卫面）+ 07 矿（工作线面）。
> 本节全是**可判定**条款 ⇒ 每条都配一条**退出码可判**的命令（见各条「守卫」）。

1. **声明即承诺（盖章语义）**：状态声明的 `verified_at` 是**证据基线**，不是时间戳 ⇒ 盖章前必须**逐条实跑**
   该声明的 `verify_cmd` ⇒ **盲 bump = 把「源码变了」的信号静音**。复核判据是**语义**不是时间
   （文件动过 ≠ 声明失效）；且「我删过的 API 在其 sources 里 ⇒ 声明仍为真」**有前提**：声明描述的入口本身没被删。
   守卫：`python3 scripts/docs_truth.py --verify --block-stale` + `python3 scripts/check_claims_verify.py --check`。
2. **量具先自证**：数字与既有口径不一致时**不猜**，逐条对账；根重导出 / 清单文件（`lib.rs`/`mod.rs`）会**致虚高**
   ⇒ 判据自污染必须**当场修判据**并记进纪律。守卫：`python3 scripts/check_memory_reachability.py --check`。
3. **判据按可见性分层**：`pub(crate)` **不是**公开 API；「零引用」**≠**「没接电」（同名遮蔽 / 间接消费链 /
   语言边界 / 模块自述 default-off / 名字出现≠真调用 五种形态）⇒ 判四级口径里的「已接线」要看**限定名 + 宿主生产使用**双重核对，
   删 API 前**在删除前的树上**重验 ⇒ **少扫一个消费者面 = 漏一个消费者**。
   守卫：`python3 scripts/audit_unwired.py --check` + `python3 scripts/check_dead_code.py`。
4. **棘轮先分类再处置**：超预算**先逐条分类**（真增长 / 导入已有裁决 / 假阳性）⇒ 真增长**拆文件**降回基线以下
   （**不抬上限**）⇒ **绝不 `--update-baseline` 一把梭**、**绝不用例外挂账**（例外是临时通道）、
   **绝不抬 env 预算**（换名或复用已登记名）。守卫：`python3 scripts/arch_guard.py --strict`。
5. **工作线三件套 + 进度页写「还差什么」**：登记必须有**设计稿 + 进度页 + 守卫命令**，只登记设计稿**不算登记**；
   进度页的「还差什么」**逐条带判据**（做完怎么验）；每条可判定断言都要有一条**退出码可判**的命令能验它。
   守卫：`python3 scripts/check_doc_class.py --check`。
6. **待裁决必带「默认处置」**：需要 owner 拍板的条目要写「**不裁决时会发生什么**」⇒ 每条**可逆**；
   清单只列真需要 owner 一句话的事项（技术性收口不占 owner 决策带宽）；裁决与已落地实现矛盾 ⇒ **重拍并改写口径**。
   守卫：`python3 scripts/check_doc_class.py --check`（`DECISION` 类强制项）。
7. **通道有了 ≠ 能力生效**：默认关的能力**不许写成系统现状**；默认关是**三重**（声明面 / 域面 / 行为面各有测试）；
   「通道已建」与「误伤已修」是两件事（后者取决于**声明清单**这个可判事实）。守卫：各族的接线守卫测试。
8. **经验与守卫不许退化成散文**：经验条目必须「**段型 + 可点击出处 + 一条守卫**」，机器层失败模式与经验矿
   **必须双向互引** ⇒ 一条教训不许有两个互不知情的副本。
   守卫：`python3 scripts/check_experience_anchors.py --check` + `python3 scripts/check_failure_knowledge.py`。
