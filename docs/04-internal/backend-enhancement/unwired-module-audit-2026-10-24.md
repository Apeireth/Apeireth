# 模块级「整块未接线」核查报告（2026-10-24 第四轮）

> 背景：符号级审计（`scripts/audit_unwired.py`）查的是**单个符号**有没有生产调用者。
> 它抓不到「**整个模块**都没接电」—— 后者每个符号都是孤儿，逐条看像零散小事，
> 加起来却是一整块能力缺失。
>
> 本轮补上这个盲区：新增 `scripts/audit_unwired_modules.py`，
> 产出 92 个候选，**人工过筛后判出 16 个真缺口**。

---

## 1. 工具与判据

### 1.1 为什么需要新工具

子代理核查 G5 时发现四条**模块级**未接线，符号级基线里**看不出来**：

| 模块 | 缺的能力 |
|---|---|
| `JobBoard` | 并行工具派发、长任务过程输出留存 |
| `CallScheduler` | 并发安全白名单的生效路径 |
| `hallways` | 记忆「走廊」结构 |
| `cross_diary` | 跨日记上下文 |

### 1.2 判据（三层，缺一不可 —— 每层都是被实测打出来的）

1. **独特标识符在模块外零引用** ——
   「独特」= 该标识符全仓出现次数 ≤ 40。
   为什么必须这样：通用名（`new` / `status` / `len` / `parse` / `settle`）
   全仓成百上千个同名 ⇒ 裸计数会把它们算成「模块外有人用」。
   实测 `new` 出现 **5218** 次、`settle` 在 `job_board` 之外也有同名
   ⇒ 靠这些名字撑着的「引用」全是假的，**整块未接线会被漏报**。
2. **限定路径未被使用** ——
   否则「模块接电但 pub 类型只是内部实现」会误报（实测 `nervous_snapshot`）。
3. **只有 `pub use`（重导出）、没有私有 `use`** ——
   重导出只是转发**不是消费**（实测 `job_board` 只被 `pub use`）；
   反过来**私有 `use` 才是消费信号**。

### 1.3 已知局限（**它是线索工具，不是判决**）

- `use` 引入后直接调用看不见（限定路径只出现在被剔掉的 use 行里）⇒ **会漏报**；
- 二进制入口（`main.rs`）的 pub 类型是内部实现 ⇒ 已排除；
- 判据对「模块整体接电但部分类型没外用」会假阳性 ⇒ **产出必须人工过一眼**。

⇒ 刻意**不做成 CI 棘轮**：一半候选是「默认关的功能族」，
做成棘轮会逼人给每个模块编理由，反而制造台账噪音。

## 2. 结果

**92 个候选 → 人工过筛 → 50 个整块未接线 → 按性质分类：**

| 类别 | 数量 | 含义 |
|---|---|---|
| **A 真缺口** | **16** | 整块未接线且能力对用户有意义 ⇒ 缺一个**具体接线点** |
| B 重复实现 | 6 | 同能力另有主实现 ⇒ **不是债** |
| C 有意不接 | 7 | 模块自述 default-off / 研究原型 / roadmap 档期 ⇒ **不是债** |
| E 待裁定 | 2 | 缺 owner 裁定（归属哪个消费点 / 要不要执行面） |
| D 真死代码 | **0** | —— |

### 2.1 A 类 16 条（完整清单见台账 `unwired-ledger.md` §5.4）

每个都缺一个**具体接线点**，不是「整块没写」：

- **用户能感知**：便携包 CLI、限流 hook、发言权仲裁、上下文分层、伙伴持久化；
- **可追溯性**：按 principal 全库遗忘（被遗忘权）、里程碑写入、推理字段剥离；
- **检索质量**：查询扩展、跨日记注入、TOC 树路由；
- **能力矩阵已宣称但未接**：`repo_map` / `file_fetcher` / `portable_bundle` / `three_tier_vault`
  —— 这四条**文档已经宣称了**，属「宣称 vs 代码」不一致。

### 2.2 一个值得注意的结论

**D 类（真死代码）0 条** —— 没有任何模块同时满足「无重复实现 + 无设计意图 + 零引用」。

这说明模块级债的主体是**「接线缺口」与「有意不接」**，不是死代码。
所以模块级还债的正确姿势是**接线**（有产品价值的）或**记录**（有意不接的），
而不是删代码。

### 2.3 与符号级的关系

- 符号级 G5 待判：**77 → 4**（剩 4 条全是空闲看门狗，属待 owner 决策）；
- 模块级：**50 个整块未接线**（16 A + 6 B + 7 C + 2 E + 其它）。

两者**互补**：符号级管「一个函数没人调」，模块级管「一整块能力没有入口」。
本轮两条都收敛到可行动的状态。

1. **A 类 16 条按价值排序接线** —— 建议先做：
   `universal_forget`（被遗忘权，隐私承诺）、`rate_limit`（失控防护）、
   `reasoning_adapter`（推理模型适配）、`partner_store_sqlite`（持久化）；
2. **E 类 2 条请 owner 裁定**：`semantic_axis` 的归属、`eight_anchors` 要不要执行面；
3. **B 类 6 条**：要么删（重复实现），要么并入生产主实现（保留独有能力的部分）——
   例：`wiki_fs` 的 `[[wikilink]]` 与反熵 lint 应并入生产的 `WikiEntryStore`。
