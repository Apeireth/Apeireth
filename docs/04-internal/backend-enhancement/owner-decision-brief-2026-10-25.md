## D-8｜`rubric::synthesize` 的加权平均：分母**不含** `confidence` —— 口径要你定

**这是我在执行 D-2 时查出来的真语义问题，不在 D-2 的批注范围内 ⇒ 我不擅自改。**

### 现状（代码事实）

`crates/foundation/governance/src/rubric.rs` 的加权合成：

```rust
sum_weighted_score += ballot.stance.score() * ballot.confidence * weight;  // 分子含 confidence
sum_weight += weight;                                                      // 分母不含 confidence
let weighted_score = (sum_weighted_score / sum_weight).clamp(-1.0, 1.0);
```

⇒ **分子乘了 `confidence`，分母没乘**。

### 为什么这在 D-2 之前看不出来

在那之前，`confidence` 基本恒为 `1.0`（`Ballot::new` 从没被生产代码构造过）⇒ 乘不乘都一样。
D-2 引入**真置信度**（顾问显式给的 `verdict.confidence`）后，这个不一致**立刻可见**。

### 两种口径，结论不同（下面数字都是可复算的）

场景：顾问 A 赞成（`score = +1`，`confidence = 1.0`，`weight = 1.0`），
顾问 B 也赞成（`score = +1`，`confidence = 0.2`，`weight = 1.0`）。

| 口径 | 公式 | 结果 |
|---|---|---|
| **现状（压制口径）** | `Σ(score×conf×w) / Σ(w)` | `(1.0 + 0.2) / 2.0 = 0.60` ⇒ 恰好卡在 `Approve` 阈值（0.6）上 |
| **影响力口径** | `Σ(score×conf×w) / Σ(conf×w)` | `(1.0 + 0.2) / 1.2 = 1.00` ⇒ 强赞成 |

再取一个更狠的：**一张 `confidence = 0` 的票**（顾问自己说「我完全没底」）+
一张 `confidence = 1` 的赞成票：

| 口径 | 结果 | 含义 |
|---|---|---|
| **现状（压制口径）** | `(1.0 + 0) / 2.0 = 0.50` | 零置信度票**零发言权**，却把别人的加权分**压到 0.5**（中立档） |
| **影响力口径** | `(1.0 + 0) / 1.0 = 1.00` | 零置信度票**不参与**（等价于弃权），不牵连他人 |

**这就是要你定的点**：

- **压制口径**（现状）：低置信度的票**把结果往中立拉**。好处 = 整体更保守；
  坏处 = 一张「我没底」的票能**单方面**把一群高置信度同意拉到中立。
- **影响力口径**：低置信度的票**自己少说话**（权重按置信度打折），不牵连他人。
  好处 = 符合「票的权重 = 域权重 × 置信度」的常规加权平均定义；
  坏处 = 整体不那么保守（但这本来就该由**域权重**调节，不是由 confidence 暗中调节）。

### 我的建议：**影响力口径**（分母也乘 confidence）

理由：
1. **加权平均的定义**就是 `Σ(x_i·w_i) / Σ(w_i)`，其中 `w_i` 是票的**总权重**。
   现状把 confidence 塞进分子却没塞进分母，**分母就不是权重和** ⇒ 公式自相矛盾。
2. 现状下 `confidence = 0` 的票是**纯粹的负作用**（零贡献 + 全额占分母），
   这在任何加权平均里都不是「零权重」，而是「负权重」—— 没有语义。
3. 想让整体更保守，正确旋钮是**域权重**（`AdvisorDomain::default_weight()`，已存在且可调），
   不是让 confidence 在公式里做暗箱。

## D-9｜记忆的「遗忘」是什么 —— **降权/归档，不是删除**（owner 裁定 2026-10-25）

### owner 原话（裁定）

> 「选择性遗忘也要慎重考虑，我觉得这应该被描述为一个**权重机制**，而不是真的忘掉。
> 当记忆极其庞大的时候，根据**日期、重要性、时效性**等排列相似记忆的重要性，
> **不重要的往后排**，这样也才符合『遗忘』。但我们又不是真拟人真仿真，
> **我们不要忘掉，相反，我们要所有东西都记得牢靠、管的靠谱**。」

### 这条裁定纠正了什么（我之前的偏差）

我在记忆方案里把「**选择性遗忘**」当成一个和「删除」同族的动作来度量，
并引用了公开基准（MemoryAgentBench 四能力之一的 *selective forgetting*）。
**这是错的**：拟人化系统的「遗忘」= 信息消失；**本产品的「遗忘」= 排序靠后**。
两者在存储层完全不是一回事，混着说会直接导致数据被删掉。

### 正式口径：三级处置（**只有第三级会掉数据**）

| 级 | 动作 | 数据还在吗 | 谁触发 | 可逆 |
|---|---|---|---|---|
| **① 降权**（= 本产品语义的「遗忘」） | 只改**排序权重**：旧 / 不重要 / 已失效 / 与更新条目重复的记忆**往后排**，默认不进入上下文预算 | **在**，且**永远可按需检索到** | 自动（权重模型） | ✅ 换权重即恢复 |
| **② 归档**（= 冷层） | 移到冷存储（压缩 / 加密 / 离线介质），降低常驻成本 | **在**，**无损保真**，按需取回 | 自动（容量策略） | ✅ 换回热层即可 |
| **③ 销毁**（= 真正的删除） | 内容从所有层与派生索引中移除，只留**墓碑** | **不在** | **仅在**：被遗忘权 / 用户明确「删掉这条」/ 法定义务 | ❌ 不可逆（有审计） |

**铁律**：
1. **默认永不销毁**；销毁必须**有授权记录 + 墓碑**，且 `verify` 能证明内容已消失、索引已清。
2. **降权与归档都不许丢内容**，只许改「多久被看到」。
3. 三类动作**全部可审计**（与 provenance 同源：谁、何时、因为什么被降权/归档/销毁）。

### 降权模型的因子（可重算，属 D5 判断层）

`weight = f(时间新旧, 重要性, 时效性(valid_until), 访问史, 与更新条目的重复度, 出处权威性)`

* **只影响排序与预算取舍**，不影响存储、不影响能否检索到；
* 权重是**派生数据**（D5），换算法/换参数可**全量重算** ⇒ 符合纵深体系「越深越可重算」；
* 可解释：一条记忆为什么排到后面，必须能说出是哪个因子导致的（否则就是黑箱，百年后没人敢用）。

### 指标也随之改写（替换原「遗忘正确率」）

| 新指标 | 定义 | 为什么这样定 |
|---|---|---|
| **降权正确率** | 该往后排的（旧/失效/重复/低重要）是否真的往后排了 | 度量排序质量，不度量删除 |
| **保真可达率**（关键） | 被降权/归档的记忆，**在明确需要时仍能被检索到** | 这是「**不丢**」的机器证明 |
| **销毁合规率** | 所有销毁都有授权与墓碑；**越权销毁恒为 0** | 把「不可逆动作」锁死 |
| **秩位位移** | 降权后条目下移多少位（纯排序层，数据不动） | 量化「遗忘」的强度 |

**对外结论的诚实要求**：若引用公开基准的 *selective forgetting* 分数，
必须注明**我们的口径是「降权 + 仍可检索」，不是「删除」**，不得与拟人系统的分数直接比较。
