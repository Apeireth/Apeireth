## §1. 为什么是这样

P3 是 Apeireth 最关键的图, 它把"AI 做了一个决策"这件事拆成可追溯的流程, 回答 3 件事:

1. **谁先做** (思想 → 提案 → 行动 三域分离) — D2 §2
2. **谁卡它** (原则洋葱 × 权限洋葱 正交) — D2 §7
3. **谁记账** (5 个 lifecycle hooks + 6 历史流) — 借鉴 claude-mem + D2 §5

P3 的核心设计选择:

- **思行二分**: 思想完全自由 (D1 §18.2), 行动必须经过提案 + 原则 + 权限 + HA (D2 §2+§7+§9)
- **原则权限正交**: 两者都通过才进入执行 (D2 §7)
- **HA 硬门槛**: 触及关键操作必须真实人类批准 (D2 §9 + D2 §11 单/多部署兼容)
- **5 hooks 触发器**: UserPromptSubmit / SessionStart / SessionEnd / PostToolUse / Stop (借鉴 claude-mem)

## §5. 与 P1+P2+P4 的关系

- **P1** 写"哪些组件存在"
- **P2** 写"哪些进程 + 父子关系 + 重启策略"
- **P3** 写"决策怎么走 (思/提/行 × 原/权 × HA × hooks)"
- **P4** 写"升级怎么走 (双根可演化但需重治理)"

P3 是 P1+P2 的"运行时刻", P4 是 P1+P2+P3 的"演化时刻"。三图一起才能完整理解 Apeireth 的运行时 + 演化时。
