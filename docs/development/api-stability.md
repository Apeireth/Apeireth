# API 稳定性分级 (Stability Tiers)

> 对外开发者的兼容性承诺口径：**只有明确标注的才承诺，其余一律如实告知"不承诺"**。这比含糊的"稳定 API"更负责任——你不会因为我们的装腔而踩坑。

## 分级定义

| 级别 | 含义 | 兼容性承诺 | 变更流程 |
|---|---|---|---|
| 🟢 **稳定 (Stable)** | 对外承诺的公共 API | 同一大版本内不破坏兼容（semver：破坏性变更 = major） | 破坏性变更须走 [RFC](rfc-process.md) + 迁移说明 |
| 🟡 **实验 (Experimental)** | 允许外部使用但可能变动 | 尽量不破坏，但保留 breaking 变更权（会在 CHANGELOG 显著标注） | 变更记入 CHANGELOG，给迁移提示 |
| 🔴 **内部 (Internal)** | 项目内部实现细节 | **无任何承诺**，随时可能变 | 无需公告（但 CHANGELOG 尽量记） |
| ⚫ **冻结 (Frozen)** | 哲学锚 / 基线值 | **0 改**（per 哲学锚纪律） | 任何改动 = 重大变更，Lead 终审 |

## 当前分级登记（2026-10 对账口径）

**诚实声明**：Apeireth 目前处于 v2.0.0-rc 阶段，**整体 API 尚未进入稳定期**。以下分级是目标状态与现状的如实对照，未登记 = 🔴 内部级：

| 范围 | 级别 | 说明 |
|---|---|---|
| 哲学锚 / R11 baseline 3 值 / `workspace.version` | ⚫ 冻结 | per `CODEOWNERS` 头注与 09-anchor / 11-baseline 纪律 |
| `docs/03-reference/api.md` 登记的对外端点/工具协议 | 🟡 实验 | 现阶段承诺"尽量不破坏"，1.0 后逐项升 🟢 |
| 各 crate 公共类型与函数 | 🔴 内部 | **无兼容性承诺**；升级到 🟡/🟢 需逐 crate 走 RFC 登记 |
| `legacy/` 目录 | ⛔ 归档 | 不构建、不维护、不接 PR 功能改动 |

> 1.0 发布前将启动「稳定级清单」RFC：逐 crate 评审哪些进入 🟡/🟢，届时本表逐行登记、不再有"整体未稳定"的模糊地带。排期跟踪于 [community-ops.md](community-ops.md) §八 挂账事项。

## 对使用方的实操建议

- **现在就依赖 Apeireth 做集成？** 请锁定具体 commit / 版本，并关注 [CHANGELOG.md](../../CHANGELOG.md) 中标注 ⚠️ breaking 的条目；
- **想做适配器/插件/周边工具？** 优先围绕 🟡 实验级协议设计（如工具协议、adapter 接口），并为变更预留余量；重大依赖点建议先开 [Discussion](https://github.com/Apeireth/Apeireth/discussions) 说明你的用法——**你的用法会反过来影响我们保什么**；
- **看到"稳定"字样的宣传？** 以本文件为准。任何文档/README 与本表冲突，以本表为权威口径。

## 变更纪律（对维护者）

1. 升级/降级任何一行的分级 = 技术决策，走 RFC；
2. 🟢 稳定级的破坏性变更必须附**迁移说明**，并在 CHANGELOG 显著标注；
3. 不允许"悄悄 breaking"——`grep` 所有构造点 + all-targets 编译是底线，CHANGELOG 如实记录是义务。

## 与「0 装 PASS」的关系

稳定性承诺本质也是一种"不装"：**承诺了就要做到，没做到就如实标注差距**。与性能表（未达标如实标"❌ 未达标（差距 2.2 倍）"）同一纪律。
