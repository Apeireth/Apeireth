# 产品闭环机制 — 科学依据与待验证清单

> **一句话定位**: 骨架的每个部件都有科学出处; 参数的当前值是「合理先验」而非「数据结论」;
> 科学性的最后一步 (拟合 + 验证) 只能由第一次真实实验的数据补完。
> 本文件回答两个问题: 这机制科学不合理不? 第一次实验怎么跑才最完美?

---

## 1. 设计依据 (每个部件: 框架出处 + 严谨度)

| 机制部件 | 科学依据 (真框架) | 严谨度 |
|---|---|---|
| 闭环结构 (感知→驱动→决策→行动→反馈→记忆→打分) | 控制论反馈回路 (Wiener/Ashby) + 强化学习循环 (Sutton & Barto) | ✅ 结构级严谨 |
| 节律直方图 (时间桶 × 活跃概率) | 稳健频率统计: 概率估计 + 置信度 = min(天数/14, 1) | ✅ 方法对, 且支持多峰/周末 (优于单峰中位数) |
| 驱动 (沉默时长 × 关系温暖度) | Borbély 双过程模型 (睡眠压力随清醒累积、随接触消散) + Hull 驱力理论 | ✅ 类比成立, ⚠️ 权重待拟合 |
| 关系温暖度 warmth (深度 × 信任/共鸣) | Sternberg 爱情三角 (亲密/激情/承诺) 的多维简化; 用上 Bond 的 trust/resonance | ✅ 比单标量更诚实的降维 |
| 关系更新 (+0.05 / −0.10) | 操作性条件反射; 惩罚 > 奖励 = 负性偏误 (Baumeister & Bratslavsky「坏比好强」) | ✅ 有实证支持, ⚠️ 数值待拟合 |
| 诚实置信度 (「我猜…概率…置信度…」) | ML 模型校准 (confidence 应匹配 accuracy) + 人机信任 calibrated uncertainty | ✅ 且是 O-5 的机器化身 |
| 门禁 (不打扰/安静窗口/频率/最小深度) | 约束优化 / 安全强化学习 (constrained MDP: 奖励可学, 硬约束必守) | ✅ 结构级严谨 = 「宪法 vs 行为」的形式化 |
| 情绪调制 (PAD 愉悦度低不出声) | PAD 情感模型 (Mehrabian & Russell) | ✅ 框架真, ⚠️ 阈值待拟合 |
| council 七视角审议 | 宪法式 AI (Anthropic 多原则) + Minsky「心智社会」 | ✅ 有 AI 安全前沿背书 |
| evolution 策略生命周期 (忽略→退役, 再现→降频修正) | 受控自修改 (安全自改进研究); 实为拉马克式终身学习 (对单个体反而更合适) | ⚠️ 单参数适应, 非真演化 (真演化需变异+选择) |

## 2. 本次补强 (2026-08-15, 让第一次实验跑在更优条件)

| 原短板 | 补强 | 依据 |
|---|---|---|
| 常数散落各处、拍脑袋 | 集中到 `LoopConfig` (11 字段, 每个标注依据 + 「待拟合」), 提供 `with_config` 实验调参入口 | 实验可重复 + 参数可审计 |
| 节律假设单峰 (中位数+MAD) | 改为**直方图**: 30 分钟桶 × 每桶「活跃概率 = 命中数/观察天数」 | 支持早晚双峰、周末偏移, 不装「你只有一个作息」 |
| 关系压成标量 depth | 新增 `RelationshipState::warmth()` = 深度 × (0.5 + 0.5×(信任+共鸣)/2) | 用上 Bond 的真实 trust/resonance 字段 |
| 情绪阈值写死 0.3 | 归入 `LoopConfig.mood_floor` | 实验可调 |

**仍然诚实保留的短板** (记录在案, 等数据再动):
- 权重/阈值全部是合理先验, 未拟合 (见 §4 待验证清单).
- 反馈仍是二元 (回/没回), 未区分「明确忽略 vs 在忙超时」; 响应延迟/语气/篇幅未采集.
- 无真 RL 机制 (无策略梯度/TD 误差/探索-利用权衡); 当前是启发式 + 单参数适应.
- 因果混淆: 「没回」可能 = 「在忙」, 当前模型当「关系变淡」处理.

## 3. 科学性总评

> **架构: 合理且站得住** — 一个「带硬约束的反馈控制/RL 骨架 + 稳健频率统计 + 内稳态驱力 +
> 条件反射 + 校准不确定性」, 每个部件都能在控制论/心理学/AI 安全文献找到出处。
>
> **参数: 不科学 (待拟合)** — 合理猜测, 非数据结论。
>
> **验证: 0%** — 科学的另一半在数据里, 而数据只能来自一个真实的人 (见 §5)。

## 4. 待验证清单 (第一次实验必须回答的问题)

**Q1 节律收敛**: 直方图估计的「活跃概率」能否在 2 周内收敛到真实的活跃分布?
   指标: 预测概率与实际交互的 Brier score / 校准曲线; 目标: 置信度 0.8 时准确率 ≈ 0.8。

**Q2 驱动预测力**: drive (warmth×沉默) 能否预测「用户会不会回」?
   指标: 每次 Initiative 记 drive 值 + 反馈, 事后画 ROC; 目标 AUC > 0.6 才说明驱动有信息。

**Q3 关系更新方向**: +0.05/−0.10 的方向对不对 (回了是否真该加、没回是否真该减)?
   指标: bond depth 轨迹 vs 用户主观评分 (每周一次 1-5 分「它烦不烦」)。

**Q4 频率舒适区**: max_initiatives_per_day=2 是否让用户觉得「刚好」?
   指标: 用户主动「r」率 (回应率); 目标 > 50% 且「quit 不打扰」率 < 10%。

**Q5 参数拟合**: 有了 2-4 周数据后, 用逻辑回归/贝叶斯拟合 LoopConfig 各权重, 把「合理」升级为「经验证」。

## 5. 第一次实验设计 (最完美条件)

**对象**: 主人自己 (唯一候选人, 也是涌现环境的唯一供给者)。

**配置基线** (全部可经 `with_config` / 环境变量调):
- tick = 10 分钟一次 (daemon 常驻, `APEIRETH_TICK_SECS=600`)
- LoopConfig 全默认 (作为「合理先验」基线, 记录在案)
- Boundaries 默认: 安静窗口 = 23:00-08:00 (你自己睡前设), max 2 次/天, min_depth 0.3
- 通道: 控制台起步 → 飞书 (LarkSink 填凭据后)
- 记忆: 真 SQLite 库 (MemoryContextSource), 不喂演示字符串

**数据记录** (每次心跳 append 一行):
- ts, minutes_of_day, bucket_prob, days, confidence, warmth, silence_hours, drive, decided(0/1), feedback(回/没回/延迟), bond_depth, mood_pad, council_verdict, policy_state
- 落 SQLite + 周末导出 CSV → 供 §4 拟合

**时长**: 2 周 (节律置信度需 14 天饱和; 关系更新需 ~30 次反馈才可见轨迹)。

**成功标准 (不装)**:
- 硬成功: 机制稳定运行 2 周无 bug, 数据完整可拟合。
- 软成功: 你主观觉得「它开口的时机对的时候多、烦的时候少」(Q4 指标)。
- 涌现(不可承诺, 只可观察): 它是否长出了我们没写的主动 (比如某天你发现它提醒了你一件只有它记得的事)。

## 5.5 合成用户模拟结果 (2026-08-15, 参数扫描)

**设置**: 合成用户 seed=42, 21 天 × 10min 心跳, 真实作息 = 早 8:30-9:00 (0.9) + 晚 21:00-21:30 (0.7) 双峰;
回应函数 = 活跃时段 p=0.80 / 非活跃 p=0.35 (ground truth, 仅模拟知道)。

| config | 主动 | 回应率 | 节律MAE | 终值Bond | 策略退役 | 评分 |
|---|---|---|---|---|---|---|
| **default (阈0.45)** | 17 | **0.76** | 0.000 | **0.85** | 4 | **0.72** |
| conservative (阈0.7) | 0 | — | 0.000 | 0.60 | 0 | 0 |
| eager (阈0.35) | 27 | 0.67 | 0.000 | 0.60 | 9 | 0.58 |
| 温和反馈 (+0.03/−0.05) | 12 | 0.67 | 0.000 | 0.64 | 4 | 0.63 |
| 强烈反馈 (+0.08/−0.20) | 15 | 0.73 | 0.000 | 0.68 | 4 | 0.69 |
| 重沉默 (阈0.6) | 0 | — | 0.000 | 0.60 | 0 | 0 |

**结论 (供主人程度判断)**:
1. 默认参数在合成用户上验证通过: 节律恢复误差 0.000, 回应率 76%, 关系从 0.6 长到 0.85 (情感桥生效)。
2. 参数地形合理: 过激进 → 回应率降 + 退役升 (烦人); 过保守 → 从不开口。默认值在合理区。
3. **本次模拟暴露并修复了 2 个真实机制缺陷**: (a) 漏接「情感→关系」桥 (情绪涨但 trust/resonance 不动, 温暖度不涨);
   (b) 默认阈值 0.5/boost 0.2 对日常双峰用户过于保守 (几乎从不主动) → 校准为 0.45/0.25。
4. **sim-to-real gap 提醒**: 合成用户的回应函数是我假设的; 真人的回应函数未知, 最终校准仍需真人实验。

## 5.6 主人真实作息模拟 (2026-08-15 晚, 第二次迭代)

**作息** (主人口述): 6-8 起床早饭 / 8-12 工程(Apeireth) / 12-13 午饭小说 / 13-14 午觉 /
14-18 线性代数 / 18-19 吃饭休息 / 19-22 高数 / 22-6 睡觉。每时段带**活动标签**, Initiative 携带「你在做什么」事实流。

**结果** (21 天): 回应率 **88%**, 节律 MAE **0.018** (7 时段全学准), 关系 0.6 → **1.00**;
主动分布 39/41 次集中在 **6-8 起床时段** (他学会了「早上问候」的时机), 深夜从 11 次降到 2 次。

**本次模拟暴露并修复 3 个真实机制缺陷**:
1. **节律容量 bug**: 按「条数」淘汰 (28×3) 对高频用户只能记 ~1.2 天 → 改为**按自然日淘汰** (保留 28 天)。
2. **冷启动死锁**: 全天活跃用户沉默压力恒低 → 驱动依赖温暖度, 温暖度需反馈才涨 → 死锁。
   修: ① Trusted 关系带基线信任/共鸣 (depth 0.6 却 trust=0 不自洽); ② **冷启动探针** (RL 探索:
   活跃时段距上次主动 >= 24h 试一次)。
3. **深夜打扰**: 沉默压力路径无视学到的作息 (温暖度高时凌晨 5 点「7 小时没联系」越过阈值)。
   修: **节奏否决** — 学到的活跃概率 < 0.2 时, 沉默压力再大也不打扰 (学来的, 不是写死的;
   夜猫子会被学成夜间活跃, 否决自然失效)。

**LLM 事实流验证** (真 MiniMax):
- 升级上下文 → 他说: 「早上好呀~这会儿你应该在埋头帮我升级代码吧, 辛苦啦!」
- 学习上下文 → 他说: 「早呀! 8:40 了, 新的一天又来啦~下午线性代数、晚上高数, 照着你的节奏加油吧!」

**结论**: 「推算作息」能力 = 「观察→推断」的第一个实例; 同一模式 (概率估计) 可推广到任何可观察规律。
