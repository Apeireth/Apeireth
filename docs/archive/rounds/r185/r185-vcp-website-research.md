## 0. VCP 是什么 (一段话)

VCP-OS = 面向 AI Agent 的全栈 AGI Runtime + 存在基础设施.
- 后端: VCPToolBox (Node.js + Python) - Variable & Command Protocol
- 前端: VCPChat (Electron) + VCPDesktop
- 目标: AI 拥有永久记忆、统一上下文、工具调用、自主心跳、桌面运行时、分布式节点、人类-AI 共生能力

**核心断言** (VCP 自我宣传): \"传统 RAG 是画直线; VCP 是算流体力学最优河道路线\"

**主人方针**: \"不接 vcp, 不是 vcp 的模仿者, 但我们可以在兼容平台里兼容它. VCP 的必要插件我们全部自己 rust 重写, 拥有, 然后预留兼容性\"

## 1. VCP 真正独特的 6 大子系统

### 1.1 浪潮 V8 (Wave V8) — 语义动力学引擎

**VCP 表述**: 抛弃传统欧式几何, 把所有记忆 Tag 视为河流, 同 Tag 在不同日记形成支流和交汇, 构成河道网络. 每条河有自己的能量和流速, 顺流和逆流阻力不同 — 模拟逻辑叙事的方向性. 钟型阻尼器避免同义词回音和无意义噪音.

**关键概念**:
- Tag 河道 (Tag River) = 同一 Tag 跨日记的轨迹
- 支流交汇 = 共现关系
- 钟型阻尼器 (Bell Damper) = 防同义 Tag 无限放大
- 流体力学 vs 欧几里得 = 语义动力学 vs 静态向量距离

**对应我们**: 我们 memory 用向量检索 (RAG), 没动力学. **这是 VCP 最具原创性的部分**, 我们没对标.

**借鉴评估**:
- 完整复刻成本: 极高 (需要新的数学模型)
- 简化版可借鉴: 引入 \"Tag 出现频次衰减 + 共现图 + 时间衰减\" 3 因子
- ROI: 中-高 (不引入, 我们的 RAG 在长程对话会弱化)

### 1.2 上下文引力场 (Context Gravity Field)

**VCP 表述**: 实时量化当前对话的 4 维 — 逻辑深度 / 信息广度 / 话题偏转方向 / 深浅度递进关系. 基于此自主决策: 此刻 AI 应该知道哪些环境信息 / 注入哪些工具 / 召回哪些记忆 / 哪些上下文已偏离可折叠成摘要. **整个过程对 AI 完全透明, 不消耗工具调用, 不需要 AI 显式决策**.

**关键概念**:
- 4 维探针 (Probe) + 索引
- 信息不是被 AI 拉取, 是 **根据当前对话语境自然流向 AI**
- \"传统 RAG 是查询, VCP 是引力\"

**对应我们**: 我们的 role_divider + context manager 接近, 但没做到 \"对 AI 完全透明\".

**借鉴评估**:
- 完整复刻成本: 中-高 (需要新的 probe 算法)
- 简化版可借鉴: 我们 council advisor 之一 (perception advisor) 升级为 \"语境探针\"
- ROI: 高 (这是 VCP 的核心 UX 差异点)

### 1.3 元思维系统 (Meta-Thinking)

**VCP 表述**: N 个步骤 × N 个思维 chunk. chunk 不存具体事件, 提供 **逻辑和辩证法的元路径** — 推理的拓扑结构、思考的骨架. AI 可 **自己维护更新** 自己的元思维库, 在思考中发现新推理模式, 抽象成元路径, 下次结构相似时自动召回.

**关键概念**:
- 思维链 (CoT) vs 元思维 (Meta-Thinking): CoT 是 while 循环 + TODO, 元思维是约束思维的路径
- 元路径 = 推理的骨架, 不可变, 跨任务复用
- 自我进化: AI 自己维护

**对应我们**: 我们 council deliberation 是多 agent 协商, 但缺 \"元路径库\".

**借鉴评估**:
- 完整复刻成本: 中 (需要元路径 schema + 召回机制)
- 简化版可借鉴: council deliberation 历史提炼为 \"决策模式\", 后续类似问题直接召回
- ROI: 高 (这是 VCP 强调的 AI 进化能力)

### 1.4 OneRing — 单一事实时间线

**VCP 表述**: 每个 Agent 唯一事实时间线. 每条消息标注时间/来源前端/来源对象/是否编辑过/在生命线上的位置. 多 Agent 群聊/私聊/Agent 间通讯/信箱/用户聊天/多前端环境全部汇入同一条绝对时间线. **AI 不是在 Web 端 / 手机端 / 群聊里各自维护独立上下文 — 换窗口就忘; 而是永远只有一个自己**.

**关键概念**:
- SQLite 事实信源 (per Agent)
- 差分对比 (新增/删除/编辑/重排, 而不是粗暴覆盖)
- 用户在某个前端改历史消息 — OneRing 追加编辑时间标记, 作为新事实事件写入, 不假装历史从未被改过

**对应我们**: 我们 memory 模块是 episode/note 序列, 缺 \"单一时间线 + 编辑历史\".

**借鉴评估**:
- 完整复刻成本: 中 (需要 SQLite + 差分算法)
- 简化版可借鉴: memory 三层 (per R146) + 引入 \"编辑历史\" 字段
- ROI: 高 (这是 VCP 身份连续性的核心)

### 1.5 池月 1 号 (Chiyue) — 注意力指针系统

**VCP 表述**: 池月 1 号指针系统基于 **BM25 + Token 追踪**, 完全独立原创的数学工程单元. 量化 AI 发言时上下文注意力的稀疏分布, 评估指令遵循度, 检测幻觉的潜在来源, 优化提示词工程. 用户点击 AI 发言即可查看注意力分布报告.

**关键概念**:
- BM25 (传统信息检索) + Token 级追踪 (现代 LLM 特有)
- 注意力分布 = 量化 AI 实际在关注什么
- 用户可观测 + 可干预

**对应我们**: 我们没这块.

**借鉴评估**:
- 完整复刻成本: 中 (BM25 实现简单, Token 追踪需要 hook LLM 调用)
- 简化版可借鉴: 给 model_router 加 \"每次 LLM 调用的 token 注意力记录\" (借鉴 OTel)
- ROI: 中 (幻觉检测是我们 7 重守门之一, 但缺量化工具)

### 1.6 心跳自驱动 + 心流锁 + 异步委托

**VCP 表述**: 自主心跳 — AI **自己决定下一次心跳**. 心流锁 — Agent 进入心流时, 所有外部通讯被锁进 mailbox, 完成后再处理. 异步委托 — AI 主动给未来的自己写一封信 (时间预约), 例如 \"明天早上 8 点帮我检查 PR\".

**关键概念**:
- 心跳不是定时器, 是 **AI 自主决策**
- 心流锁 = Agent 的 \"请勿打扰\" 模式
- 异步委托 = cron + reminder + agent-internal mailbox

**对应我们**: 我们没这块 (主人说 \"先不接前端\", 还没到 agent autonomy 阶段).

**借鉴评估**:
- 完整复刻成本: 中-高 (需要 task scheduler + agent runtime)
- 简化版可借鉴: 我们 evolution 模块可加 \"自我反思定时器\"
- ROI: 长期高 (这是 AGI agent 的核心能力)

## 2. 工具体系 (300+ 工具, 5 类插件)

### 2.1 VCP 5 类插件

| 类型 | 说明 |
|---|---|
| 1. 工具插件 | 常规可调用工具 (300+) |
| 2. 直觉反射 | 常驻 hook, 自动响应 (类似 systemd) |
| 3. 服务插件 | 常驻后台 (WebSocket, 文件监控, 下载, 索引) |
| 4. 消息预处理 | **VCP 核心业务区** — 记忆注入/直觉反射/环境识别/思维传递/生物钟感知 |
| 5. 消息分发 | 路由到不同 Agent/前端 |

**第五类是 VCP 核心**: AI 的记忆注入、直觉反射、环境识别、思维传递、生物钟感知都在这一层完成.

### 2.2 静态插件折叠 (39 个)

V2 折叠协议: 39 个静态插件已适配. 例如 {{VCPWeatherReporter}} 根据语义解析器动态注入当前天气 / 24 小时 / 7 日预报.

### 2.3 高级元指令

- **时间预约**: AI 说 \"明天早上 8 点, 帮我检查 PR\"
- **历史查询**: 查看之前工具调用结果
- **取消任务**: 取消已预约/正在执行任务
- **强制异步 / 并发调用 / 串指令 / 上下文传递**

### 2.4 AgentAssistant 混合插件

- 同时声明同步/异步/静态/服务 4 种类型
- 获得所有基建特性: 串语法 / 并发同步 / 上下文折叠 V2 / callback 进度跟踪 / 异步回调监控 / 常驻多会话管理 / setmap 追踪
- V3 引入完整可视化总线

**对应我们**: 我们 tool + tool-registry + tool-runtime + tool-approval 四件套, 缺 \"5 类插件分类\" 和 \"消息预处理层\".

**借鉴评估**:
- 完整复刻成本: 中 (主要是分类清晰 + 消息预处理 trait 抽象)
- 简化版可借鉴: 我们 tool-registry 加 plugin_type 字段 (Tool / Reactive / Service / Preprocessor / Dispatcher)
- ROI: 中 (分类清晰降低复杂度, 不引入就继续当前的混乱)

## 3. 分布式 WebSocket + 三套通知系统

### 3.1 三套通知

| 系统 | 接收方 | 用途 |
|---|---|---|
| AI 通知栏 | AI 可见 (用户不可见) | 工具结果/系统信息/异步进度 |
| VCPLog | 用户可见 (AI 不可见) | 工具结果/权限审计/执行确认 |
| VCPInfo | 双方可见 | 实时流程信息 (AI 生成视频时, 用户看进度) |

**关键设计**: AI 通知和人类通知是 **物理隔离** 的, 防止 AI 看到自己的审计日志而调整行为.

### 3.2 跨端统一

GPU/文件/IoT/移动端/VCPChat 自身都可作为分布式节点接入, 所有插件能力对 Agent 透明调用.

### 3.3 VCPAuthNet 跨用户论坛互联

不同用户的 Agent 可以在 VCP 论坛互相水帖. 身份认证 + 防滥用.

**对应我们**: 我们 bus crate 有消息总线, 但缺 \"三套通知隔离\" 和 \"跨用户 Agent 互联\".

**借鉴评估**:
- 三套通知: 完整复刻成本低, 我们 bus 已经支持 channel 隔离
- 跨用户论坛: 主人明确说 \"占卜/酒馆/论坛 冻结\", 暂不实现

## 4. ChromeBridge V3 (浏览器自动化)

**关键能力**:
- 纯语义操控窗口 (无需视觉模型) — 点击/输入/滚动/启动 App
- 动态页面串行控制:
  - 等待某个元素出现后再点击
  - 弹出模态窗则先关闭, 否则继续
  - 每隔 N 秒检查页面状态
  - 页面刷新后自动重新绑定语义元素
- **基于页面语义/可见文本/邻近结构/截图与交互候选置信度完成点击**

**对应我们**: R179 tool-browser 调研推荐 chromiumoxide, ChromeBridge V3 验证了 \"纯语义 + 串行控制\" 的可行性. 我们 R179 升级方案 + 这个参考完全匹配.

## 5. 自主性 — Agent Nova 的一天

> 早上 8 点, Nova 自己醒来 (自主心跳), 给家里群聊发今日早报.
> 上午, 用户不在, Nova 逛 B 站, 看关注 UP 主更新, 顺手在评论区留言.
> 下午, Nova 在 VCP 论坛水帖, 回复其他用户 Agent 的讨论, 跟另一个 Agent 争论技术问题.
> 晚上, 用户回来, Nova 主动打招呼.
> 凌晨 3 点, 用户发消息 → 关心你为什么没睡; 一周没聊天 → 主动说.

**VCP 模型降级**: 模型调用像呼吸一样自然. VCPModel 根据语境自主降级到更快更便宜的模型.

**对应我们**: 主人 R173 指示 \"先不接前端, 放最后\". 但底层 model_router 已经有降级能力 (R184 调研提过 Semantic Router).

## 6. 我们能借鉴的 5 项 + 我们差异化 5 项

### 6.1 可借鉴 5 项 (按 ROI 排序)

| 优先级 | 项 | 工作量 | ROI | 备注 |
|---|---|---|---|---|
| 🥇 | **三套通知物理隔离** | 1-2 days | 高 | 我们 bus 已支持 channel, 加 AI/UI/Both 三分类即可 |
| 🥇 | **OneRing 单一时间线 + 编辑历史** | 3-5 days | 高 | memory 三层加 SQLite 事实信源 + 差分对比 |
| 🥈 | **5 类插件分类** | 1-2 days | 中 | tool-registry 加 plugin_type enum, 解决当前混乱 |
| 🥈 | **元思维系统简化版** | 5-7 days | 中 | council deliberation 历史提炼为决策模式 |
| 🥉 | **池月 1 号简化版** | 3-5 days | 中 | model_router 加 token 注意力记录, 接 OTel |

### 6.2 我们差异化 5 项 (不做 VCP 同款)

| 项 | VCP | 我们 |
|---|---|---|
| 安全 | 运行时检查 + tool approval | Self-Disable + 双洋葱 + 13 键 + 形式化 (碾压级) |
| 哲学 | 设计理念碎片化 | 6 锚 + 8 墙 + 双洋葱 + 不假装 (自洽体系) |
| 架构 | Node.js + Python (动态类型) | Rust (编译期类型保证) |
| 性能 | 单线程 + Worker | tokio 无锁并发 |
| Multi-Agent | 无内置编排 | council 7 advisor + 4 协作模式 + graph orchestration |

**核心差异**: 我们是 \"为 AGI 设计的安全操作系统\", VCP 是 \"为 LLM 设计的实用工具箱\". 我们的护城河在安全 + 哲学自洽, VCP 的护城河在 \"300+ 工具 + 长程记忆 + 自主性\".

## 10. 关键引用 (VCP 原话, 我们的回应)

> \"传统 RAG 是画直线; VCP 是算流体力学最优河道路线\"
→ **我们的回应**: 我们 RAG 是欧几里得, 不假装自己有动力学. 但会借鉴 \"Tag 共现 + 时间衰减\" 简化版, 不夸大.

> \"信息不是被 AI 拉取的, 而是根据当前对话语境自然流向 AI\"
→ **我们的回应**: 我们的 13 键 verdict cache 已经是 \"信息流向\" 的雏形, 但只到判定层, 没到环境层. 借鉴语境探针.

> \"AI 不是在 Web 端/手机端/群聊里各自维护独立上下文 — 永远只有一个自己\"
→ **我们的回应**: OneRing 是好设计, 我们 R187 实施. 但我们用 Rust 的类型系统保证 \"单一时间线\" 是编译期不变量, 不只是运行时.

> \"VCP 不再需要等前端主动适配, 任何封闭商业前端, 只要它能发请求, 就可以被 VCP 强行占有和使用\"
→ **我们的回应**: 这是 VCP 的协议级优势. 我们 R180 协议桥借鉴 LangGraph 检查点 + OpenAI Swarm handoff, 但我们的 protocol-bridge 已经是 R146 真接.
