## 4. 统一测量口径

- **计时器**: `std::time::Instant`（Windows 下 QPC，分辨率 ~100 ns 量级）。零第三方计时/统计依赖（`support.rs` 手写 nearest-rank 统计）。
- **样本 = batch 摊销**: 亚微秒级操作每样本取 `batch` 次连续执行的平均（调度 256、HUD 帧 256、折叠 5、CoW/SAGA 10），摊薄计时器开销；I/O 与毫秒级操作 batch = 1（逐次计时）。
- **warmup 不计数**；样本量按 `BENCH_SCALE` 可缩放。
- **统计**: min / mean / stddev（样本标准差, n-1 分母）/ P50 / P90 / P99 / max；百分位 nearest-rank（idx = ceil(p/100·n) − 1）。
- **判定**: P50 与目标比较；差距倍数 = P50 / 目标值（未达标行展示）。P99 超目标而 P50 达标时，判定栏仍标达标但括注 P99 超标（本轮无此情形）。
- **数据可复现**: 全部语料/向量/事件由确定性 xorshift64* 程序生成（种子固定），查询集固定 200 条，跨轮可比。

**依赖说明（零新增第三方依赖优先）**:
- 计时、统计、数据生成、CLI 全部纯 std 手写，未引入 criterion 或任何计时库。
- `fs-err 3.3.1` 是唯一进入 `Cargo.lock` 的第三方包：它是 workspace 既有声明依赖（根 `Cargo.toml` `[workspace.dependencies]`），且 `clippy.toml` 强制全仓 `std::fs` → `fs_err`（harness 的临时目录/取回读写因此不能用 `std::fs`）；它是该声明的首个消费方，无新增传递依赖（仅 build-dep `autocfg`）。
- `tokio` 复用 workspace 既有声明（冷启动/打断基准需要 async 运行时）。
- `Cargo.lock` 增量 = `apeireth-bench-harness` 包条目 + `fs-err` + 两条既有清单的依赖边补记（`apeireth-perception` / `apeireth-sdk` 的 path 依赖，锁文件陈旧项修正，非本战役引入）。

## 6. 逐基准口径与噪声边界

- **hybrid-search-query**: 10,000 节点 / 128 维确定性向量 / 200 条确定性混合查询（ASCII 词 + CJK 双字词），逐查询计时一次。样本分布 = 查询工作负载延迟（含查询间方差），非同一查询重复噪声。Run 2 尾部单点 10.30 ms（max）来自调度抖动；P99 = 6.36 ms。**P99 样本量 n=200，为本轮 P99 最可信的一组。**
- **hybrid-search-build**: 10K 节点双路插入 3 次重建（n=3，P99 退化为 max，仅作量级参考）。
- **quota-dispatch / quota-preempt-pip**: 每样本 256 个周期摊销（单周期 ~0.6–1.3 µs，低于单次计时开销），n=80。观察到 CPU 频率缩放造成的分段漂移（同轮内 0.41→0.81 µs 平移），两轮均达标且距 50 µs 目标有 ~40–60× 余量。
- **causal-cow / saga-rollback**: 每样本 10 操作摊销，n=40（P99 = 顶部样本外插，读数谨慎）。分支/快照对象按被测语义保留在模型内（不伪造回收路径）。
- **barge-in-roundtrip**: 端到端含 tokio 任务唤醒调度，n=200。长尾来自异步唤醒抖动（P99 203.8 µs / max 248.3 µs，Run 1 max 496.6 µs），距 1 ms 目标仍有余量。单等待者口径；多等待者广播扇出成本随等待者数增长，未测。
- **ember-hud-tick**: 每样本 256 帧摊销，n=80。**仅驱动侧 uniforms 合成**；浏览器/CSS/GPU 绘制链路不在计时区间（无浏览器 harness，如实标注边界）。
- **os-sandbox-spawn**: `ProcessExecutor.execute` 沙箱执行 `cmd.exe /D /S /C "exit 0"` 全程（边界初始化 + AppContainer 路径受控进程创建 + 等待退出 + 输出捕获），n=50。被测边界无公开"spawn 不等待"API，故以最小子进程全程计。同机无隔离对照（`os-sandbox-plain-spawn`）显示子进程启动+等待本身就占 ~53 ms（含进程创建、杀软扫描、10 ms 轮询监督步长），**受控边界增量 ≈ 6.9 ms（均值口径）**。JobObject 创建+限额单独测得 P50 1.8 µs。两轮波动大（96.5 → 59.6 ms），与本机安全软件/进程创建开销强相关。
- **cold-start**: 每轮全新数据目录（真冷：无热页缓存/无连接池复用），计时 = SQLite 记忆+会话存储打开（含迁移）→ `ProductionModules::build` → 注册 → `build().await` 到 ready；不含 tokio 运行时创建/临时目录创建/Runtime 销毁。n=30，两轮 P50 61.98 / 63.39 ms，一致性最好的一组。
- **idle-footprint**: 完整生产组装驻留后静置 2 s，每 500 ms 读一次进程工作集，n=5 读数（P99 = max 附近，小样本如实标注）。Windows 读数取 `Get-Process ... .WorkingSet64`。工作集受页缓存共享/分配器高水位影响，两轮 24.47 / 17.47 MiB（Run 1 伴随此前多轮运行的高水位）。组装前进程基线 15.29–22.36 MiB，组装驻留增量约 2.1–2.4 MiB。按 1 MiB = 2^20 B 从严判定（目标原文为 MB）。
- **fold-surface**: 1,000 条事件（960 追加 + 20 替换 + 20 掩码）纯折叠，每样本 5 次摊销，n=60。Run 2 双峰（187–414 µs）疑似跨 CCX/频率迁移，如实呈现。
- **spill-truncate / spill-retrieve**: 128 KiB 长尾、keep=2000；落盘写无 fsync（被测档位契约）；取回为同文件热读（页缓存下界），冷读会更慢。临时目录在系统 `%TEMP%`。
- **atomic-write-\***: 4 KiB 载荷反复原子替换同一目标；持久档 fsync 长尾显著（max 11.5–13.3 ms，磁盘/文件系统相关），Windows 无父目录 fsync 等价语义（被测代码既有平台边界）。

## 7. 诚实边界：未达标行与缺口

1. **微内核冷启动（❌ 未达标，差距 6.2 倍）**: 61.98 ms vs 10 ms。本轮未做分段归因（如实承认）；口径内可感知的成本候选：SQLite 建库+迁移（rusqlite bundled 首次建表）、模块/工具对象构造、`build().await` 组装。潜在优化方向（未实施）：迁移合并/延迟执行、连接池预热复用、模块懒加载。在达成前 README 行保持 ❌。
2. **OS 物理沙箱 spawn（❌ 未达标，差距 4.0 倍）**: 严格口径（沙箱 spawn 全程，含子进程启动+等待）59.58 ms vs 15 ms。分解口径（受控边界增量 = 沙箱 − 无隔离对照 ≈ 6.9 ms；JobObject 初始化 ≈ 1.8 µs）满足 15 ms，但目标行写的是 spawn，表按严格口径判定不达标。根因大头是本机进程创建+等待成本（对照组 52.81 ms），与安全软件/执行器 10 ms 轮询监督步长相关。
3. **Ember HUD（✅ 附脚本实测，但口径收窄）**: 实测为驱动侧 uniforms 合成（0.037 µs/帧）；README 行原文含 "CSS ambient glow" 的浏览器绘制，该段**无 harness**（需要浏览器侧端到端测量方案），不假装覆盖。
4. **P99 小样本**: n=30（cold-start）/ n=40（causal/saga）/ n=50（os-sandbox）/ n=5（idle）的 P99 本质是顶部样本，读数谨慎；n=200 组（hybrid/barge/spill/atomic）P99 相对可信。
5. **轮间噪声**: Run 1 整体偏慢 1.2–2.0×（后台负载/频率缩放），两轮原值均如实并列；不择优引用。
6. **边界口径**: barge-in 为单等待者；spill 取回为热读下界；idle-footprint 为 harness 进程驻留值（与最终守护进程二进制的绝对值可能有出入，依赖裁剪/LTO 配置）。
