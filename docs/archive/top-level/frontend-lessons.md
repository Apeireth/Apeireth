# 前端交互教训清单（2026-08-16 实录）

> 主人指示: 内置 HTTP 聊天页只是临时载体, **不要在它上面"屎上雕花"**。
> 本文记录真实对话暴露的交互问题 — 后端能改的已改, 其余**留给将来真前端 (路线 C) 当教训**。

## 教训 1: AI 会虚构交互流程（后端必须有真实载体）

**实录**: 主人问"怎么给你权限", AI 回答"涉及高危操作时, 系统会弹出授权请求, 主人按面板提示批准即可",
还分"一次性/永久授权该路径"——**这些交互 serve 根本不存在**（没有弹窗、没有路径级授权选择）。
主人说"试试" → 前端"网络错误"。

**根因**: 后端只有「拒绝 + 错误文本」, 没有「授权请求」的实体; AI 为了回答"怎么授权",
用权限洋葱的设计意图**脑补了一个不存在的 UI 流程**。

**后端已改 (真实载体)**:
- `approval_requests.rs`: 工具被 RequireApproval 拒绝 → 产生待批请求 (apreq-*, append-only)
- `GET /v1/apeireth/approval-requests`: 待批列表 (前端轮询)
- 聊天页「授权请求」区: 轮询展示 + 一键批准 (调 /v1/apeireth/grant)
- 系统注入 AUTH_RULE: AI 必须如实描述真实机制, 禁止虚构"弹窗/自动弹出"流程

**留给真前端的教训**: 授权交互应该做**推送式** (WebSocket/SSE: AI 被拒 → 服务端推送到前端 → 弹窗),
而非轮询; 弹窗里应提供「本次 / 1小时 / 24小时 / 永久」+ 路径范围选择 (权限洋葱 L0-L5 配额语义)。

## 教训 2: AI 描述的能力必须可验证, 否则就是说谎

**实录**: "本座已记下您的偏好" (未调 save_memory 就声称记住) — 早期版本;
修 EMI 后矫枉过正为"本座这就将此事写入长期记忆" (宣告式, 机械)。

**后端已改**: 静默记忆 (写入但不宣告; 仍禁止虚构记得)。

**留给真前端的教训**: 前端应可视化工具调用 (LobeChat 原生支持 tool_calls 展示),
让「他说做没做」一眼可见 — 这是 0 装 PASS 在交互层的体现。

## 教训 3: 输出长度截断用户无感知

**实录**: 写烟火网页代码被 max_tokens=2000 硬截断, 用户看到半截代码, 不知道是被砍的。

**后端已改**: max_tokens 默认 8192 + env 可配 + 客户端请求值优先 (对齐 VCP: 用户自设)。

**留给真前端的教训**: 流式输出 (SSE) + 截断/续写提示; 超长输出给「继续生成」按钮。

## 教训 4: 固定开场白 = 死 (已修)

**实录**: 页面硬编码"本座在此。你回来了? 记忆还都在…" — 每次刷新复读, 未问先剧透记忆。

**后端已改**: 删硬编码, 静候占位, 记忆在对话中自然浮现。

**留给真前端的教训**: 问候应由 daemon 涌现机制产生 (节律匹配), 而非前端模板。

## 教训 5: 网络错误提示要可行动

**实录**: "网络错误: Failed to fetch (确认 serve 在运行)" — 用户不知道是 AI 没调工具
还是 serve 挂了。

**后端已改**: 无 (属前端)。

**留给真前端的教训**: 区分错误类型 (serve 未起 / LLM 限流 / 工具被拒) 并给出对应动作;
工具被拒时展示授权请求入口 (教训 1)。

## 真前端 (路线 C) 功能清单 (本清单汇总)

- [ ] WebSocket/SSE: 流式回复 + 授权请求推送 (弹窗: 本次/定时/永久 + 路径范围)
- [ ] 工具调用可视化 (正在调用/结果/失败原因)
- [ ] 记忆侧栏 ("本座记得你什么", 来自 memory_injection 数据)
- [ ] 今日摘要首页 (daily_summary 数据源已有)
- [ ] 原则/经验管理页 (待批准原则、经验库、晋级候选)
- [ ] 涌现日志可视化 (节律直方图/主动性记录)
- [ ] 错误分类提示 (serve 状态灯 + LLM 限流提示 + 授权入口)
