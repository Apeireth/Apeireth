## 3. 已落定的核心设计（拍板记录）

1. **宪法 vs 演化**（主人 2026-08-15 亲自修正过）：
   「固定『机制』(它怎么运作 / 模块怎么协作 / 反馈动什么)，放开『欲求』(它想要什么 / 在乎你哪件 / 何时开口)」
   ——「AI 发现你想要什么」和「AI 长出它自己想要什么」是同一个过程。
2. **风险分级 → 席位矩阵**：Info 0 席 / Low 1 席 / Medium 3 席 / High 5 席 / Critical 7 席（stage1 §20.3）。
3. **只审动作，不审对话**（Thought 自由 / Proposal 哲学键 / Action 权限层 = sovereignty 三域分离）。
4. **权限包**（主人原话）：
   > 「我们完全可以针对ai会执行的不同任务发权限包嘛，权限包会有保质期，权限大小，这样按需给他需要的权。
   > 同时我们也可以自定义权限包（让用户来决定日常给的权限是什么，什么要放）」
   > 「不可逆类的，对外类的，一样可以放到包里去，发了权限就不用再每次确认了，但我们要有一个监督机制就行，
   > 就是记录ai到底干了什么……高危动作不必每次确认，而是一次有力的确认后，单独授权一段时间，
   > 比如人脸验证了一次，授权1天不限次数的权限之类的」
   —— 落定：日常包默认永久 + 90 天强制提醒续签；sudo 模式（责任自负 + append-only 审计）；
   单人物理签 = Windows Hello 起步 + FIDO2(YubiKey) 留口；sudo -v 先例。
5. **7 个 council advisor 的真实定位**（审计发现）：它们是 0 token 的 Rust 关键词网（contains() 子串匹配），
   只审「动作摘要」（如 action=offer_help, tool=ShellExec, risk=High），**永远不扫对话/记忆自由文本**；
   是免费的第一张网，不是安全主力。真正防线 = 能力限制 + 洋葱门 + 宪法评审(LLM 按原则) + 主人批准 + 熔断。
