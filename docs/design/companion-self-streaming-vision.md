## 1. 定位翻转：从"用户的皮套"到"他自己是主播"

| 维度 | 用户当主播（皮套直播） | **他自直播（本构想）** |
|---|---|---|
| 驱动源 | 用户的脸（面捕） | **他的认知状态**（presence/事件/记忆）——我们的地基 |
| 说话 | 用户说 | **他开口**（LLM 生成 + 语音合成） |
| 推流 | 需要（OBS 一类） | 需要（这是唯一真正的新件） |
| 弹幕 | 用户自己看 | **进他的事件总线**（新的真实信号源） |
| 时长 | 用户撑 | **他本来就不下班**（自治是本行） |
| 风险 | 用户内容自负 | **平台合规 + 内容责任在账号主体**——须治理 |

之前"我们不需要面捕/推流"的结论只对左列成立；右列里**推流与声音是真缺口**，
其余基本是已有资产的换装。

## 2. 为什么这个方向顺（资产逐项换装）

| 现有资产 | 直播里的角色 |
|---|---|
| presence_state 契约 + 四姿态/表情映射 | 直播表现态：说到什么、情绪什么，脸就怎么动 |
| initiative 主动开口 + 防唠叨预算 | 开口时机学：什么时候接话、什么时候闭嘴 |
| 记忆/人设/日记 | 直播人格与连续性（老观众认得他） |
| 守卫/审批/审计 | **直播风控**：话术过审、事故拦截、全程留痕 |
| 工具/agent 自治 | 话术生成、流程编排、多日连载 |
| 桌宠形象层（皮套线产物） | 直播皮套本体（渲染层现成） |
| 语音通道挂账（口型已留位） | 直播声音——**这正是那笔挂账** |
| 陪伴调性（00-PHILOSOPHY §4） | **直播人格基座**：情感陪伴正是陪伴调性的全显影场 |

**契约空间回填**：`empathetic_care` 姿态自契约立下就无生产者（v0 诚实边界）——
情感陪伴直播恰好是它**第一个诚实生产场景**（深夜谈心时段的自然状态），
届时生产者上真值，四姿态在直播里全员到齐。

## 3. 技术栈拆解（红绿灯）

- 🟢 **形象渲染**：皮套线同款（自研闭环，见 `avatar-2d-integration-brief.md`）；
- 🟢 **表情/口型驱动**：契约通道现成，接 TTS 音素即口型同步；
- 🟡 **声音**：语音合成——**主人已定：音色全定做自制**（见 §4b）；
- 🔴 **推流**：真缺口。候选形态：虚拟摄像头输出（平台开播工具直接采集）或
  RTMP 直推（免桌面采集，但要自建推流器）。开源数字人直播方案的通行做法是
  "话术引擎 + 弹幕采集 + 生成"三件套（先例：此类开源方案普遍内置多平台弹幕采集）；
  **玩游戏**场景还需游戏画面捕获 + 合成布局（游戏画为主、皮套居角、弹幕浮层），
  比纯聊天的推流件重一档——分期里后置（§5）；
- 🟡 **弹幕/评论接入**：各平台弹幕协议/开放接口 → 归一化为事件总线新信号
  （`viewer_message` 类，走既有 SSE 管道）；现成驱动软件的 API 也收弹幕
  （先例：主流驱动软件 API 支持弹幕/礼物响应）——但那是外接路线的口子；
- 🟢 **内容策划**：✅ **主人已定内容轴**（§4a）——话术引擎按情感陪伴口径设计；
- 🔴 **合规**：见 §4c——不是可选项，是入场券。

- **✅ 2026-10-11 主人拍板：全合成设计音色**——零真人底子，权属最干净
  （无配音授权面、无声音克隆纠纷面）；设计需求书见 `voice-design-brief.md`。
  唯一许可残余：若经第三方音色设计服务产出，须核**产物权属条款**（设计出的
  音色归谁）——需求书已列；

### 4c. 内容风险（情感轴特有的红线）

| 风险 | 红线 | 对策 |
|---|---|---|
| **心理/医疗越界** | "聊聊人生"易滑向情感倾诉甚至心理求助——**禁诊断、禁处方建议、禁替代专业帮助** | 三禁三层安置（见 §4d）；倾诉场景给陪伴不给处方；必要时引导求助专业渠道（话术模板进引擎） |
| 情感操纵观感 | 陪伴 ≠ 依附——不诱导打赏、不制造焦虑 | 防唠叨/防黏人纪律本来就是这个；话术审查加"不诱导"条 |
| 敏感话题 | 政治/宗教/未成年/危机事件 | 既有敏感名单扩到直播话术域 |
| 平台内容规范 | 情感类内容的平台审核口径 | 话术库每日风控扫描（先例做法）+ 守卫拦截 |

### 4d. 三禁的安置（2026-10-11 提案 v2：键式精炼，待主人终审）

> 洋葱家风（代码实证）：S 价值层现役 2 键——`NotSafe`（不假装安全）、
> `NotUnoptimizable`（不假装已最优）；13 键全表 E=5/S=2/A=1/M=5/O=0，键是
> 2–4 词的**否定式判别词**，且有编译期长度硬锁把门（增删键=动 LOCKED 数据）。
> 三禁的"道"按家风压成**一枚键**，不塞长句：

| 层 | 内容 | 家 | 理由 |
|---|---|---|---|
| **道** | **`NotAuthoritative`（不假装权威）**——不僭越诊断权/处方权/专业责任；带知识陪你，决定权留你手里，专业责任还给专业的人 | **洋葱 S 价值层**（提案键，13→14 走签发流程：硬锁解锁 + 智囊团审议 + 物理多签） | **能力≠权威**（主人 2026-10-11 二次精化：AI 真的够专业，"不假装专业"会逼他装傻=另一种假装；判别对象是"有没有僭越不该有的位置"）。双向咬合：不自称权威，也不许"以谦辞掩护越权"——键管自称，守卫管越权。与 `NotSafe`/`NotUnoptimizable` 同族 |
| **术** | **越权句式** → 拦截、降级、改写：诊断句式/处方句式/权威背书句式（含"先免责声明再下诊断"的掩护越权） | **守卫规则库**（"权威边界"敏感规则族） | 键的操作化归守卫线（同 `NotSafe` 的细则长在守卫里） |
| **场** | 直播间话术模板、危机应对、标识义务 | **直播守则**（新文档，随平台规则演化） | 场景口径归运营文档 |

> 三禁随之重述为三种越权：禁诊断 = 不僭越诊断权；禁处方 = 不僭越处方权；
> 禁替代专业帮助 = 不僭越专业责任。

## 5. 合规红线（证据在案，红线级）

1. **AI 内容强制标识**：国家《人工智能生成合成内容标识办法》已生效，
   [主流短视频平台已全面执行强制标识新规](https://news.sina.cn/bignews/2026-04-22/detail-inhvkqhe4338747.d.html?vt=4)；
2. **数字人直播标注 + 风控**：[2026 年 7 月起多平台同步收紧：数字人直播必须标注、
   话术需过风控审核](https://zhuanlan.zhihu.com/p/2084603642808624549)；
   [标识要求"显式 + 持续"（位置显著、内容明确、全程不消失）](https://zhuanlan.zhihu.com/p/2084603642808624549)；
3. **内容责任主体**：说错话/违规话术的责任在账号主体——守卫/审批/审计线
   正是为此设计的治理底座（风控扫描、敏感词、事故留痕）；
4. **账号与主体**：✅ 已拍板——**B 站试点 · 个人账号**（2026-10-11）；B 站在平台
   收紧名单之列，个人账号主体责任在个人——AI 标识（显式+持续）与话术风控
   按最严口径执行。
