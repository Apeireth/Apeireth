## 1. 试金石

> **任意一屏，3 秒内回答三问**：系统在做什么？我能做什么？下一步点哪里？
>
> **看一眼就像在操作一台强大的机器**——而不是在浏览一个网页。

## 2. 三大命题

### P1 · 系统中枢（System Hub）

- 第一现场是**系统状态**：agent、任务、工具、资源、治理、事件流、告警。
- 聊天/卡片/表单都只是中枢里的**视图**，不是全部；首页不是"谁找我了"，而是"系统现在怎么样、哪里需要我"。
- 界面必须能表达**时间**：正在发生（实时）、刚发生（事件/日志）、发生过（回放/审计/追责）。

### P2 · Agent 是单位，不是中心

- **无预设中央 AI**：产品不内置"一个他"；agent 由用户带入（BYO）。
- **接入**：提供常见服务商的接入模板，用户只填凭据（API key 等）即可；无 agent 时系统有明确的空态与自检，不假装有 AI。
- **特别关注（双模式）**：
  - **视觉高亮**：pin 住一个 agent，界面各处跟随它的状态（检查器、列表高亮、事件过滤）。
  - **指挥授权**：被关注的 agent 成为团队 **leader**（权限边界见 §7 待定）。
- **检查器**：任何 agent/单位可被聚焦查看「此刻 / 在做什么 / 排队 / 利用率 / 状态程序 / 动作」——聚焦是**用户选择**，不是产品设定。

### P3 · 能力可授予（per-agent）

- 旧范式里的关系/存在能力（情绪 PAD、关怀、记忆、presence 等）不再绑定"中央他"，而变成**能力开关**：
  - 出现在**每个 agent 的设置界面**；
  - 可随时**赋予 / 剥夺**，由用户按需决定；
  - 能力的存在与状态必须可被看见（开/关/未接线三态，0 装）。
- 能力归属是**数据/治理问题**，前端只提供可见、可操作的面；后端语义由对应线定义。

## 3. 六条设计原则

1. **状态先行**：先表达"系统正处于什么状态"，再表达"这是什么功能"。
2. **结构清晰，密度优先**：SaaS 的层级纪律（模块 / 可读 / 数据可视化）+ 指挥舱的密度与动态。
3. **明暗对等（全双模式）**：**所有面都支持明暗两套**；每面可有默认模式（中枢默认暗、图纸/阅读面默认亮），用户可全局切换；两套**独立验收**（"暗色精细、浅色糊弄"直接判不通过）。
4. **金色 = 系统信号/能量**：不再是"他"的专属色；只用于**系统活动 / 信号 / 能量 / 告警语义**，不做装饰。
5. **游戏级反馈，诊断性动效**：动态全部由真实状态驱动（进度 / 信号 / 队列 / 告警）；每个动效必须能回答"系统现在在干什么"；无源动效不上屏。
6. **熟悉交互，低学习成本**：借用即时通讯的熟悉模型（会话列表 / 消息流 / 通知 / 群组 / 红点），叠加命令面与快捷键。

## 4. 视觉语言：一套语法，三副面孔（按「任务阶段 × 密度」分，不按界面层级硬切）

| 面孔 | 任务阶段 | 信息密度 | 默认模式 | 语言要点 |
|---|---|---|---|---|
| **指挥仪表盘** | 中枢 / 实时值班 / 监控 | 高 | **暗** | 发丝网格面板；等宽遥测微标签；中央空间面（agent 编队 / 系统图）；右侧固定检查器；底部时间轴 + 事件日志；回放/倍速 |
| **技术图纸** | 工作 / 配置 / 数据审视 | 中高 | **亮** | 纸白 / 米白底；黑线稿与工程标注；剖面 / 图层 / 网格；单点信号色；表格与表单的"图纸感" |
| **编辑终端** | 阅读 / 长文 / 详情 / 复盘 | 中低（阅读节奏） | **亮** | 强排版：大字号标题 + 等宽元信息 + 细分说明；高对比单色；留白与分段节奏 |

**共享层（三副面孔都必须遵守）**：

- **令牌**：一套设计令牌（颜色 / 字阶 / 间距 / 圆角 / 层级 / 动效时长 / 材质），明暗两套值对等。
- **网格**：统一列网格与发丝分隔线；面板方角/小圆角，禁止大圆角卡片堆。
- **排版**：显示字（大标题）+ 等宽字（数据/ID/遥测）+ 正文字三系；微型大写标签仅用于元信息。
- **信号色纪律**：全界面只保留**一个饱和色**（金 = 系统信号/能量）承担状态语义；其余用明度/层级表达。
- **动效纪律**：时长/缓动进令牌；动效必须有真实来源；`prefers-reduced-motion` 必须被尊重。

**3D 立体感（本版裁定）**：

- 业务界面**不引入 3D 引擎**；面板/层次/材质用 CSS 2.5D（深度阴影、玻璃、视差、模糊）实现。
- "惊艳"集中投入**一个中央空间面**（agent 编队 / 系统图）：先做 **2.5D（Canvas 点云/连线/景深模糊）**，W1 中期用同屏对照评估是否升级轻量 WebGL。
- 真 3D 场景（形象 / 场景 / 桌宠等）属 **3D 立项**，不在本范式承诺范围。

**反范式（明确不做）**：

劣质卡网（大圆角卡片堆砌、无主次、无真实状态）／纯装饰科幻（无源动效）／低密度大留白／"他"中心的显影界面／静态仪表盘（只有数字没有时间与过程）。

## 5. 信息架构骨架（v0.1 提案，随设计细化）

```
系统中枢（首页）
├─ 中央空间面：agent 编队 / 系统图（可聚焦、pin、指挥授权）
├─ 遥测区：agent 状态 / 任务与队列 / 工具与资源 / 治理与告警
├─ 检查器（右侧）：被关注单位的「此刻/手上/排队/利用率/状态/动作」
└─ 时间维：事件日志（当前行高亮）/ 回放 / 审计入口

工作区 / 任务流（具体形态待设计）
会话（即时通讯模型：列表 / 消息流 / 通知 / 群组 / 红点；是中枢的一种视图）
卷宗（治理 / 审计 / 记忆 / 回放；与调性正交的全局账本）
设置（BYO 接入模板 / per-agent 能力开关 / 明暗与密度 / 主题）
命令面与搜索（全局入口，快捷键驱动）
```

**首启与空态**（待设计，先立约束）：无 agent 时必须诚实展示"系统已就绪、等待接入"，并给出接入模板入口；不得用假数据铺屏（0 装设计语言）。

## 6. 0 装设计语言（继承并强化旧纪律）

- 一切动态/读数必须由**真实来源**驱动；模拟态显式标注（`SIM` 类等宽小字）。
- 空态写数据契约（"当 X 发生时这里会出现 Y"），不写"暂无数据"糊弄。
- 能力不可得/未接线必须可识别为"不可得/未接线"，不得用默认值冒充。
- 视觉上的"炫"必须可解释为状态（进度/信号/告警/能量），否则删掉。
