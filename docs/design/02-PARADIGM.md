## 1. 试金石

> **任意一屏，3 秒内回答三问**：我在做什么工作？下一步做什么？系统是否正常？
>
> **看一眼就像在操作一台强大的机器**——而不是在浏览一个网页，也不是在参观一个监控中心。

- 首屏（工作空间）的落点必须是**工作画布**；空间化视觉是环境，不抢戏。
- 控制塔的落点可以是全息基地；但它**不承担"开始工作"**。

## 2. 命题

### P1 · 工作空间优先（默认首屏）

- 用户每天打开 Apeireth 的第一现场是**工作**：当前工作 / 最近工作 / 文件 / 项目 / 应用入口 + **可变工作画布** + **AI 协作栏**。
- 核心对象从"聊天"升级为"工作"：对话只是工作画布的一种形态（还有文档/图像/数据/代码/任务流画布）。
- 首屏要能**开始工作**：新建工作、打开最近工作、拖入文件、发任务。
- 空态诚实：没有工作时给"开始一个工作"的入口与数据契约，不铺假数据。

### P2 · 应用空间（能力展开）

- 承载 Word / Photoshop / 浏览器 / 终端等**工作内应用**；它们**共享同一个工作上下文**，不是彼此独立的窗口。
- Starport（应用注册/打开/聚焦/关闭/钉住）从"应用启动器"升级为**工作内应用空间**。
- 应用空间不承担系统监控；系统状态在控制塔。

### P3 · 控制塔（系统状态，主动进入）

- **不是第一屏**。用户**主动进入**（一次交互 + 转场）来理解/审计/控制系统。
- 适合：Agent/模型状态、Provider 连接、CPU/GPU/内存/本地模型、工具调用与 Trace、审批队列、权限与治理、
  后台任务、错误与恢复建议、文件锁/协作冲突、系统事件与运行日志、**轨迹视图**、**全息基地**。
- 不适合：开始工作的入口、日常文件浏览、普通对话、应用启动、首次使用核心内容。
- **全息基地**：单独一页，进入控制塔需要一次用户交互；完整设计（城式基地 + 三层轨道环 + 暗场/图纸环境）保留在此页。

### P4 · Agent 是单位，不是中心

- **无预设中央 AI**：产品不内置"一个他"；agent 由用户带入（BYO）。
- **接入**：提供常见服务商的接入模板，用户只填凭据（API key 等）即可；无 agent 时系统有明确的空态与自检，不假装有 AI。
- **特别关注（双模式）**：① 视觉高亮（pin 一个 agent，界面各处跟随）；② 指挥授权（被关注 agent 成为团队 leader，权限边界见 §7）。
- **检查器 / AI 协作栏**：工作空间右栏是**AI 协作栏**（围绕正在编辑的对象）；控制塔里保留 **agent 检查器**（此刻/在做/排队/利用率/状态程序/动作）。聚焦是**用户选择**，不是产品设定。

### P5 · 能力可授予（per-agent）

- 旧范式里的关系/存在能力（情绪 PAD、关怀、记忆、presence 等）不再绑定"中央他"，而变成**能力开关**：
  - 出现在**每个 agent 的设置界面**；可随时**赋予 / 剥夺**，由用户按需决定；
  - 能力的存在与状态必须可被看见（开/关/未接线三态，0 装）。
- 能力归属是**数据/治理问题**，前端只提供可见、可操作的面；后端语义由对应线定义。

## 3. 八条设计原则

1. **工作优先**：先让用户完成事情，再谈氛围；首屏是工作空间，工作画布是焦点。
2. **状态先行**：先表达"系统正处于什么状态"，再表达"这是什么功能"。
3. **观察与操作分离**：控制塔的全息基地只"看 + 选"（点选/双击聚焦/拖视角/滚轮/右键菜单），**不是编辑器**；
   写操作只走固定面（命令条 / 检查器 / 待签卡）；工作空间的操作落在工作画布与 AI 协作栏。
4. **空间化视觉退居环境层**：星空/星球/桥/深舱/光晕不删除——空屏/首启/控制塔可完整展示；
   工作空间作低对比背景；编辑时自动降低存在感。**空间化视觉负责灵魂，工作画布负责完成事情。**
5. **明暗对等（全双模式）**：所有面都支持明暗两套；每面可有默认模式；两套**独立验收**（"暗色精细、浅色糊弄"直接判不通过）。
6. **金色 = 系统信号/能量**：不再是"他"的专属色；只用于系统活动/信号/能量/告警语义，不做装饰。
7. **游戏级反馈，诊断性动效**：动态全部由真实状态驱动；每个动效必须能回答"系统现在在干什么"；无源动效不上屏。
8. **熟悉交互，低学习成本**：工作空间借用即时通讯/文档工具的熟悉模型（列表、画布、输入框、通知），叠加命令面与快捷键。

## 4. 视觉语言：一套语法，三空间 × 三副面孔

| 空间 | 默认模式 | 面孔 | 语言要点 |
|---|---|---|---|
| **工作空间**（首屏） | 亮（暗色可用） | **编辑终端 / 技术图纸** | 工作画布为主：强排版、清晰层级、低对比环境背景；AI 协作栏半透明压边；命令条常驻 |
| **应用空间** | 随应用 | **技术图纸** | 应用 chrome 极简；共享工作上下文（文件/选区/版本）；工具栏克制 |
| **控制塔**（主动进入） | 暗 | **指挥仪表盘** | 全息基地（城式基地 + 三层轨道环）、遥测、轨迹视图、审批、事件日志；发丝网格 + 微标签 |

**共享层（所有空间必须遵守）**：

- **令牌**：一套设计令牌（颜色 / 字阶 / 间距 / 圆角 / 层级 / 动效时长 / 材质），明暗两套值对等。
- **网格**：统一列网格与发丝分隔线；面板方角/小圆角，禁止大圆角卡片堆。
- **排版**：显示字 + 等宽字 + 正文字三系；微型大写标签仅用于元信息。
- **信号色纪律**：全界面只保留一个饱和色（金 = 系统信号/能量）承担状态语义。
- **动效纪律**：时长/缓动进令牌；动效必须有真实来源；`prefers-reduced-motion` 必须被尊重。

**环境层（Astra 评审后定稿）**：

- 视觉身份元素（星空/星球/桥/深舱/光晕/暗场/地平网格）**只在环境层使用**：
  空屏/首启/控制塔可完整展示；工作空间低对比背景；编辑时自动降低存在感；任务运行时用光/呼吸/微动表达状态。
- 判据：**工作画布是焦点**；若环境永远主导，说明设计跑偏成"漂亮监控中心"。

**全息基地（控制塔独有，完整保留）**：

- 形态 D：城式基地 + 三层轨道环（记忆/编排/能力）+ 治理闸门环；基地不转、环不均匀旋转；基地形象层可替换。
- 环境：暗 = 无边暗场 + 地平网格（不画机库）；亮 = 米白工程纸/制图桌面。
- 进入方式：**单独一页，一次用户交互 + 转场**（不是首屏的一部分）。
- 交互：只"看 + 选"；写操作走控制塔的命令条/检查器/待签卡。

**反范式（明确不做）**：
劣质卡网（大圆角卡片堆砌、无主次、无真实状态）／纯装饰科幻（无源动效）／低密度大留白／"他"中心的显影界面／静态仪表盘／把工作画布做成聊天窗口的复制品／首屏即场景秀。

## 5. 信息架构骨架（v0.5）

```
工作空间（默认首页）
├─ 左栏：新建工作 / 最近工作 / 文件 / 项目 / 应用空间入口 / 收藏
├─ 中央：可变工作画布（对话 / 文档 / 图像 / 数据 / 代码 / 任务流）
├─ 右栏：AI 协作栏（当前目标 / 正在处理的文件 / AI 正在做什么 / 建议 / 待确认 /
│        已完成 / 版本与差异 / 撤销回退 / 权限范围）
└─ 底部：命令输入条 + 轻量状态（连接 / 保存 / 任务状态）

应用空间（工作内能力展开）
├─ 应用视图：Word / PS / 浏览器 / 终端（共享当前工作上下文）
└─ Starport：工作内应用空间（注册 / 打开 / 聚焦 / 关闭 / 钉住）

控制塔（主动进入；入口 + 一次交互 + 转场）
├─ 全息基地（单独一页：城式基地 + 三层轨道环 + 暗场/图纸环境）
├─ 轨迹视图（事件账本 + 时间概览 + 记录检查器）
├─ Agent / 模型 / Provider / 资源（CPU/GPU/内存/本地模型）
├─ 工具调用与 Trace / 审批队列 / 权限与治理 / 后台任务 / 错误与恢复
└─ 文件锁与协作冲突 / 系统事件与运行日志

全局：命令面与搜索（快捷键驱动）、明暗与密度、BYO 接入模板、per-agent 能力开关
```

- **工作空间是默认首页**；"聊天"不再是最高层的唯一中心，而是工作画布的一种形态。
- **首启与空态**：无工作时诚实展示"开始一个工作"，给出新建/打开/拖入入口；不得用假数据铺屏（0 装设计语言）。

## 6. 0 装设计语言（继承并强化旧纪律）

- 一切动态/读数必须由**真实来源**驱动；模拟态显式标注（`SIM` 类等宽小字）。
- 空态写数据契约（"当 X 发生时这里会出现 Y"），不写"暂无数据"糊弄。
- 能力不可得/未接线必须可识别为"不可得/未接线"，不得用默认值冒充。
- 视觉上的"炫"必须可解释为状态（进度/信号/告警/能量），否则删掉。
- 工作画布的 AI 建议必须可追溯（锚点/来源/差异），不得伪造成已执行。
