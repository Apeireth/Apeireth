> `Status: ✅ 规范定稿（2026-10-11）`，`pet-resident-projection.md` §2 形象路线的配套规范。
> 拍板记录（2026-10-11 主人）：① **首启可选、双形态并存**（光态哨兵=省电默认档，
> 角色形象包=可选华服，老机器自动回落光态）；② **许可白名单含商用/署名类**。
> **用词纪律**：本规范引用同类做法一律中性描述；许可条款引用用许可标识符
> （法律词汇，非项目词汇）；合规台账（§5）必须用真实名称与链接——署名义务的字面要求。

---

## 1. 为什么单独立规范

自有美术未到位前，用**开放许可的角色形象**把平台养起来（表情映射/口型/姿态/
换装这些"接形象的能力"才是真资产）。但开放形象生态的许可参差是最大的坑：
资产"免费"不等于可商用，运行时"开源"不等于可集成。**先过许可关，再谈好看。**

## 1b. 渠道三分与责任边界（2026-10-11 三次拍板：平台先行，形象用户自备）

形象资产的来源分三条渠道，责任边界不同——**平台不随包分发任何第三方形象
资产**，这是全部风险隔离的根：

| 渠道 | 是什么 | 许可责任 | 准入要求 |
|---|---|---|---|
| ① 用户自带形象 | 用户从生态自行获取、本机装载的形象包（平台只给格式规范与装载口） | **用户自担**（使用条款写明免责：用户须自证有权使用其资产；平台不分发、不托管、不生成派生） | 平台侧只校验格式合法性（清单/路径安全），**不审用户资产许可** |
| ② 测试/演示形象 | 开发、CI、演示用的临时形象 | 团队担 | **只收白名单**（T1/T2），且**不进发布物**（CI 素材许可门禁把关） |
| ③ 官方自制形象 | 后补的官方"他"（自制/委托，合同锁 CC0 或 CC-BY-4.0 交稿） | 团队担 | 走 §4 全流程准入 + §5 台账 |

- **指引"去哪里找"的口径**：文档列出第三方生态入口用中性描述 + 链接，必须附
  一句"许可各异，接入前请自行核对授权条款"——指路不背书。
- **"先用后换"红线**：测试形象绝不进发布物；CI 门禁 = 发布清单内所有形象资产
  必须在 §5 台账有行，无行即红。
- 选型调研（`reports/avatar-runtime-selection-2026-10-11.md`）已核实：白名单内
  现成 2D 角色资产近乎为零——这正是"用户自备 + 官方自制后补"策略的证据基础。
- **落地状态（2026-10-11）**：
  - ① 用户自带形象装载口 ✅——`user-avatar.ts`（格式合法性校验 + 免责确认 +
    IndexedDB 本机持久化 + 内嵌许可元数据透传）、`PetWindowView` 右键菜单接入；
  - ② CI 素材许可门禁 ✅——`asset-licenses.json` 台账（11 素材全 first-party）
    + `scripts/check-asset-licenses.mjs`（无行即红、白名单外拒、陈旧行红）
    + `pnpm check:assets` + workflow `companion-desktop-ci.yml` 接入（最小改动）；
  - ③ 用户指引 ✅——`docs/02-guides/avatar-byo-guide.md`（指路不背书）；
  - ④ 官方形象委托需求书 ✅——`docs/design/avatar-commission-brief.md`（待主人签发）。

## 2. 路线定位（与范式层的关系）

- **光是他的本体，角色形象是他穿的华服**——"光不长脸"哲学不推翻：金色纪律保留
  （存在金 = 他，角色皮肤不得占用存在金语义），形象可换、气质参数全走同一份
  `PetFrame` 契约（呼吸/姿态/眼神/口型）。
- 首启向导/设置里选形象：光态哨兵（默认）或角色形象包；T0 梯队强制光态/微光简模
  （`tier0Safe` 纪律，三档梯队只减排场不减功能）。

## 3. 许可白名单（许可口径 = 允许商用 + 署名类）

| 档 | 许可 | 义务 | 处置 |
|---|---|---|---|
| T1 无义务 | 公有领域等价（CC0 / Unlicense / 等效声明） | 无 | 直接收，登记来源 |
| T2 署名义务 | MIT / Apache-2.0 / BSD 系 / CC-BY-4.0 | 保留署名与许可声明 | 收，随包附署名文案 + 登记 NOTICE |
| **拒收** | 非商用类（NC 后缀） | — | 一律拒 |
| **拒收** | 禁止演绎（ND 后缀） | — | 一律拒（我们需裁切/重映射） |
| **拒收** | 禁止二次分发 / 仅限个人使用 / 自定义条款不明 | — | 一律拒 |
| **拒收** | 许可不明、仅口头/帖子授权、找不到原始发布页 | — | 一律拒（不猜不补） |

**运行时同审（软件层，与资产分开审）**：
- 渲染运行时必须是开放许可（T1/T2 档同表）；
- "个人免费、商用集成需另行授权"的专有运行时 = **默认拒**，除非单独谈判并入档；
- 运行时的**编辑器/生成器**许可与**运行时库**许可分开核对（生成资产的工具许可
  不自动覆盖资产本身，反之亦然）。

## 4. 准入流程（每包必走，五步）

1. **提交清单**：形象包目录 + `avatar-manifest.json`（形状见 §6）；
2. **许可核验**：逐资产打开**原始发布页 + LICENSE/许可声明文件**核对（网页抓取
   留档），不接受转述；
3. **资产登记表**：`ATTRIBUTION.md`——每资产一行：名称 / 作者 / 来源 URL /
   许可标识 / 署名文案 / 修改记录（无修改写"无"）；
4. **NOTICE 汇总**：并入仓库 `THIRD-PARTY-NOTICES.md`（既有账本惯例）；
5. **冷静复核**：入库前二次核对署名文案与许可标识无漂移。

## 6. 形象包清单 v2 草案（批 B 落码，此处先定契约）

在 v1（`schemaVersion/id/displayName/module`）基础上扩展：

```json
{
  "schemaVersion": 2,
  "id": "theme-xxx",
  "displayName": "…",
  "module": "layers/xxx.mjs",
  "model": "models/xxx.vrm",
  "license": {
    "spdx": "CC-BY-4.0",
    "attribution": "署名文案（随包展示与 NOTICE 共用）",
    "source": "原始发布页 URL",
    "modifications": "裁切为半身 + 重映射四姿态参数"
  },
  "capabilities": {
    "postures": ["corner_quiet", "head_up", "curled_asleep", "leaning_close"],
    "expressions": ["neutral", "warm", "focused", "sleepy"],
    "visemes": ["closed", "small", "mid", "wide"],
    "gaze": true,
    "blink": true
  },
  "tier0Safe": false
}
```

- `module`（自定义形象层模块）与 `model`（形象文件，.vrm/.glb）**至少给一个**，
  可同包并存；路径均须相对包目录、无逃逸、扩展名白名单（校验已落码）；

- 校验口径沿用 v1 的严格纪律：缺主键拒绝、路径逃逸拒绝、保留字 id 拒绝；
  `license.spdx` 不在白名单 → **拒绝注册**（许可红线进代码，不只进文档）；
  **已落码（2026-10-11）**：`avatar-registry.ts::parseAvatarPackManifestV2` +
  白名单表 `AVATAR_LICENSE_WHITELIST`，坏样全拒有单测（tests/pet-avatar-registry.mjs §5）；
- 表情/口型/视线是 `PetFrame` 的扩展通道（加字段不破坏契约），口型只跟本地
  真实 speaking 信号（频率纪律：不发明动画源）。

## 7. 性能与验收（批 D）

- 角色形象层默认 `tier0Safe: false`：T0 老机器自动回落光态/微光简模；
- 预算沿用 00-PHILOSOPHY §8：内存 <150MB、失焦暂停渲染、动画走合成器；
- 每包附带真机实测记录（内存/帧率/首次加载耗时）。

## 8. 选型调研任务书（批 A 剩余工作）
