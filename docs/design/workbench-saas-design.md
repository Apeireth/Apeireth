## 一、政策与分区治理

### 1.1 总政策：吸收设计语言，保持品牌审美骨架

吸收的是**清晰度与响应式纪律**（信息层级、组件一致性、断点体系、密度自适应、微交互规范），不是配色、不是气质、不是叙事。工作台面可以"像一款高效的工作台类产品"，但必须一眼认出是 Apeireth：暖色点睛、纸面/深舱调性、图章编号、金色纪律都在。

### 1.2 三区划分（哪些面 SaaS 化，哪些不）

| 区 | 承载 | 温度定位 | 本次动作 |
|---|---|---|---|
| **聊天面**（往来层 / Scene 调） | 会话列表、消息流、输入坞、光环与呼吸、情绪光域、他的声音排版、快捷窗 | **温度**（雅致 + 情绪光域） | **不 SaaS 化**。只做两件事：① 响应式红线（全区强制）；② 可访问性 / reduced-motion。视觉与信息密度零改动 |
| **工作台面**（照看卷宗 + 机器面） | 记忆卷宗、工具面板、诊断（系统状态 / 日志）、运行时、设置、仪表（状态条 / 统计）、治理卷宗、历史、`.wb` 回合工作台 | **清晰度** | **全量吸收**第二章清单；SaaS 化的主战场 |
| **深空档**（科幻氛围档） | 全屏场景 / 遥测氛围形态 | **科幻氛围** | 另批在建，不在本文范围；但响应式红线与品牌锚对它同样适用（红线不因分区豁免） |

判据（给未来新增面板用）：**这个面是"与他相处"还是"打理他的账"？** 前者归聊天面（温度），后者归工作台面（清晰度）。拿不准的归工作台面，但宁少勿多——工作台面的清晰度可以补，聊天面的温度冲淡了回不来。

### 1.4 温度红线（聊天面不许被 SaaS 化冲淡）

**禁止引入聊天面**：中性灰阶工具化底、数据表格、统计图表、顶部工具栏、密集信息排布、工业化卡片阴影、看板拖拽、过滤器 chips 流、常驻仪表。

**聊天面允许且必须**：响应式红线（会话列 / 消息列 / 输入坞自适应）、reduced-motion 降级、命令面板快捷键（已是"一个入口"）、焦点可达与语义标签。

**原样保留**：他的消息卡（左缘金色光晕 + 衬线引语 35em 行宽）、用户消息的克制卡、"正在输入"的光环呼吸（禁止三个点）、星尘记忆卡、留白节奏、`h1.ask` 空态 hero、Ember 余烬与情绪光域。

## 二、吸收清单逐条落地规格

> 体例：每条给 **现状 → 改法 → 锚（不许动）**。标注沿用 0 装约定：✅ 现状事实 / 🟡 本文提案值待拍板。

### 2.0 现状总览（吸收前的底账）

调研走查（`frontend/companion-desktop/src` 全读）确认四件事：

1. **两套令牌层并存**：`--ap-*`（`lib/design/tokens.css`，Memory / Diary / Governance / Workbench / shell 消费）与 `base.css` 通用层（`--surface/--text/--muted/--amber…`，Conversations / Tools / Activity / Settings / RuntimeModal 消费）；语义色三套写法（`--ap-semantic-*`、一组工具类十六进制如 `#4ade80/#f87171`、另一组 `#2ecc71/#e74c3c`）。
2. **重复模式 ×5-7 未标准化**：搜索工具条（输入 min240/max380 + chips + 右动作）×7 处类名各异；卡片头 / 脚 ×5；状态 badge / pill ×6；弹层（backdrop + head/body/foot）×6 各写一套；key-value 行 ×5；手风琴折叠 ×3。
3. **响应式缺口**：shell 断点 1180 / 980 / 820 / 800 与视图断点 900 / 860 / 720 / 600 / 520 两套并存；Conversations / Tools / Activity / Guard / Grants / Approvals / Workbench 内部**零布局断点**；全库零容器查询；~900px 以下最先破的是表格截断、卡片头挤压、设置双栏。
4. **硬编码清单**（宽度）：rail 76px（`.drawer left:76px` 手工同步）、drawer `clamp(720px,52vw,960px)`、`.wb` 344px ×3 处重复声明、`mv-list min(340px,44%)`、搜索框 240/380 ×3、`settings` 子导航 200px / 内容 900px、guide-card 240px、trace 弹层 640px、RuntimeModal 580px、`.col 640px` / `.dock-col 860px`、`bottom:148px` 等 px 定位件、`100vh` 假设。（颜色硬编码清单见 V1。）

### 2.1 视觉

#### V1 大留白 + 中性灰阶打底 + 品牌暖色点睛

**现状**：工作台面已有调性底（深舱渐变 / 纸面），但"中性灰阶"没有令牌——层级靠散落硬编码（ActivityView 约 40 处十六进制与 rgba、fallback 变量如 `var(--text-dim,#888)`）；留白是各视图自己定的 32–36px 固定 padding。

**改法**：
- 新增中性灰阶令牌组 `--ap-neutral-0…5`（深浅主题各一档；只表达层级，不表达情绪）；文字三级固化命名为 primary / secondary / tertiary（即 bone / bone-68 / bone-42 既有值，不改值，只给职能名）。
- 工作台面的底 = 调性底（深舱 / 纸面，A6 不动）；其上面板 / 卡 / 行一律走中性灰阶；**品牌暖色点睛**：accent 金只用于选中、焦点、主行动按钮、"他在"信号四处。
- 留白归 8pt 栅格（4/8/12/16/24/32），与既有 2–28px 刻度衔接；视图边距由固定 32px 改为 `clamp(16px, 2vw, 32px)`。
- 硬编码色回收：语义三套写法归一到 `--ap-semantic-*` 四值（✅ 令牌已有），逐视图清理（清单见 2.0-4）。

**锚（不许动）**：琥珀金 / 骨白主调（A1）；金色纪律（A2）；调性底色与纸面恒纸面（A4/A6）；语义色"克制使用、禁装饰"纪律。

#### V2 层级靠阴影与卡片分组

**现状**：三种阴影公式已在用（大浮层 `±26px 0 60px -30px`、弹层 `0 24px 70px`、金辉光）；卡片五种头 / 脚范式并存；分组靠标题 + 列表堆叠。

**改法**：
- 阴影令牌化为三级 elevation：`--ap-elev-1`（卡：0 1px 2px）/ `--ap-elev-2`（浮起：0 8px 24px -12px）/ `--ap-elev-3`（弹层：0 24px 70px）；深浅双纸面各配色温（浅 `rgba(20,19,22,*)`、深 `rgba(0,0,0,*)`，沿用现有公式）。
- 卡片分组 = 节标题（等宽小字 eyebrow）+ 卡栅格；同组同高同内距；组间靠留白与 1px `--ap-line` 细线，不靠彩条。
- hover / 浮起只升一级 elevation + 描边微亮，不位移超过 2px。

**锚**：斜切角 10px / 括号角标 / 图章编号组件语言（A7）不动；金辉光只属于他（A2）；阴影透明度克制、不加彩色阴影。

#### V3 线性扁平图标

**现状**：线性图标已在 rail / 卡片 / 按钮使用（Chevron / FileText / Search / Clock / Zap 等，前端已接入的开源图标包），但尺寸 10–24px 不一、颜色随文字灰度随机。

**改法**：
- 图标规格表：16px 行内 / 20px 工具栏 / 24px rail（底部状态条 12px）；线宽统一 1.5；单色。
- 颜色三级：默认 tertiary（bone-42）→ hover secondary → 激活 gold-ui（仅选中态或"他的信号"）。
- 禁多色、禁填充、禁渐变、禁表情化插画；空态插画位沿用"光纹生成，不默认美术资产"的分级启用纪律。

**锚**：不引入多彩品牌图标；rail 图标现有语义不改；金色不用于普通激活以外的装饰（A2）。

#### V4 表格 + 图表混合视图

**现状**：全库只有一张真表格（历史视图 backend 账本表，窄窗截断无横向滚动）；计数条已有（stat-pill / tally-cell / chip-n），图表组件为零；记忆"图谱"是边列表。

**改法**：
- **表格规范**：sticky 表头；数字列右对齐 + 等宽 + 单位弱化；状态列 badge；次要列分级（priority 1/2/3，窄窗按级隐藏）；行 hover = 灰阶浮起，行选中 = 金内缘（既有选中语言）；窄窗转卡片流（见 3.4）。
- **图表语法**（先立三种够用）：sparkline（趋势）、迷你柱（分布）、进度弧（预算 / 配额）。细线 + 淡填充；数据色用深舱识别色或灰阶；每图必带数值 + 单位（图是数值的形状，不是装饰）；无网格线、无 3D、无渐变填充。
- **混排版式**：W3+ 为"表格为主 + 右侧图表栏"；W2 图表收进节头；W1 图表降为 sparkline 内联。
- **0 装**：无真实读模型的图表不做；数据源清单见开放问题 #3。

**锚**：识别色 ≤6 且避开存在金；语义色克制；金色不进图表（除非表达"他在"的信号点）；图表不得进入聊天面（1.4）。

### 2.2 信息架构

#### IA1 侧栏导航 + 顶部工具栏（评估既有侧栏层级）

**现状**：左 rail（76px，8 图标：对话 + 8 个抽屉面）+ 抽屉（fixed 覆盖层）+ 底部状态条；无顶部工具栏；视图内自带三级（治理 4 tab / 诊断 2 模 / 设置 200px 子导航）。rail 八图标平铺 = 记地图成本，与"一个入口"原则（A8）存在张力。

**评估结论**：层级本身健康（面 → 视图内 tab → 卡内展开三级清晰），问题在平铺无分组 + 缺一条"我在哪 / 可做什么"的视图级操作行。

**改法**：
- **rail 分组治理**（不新增层级）：三组——往来（对话）/ 照看（治理、记忆、历史、日记）/ 机器（工具、状态、日志、设置），组间细线 + 悬停组名；组序即信息架构。
- **顶部工具栏只属于工作台面**：一行 = 面包屑（照看 › 治理卷宗）+ 视图内筛选（chips / 下拉）+ 搜索入口 + 视图动作（右对齐）。聊天面不加顶部工具栏（1.4 红线）。
- 命令面板仍是唯一需要记忆的全局入口（A8）：工具栏只承载"当前视图的操作"，不承担跨面导航；跨面走 Ctrl/⌘+K。

**锚**：聊天面无顶部工具栏；rail 激活态金语言（选中 = 金竖条 / 金字）不动；"一个入口"不打折。

#### IA2 卡片式数据呈现

**现状**：卡片范式已多但不统一（session / gov / tool / call / mv 详情五套头脚）；卡片、kv 行、表单的使用边界靠自觉。

**改法**：
- 统一卡片骨架：`header（图标 + 标题 + badge）/ meta 行 / body / footer（动作）`，三档密度（紧凑单行 / 标准 / 富详情）；五套头脚收敛为一个组件族（P2 组件六件套之一）。
- 使用边界：**卡片承载实体与集合**（会话、工具、授权、文书、记忆条目）；参数 / 配置用 kv 行与表单；连续日志用行流（timeline），不硬套卡片。
- 空态三件套（主卡 + 次卡 + 契约文案）从治理卷宗推广到全部卡区（A8 空态即契约）。

**锚**：空态文案纪律（"当 X 发生时这里会出现 Y"）；聊天面消息卡不参与本次统一（他的消息卡是引语卡，不是数据卡）。

#### IA3 命令面板（Cmd/Ctrl+K 全局搜索与命令）

**现状**（✅ 已落地）：`CommandPalette.svelte` + `commands/registry.ts`，注册表驱动约 20 条命令（导航 9 / 主题 7 / 动作 4），拼音与缩写别名、最近榜 localStorage 持久化封顶 8 条、0 装置灰（disabledReason 显示但不可执行）、Deep-Ops 底 + 金内缘选中、Esc / 方向键 / ↵ 全通。

**改法**（P1 主项）：
- **双模式一个内核**：默认命令榜；输入即转全局搜索（跨会话、记忆、治理文书、工具、设置项），`>` 前缀强制命令模式，空查询显示"最近 + 建议"。
- **结果分组**：命令 / 会话 / 记忆 / 文书 / 工具，组头等宽小字；行 = 标题 + 类型徽 + 时间。
- **预览栏**（W3+）：右栏显示选中项详情与可执行动作（如待签文书的"签批"直达）；W1/W2 单栏。
- **快捷键表**：Ctrl/⌘+K 唤出 / 收起；↑↓ 选择；↵ 执行；→ 展开预览；Esc 关闭；Tab 切换命令 / 搜索模式。
- 与工作台面顶部搜索框**同源**（一个搜索内核、两处入口）。

**锚**：面板视觉语言（deepOps 底 / 金内缘 / 置灰 0 装 / kbd 徽章）不动；最近榜诚实持久化策略不动（损坏回落空榜，不猜不修）；"一个入口"地位不动。

#### IA4 全局搜索

**现状**：七处视图本地搜索（类名各异、宽度各异），无跨面搜索；无统一索引。

**改法**：
- 统一搜索内核（一个前端索引服务）：索引会话标题 / 会话预览、记忆条目、审批与审计账目、工具注册项、设置项；结果深链直达所属视图并定位条目。
- 结果行 = 卡片行（IA2 骨架）+ 类型徽 + 深链；命中词高亮用下沉金（纸面）/ 亮金（深底）——档案调 ink-gold 两态令牌已有。
- 空态契约文案 + "搜索范围"说明（诚实告知索引了什么）。
- 消息正文是否入索引列开放问题 #8（隐私 / 性能权衡）。

**锚**：深链只切视图不破层序（仍是抽屉 / 页面层，"用户从未离开舰桥"）；高亮不用金色装饰（金 = 强调命中词的"实"，不是色块）。

### 2.3 交互

#### IX1 轻量自然动效（尊重 reduced-motion）

**现状**：两个时间尺度已在（界面过渡 ≥2s 通则 🟡、照明 ≥60s）；组件层实际已在用 0.18–0.6s 微动效（hover 0.18–0.28s、ap-rise 0.22s、抽屉 0.34s、消息入场 0.42s）；`prefers-reduced-motion` 全局一刀切静止（`tokens.css` 尾部 `*{animation:none;transition:none}`）。

**改法**：
- 明确**第三个时间尺度——功能确认层 120–320ms**（hover / press / 展开收起 / 入场位移 ≤8px + 透明度），缓动 easeOutQuint；与"界面过渡 ≥2s"、"环境照明 ≥60s"并列为三尺度表（数值 🟡，待回写 `01-DESIGN-SYSTEM.md` §7.1，见开放问题 #2）。
- 面板开合沿用现有 0.25–0.38s；拖拽落位 200ms 回弹（P3）。
- **禁止**：弹跳、装饰性视差、循环动效（呼吸光除外——那是他的信号）、加载假动画。
- reduced-motion：保持全停（现状），另将拖拽 ghost、预览栏淡入等新交互纳入静态化清单。

**锚**：Ember 呼吸光（2.8s / 4.0s）、光环呼吸、照明 90s 过渡一律不动（A3/A9）；聊天面动效节奏零改动；动效"秒级不闪"的下限对界面过渡仍有效。

#### IX2 可拖拽组件（面板布局 / 看板）

**现状**：无拖拽；`.wb` 五块手风琴顺序固定；无布局持久化。

**改法**（P3）：
- **范围**：工作台卡片栅格重排 + `.wb` 块顺序 + 未来看板列（看板依赖后端任务数据模型立项）；**聊天面消息流不可拖**（回溯 / 重说走事件溯源，另案处理）。
- **交互**：拖拽手柄（6 点）→ 悬停抬升 elev-2 → 栅格吸附 → 落位 200ms 回弹；拖动中显示占位缝（灰阶虚线，不挣金）。
- **键盘可达替代**：聚焦手柄 + ↑↓ 移动位次；命令面板提供"移动卡片 / 重置布局"命令（一个入口）。
- **窄窗**：W1 禁拖，改"排序模式"（上移 / 下移按钮 + 禁用拖拽手柄）。
- **持久化**：布局入本地偏好（键前缀 `apeireth.layout.*`），损坏回落默认（不猜不修，与命令最近榜同款策略）。
- **无障碍**：拖拽状态播报（aria 拖放语义）、reduced-motion 直落无动画。

**锚**：拖拽只动位置不动卡片视觉语言（A7）；拖拽态不挣金（金内缘只给选中与他的信号）；拖拽不进聊天面（1.4）。

#### IX3 工作流可视化（审批 / 治理流）

**现状**：审批 = 对话内待签文书卡（in-context）+ 治理卷宗事后账（四 tab）；`ExecutionTimeline.svelte` 已有步骤 DOM（状态图标 + kind/tier 标签 + 可展开 receipt）但**全库无 `.exec-*` 样式**（裸渲染）；治理流的"请求 → 守卫 → 签批 → 执行 → 审计"目前只能横向翻四个 tab 拼出来。

**改法**（P3）：
- **治理流图**：沿用连线图语法（树状节点 + 直角连线 + 对勾图章，A7/`01-DESIGN-SYSTEM.md` §5.6③）画线性五段流：请求 → 守卫 → 签批 → 执行 → 审计；节点 = 状态点（待 / 过 / 拒 / 超时）+ 图章；识别色分工：蓝 = 审批、绿 = 授权、红 = 守卫、工业黄 = 审计。
- **两个深度**：审批卡内嵌 mini 流（只画到当前段）；治理卷宗 tab 内全流图（hover 出该段计数，点击深链到对应账目）。
- **ExecutionTimeline 补样式**：归入同一语法（时间轴 = 竖直直角连线）。
- **0 装**：流图只画真实生命周期状态（审批 / 审计读模型），无模拟流动动画；未知态按模拟态标注纪律标 `SIM`。

**锚**：连线图语法本身不动；识别色 ≤6 且避开存在金（A2）；待签段允许金（"他停下了等你"的既有语义），其余段不挣金；聊天面审批卡保持待签文书卡形态（不改成流程图）。

### 3.5 布局技术约定

1. **断点唯一出处**：断点表以 `lib/design/` 层为唯一定义点（CSS 注释头 + TS 常量双镜像、同 PR 改）；`App.svelte` 内 `innerWidth < 1180` 的 JS 判定改读共享常量。组件不得私自定义新断点。
2. **容器查询**：抽屉内嵌视图与 `.wb` 块一律按**容器宽**响应（抽屉宽 `clamp(720px,52vw,960px)` 与窗口解耦）；引入 `@container` 一处声明（如 `design/container.css`）。全库目前零容器查询，这是"窄窗降列"真正生效的前提。
3. **流式单位**：内容列用 `min()` / `clamp()` / `minmax()`；搜索框宽度统一为一个令牌（替代 240/380、200/320 两套）；硬编码 px 回收清单逐项改造：`.wb` 344px ×3、`mv-list min(340px,44%)`、`settings` 子导航 200px / 内容 900px、guide-card 240px、trace 640px、RuntimeModal 580px、`.col 640px` / `.dock-col 860px`。
4. **rail 宽单源**：`--rail-w` 变量（76/64px 两值），`.drawer left` 与一切依赖 rail 宽的定位改引用变量（现状两处手工同步是断点改一处漏一处的根源）。
5. **高度模型**：`100vh` → `100dvh`（或窗口高度变量）；弹层 `max-height` 用 dvh；`.scroll-bottom-btn` 锚定输入坞顶（现状 `bottom:148px` 依赖 dock 实高，换字号 / 密度即错位）。
6. **溢出纪律**：任何面板禁横向滚动；文本 `ellipsis + title`；表格窄窗转卡片流（3.4）而非截断。
7. **字号纪律**：工作台面基准字号随密度档，`clamp()` 设上限（不随视口无限放大）；数据数字一律等宽（A7 图章 / 编号语言）。
8. **红线豁免**：无。聊天面也在红线内（1.4"允许且必须"）；深空档在建亦须按本章实现。

### 3.6 终端 TUI 自适应（终端行列自适应布局）

桌面端与终端端**同一套语义、两套排布**（功能不随形态减配，A8）。终端 UI 技术栈沿用本仓既有 Rust 终端 UI 依赖；布局按终端列数 C × 行数 R 重排，**resize 事件 = 纯布局重排，不重建状态**。

**列档**：

| 档 | 列数 C | 形态 |
|---|---|---|
| T1 | < 80 | 单栏聚焦：当前页 + 底部状态行 |
| T2 | 80–119 | 双栏：主区 70% + 侧栏 30%（列表 / 详情二选一） |
| T3 | 120–179 | 三栏驾驶舱：主区 50% + 侧栏 25% + 遥测栏 25% |
| T4 | ≥ 180 | 超宽：三栏 + 顶部遥测带（图表 / 状态行全展开） |

**行档**：

| 档 | 行数 R | chrome |
|---|---|---|
| R1 | < 24 | 页头折成单行 tab 行；状态条 1 行 |
| R2 | 24–39 | 页头 + tab 行 + 状态条 |
| R3 | ≥ 40 | 全 chrome：页头 + tab + 状态条 + 快捷键提示行；列表双行/项 |

**折叠顺序**（空间不足时按序丢）：遥测带 / 栏 → 侧栏详情 → 页头副题 → 快捷键提示行 → 状态条指标数（四指标 → 两指标 + 计数）。

**对齐纪律**：宽字符（CJK）按显示宽（2 格）计算列对齐与截断；表格列宽按比例分配；过小终端（C < 60 或 R < 12）显示单行诚实提示（"请加宽终端至 80 列"）而不是崩版或叠字。

**语义同源**：状态条四指标、命令面板（唤出键 + 同一注册表）、空态契约文案、0 装置灰、金色纪律（终端金 = 高亮选中与"他在"信号）与桌面一致；深空档科幻氛围是终端端的渲染层，不改本节布局语义。

## 六、开放问题

1. **顶栏与"一个入口"的边界**：全局搜索框是常驻顶部工具栏，还是只在命令面板内（推荐后者 + 工具栏放召唤按钮，最贴"一个入口"）？
2. **三时间尺度的规范回写**：功能确认层 120–320ms 与界面过渡 ≥2s 通则并存条款，需主人拍板后回写 `01-DESIGN-SYSTEM.md` §7.1（本文 🟡）。
3. **图表数据源清单**：状态条四指标之外（token 用量 / 成本 / 缓存命中 / 回合耗时）在现役读模型是否有真值？没有就不上图（0 装），仪表卡范围随答案收缩。
4. **密度档默认映射**：是否随调性微调（深舱默认紧凑、纸面默认宽松）？还是全区统一按断点？
5. **拖拽布局的持久化位置**：纯本地偏好，还是进配置契约（"布局也是数据"）？后者需后端配置面配合。
6. **W4 增栏内容**：哪些视图有第二数据栏（图表 / 详情 / 遥测）？需逐视图定，避免为宽屏凑栏。
7. **终端 TUI 立项节奏**：本次 3.6 规格是随桌面 P1 同步实现，还是绑定终端驾驶舱立项（既有调研的 P3 梯队）？
8. **全局搜索是否索引消息正文**：隐私 / 性能权衡（会话标题与记忆条目先行是否足够）？
9. **红线外（宽 < 900）**：维持现状 best effort 即可，还是要立低优先承诺（如窄到 720 仍可用）？
10. **命令面板预览栏的权限边界**：预览治理文书细节是否需要即时鉴权（与审批动作同一治理面），还是仅显示元数据？
