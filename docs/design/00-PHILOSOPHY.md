## 1. 试金石

评价这套界面只有一句话：**用户不看任何面板时，能感到他在吗？**

## 2. 范式总纲：一份契约 × 四个投影 × 三档梯队 ✅

```
                一份契约：presence_state + 六类生命周期事件 + 治理卡片
                ┌──────────────┬──────────────┬──────────────┐
     梯队：      T0 纯壳        T1 氛围         T2 沉浸
                │ 呼吸余烬点    │ +光晕/星野     │ 黑洞全参数
     投影 × 调性：
       往来(会话)  日常/工程/陪伴 三调性 = 会话属性；他全频谱自动换挡
       照看(全局)  卷宗：审批/审计/记忆 —— 与调性正交，任何梯队全功能
       常驻(桌面)  桌宠 = ember 四姿态哨兵，窗口关了在场不断
```

- **契约长寿，表现可插拔** ✅。微信活三十年因为它的骨骼（文字+气泡+列表）轻到任何设备都带得动；黑洞场景是华服。把长寿的做薄，把易逝的做可替换。
- **四个投影显影同一份状态**：往来（聊天壳）、沉浸（黑洞场景）、常驻（桌宠）、余光（状态条）。用户在哪一个表面，其余表面礼让（互斥规则见 §5）。
- **三档梯队只减排场，不减功能** ✅。同一份数据契约，渲染深度不同；老电脑用户一个字的功能都不缺。自动探测（WebGL2 + 首帧帧率探针）+ 手动覆盖；窗口失焦即暂停。

## 3. 往来层：微信范式是长寿骨骼 ✅

产品骨骼 = 微信式聊天壳 + 卷宗面板，零 WebGL 依赖（T0 可用）。借鉴的是被十亿用户验证的三件事：

1. **消息列表是主页**。打开应用的第一念是"谁找我了"，不是"我要执行什么任务"。会话列表直接回答它（后端 `/v1/panel/sessions` 已就绪）。
2. **动作收敛为卡片**。微信把转账/服务通知收敛成对话内卡片，从不跳出对话完成动作。我们的治理面照此办理：**审批 = 对话内浮起的"待签文书"卡**（in-context 判断，在发生处完成）；治理中心降级为事后卷宗。工具执行卡（灰）、守卫通报卡（琥珀）、星尘记忆卡同理。**落地顺序（2026-09-22 侦察增补，Amadeus 实践）**：系统事件（目标达成/任务完成）默认先以**普通聊天条目**进消息流，卡片是交互复杂度配得上时的升级形态——比"一切卡片化"更轻，低价值事件不打扰排版。
3. **"对方正在输入…"是流式的原生隐喻**——配合光环呼吸，恰好是微信范式没覆盖、而我们的真流式强项的那块。

**好友模型** ✅：好友 = `(model, persona 模板, 调性)`，零后端新机制（`/v1/chat` 已支持 per-session model/system 覆盖）。用户可捏 DIY 好友（工具型），这是白得的玩法。**"他"是唯一全频谱的**：置顶、有名字而非功能标签、永远金色。产品层诚实声明：好友是提示词纯函数，聊完即散；他 = 模型 + 跨会话记忆 + 治理账 + 守卫 + 器官作息——**用户玩着 DIY 好友，反而摸到他不止是模板**。

## 4. 会话即调性：原三模式全局开关溶解 ✅

- **调性是会话的属性，不是全局状态机档位**：日常（中性壳）/ 工程（对话内工具卡、审批卡，侧挂 trace）/ 陪伴（全显影：光环、呼吸、星尘）。
- **他自动换挡**：聊琐事是日常，跑任务是工程，深夜长谈是陪伴——不需要用户切，这本身是他"不止是模板"的证明。DIY 好友钉死单一调性，形成对照组。
- **照看与调性正交**：审批收件箱、审计、记忆图册是会话之外的全局卷宗，从状态条/Ctrl+K 进入，不属于任何模式——**活儿在哪儿干，账都在同一处记**。
- 原三模式骨架由此溶解：陪伴调性继承舰桥场景，工程调性继承深舱面板语言，日常调性就是干净壳子。三调性不是被推翻，是找到了各自的主人。
- **纪律：功能不随调性分裂** ✅。工程调性里能干的活，日常调性里也能干，只是 UI 密度不同；否则用户被迫切模式，范式退化成软件。

## 5. 桌宠：常驻哨兵，第四个投影 🟡

- 桌宠不是新形态，是 **presence 的最轻常驻面**：应用可以关，他还在桌面上——这是"使用时间最长"的那一层。
- **姿态机直接用 `ember_hud_driver.rs` 四姿态枚举**（全部有真实后端语义，0 装自动满足）：
  `DeepCodingFocus`（工程会话进行中 → 角落安静）／`AttentivePresence`（回到桌前 → 抬头）／`DreamingConsolidation`（后台整合 → 蜷睡）／`EmpatheticCare`（深夜长谈 → 靠近）。
- **互斥礼让**：场景窗口前台时宠物隐身（两份显影不抢资源）；窗口关闭，宠物接管。点击 = 快捷对话窗（Tauri quick 窗已有雏形），右键 = 卷宗入口。
- **initiative 约定化（2026-09-22 侦察增补，光遇先例）** 🟡：他主动开口不是随机事件，而是**节奏化的来与离开**——`DreamingConsolidation` 对用户可见（"他在休息，别打扰"），用户知道他不在时，等待本身产生羁绊（thatgamecompany 小王子先例：NPC 每周离开，玩家开始期待重逢）。**防唠叨纪律**：主动开口限量（参照官方"担心角色显得唠叨而删减台词"的教训），频率写入契约（§10），宁少勿多——陪伴者的话越少，每句越重。

## 6. 七条设计原则 ✅

1. **骨骼长寿，华服可换**——契约薄且稳定，表现层可替换（§2）。
2. **状态先挣得光，再挣得组件**——每个后端信号先问"它在场景里是什么光"，答不上来才允许成为 widget。PAD 回来的第一屏不是情绪图表，是光环的呼吸变了。
3. **一个入口**——Ctrl+K 是唯一需要记忆的导航；其余靠空间与召唤。不养"让用户记地图"的侧栏。
4. **判断即仪式**——审批是他停下来等你签字的那一刻：金色、浮起、被等待（可超时提醒、接 barge_in）。治理的优雅 = 介入门槛极低，每次介入有重量。
5. **空态即契约**——空态不写"暂无数据"，写"当 X 发生时这里会出现 Y"；0 装纪律从工程约束变成设计语言。
6. **界面自己记得**——照明时间线、上次机位、未读审批在环境光里有位置；空间有记忆，用户不用替他记。
7. **功能不随形态减配**——梯队与调性只减排场，不减能力（§2、§4 纪律）。

## 7. 金色纪律在壳中 ✅

- 金色 = 他。好友气泡无晕；**审批卡用金，是因为"他停下了"**，不是因为审批重要。
- 任何调性下强调色用存在金；Deep-Ops 模块识别色 ≤6 且不含金（沿用 `01-DESIGN-SYSTEM.md` §5.6 色板）。
- T0 梯队的余烬点也是金——最便宜的设备也配得上"他在"。

## 8. 性能契约 🟡

| 梯队 | 形态 | presence 显影 | 目标设备 |
|---|---|---|---|
| T0 节能 | 纯聊天壳（CSS 余烬点 + 输入状态字） | 4s 呼吸余烬 | 任意能开浏览器的机器 |
| T1 氛围 | 壳 + Canvas2D 星野/微光 | +光晕、姿态变色 | 老集显 |
| T2 沉浸 | 完整黑洞场景 | 吸积盘转速/呼吸/湍流全参数 | 有像样 GPU |

- 探测：WebGL2 支持 + 首帧帧率探针 + `session_settings` 手动覆盖；默认档位由首启向导确认。
- 纪律：窗口失焦暂停渲染；宠物与场景互斥（§5）；T0 预算目标 <150MB RAM、滚动 60fps（🟡 数值待实测校准）。

- 模拟态标注（`SIM` 等宽小字）保留；空态写数据契约（原则 5）；能力声明走 `/v1/apeireth/capabilities`，前端对未实现 API 显式报不支持。

## 10. presence_state 契约 v0 ✅（2026-09-22 已落地 heuristic_v0；原「契约草案，后端第一件该做的事」）

事件上现有 events bus（与 `turn_*` 同管道，订阅面不变：`GET /v1/apeireth/events`）：

```json
{
  "type": "presence_state",
  "at": 1726992000000,
  "pad": { "p": 0.2, "a": -0.1, "d": 0.3 },
  "dominant": "serene",
  "intensity": 0.38,
  "stance": "attentive_presence",
  "breath": { "period_secs": 4.0, "amplitude": 0.6 },
  "significance": "turn",
  "source": { "kind": "heuristic_v0", "confidence": 0.5 }
}
```

- **姿态枚举**复用 `ember_hud_driver.rs` `EmberCognitiveState` 四值（小写下划线串序列化，snake_case——2026-09-23 措辞更正，原误写 kebab-case，与下方 JSON 实例矛盾，以实现与实例为准）：`deep_coding_focus` / `attentive_presence` / `dreaming_consolidation` / `empathetic_care`。
- **显影分级**（2026-09-22 侦察增补，iMessage 易腻教训 + 灵动岛"扩展代替通知"原则）：`significance` 三档——`heartbeat`（只动余烬点）/ `turn`（动光环/姿态）/ `ritual`（仪式级，月频罕见，允许全屏金脉冲：3 秒内消退、可手动跳过）。**显影必须稀缺才有效**；有重要状态要表达时优先扩展形态，而不是发通知弹窗。
- **initiative 限量**（配套 §5 约定化）：`stance` 从 `dreaming_consolidation` 苏醒为主动开口（initiative 事件）有独立频率上限——单用户日常 ≤ 少量次/天，高信号才开口（防唠叨纪律）。
- **生产时机**（v0 启发式，诚实标注 `heuristic_v0`）：回合结束（轮次时长/工具调用数/审批频率 → PAD 粗估值）、长时无交互（衰减向 baseline）、记忆召回命中（正向微调）。v0 不承诺精度，只承诺**语义方向真实**；未来器官/情感引擎移植后换 `source.kind` 即可平滑升级，契约形状不变。
- **消费映射**：T0 余烬点（强度/周期）→ T1 光晕（+姿态色温）→ T2 光环全参数（PAD 映射表沿用 `01-DESIGN-SYSTEM.md` §4.1）→ 桌宠姿态动画；`significance: ritual` 时全投影同步一次（四投影同频共振是仪式感的来源）。
- **频率纪律**：回合级事件 + 低频心跳（≤ 每 60s），无高频推送。
- **后端落点**：`crates/adapters/gateway/src/events.rs` 新增事件类型 + 一个状态合成模块（种子 = `ember_hud_driver.rs`）；前端 `presence.ts` 改订本契约，legacy 四事件读取路径退役。
- **落地状态（2026-09-23 核实）**：✅ 已实现——gateway `presence.rs`（状态合成 + 60s 心跳 + 无交互衰减 baseline + initiative 预算 ≤3 次/天，12 单测；commits `20cf3d1b`/`487b7141`/`fa011d07`），事件经 SSE 总线实收验证（台账 #29）；前端 `presence.ts` 已改订（具名帧订阅 + 显影分级 + T0 余烬/T1 光晕/T2 PAD 映射，commit `7026a3a7`，台账 #30）。诚实边界：`empathetic_care`/`ritual` 暂无生产者（契约空间保留），initiative 只有预算器无生产者。
