## §1 Astra 的核心判断（要点转述）

1. **问题不是"首页缺几个按钮"，而是整个前端还没确定 AI OS 的基本空间模型。**
   现有实现的基础是对的（宿主窗口 / 会话入口 / 工作台 / 应用注册 / 文档应用 / 自研 UI 引擎 / 治理与 Trace），
   但当前形态更像"漂亮的展示屏"——擅长表达"系统是什么、怎么运行、是否健康"，
   不擅长表达"我在做什么工作、我在编辑什么"。**两者必须分开。**
2. 现有视觉的"几个明显信号"：大量空间场景背景、rail/drawer/状态栏/控制塔式信息、
   复杂状态颜色与监控数据；系统状态/agent/工具轨迹比"内容"更容易成为焦点。
3. 提出 **三个空间**：**工作空间（默认第一屏）**、**应用空间**、**控制塔（系统状态，主动进入）**。
4. **Workbench 应重定义为「AI 协作栏」**：始终围绕"用户正在编辑的对象"——当前目标 / 正在处理的文件 /
   AI 正在做什么 / 建议 / 待确认 / 已完成 / 版本与差异 / 撤销回退 / 权限范围。
5. **文档应用方向是对的，但还偏"技术演示型文档编辑器"**：需要补版本树、AI 修改建议、差异视图、
   局部接受/拒绝、多人多 Agent 编辑锁、光标/选区级协作、编辑动作可追溯、文件与 AI 对话双向定位。
   图像编辑同理：画布/图层/选区/AI 建议/操作差异/版本节点/回退；AI 要说明"改了哪层、影响了哪、用了什么工具、什么没变、要不要批准"。
6. **视觉设计不需要被推翻**：旧范式的具象视觉元素应从"工作内容层"退到"环境与身份层"（Astra 原建议；
   **owner 2026-10-31 修正：旧范式具象元素不进入新范式**，环境层只约束功能，具体语言由施工方创造）——
   空屏/首启/控制塔可完整展示；工作画布作低对比背景；文档/图像编辑时自动降低存在感；任务运行时用光/呼吸/微动表达状态。
   核心原则：**空间化视觉负责让 Apeireth 有灵魂，工作画布负责让用户完成事情。**
7. **导航层级建议**：一级 = 工作空间（默认首页）/ 应用空间 / 控制塔；二级 = 当前工作 / 最近工作 / 文档 /
   图像 / 数据 / 浏览器 / 终端 / 记忆 / 日记 / AI 协作线程；"聊天"不再是最上层唯一中心，而是工作画布的一种形态。
8. 概括：**首页让人开始工作，工作空间让人完成工作，应用空间让能力展开，控制塔让人理解系统。**

## §2 三空间模型（Astra 建议的落地结构）

| 空间 | 定位 | 主要结构 | 不该承担 |
|---|---|---|---|
| **工作空间**（默认首屏） | 用户每天真正干活的地方；核心对象从"聊天"升级为"工作" | 左：工作/项目/文件/应用；中：**可变工作画布**（对话/文档/图像/数据/代码/任务流）；右：**AI 协作栏**；底部：输入/状态 | 系统监控、应用启动器、治理台账 |
| **应用空间** | 承载 Word / PS / 浏览器 / 终端等能力；共享同一个工作上下文 | 应用内视图 + 工作内启动/切换；Starport 作为"工作内应用空间"而非启动器 | 成为系统状态面板 |
| **控制塔** | 用户**主动进入**，理解/审计/控制系统 | 全息基地（单独一页，交互一次进入）、Agent/模型/Provider、CPU/GPU/内存、工具调用/Trace、审批队列、权限治理、后台任务、错误恢复、文件锁/协作冲突、事件日志、轨迹视图 | 开始工作的入口、日常文件浏览、普通对话、应用启动 |

## §3 AI 协作栏（Workbench 重定位）

始终围绕"当前正在编辑的对象"：

- 当前目标 / 正在处理的文件 / AI 正在做什么 / AI 建议了什么 / 待确认操作 / 已完成操作 / 版本与差异 / 撤销回退 / 权限范围。
- 实时修改 Word/图像/数据时必须显示"**改了什么**"：如"AI 正在修改：产品方案.docx；变更：重写第 2 节 / 删除重复段落 / 插入市场规模表格；[查看差异] [接受] [拒绝] [回退]"——比"Agent 正在运行"更有价值。
- 文档/图像的编辑建议**锚定到选区/图层**（选中一段 → 建议绑定到该段，而不是另起一个聊天）。
- 与现有设计的关系：我们此前把右侧叫"检查器"，现在**按对象重定义**为 AI 协作栏（控制塔里仍保留 agent 检查器）。

## §4 文档/图像编辑方向（Astra 建议的后续能力）

- 文档：版本树、AI 修改建议、差异视图、局部接受/拒绝、多人多 Agent 编辑锁、光标/选区级协作、
  编辑动作可追溯、文件与 AI 对话双向定位。
- 图像：画布/图层/选区/AI 建议/操作差异/版本节点/回退；AI 说明改了哪层、影响区域、工具、未变内容、是否需要批准。
- 这些是**后续轮次**能力；首轮设计原型只要求把"AI 建议 → 差异 → 接受/拒绝/回退"的形状做出来（见提示词 §7）。

## §5 视觉设计的处置：退居环境层 + 创意留白

- **旧范式的具象视觉元素不进入新范式**（owner 2026-10-31 修正）。Astra 建议"保留旧元素、降为环境层"，owner 采纳其"视觉不推翻、退居环境层"的结构，但**不采纳"沿用旧元素"**——避免施工方误以为必须复刻旧画面。
- 环境层改为**只约束功能**：低对比、有纵深、不抢内容、明暗两套；**具体视觉语言（光、雾、材质、地面、纵深手法）由施工方创造**。
- 工作空间/应用空间/控制塔的分工不变：工作画布是焦点；环境不抢戏。
- 正确性判据：**工作画布是焦点**；若环境永远主导，用户会觉得在"漂亮监控中心"而不是操作系统。
