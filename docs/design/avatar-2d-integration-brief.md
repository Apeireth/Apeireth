## 1. 两条接入路线

| 路线 | 做法 | 优 | 劣 |
|---|---|---|---|
| **A. 内嵌运行时（自研闭环）** | 渲染运行时库作为依赖内嵌进桌宠窗，形象文件（分层 2D 网格变形格式 / 开放 3D 人形格式）由我们装载；契约参数直驱 | 零外接软件、体验一体、可进 T0/T1/T2 梯队 | 需选型一个许可干净的运行时；表情/口型映射自己写（工作量已有先例，3D 线同构） |
| **B. 复用现成驱动软件（外接）** | 形象交给市面主流驱动软件跑，我们经它的 API 发动作/收弹幕 | 生态资产全兼容、面捕/弹幕 API 现成 | **那是给"人脸驱动+直播"设计的工具**：多一个常驻外接进程、体验割裂、许可与分发责任更绕；对桌宠是绕路 |

**材料立场**：A 是正道（B 的能力恰好是我们不需要的那半——面捕/直播是"用户当主播"的需求）。B 只在"自直播"命题下才有价值（见 `companion-self-streaming-vision.md`）。

## 2. 运行时选型与许可要点（红线三条）

1. **运行时随产品分发 = 我们在分发别人的许可**。白名单（主人拍板口径：允许商用 +
   署名类）下：
   - **开放 3D 人形格式**运行时三件套全在白名单（实证见选型报告），且模型自带
     机读许可声明——**最干净**；
   - **分层 2D 网格变形**的主流生态运行时是**专有许可**：个人/小规模免费，
     年营收超门槛须签付费出版许可，另有竞品限制条款——按红线默认拒，除非
     主人**知情改判**（准入规范留了"单独谈判并入档"的口子）；
   - 社区 2D 骨骼格式运行时白名单内有一支（MIT），但工具链与资产生态薄
     （npm 实探负证在案）。
2. **资产许可与运行时分开审**：模型市场大面积"仅个人使用/禁改禁转"——
   自带形象（BYO）策略已免疫（用户自担）；随包官方形象必须白名单 + 台账。
3. **改判的代价要写进合同**：若接专有运行时，规模化商用前须补签出版许可
   （费用/追溯条款），且产物分发受其条款约束——这是产品级承诺，不是技术细节。

## 3. 参数映射（契约侧已就位）

| 契约通道（PetFrame/character-mapping） | 分层 2D 网格参数 | 开放 3D 人形参数 |
|---|---|---|
| 口型开合（真实说话信号） | 嘴部开合/形状参数 | 口型音素 a-i-u-e-o |
| 眨眼（确定性生理节律） | 眼睑开合 | 眨眼表达式 |
| 视线（glance + 微漂移 + 可加鼠标跟随） | 眼球/头部角度 | 视线三驱动（骨/形/贴图） |
| 呼吸（契约节律） | 身体起伏 | 胸部骨 |
| 四姿态（角落安静/抬头/蜷睡/靠近） | 身体角度/位移/缩放 | 标准骨变换 |
| 待机微动作/入定档 | 参数叠加（幅度封顶纪律同源） | 同左 |

结论：**契约一个字段都不用加**，只有"鼠标视线跟随"是可选小扩展。
