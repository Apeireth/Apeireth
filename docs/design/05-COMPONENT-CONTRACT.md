## 0. 定位：组件层分三段

| 段 | 交付物 | 依赖 | 现在能做？ |
|---|---|---|---|
| **① 契约（本稿）** | 组件分类、API 形状、状态矩阵、令牌映射规则、数据契约、可测性要求、验收清单 | 只依赖范式与施工规格 | ✅ **现在就能做** |
| **② 打样** | 在原型层跑起来的真实组件（结构 / 状态 / 事件可断言） | D1 令牌冻结（owner 签） | ⏳ 等 D1 |
| **③ 生产** | 产品仓正式组件层，接真实数据、焦点/IME、虚拟化 | 引擎产品仓最小垂直切片通过（W1 前置门） | ❌ 门未过 |

**三段的分工**：范式（产品原则）→ D1 令牌（视觉值）→ **本稿（组件形状）** → 引擎实现（代码）。
本稿只做中间的"形状"，因此**不依赖引擎、也不等 D1 就能先立骨架**；D1 一来即可对齐。

## 1. 组件分类（按语义域，不按画面）

| 域 | 必备件（最少集） | 可选件 | 说明 |
|---|---|---|---|
| **工作画布** | 消息块、流式追加块、工具过程块、审批卡、输入区（命令条）、附件项、文档页、图像画布 | 目录树、标注层、版本标记 | 首轮画布形态 = 对话 / 文档 / 图像 |
| **AI 协作栏** | 建议条目、差异视图、锚点标记、动作条（接受/拒绝/回退）、状态条 | 建议历史、追问输入 | 必须可读"这条建议是什么、改哪、改成什么" |
| **应用 chrome** | 应用入口项（Starport）、工具栏、图层面板、终端条、窗口标题栏 | 状态栏、溢出菜单 | 应用空间内部形态由当前应用决定 |
| **控制塔** | 遥测读数块、Agent 列表项、检查器面板、事件日志行、待签文书卡、轨迹账本行、时间概览条 | 阈值编辑器、告警分组 | 控制塔只"看 + 选"，不直接写 |
| **共享基础件** | 按钮、文本输入、选择器、开关、标签页、列表行、表格、模态/抽屉、气泡提示、加载态、空态、错误态、徽标、图标、Toast | 分段控件、进度条、树 | 这些是"通用件"，不承载业务语义 |

**规则**：
1. 每一件都必须能归入某一域；跨域复用的放"共享基础件"。
2. **允许增补**：施工方可按设计需要新增组件，但必须满足 §2/§3 契约，并登记回本表。
3. 本表是**下限**，不是上限——视觉与形态自由度保留给施工方与 owner 审美门。

## 2. 组件 API 契约（硬规则）

1. **纯函数**：`render(props) -> 视图树`；同样的 props 产出同样的树。组件**不取数据**、不含业务语义。
2. **事件经 props 进**：组件不直接调用运行时；动作以回调形式传入。
3. **不写内联样式**（动态值经 CSS 变量传入）；**不设 id**；class / token 由调用方给。
4. **组件不发明视觉语言**：形状、间距、时长、色值一律来自令牌（§4），组件只声明"要哪个令牌槽"。
5. **具名插槽**用泛型参数表达；不接受字符串拼接 HTML。
6. **必须可 native 单测**：不依赖浏览器、不依赖 wasm；断言行为，不断言源码文本。
7. **禁用项**：全局状态读取、隐式网络调用、直接操作 DOM 树之外的结构。

## 3. 状态矩阵（交互态八态 + 内容态三态）

**交互态**（每个交互件必须全覆盖）：

| 状态 | 触发 | 表现要求 | 机械判据 |
|---|---|---|---|
| default | 静止 | 基线形态 | 有基线快照 |
| hover | 指针悬停 | 有可见反馈 | 指针事件可触发 |
| focus | 键盘聚焦 | 焦点可见、可 Tab 到达 | 焦点序可达 |
| active | 按下/激活 | 与 hover 可区分 | 按下事件可触发 |
| disabled | 不可用 | 不可交互、语义可读 | 交互事件不触发 |
| loading | 进行中 | **布局不跳变**、旧内容可辨 | 状态可切换 |
| error | 失败 | **必须给可读错误文本** + 可否重试明确 | 错误态可构造 |
| selected | 被选中 | **能选就必须有** | 选中态可构造 |

**内容态**（叠加在交互态之上，不是第九个交互态）：`empty` / `awaiting-approval` / `unavailable`。

- `empty` = 还没有内容，**必须说明接下来能做什么**；
- `awaiting-approval` = 等人拍板，**必须显示待决对象与后果**；
- `unavailable` = 能力存在但当前不可用，**必须说明为什么不可用**。

## 4. 令牌映射（规则先定，值待 D1）

- 令牌用**语义名**，不用色值名；调用方只说"要哪个语义槽"。
- **唯一高饱和 = 系统信号色（金）**；成功/警告/危险/信息低饱和、只承担语义；工作画布内容色与图片原色不受限。
- **明暗双模**：每个令牌有 light / dark 两值，缺一即不合格。
- **密度两档**：紧凑 / 标准（本稿只定档位名，值待 D1）。
- **单源**：D1 是令牌的唯一真源；组件与实现都从 D1 取值，不得各自硬编码。

| 语义槽 | light | dark | 备注 |
|---|---|---|---|
| （待 D1 回填） | 待 D1 | 待 D1 | 本稿不预设具体色值/尺寸 |

## 5. 数据契约（每个交互件的输入 / 输出 / 失败）

1. **来源标签统一**：`LIVE` / `MOCK` / `STALE` / `UNAVAILABLE` / `NOT_WIRED`；无标签的"看起来像真数据"禁止上屏。
2. **建议类条目**至少携带：`suggestion_id / work_id / artifact_id / anchor_type / anchor_id / before_version / after_version / trace_id / permission_scope / source`。
3. **失败一律可读**：错误必须有文本 + 是否可重试；禁止只给红框或静默。
4. **动作必须留痕**：接受/拒绝/回退都要产生可追溯记录（含时间与来源）。

---

## 6. 可测性要求

- 每个组件：**≥ 1 条结构断言 + 八态覆盖断言 + 事件回调断言**；
- 断言**钉行为不钉字面量**（视觉契约字符串如 class 名属例外，可钉）；
- **禁止源码镜像测试**（读文件文本断言）——这是旧线的结构债，新组件不得复现；
- 组件层可测性指标（W1 必报）：行为测试数、覆盖的交互路径数、是否存在源码镜像（应为 0）。

---

## 7. 验收清单（机械可查）

- [ ] 每个组件在 §1 表里登记，且归入某一域；
- [ ] 每个交互件八态全覆盖，`selected` 不缺；
- [ ] `empty` / `awaiting-approval` / `unavailable` 三个内容态都有可读文案；
- [ ] 组件不含数据获取、不写内联样式、不设 id；
- [ ] 所有色值/尺寸来自令牌，无硬编码（令牌表可查）；
- [ ] 每件有 native 可跑的断言，且无源码镜像测试；
- [ ] 每件的失败态可构造、错误可读；
- [ ] 新增组件已回写 §1 表；
- [ ] 明暗双模两套取值齐备。

---

## 8. 留白条款（明确**不**预设的东西）

以下全部**不**在本稿约束范围内，由 owner 审美门与施工方创作决定：

布局尺寸与比例、栅格与分栏像素、控件高度、圆角、阴影、字重与字族、图标风格、
动效时长与曲线、密度具体值、材质与纹理、是否用 3D 或 Canvas 承载某块画面。

本稿只约束：**语义、结构、状态、数据诚实、可测性**。

---

## 9. 与现有引擎资产的关系

- 现有 `crates-ui` 里的组件与 DOM 层属于**旧线能力证据与 API 参考**，**不是新范式的组件真源**
  （旧线已冻结；其视觉契约字符串不作为新范式基准）。
- **可复用**：纯函数渲染模型、组件注册表、虚拟树与差分机制、事件接线与成对挂卸的纪律。
- **不复用**：旧组件的视觉契约、class 名与结构；新组件按本稿与 D1 重做。
- 旧组件清单（button / badge / card / icon / tool_card / tool_grid / status_bar / governance_tab /
  settings_* 等）在产品仓的现状见引擎线的能力矩阵答复，本稿不逐一评价。
