## §3. 前端与后端的关系（§18.7 双洋葱）

### 3.1 §18.7 双洋葱视角

| 层 | 内容 | 前端 |
|---|---|---|
| **外层**（关系形态）| 用户可感知的能力/接口/体验层 | **前端 = 外层**（Web UI / CLI / Desktop）|
| **内层**（基础设施）| 记录/迁移/约束/根原则的执行机制 | **后端**（17 crate + 双洋葱 + 12 键 + 5 重守门）|

**关键洞察**：
- 前端 = **外层洋葱** = **可演化**（OTA / 部署 / 升级）
- 后端 = **内层洋葱** = **稳定**（双洋葱统一体编译时 hardcode）
- **前端永远不直接访问 L0 HA** —— 必须走 API gateway 的 V1+V2+V3 AND 门

### 3.2 平台三件套（§18.5）

- **提供（provide）** = 前端 = **用户感知的能力**
- **约束（constrain）** = 后端 = **V1+V2+V3 AND 门 + 5 重守门**
- **记录（record）** = 后端 = **6 历史流 + audit log**

---

## §4. 前端 5 重守门对应

| 守门 | 前端实现 |
|---|---|
| **1. 编译时 hardcode** | TypeScript 类型系统 + Rust 类型同步（自动生成）|
| **2. 运行时拦截** | HTTP 拦截 + WebSocket 鉴权（API gateway 层）|
| **3. 多 AI 一致** | 多个前端 agent 共享状态（WebSocket broadcast）|
| **4. 物理隔离 HA** | HTTPS + 真实人类登录（OAuth2 / WebAuthn）|
| **5. 反思期审计** | 前端不参与（前端只是接口，audit 在后端）|

**关键差异**：前端**不能直接实现**"编译时 hardcode"（前端是 JS/TS，类型系统弱）—— **必须由后端 Rust 类型同步** + **API gateway 拦截** 来保证。
