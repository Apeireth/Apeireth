## §4. 5 项可选补强建议（不冲突、不假装）

仅列出**明确不冲突 + 工程上简单可落地 + 显著提升架构质量**的建议：

### 4.1 建议 1（M2）：阶段 4 §6 9 阶段生命周期可考虑"控制器循环"视角

**当前**：§6 用 enum + struct 状态机实现 9 阶段。
**可选补强**：把状态机视为"desired state vs actual state + reconcile 循环"——不是替换，是补充视角。

**实施成本**：低（在状态机基础上加 reconcile 函数）。
**风险**：与现有 enum 不冲突，纯粹是**视角补强**。

### 4.2 建议 2（M4）：明确 6 历史流为 "Append-only Log"

**当前**：§4 HistoryStreams 是 6 个 Vec<History> 字段。
**可选补强**：明确每个历史流是 append-only log（push-only API，无删除 / 无修改），存储层用 sled / SQLite append-only 模式。

**实施成本**：低（结构定义 + API 标注）。
**风险**：与现有 trait 不冲突，强化 M4 事件溯源原则。

### 4.3 建议 3（M5）：明确 apeireth-bus 5 层 = "控制面 + 数据面"

**当前**：§3 apeireth-bus 5 层通信总线（inproc / UnixSocket / pipe / gRPC / WS）。
**可选补强**：明确**控制面** = L0 inproc + L1 UnixSocket（高频配置），**数据面** = L2-L4（事件流 + RPC + 多前端）。

**实施成本**：极低（文档标注）。
**风险**：不冲突，强化 Service Mesh 模式。

### 4.4 建议 4（M6）：双洋葱统一体 = "防腐层 Anti-Corruption Layer" 的正式定位

**当前**：§1.2 12 键编译时实现 + §3 双洋葱 trait。
**可选补强**：在文档中显式标注双洋葱统一体 = ACL（防腐层），隔离外部 API（HTTP / WASM / PyO3）与内部领域（中央 AI / 记忆 / 演化）。

**实施成本**：低（文档）。
**风险**：不冲突，DDD 模式正式落地。

### 4.5 建议 5（M7+M9）：自创生 + 涌现的"形式化定义"

**当前**：§3 LifeForce trait + Emergence trait 是工程接口。
**可选补强**：在文档中显式定义"自创生 = 系统能 self_replicate 自身组件（不复制主 AI 本身）+ self_maintain（不崩溃）"+ "涌现 = 不可预设的整体能力，监测机制见 §10.5 反思期"。

**实施成本**：低（文档）。
**风险**：不冲突，强化 Maturana / Kauffman 理论基础。
