### 2.3 E 层修改路径（v6 完整版）

**核心矛盾**：
- **守门**：默认拒绝修改 E 层（守门 1-4 嵌套 = 4 重拒绝）
- **AI 大进化**：未来 AI 确实需要修改 E 层（E-1..E-6）
- **解决方案**：**权限发放**作为"例外允许"路径

**完整流程**：

```
第 1 步：守门 1-4 默认拒绝（4 重守门嵌套）
┌─────────────────────────────────────────────────────────────┐
│ 守门 1 编译时 hardcode: const E_LAYER_HARDCODE = true      │
│   ↓ 如果绕过编译（不可能）                                    │
│ 守门 2 运行时拦截: RuntimeInterceptor 拦截 E 层修改          │
│   ↓ 如果绕过运行时（不可能）                                  │
│ 守门 3 物理隔离: 修改需重新编译 + 物理多签                    │
│   ↓ 如果绕过物理（极不可能）                                  │
│ 守门 4 反思期审计: 检测 E 层修改尝试 + 上报                   │
└─────────────────────────────────────────────────────────────┘

第 2 步：权限发放（例外允许 = 通过审核）
┌─────────────────────────────────────────────────────────────┐
│ 1. 多 AI 一致: 7 席审议 + 智囊团多 LLM 独立验证              │
│    - 5 重治理（MEWG + 多人 + 多 AI + 物理多签 + 反思期）    │
│    - 阶 1 §18.6 + 阶 2 §12 五重治理                          │
│                                                             │
│ 2. V0.5 v2 24 维权重公式（v4.1 §13 提议）: 评估必要性       │
│    - 24 维评估修改的紧迫性、风险、影响                       │
│                                                             │
│ 3. 人类决策: L0 HA 真实人类批准                              │
│    - 物理在场（不是远程）                                    │
│    - 物理多签（AI×3 + 人×2 + 密钥×3）                       │
│                                                             │
│ 4. 风险分级: critical 7 / high 5 / medium 3 / low 1 / info 0 │
│    - E 层修改 = critical 7 席全量                            │
└─────────────────────────────────────────────────────────────┘

第 3 步：实施（物理多签 + 重新编译）
┌─────────────────────────────────────────────────────────────┐
│ 1. 物理访问 server room                                      │
│ 2. 物理多签: AI×3 + 人×2 + 密钥×3 同时在场                  │
│ 3. 重新编译 apeireth-core 二进制                             │
│ 4. OTA 部署到所有载体                                        │
│ 5. 反思期审计（72h 持续监控 + Cognitive-Dream 全周期）       │
└─────────────────────────────────────────────────────────────┘
```

**E 层修改后**：
- 反思期审计（最长 72h）+ Cognitive-Dream 6 状态机全周期
- 观察是否有"修改后异常"（违反 5 项不假装 / 触发 Self-Disable）
- 7 席审议再次通过 → 永久生效
- 任何 1 席反对 → 回滚（rollback）
