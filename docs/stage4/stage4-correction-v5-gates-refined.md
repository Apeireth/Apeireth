## §1. 主人 5 个精炼指令

### 1.1 守门 1：编译时 hardcode 范围扩大到原则洋葱

> 主人原话："让违反原则洋葱的代码失效，这样就把 12 键并到洋葱里后还让范围更广了"

**理解**：
- ❌ v4："让违反 12 键的代码编译失败"（**范围窄**）
- ✅ v5："让违反**原则洋葱**的代码编译失败"（**范围更广**——12 键 + E/S/A/M/O 5 层 + 5 项不假装全部包含）

**v5 修正**：
```
守门 1（v5 编译时 hardcode）:
  范围 = 原则洋葱整体（E/S/A/M/O 5 层 + O 层 12 键 + 5 项不假装 + S/A/M/O 各层内容）
  实现 = const fn check_principle_onion(action) -> Result<(), PrincipleViolation>
  不只是 12 键 = 整个原则洋葱
```

### 1.2 守门 2：运行时拦截（没毛病）

> 主人原话："运行时拦截没毛病"

**v5 修正**：保留，作为守门 2，**中间层**（拦截所有决策）。

```
守门 2（v5 运行时拦截）:
  范围 = 所有决策前
  实现 = async RuntimeInterceptor::check(action) -> Verdict
  中间层 = 物理隔离 + 反思期审计（外层）+ 编译时（内层）之间
```

### 1.3 守门 3：多 AI 一致不是守门，是权限发放

> 主人原话："多 ai 一致没必要弄成守门的，因为修改原则需要多ai一致，所以守门就是把原则洋葱和权限洋葱守住就可以了，这样一个嵌套结构。就可以弄成把没有相应权限而运行的代码拦截就行，然后权限的发放由多ai发放或人类决策，就像那个权重公式。"

**v5 关键洞察**：
- ❌ v4："多 AI 一致 = 5 重守门之一"
- ✅ v5："多 AI 一致 = **权限发放机制**，不是守门"

**v5 修正（核心重构）**：
```
守门（gates）= 守住原则洋葱 + 权限洋葱 = 4 个（不是 5 个）
  1. 编译时 hardcode（原则洋葱整体）
  2. 运行时拦截（所有决策前）
  3. 物理隔离（重大修改需物理访问 + 多签）
  4. 反思期审计（守护越权检查）

权限发放（permission grant）= 多 AI 一致 或 人类决策：
  - 公式 = V0.5 v2 24 维权重公式（v4.1 §13）
  - 实施 = apeireth-council 智囊团审议（7 强制 + 动态专家）
  - 人类决策 = L0 HA 真实人类批准
  - 权限发放的对象 = 风险分级（critical 7 / high 5 / medium 3 / low 1 / info 0）

"守住没有相应权限而运行的代码"= 守门 1-4 联合工作
```

### 1.4 守门 4：物理隔离精炼讲解（主人要求）

> 主人原话："物理隔离是个什么情况，你给我讲解一下"

**物理隔离精炼讲解**：

**类比**（日常生活）：
- **核武器发射按钮**：物理双人制（两把钥匙两个人在场）
- **银行金库**：物理多签门（多个银行家同时在场）
- **服务器机房**：物理钥匙 + 多个人员

**具体到 Apeireth**：

| 维度 | 具体内容 |
|---|---|
| **L0 HA 核心修改** | 必须有真实人类**物理在场**（不是远程验证）|
| **物理多签** | AI × 3（不同 LLM）+ 人 × 2 + 密钥 × 3 同时在场 |
| **重新编译** | 修改需要重新编译 `apeireth-core` 二进制（不只是更新配置）|
| **不可绕过** | 不是网络验证可绕过的，必须物理访问机器 |

**为什么需要物理隔离？**

```
网络攻击可以绕过其他守门:
  ↓
远程攻击 → 可能绕过运行时拦截（如果拦截器被攻破）
↓
AI 自己绕过编译时（理论不可能，但仍需物理层兜底）
↓
多 AI 一致被攻破（如果多个 AI 同时被攻破，仍需物理验证）
↓
物理隔离 = 最后的兜底防线（人在回路 + 物理在场）
```

**实际场景**：
```
场景：主 AI 想修改 E-1 "保证自身存活"
   ↓
守门 1 编译时 hardcode → E-1 是 const，改不了（编译失败）
   ↓ 如果绕过编译（不可能）
守门 2 运行时拦截 → RuntimeInterceptor 拦截
   ↓ 如果绕过运行时（不可能）
权限发放 → 修改 E-1 是 critical 风险，需要 7 席审议 + MultiHuman 多签
   ↓ 如果绕过审议
守门 3 物理隔离 → 重新编译 apeireth-core 二进制
                      → 需要物理访问服务器
                      → AI × 3 + 人 × 2 + 密钥 × 3 同时在场
                      → 不可能绕过
```

### 1.5 守门 5：反思期审计 vs 生命力反思（注意不要混淆）

> 主人原话："反思期审计的话可以，就是相当于反思ai有没有越权呗，这个没啥问题，不过注意不要和ai自己有的生命力反思搞混了"

**v5 关键区分**：

| 概念 | 守门 5（反思期审计）| 生命力反思（apeireth-life-force）|
|---|---|---|
| **目的** | 守护越权检查 | AI 自身的成长/演化/反思 |
| **触发** | Cognitive-Dream 24h 自动 | AI 自己意识到要反思 |
| **检查内容** | 所有决策是否越权 | 经验沉淀 / 方法论晋升 / 涌现观测 |
| **失败处理** | Self-Disable 防护 + 上报 | 自动演化（成长）|
| **L0 HA 影响** | 不直接修改 | 不影响 L0 |
| **位置** | 守门（外层）| 内层（不在洋葱守门内）|

**v5 修正**：
```
守门 5（v5 反思期审计）:
  目的 = 守护越权检查（不是演化）
  触发 = Cognitive-Dream 24h 自动
  检查 = 所有决策是否越权
  失败 = Self-Disable 防护 + 上报
  与生命力反思的区别：完全独立的两个机制
```

### 1.6 5 项不假装放到 O 层或 M 层

> 主人原话："5项不假装一样给我放到O层或者M层去"

**v5 修正**：
- ❌ v4："5 项不假装 = 在原则洋葱整体内（没说具体哪层）"
- ✅ v5：**5 项不假装 = O 层内容**（与 12 键同层）

**理由**：
- O 层 = 操作原则（"AI 可改走权限矩阵"）
- 5 项不假装 = 操作时的"不假装"原则（操作层面）
- 12 键 = O 层的"判定标准"
- 5 项不假装 = O 层的"核心精神"
- 一起放在 O 层最自然

```
O 层内容（v5）:
  - 🔑 12 键（V3 9 键 + v4.1 新增 3 键 = 12 键判定标准）
  - 🛡️ 5 项不假装（核心精神：不刷 KPI / 不假装 ASI / 不假装完整证明 / 不假装 100% 完美 / 不假装 Phenomenal）
  - O-1..O-6（具体操作原则）
```
