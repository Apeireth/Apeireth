# 0013. 定位重裁定：开源免费的个人工具型助手，动态红线取代「完全本地」

- **Status**: Accepted（owner 2026-10-23 口述拍板）
- **Date**: 2026-10-23
- **Owners**: owner（拍板） / 架构线（落文与实施约束）
- **Supersedes**: ADR-0012（中央 AI 与每户伙伴并存）
- **契约影响**: 无（纯裁定文档，不改 `contract.toml`；不新增 crate / env / 依赖边）
- **例外关联**: —
- **预算净额**: 依赖边 ±0 / 开关 ±0 / crate ±0 / 文件尺寸 +0（仅新增本文档）

## 1. 背景：为什么重裁

ADR-0012 是在「每户一个伙伴」为主战场的假设下写的。owner 2026-10-23 重新裁定两件事，
原有假设失效，需要一份取代 0012 的现行定位：

1. **主战场 = 个人用户的工具型助手**（不是家庭陪伴产品，也不是企业 SaaS）；
2. **红线 = 动态红线** —— 不再是「完全本地」（数据一律不出机器），而是
   **「用户不想外露的数据不能外流」**，按**对象 / 用途 / 可撤销**逐条控制。

同时明确一条**永久性商业约束**：

> **本项目从头到尾开源免费，不收费。**（owner 2026-10-23 声明）

## 2. 决策

### 2.1 开源免费，不做商业化

- 许可证维持 **Apache-2.0 OR MIT**（`LICENSE` / `LICENSE-MIT` 已在仓）；
- **不做**：订阅、按量计费、额度包、企业授权费、"免费版 / 专业版"分档；
- 因此 `docs/archive/stage4/...` 里那张 **T-3203「pricing 页面（R21+ 商业化预留，3 档 free/pro/enterprise）」作废**——
  归档文档不改（契约：`legacy/` 与 `docs/archive/` 只引用不改），但**该任务不再执行**，任何人读到它都以此条为准；
- 由此推论：**单价表（`model_profile.rs` 的 price 字段）不是定价输入**，只用于
  ① 用户自备 key 时的本地成本自述、② 预算/限流的资源折算。它**不承担商业功能**。

### 2.2 红线从「位置」改为「意愿」

旧口径用**数据在哪**判断安全（"完全本地"）；新口径用**用户是否愿意让它出去**判断：

| 维度 | 旧（完全本地） | 新（动态红线） |
|---|---|---|
| 判据 | 数据是否离开本机 | 用户是否允许**这一类数据**离开本机 |
| 粒度 | 一刀切 | 按**对象**（哪份数据）× 按**用途**（给谁、干什么） |
| 可撤销 | 不可撤销（已导出即失控） | **可撤销**：外发登记 + 撤回本系统内派生结论 |
| 失败模式 | 一放开就全放开 | 逐条放行，越权即帧 |

**这条红线的唯一实现面** = 出境脱敏闸（`crates/capabilities/tools/src/redaction_bridge.rs`）
+ 出网控制（`egress.rs`）+ 对象级判定（`object_access.rs`）+ 出域账本。
当前状态：**代码在仓、未接电**（`claims.yaml` 零命中，`provider.rs` 零挂载点）。
**它是本项目的承重墙**：砍掉它，"个人工具型助手"就退化成"另一个本地聊天壳"。

### 2.3 一个内核，两种配置

ADR-0012 的「两类主体并存」在工程上仍然成立，但表述改为**一个内核 + 两种配置**：

| 配置 | 域模型 | 形态 |
|---|---|---|
| **个人线**（主战场） | 单域轻装 | 一个人、一台机器、一个伙伴；数据默认不出本机，出则逐条授权 |
| **企业线** | 多域 + 深养成 | 每员工/每团队一域；域间默认隔离、跨域拒绝即帧 |

不变的部分（从 0012 继承，仍然有效）：

- 域平面（`domain_plane.rs`：每户一域、三面按域分库、跨域拒绝即帧）**不新造租户层**；
- 主体身份不进 `apeireth-core` 全局单例，身份是**装配根注入物**；
- **成长不跨主体合并**（"你的成长补给我"是幻觉，不是功能）。

### 2.4 企业线的两条硬约束

1. **员工不能被养成** —— 深养成是针对「组织/岗位」的，不是针对自然人的人格塑造；
2. **企业线伙伴的主体归属必须先答**：伙伴是给**个人员工**还是给**组织**？
   两者数据归属完全不同（前者随人走、后者随组织留存），未答之前企业线不得开工。

## 3. O-6 三阶审查

- **总体最优**：主战场收敛到个人工具型助手，避免同时背"家庭陪伴 + 企业 SaaS + 平台"三条产品线的
  范围与合规负担；开源免费去掉定价与单位经济这两块最大的不确定性。
- **系统最优**：红线从「位置」改为「意愿」，把安全能力从"部署形态"下沉到"运行时逐条判定"，
  与既有对象级判定/出网控制/脱敏闸的既有代码对齐，**不需要新架构**（缺的是接线）。
- **架构最优**：维持 ADR-0012 的域平面与"不新造租户层"；本次只改**定位与红线判据**，
  不改数据归属的工程实现，因此零预算变化。

| README / 状态页若出现"商业化/付费"表述 | 与本文冲突 | 后续按本文校正（列待办，不阻塞） |

## 5. 明确的「不做」

- 不做订阅/计费/额度包/企业授权收费；
- 不用"本地"作为能力卖点（本地只做数据主权，不做能力）；
- 不承诺 provider 侧的行为（例如"模型侧残留已抹除"）——我们能管住 instruction 与开关，
  不能替 provider 承诺；
- 不在企业线主体归属未定时开工企业线。

## 6. 回滚

本文是产品定位裁定，无代码回滚面。若未来定位再变，按本仓惯例：
**新增 ADR 取代本文**，不修改本文正文；工程实现（域平面、脱敏闸）不受定位变化影响。
