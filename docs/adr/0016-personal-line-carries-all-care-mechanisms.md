# ADR-0016：个人线带全部 14 条关怀机制，默认关，用户自行开启

- **状态**：Accepted（owner 2026-10-24 裁定）
- **取代**：无（首次裁定该问题）
- **相关**：ADR-0013 §2.3（个人线定位 / 动态红线）、ADR-0014 §1.1（「羁绊阶段」改名）、
  ADR-0014 §6（最小诚实自述集）

---

## 1. 背景：四方各说各话，长期无人裁

| 来源 | 说法 |
|---|---|
| ADR-0013 §2.3 | 个人线 = 「一个人、一台机器、一个伙伴」；**完全没提带不带关怀机制** |
| 外部顾问 §一.1 | 预装 14 种关怀机制本身**已构成关系设计**；「平台不定义关系」不成立，但「关系可质询、可重写、可退出」才可信 |
| owner 口头（2026-10-23） | 「关怀这种行为当然可以有，虚假的玫瑰一样能为人提供真实的情绪价值」→ 关怀是**真价值**，不是负债 |
| 我此前的建议 | 「12 条冻结标 EXPERIMENTAL」—— **已撤回**（前提「关怀是负债」被 owner 推翻） |

同时卡着两件事：词表纪律适不适用于关怀机制节；「羁绊阶段」改不改名。

## 2. 裁定（owner 2026-10-24 原话要点）

> **个人线带不带那 14 条关怀机制？默认关，在前端的设置界面能让用户自己打开不就行了，
> 这区别不是很大。**（前端在重构，由前端负责人团队做，不要打扰。）

拆成两条：

### 2.1 机制归属：**个人线全带**（14 条全留）

- 不是「带一部分」，不是「企业线带个人线不带」——**全带**；
- owner 的判据很干脆：**默认关 + 用户能自己打开**，这两种选择的差别就不大了。
  也就是说：「带不带」这个问法本身在「默认关 + 可自开」的前提下不再是关键决策。

### 2.2 开启权：**用户自己开**，实现分两层

| 层 | 谁做 | 状态 |
|---|---|---|
| **数据面**（配置文件 + CLI） | 后端（本 ADR 落地） | ✅ **PRODUCTION WIRED** |
| **界面面**（前端设置页） | 前端团队（重构中） | 待前端接入，**本 ADR 不涉及** |

**接口约定**：前端将来读**同一个** `bio-mechanisms.json`（数据根下），
不新增 API 契约 —— 这样前端重构不受本 ADR 约束，也不会产生两套真源。

## 3. 落地：三层优先级（env 最高）

```
1. env 显式设置（专业用户 / CI / 临时调试）—— 最高优先，且 =0 可显式关掉配置文件里的开启
2. 用户配置文件 bio-mechanisms.json（`apeireth bio enable <机制>` 写它）
3. 默认关
```

**为什么 env 要能覆盖配置文件**：否则「用户开了但想临时关一下」就没有路径（只能改文件）。
`apeireth bio list` 会把「配置文件开了但被 env 关着」这个最容易困惑的状态**显式说出来**。

### 3.1 三个动词

```
apeireth bio list                  # 14 条逐条：配置 / 有无独立 env / 是否生效
apeireth bio enable <机制>         # 打开一条
apeireth bio disable <机制>        # 关掉一条
```

机制名闭集（与 `BioMechanismKind::as_str` 逐一对应）：
`neuromodulation` / `homeostasis` / `circadian` / `immune_memory` / `nociception` /
`recovery` / `attachment` / `social_repair` / `quorum` / `lifecycle` / `play` /
`ritual` / `ecosystem_health` / `capacity`。

**拼错即拒绝**，并列出可选名 —— 不猜用户想开哪条。

### 3.2 「生效」这个词的精确含义

`list` 里的「生效」= **配置面判定**（配置开 + 未被 env 覆盖），
**不是**「该机制真的在跑」。后者要看自述面 `capabilities.bio_mechanisms`
的 `wired` 字段（9/14 已接信号源，其余 `wired:false` + 真因）。

两个问题分开答，不混 —— 这是我们「0 装诚实」的一贯口径。

## 4. 与词表纪律的关系（ADR-0014 §6）

选了「全带」之后，关怀机制节**适用**词表纪律：

- 5 个机制 wire 名仍是体验名（`nociception` / `attachment` / `ritual` / `quorum` / `play`），
  已登记债栏 **D32**；
- 处置建议是**保留键位 + 在节旁显式标注是读数**（不动冻结合同三侧），
  而不是改 wire 名（那要同步 render / schema / fixture 三侧）；
- 「羁绊阶段」→「互动连续性记录」（ADR-0014 §1.1）**成立**，可执行。

## 5. 不做

- **不做前端界面**（前端团队负责；本 ADR 只提供数据面）；
- **不默认开启任何一条**（默认关是 ADR-0013 动态红线的直接推论）；
- **不删任何机制代码**（即使某条从未被用户打开过 —— 默认关 = 零行为，删了回收不回来）；
- **不假装「生效」等于「在跑」**（见 §3.2）。

## 6. 可检验的验收

1. `apeireth bio list` 列出 14 条且状态如实；
2. `apeireth bio enable nociception` 后，**在没有 env 的情况下**痛觉观测面真的挂上
   （自述面 `capabilities.bio_mechanisms.nociception.wired` 从 `false` 变可见读数）；
3. 配置文件损坏 ⇒ 全关 + stderr 报错（**不静默、不猜**）；
4. 没有配置文件时，行为与「只有 env」**逐字节一致**（零行为变化）。
