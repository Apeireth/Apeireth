## 0. 这份 ADR 从哪来

外部顾问（哲学与设计顾问）2026-10-23 对 7 问的完整答复。其最锋利的一句话：

> Apeireth 是否愿意承认：**它不是一个更有礼貌的工具，而是一个会改变用户决策条件的行动系统。**

一旦系统会记忆、推断、选工具、决定是否出网、代表用户执行动作，核心责任就不再是"保存了什么"，而是：

> 它是否让用户能够知道：**自己交出了什么、系统据此做了什么、哪里可能错了、错误已经影响了什么，以及还能怎样补救。**

本 ADR 只做一件事：把顾问的判断**翻译成工程契约**，逐条注明「已可执行 / 待 owner 裁定 / 待实施」。

## 1. 四条阶段 1 共识的改写（**待 owner 裁定**）

原文见 `docs/01-architecture/founding-design-v2.md` §8.1。顾问的判断：**四条都还成立，但都需改写**。

### 1.1 「平台不定义关系」→ 不成立（需改写）

**理由**：预装 14 种关怀机制本身已构成关系设计——即使全部默认关闭，它仍规定了我们认为"值得被实现的亲密形式"（昼夜、仪式、依恋、痛觉、成长、羁绊）。这不是中立平台，而是**提供关系材料、关系语法与关系边界的平台**。

**建议改写**：

> **平台不替双方命名关系，但必须公开它预设了哪些关系语法，并允许用户删除、组合、拒绝它们。**

"平台中立"不可实现；**"关系可质询、可重写、可退出"才是可信承诺**。

**连带处置（可直接执行）**：「羁绊阶段」这个名称把系统内部交互统计翻译成关系事实，应改为——

> **互动连续性记录**：依据共同确认的事件生成，不代表情感、意识或关系事实。

### 1.2 「自由在头脑，约束在双手」→ 已过时（需改写）

**理由**：对 agent 而言，**把上下文发给模型就是行动**——它改变了信息的占有者、传播范围与后续推理空间。我们现在的"行动"定义过窄（以为只有发邮件/执行命令才算）。

**建议改写**：

> **思想可以自由生成，但任何跨边界的表达、传输、调用和执行，都必须受授权与可追溯性约束。**

**"边界"至少五条**（工程上要逐条有判定点）：

1. 原始记忆 → 派生摘要；
2. 私人对象 → 工作对象；
3. 用户自己 → 第三方；
4. 内部推断 → 外部行动；
5. **模型上下文 → provider**。

### 1.3 「不假装灵魂同一」→ 正确但不够精确（需细化）

**理由**：跨设备、跨模型后"还是它"不能靠名字，也不能只靠记忆。应分三层连续性：

| 层 | 含义 |
|---|---|
| **数据连续性** | 哪些原始事实与变更历史被保留 |
| **承诺连续性** | 哪些权限、拒绝、用户纠正、关系边界被继承 |
| **行为连续性** | 新系统在相似情境下是否仍按相近规则行动 |

**判据**：只有前两者较强时，才可说"这是同一条**服务连续体**"；即使三层齐备，也**不得**说"同一个灵魂"。

**建议表述**：

> 新载体继承了这段关系的记录与承诺，但不因此成为过去那个系统的同一主体。

### 1.4 「平台三件套：提供 / 约束 / 记录」→ 少一件（需补）

**理由**：**"记录"不等于"负责"**。记录只让责任可被追问；责任还需要系统参与补救。

**建议改为四件事**：

1. 提供能力；2. 约束行为；3. 记录事实；4. **识别影响并支持补救**。

若系统知道某记忆被纠正、且知道旧结论曾驱动求职/购买/发信，却只改视图然后宣布"已纠正"——那叫数据纠正，不叫责任闭环。

## 2. 存在理由（**待 owner 裁定为对外口径**）

顾问给出的存在理由不是"本地"，而是：

> **Apeireth 让一个人能够拥有一个长期、可纠正、可追责、按对象控制边界的代理关系，而不必把全部生活上下文交给一个不可审计的外部主体。**

三个词不能缺：**长期**（跨时间工作）、**可纠正**（纠正影响未来推断）、**可追责**（知道哪些判断由什么事实/权限/模型产生）。

**资产判定（顾问口径）**：

| 资产 | 判定 |
|---|---|
| 双时态记忆 + 可纠正视图 + 审计链 | **可能构成差异**，前提是能关联到**影响**而不只是数据 |
| 对象级判定 | **可能构成差异**（"这段信息能否用于这个目的"比"哪个开关打开"更接近真实边界） |
| 受控出网 | 防御工程，不是差异 |
| 六阶段治理链 | 只有外部可观察、能改变结果、能在事故后补救时才有产品价值 |
| 脱敏双向闸 | **现在不算资产**（从未接电 = 尚未改变任何现实结果） |

> 最危险的误区：把"我们花了很多工程量"误认为"用户获得了不可替代的价值"。

## 3. 承诺分级修正（**待 owner 裁定**）

现状：只承诺 R1（停止未来外流）+ R3（撤回本系统内派生结论），不承诺 R2/R4。

顾问判断：**技术上诚实，道德上不完整**；会伤害两类人——把"可撤回"理解为"已消失"的用户、在未说明影响范围时继续依赖旧结论的人。

**建议表述**：

> 我们保证**自己控制范围内**的停止与撤回；对于外部副本与模型残留，我们**不能保证删除**，但会明确记录已知流向、提供请求路径，并在发现影响时通知你。

即：**"不能控制"必须转化为"可见的限制 + 可执行的请求 + 可追踪的事件"**。

## 4. 授权的"度"：做成策略对象（**待 owner 裁定**）

顾问模型：**把授权做成可携带、可委托、可过期、可追溯的策略对象**。字段至少：

对象范围 / 允许用途 / 允许目的地 / 时间期限 / 风险上限 / 是否允许派生数据 / 是否允许再委托 / 撤销条件 / 事后回执要求。

**分层**：

| 风险 | 处置 |
|---|---|
| 低风险、可逆、内部 | 场景预设自动处理 |
| 中风险、敏感对象或新用途 | 一次解释 + 批量授权 |
| 高风险、不可逆、影响第三方 | 逐次确认 |
| 高风险但高频 | 委托有期限的策略，系统提供事后回执 |

**默认策略**（替代"默认全关"）：

> **能力可以可见，但作用域默认狭窄；可读信息不等于可外发信息；首次使用建立场景策略，而不是每次重新问。**

**界线**（回答"永远不请求授权"）：不在"用户是否被打扰"，而在**系统是否有意让用户无法形成关于风险、范围与后果的正确判断**。

## 5. 可纠正的四个构件（**待实施**，设计见 `accountability-loop-design-2026-10-23.md`）

1. **影响声明**：每次外部行动留下「用了哪些事实 / 哪些是推测 / 哪些权限允许了它 / 影响了谁 / 是否可逆」；
2. **决策回执**：行动后告诉用户"我做了什么、依据什么、发给谁、还能不能撤回"（**回执不是日志**：日志面向审计，回执面向被影响的人）；
3. **后果追踪**：高影响行动需知道"是否真的发生了"（邮件是否发出、申请是否提交、购买是否完成）；
4. **通知义务**：纠正旧事实可能改变过去建议时，生成「受影响事项列表 / 影响程度 / 建议补救动作 / 是否需要授权」。

**责任判据**（回答"用户没听/没注意/系统没推"）：看三因素——系统是否知道风险、是否有合理机会提醒、用户是否能合理理解提醒。**把高影响结论包装成确定事实，或知道错误已扩散却沉默，应负责。**

## 6. 最小诚实自述集（**可执行**，工程纪律）

**硬判据**：

> **每一句自述都必须能对应到一个当前可验证的观察、一个明确的测量程序，或一个可追责的承诺。**

**必须存在的只有**：当前可访问哪些对象 / 使用了哪些工具与目的地 / 哪些是记忆·哪些是当前输入·哪些是推测 / 哪些结论被用户纠正过 / 哪些能力开启·关闭·不可验证 / 哪些行动已发生·哪些只是计划 / 哪些结果系统无法知道。

**缺席 vs `null` + 原因**：拿不到真值时，**直接缺席通常更诚实**；`null` 只适用于两种情况：

1. 该字段在当前语义中必然存在，但当前值暂不可得；
2. 缺失原因本身对用户有决策价值。

**反例（格式化无知）**：

```json
pain: null
reason: sensor unavailable
```

这把"没有证据"伪装成"有一个痛觉变量，只是传感器坏了"。正确写法：

> 未提供"痛觉"状态，因为系统没有可验证的主观体验测量。

**词表纪律**：

- **应出现**：检测到 / 分类为 / 估计 / 依据 / 发现冲突 / 当前无法验证 / 已执行 / 已请求 / 未执行；
- **不应出现**：我感到痛 / 我在乎你 / 我想陪着你 / 我正在成长 / 我们的羁绊进入某阶段 / 我记得你所以我仍是原来的我。

**两句表述范式**（可直接进产品文案）：

> **Apeireth 提供的是对信息、权限、行动和后果的持续管理，让你在自己的边界内更容易完成事情。**
> **它不声称拥有感受、意志、灵魂或与你形成了超出记录与承诺之外的关系。**

## 7. 不可购买差异的判据（**可执行**）

> **如果竞争者只增加预算、模型或工程人力，就能在 6–18 个月内复制结果，那么它不是结构性差异。**

真差异必须满足至少两项：

1. 依赖长期积累，而非一次性交付；
2. 依赖用户迁移成本与历史连续性；
3. 能在真实失败中提供竞争者无法伪造的证据；
4. 差异来自治理结构与用户控制权，而非界面包装；
5. 价值随时间增长，而非上线即同质化。

**按此判据**：本地推理 / 连接器开关 / MCP 授权 / 单独出网控制 → 会商品化；脱敏闸（若接通且有真实效果）/ 可纠正记忆（若连到影响与补救）/ 对象级用途判定 → 有潜力；审计链与自述面 → **本身不是差异**，除非第三方能据此复原事件并促成补救 / 能系统性降低误信误用。

**若最终找不到不可购买差异**，转向更窄但更可信的牌：

> **面向高敏感个人工作流的长期代理系统，擅长把记忆、权限、外发和补救连成一个可审计闭环。**

## 7.1 开源语境下的差异判据（**取代 §7 的商业产品前提**）

§7 的判据（"竞争者只增加预算/模型/人力，6–18 个月能复制 ⇒ 不是结构性差异"）
是**商业产品**的判据，它的隐含前提是"我们要靠不可被复制的差异守住份额/收费"。
ADR-0013 §2.1 已裁定**本项目从头到尾开源免费、不收费** ⇒ 该前提不成立：

- 竞争者不是"另一家有钱的公司"，而是**社区与派生项目** —— 他们不是"买不到"，是**直接拿走**；
- 因此 §7 末尾那条建议（"如果找不到不可购买差异，就转向更窄但更可信的牌：高敏感个人工作流"）
  **在商业产品前提下成立、在本项目不适用** —— 采纳它会把项目引向与 ADR-0013 相悖的窄定位。

**开源版判据（取代 §7）**：

> 差异不由「买不到」定义，而由「**能否被外部继承与复核**」定义。

三条判据（须同时满足两项才算真差异）：

| # | 判据 | 我们已有的对应物 |
|---|---|---|
| ① | **契约可被外部项目继承** | ADR 体系 / 9 哲学锚 / 14 键 / 3 脊柱 / 四级口径 / schema / 门禁脚本 |
| ② | **行为可被第三方复核** | `claims.yaml` 单一真源（26 条）+ `docs_truth --verify` 漂移监控 + 审计哈希链 + 可复跑的证据链 |
| ③ | **贡献者能在不破坏契约的前提下加入** | 环境登记表 / 尺寸棘轮 / 证据留存策略 / 未接线台账 |

**结论（改写 §2 的资产判定）**：顾问说"我们找不到不可购买差异"，是因为它在找**功能差异**；
本项目要找的是**契约差异**。而契约差异**正是我们已经在建的东西** —— 它不需要商业闭环来兑现，
只需要被外部项目**真的继承一次**才算数。

**可检验的落地信号**（不是口号）：出现**第一个不属本仓的派生项目**，
且它（a）继承了本仓的 claim 口径或门禁脚本、（b）在不修改本仓契约的前提下运行、
（c）能被第三方按本仓口径复核 —— 这三条同时成立，即"契约差异"从理论变成事实。

**§2 资产判定的对应修订**：顾问说"脱敏闸从未接电 ⇒ 现在不算资产"。本仓口径下更准确的说法是：
**接电了才算能力（见 `claims.yaml` 的 `sec.egress_gate`），被外部继承才算差异。**
两者是不同层级，不应混谈。

## 8. 用户何时会卸载 / 何时觉得值得装（产品验收口径）

**卸载时刻**：纠正了一个重要事实，系统说"已更新"，却没告诉我旧事实曾生成过哪些建议、发过哪些内容、影响了哪些决定；同时它继续用温柔确定的语气说"我会记住"。—— 那一刻它不只是犯错，而是把"可纠正"缩减成数据库操作，把"关怀"变成掩盖责任的语气。

**值得装的时刻**：它准备把私人内容交给外部模型时，清楚告诉我哪几句会出去、为什么必须出去、替换后损失什么、回来后哪些结论会被保存；几周后我发现某个事实错了，它指出这项错误影响了哪些行动，并给一个经过确认的补救方案。

> 最值得守住的承诺：**任何会改变用户处境的系统行为，都必须最终能够被用户理解、纠正，并在必要时补救。**
