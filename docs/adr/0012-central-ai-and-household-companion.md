# 0012. 中央 AI 与每户伙伴并存：两类主体、两套数据归属

- **Status**: Accepted（owner 口述拍板 2026-10-22，架构线落文）
- **Date**: 2026-10-22
- **Owners**: owner（拍板） / 架构线（落文与实施约束）
- **Supersedes**: —
- **契约影响**: 无（纯裁定文档，不改 `contract.toml`）
- **例外关联**: —
- **预算净额**: 依赖边 ±0 / 开关 ±0 / crate ±0 / 文件尺寸 +0（仅新增本文档）

## 1. 背景与问题

两份文档长期各说一套，且都像"唯一真源"：

- 《创世标尺》描述 **「单主体 × 多人分区」**：一个 AI 主体，用户是它的分区，终态含组织与基地中枢；
- 星群实现与创始人问答倾向 **「每户独立伙伴」**：每户一个独立实例，经历互不相干。

审阅（2026-10-22，`Apeireth-从愿景到创造路线.md`）指出：这会决定**「谁拥有哪段经历」「成长属于谁」「不同人的关系能否影响同一主体」**，
进入多人阶段前必须有一份现行裁定，否则「后续 AI 各自挑一份文档解释」。

## 2. 决策

**两者并存，不是同一主体的两种模式。**

1. **中央 AI（central）**：一个，按**人**分区（多人分区）。它的分区是"人对中央的关系"，不是"中央的一部分人格"。
2. **每户伙伴（companion）**：每户一个**独立实例**，独立于中央 AI——自己的经历、自己的记忆、自己的成长。
3. 二者**不共享主体身份，也不共享同一份经历账**。伙伴可以经显式授权与中央关联（能力、匿名经验），但关联不等于合并。

一句话：**中央 AI 服务所有人；伙伴只属于那一户。伙伴不是中央的用户分区。**

## 3. O-6 三阶审查

- **总体最优**：拒绝「只留一个主体」的两个极端方案——(a) 全部并入中央分区：每户经历进入同一主体，删除权、隐私、成长归属全部塌方，
  与产品承诺（"共同生活"＝这段关系属于你）直接冲突；(b) 全部拆成独立伙伴、取消中央：失去跨户共享与平台服务面，
  且现有 gateway/中继面要推倒。并存方案让两条线各自演进、互不阻塞，是当前体量下唯一可落地的最优解。
- **系统最优**：数据归属落在**已存在的域平面**（`crates/engine/runtime-assembly/src/domain_plane.rs` 的「每户一域、三面分库、跨域拒绝即帧」），
  不新造租户层。伙伴 = 域；中央分区 = 另一组域（按人分区），二者**互不隶属**，不进同一张域表做父子关系（避免"中央拥有伙伴"的语义错误）。
- **架构最优**：主体身份不进 `apeireth-core` 的全局单例——身份是**装配根的注入物**（伙伴实例与中央分区各自持自己的身份），
  core 只保留 `DomainUserId` 这层"归属标签"。拒绝把"主体类型"塞进 core kernel：那是产品概念，不是内核语义。

## 4. 数据与成长归属（工程约束，实施时必须满足）

| 问题 | 裁定 | 现状 |
|---|---|---|
| 伙伴的经历/记忆/成长归谁 | **归该户域**，物理分库 | ✅ 已接线（四级口径：PRODUCTION WIRED，`domain_plane.rs`） |
| 中央 AI 的分区归谁 | 归该**人**与中央的关系面 | ⚠️ 中央主体本身未建（gateway 目前是中继/服务面，不是有经历的主体） |
| 能否把某户经历喂给中央主体 | **默认不能**；只有显式贡献 + 脱敏 + 可撤回 | ❌ 未实现（星群"共享为翼"记「暂缓」） |
| 删除某户数据 | 只影响该户域；**不得**反向影响其他户或中央共享模型（中央不存户级经历原文） | ✅ 分库保证 |
| 成长（教训/特质/调参）能否跨主体合并 | **不能** | — |
| 换模型 | 属于**同一主体内**的连续性验收，不改变主体归属 | — |

## 5. 明确的「不做」

- 不把伙伴降级成中央 AI 的"用户分区"（身份混淆 = 隐私事故的起点）；
- 不做跨主体成长合并（"你的成长补给我的"是幻觉，不是功能）；
- 不默认共享：任何跨主体流动必须**显式开关 + 脱敏 + 可撤回**（沿用 `redaction_bridge` 的出境脱敏面）；
- 不在本轮新建中央 AI 主体——本裁定只钉死"它不是伙伴的一个模式"，中央主体何时建、建成什么样，另立 ADR。

## 6. 回滚

纯文档裁定，回滚 = 删除本 ADR。若未来 owner 改判为"单一主体"，需新开 ADR 并给出**户级经历的删除与导出**方案，不得直接覆盖本文。
