## 1. 背景与问题

**问题一句话**：本仓已有 **54 条静态能力 id 全部 PRODUCTION WIRED**、但**默认开只有 6 条**、
**HARDWARE VALIDATED 达成 0 条**、**生产装配根不可达的能力 id 13 条**；而真正「还没有的面」
（浏览器、互联网检索、HTTP 写、UIA/GUI 动作、端侧推理、跨设备漫游、技能包分发、多签验签、
OTA 灰度、回放评估、路由策略层、对象级授权、检查点恢复、进程树快照、协议合规三件套）
**全部是 0 命中**。⇒ **上限不在「已实现多少」，在「面还有多少」。**

**为什么现在必须决策**（不写「以后再看」）：

1. **棘轮已顶格**（`31/31`·`118/118`·`160/160`）⇒ 按现行契约，**任何新面都不可能存在**：
   新族要么新 crate（新边）、要么新外部 dep（新包 + 新边）、要么新 env 名（新名）——
   三条路**全部**被契约挡住。⇒ 「继续创造」在现行契约下**不是难，是不可能**。
2. **继续不破棘轮的代价被量化**：0 成本档只剩 8 族且**全是「接线」**（把已有实现接进生产根），
   属于**存量**；owner 已明确「**只拓新面，不动存量**」⇒ ⇒ 只做 0 成本档 = **违背本线目标**。
3. **不破棘轮 = 永久停在「48 条默认关」**：本仓 54 条能力 id 里 48 条默认关，
   而 HARDWARE VALIDATED 为 **0** ⇒ 上线即「全能」在现行封装下不可达。

**owner 2026-11-08 原话**：「这条线的工作内容是『创造』，我们要在项目上线前，给他配套全能能力」
+「只拓新面，不动存量」+「允许破所有的，这就是这条线的意义」。

## 2. 决策

### 2.0 选项与建议（**裁决速览**）

| 选项 | 内容 | 裁决 |
|---|---|---|
| **选项 A** | 不破棘轮，只做 0 成本接线档 | ❌ **拒**：那 8 族全是**存量接线**，与 owner「只拓新面」直接冲突 ⇒ 本线目标落空 |
| **选项 B** | 无限制破棘轮（owner 口头当无限额度） | ❌ **拒**：契约形同虚设；下任无法判断「该不该加」⇒ 违反棘轮「只减不增」精神 |
| **选项 C** | **有额度的破格**（本 ADR 采纳）：额度 + 回填时点 + 归口 + 排除项 | ✅ **建议采纳**（owner 2026-11-08 已裁「允许破所有的」⇒ 本表把该授权收敛成**可管辖的额度**） |

**建议**：采纳**选项 C**；§2.2 的额度表是本线的硬边界，**任何超出项一律回本 ADR 追加**，不在实现批里"顺手多要一点"。

### 2.1 「新面」判据（本线唯一口径，机器可判）

> **新面 = 满足以下任一条**：
> ① **新能力 id / 新模型面工具名**（仓内 0 命中）；
> ② **既有族上新增的执行语义**（新动作 / 新档位 / 新维度 / 新传输 / 新协议面）；
> ③ **新的可查询或可操作对象**（新快照面 / 新账 / 新协议面 / 新可查询视图）。
>
> ⇒ **纯「把已有实现接进生产装配根」不算新面**（那是**存量接线**，归存量线；
> 本线**不碰**，见 §5 移交清单）。

### 2.2 授权破棘轮（**有额度、有到期、有归口**，不是空白支票）

| 棘轮 | 现值 | 授权上限 | 理由 |
|---|---:|---:|---|
| `max_workspace_crates` | 31 | **35**（+4） | 仅用于 4 个**新依赖闭包必须隔离**的新 crate（web / automation / trust / local-inference）；D19 已给隔离先例（178 包闭包 + `deny.toml multiple-versions=deny` 冲突） |
| `max_production_edges` | 118 | **128**（+10） | 新 crate 的必要入边 + 新族到既有面的接线边；**每波新增边必须同波登记** |
| `max_distinct_names`（env） | 160 | **176**（+16） | 新面需要真开关；**每个新名必须**：登记 `env-registry.toml`（default=off + purpose + evidence）+ **关时逐字节零变化测试** + 不拼前缀绕守卫 |
| `max_file_loc` | 6300 | **6300（不动）** | 零余量 ⇒ **新面一律新开文件**（建议 < 800 行）；既有大文件（`doc_ops.rs` 6255 / `cognitive.rs` 5201 / `execute.rs` 4731 / `sheet_ops.rs` 4387）**只读不写** |

**额度纪律（硬）**：
1. **先 ADR 后代码**（`docs/adr/README.md` §1）——每批若动额度，先出批次 ADR；
2. **额度是上限不是指标**——**允许用不完**；未用完不构成「必须花掉」；
3. **env 名不豁免登记**（`env_net_zero_exempt`）⇒ 新名照登记、照默认关、照零变化测试；
4. **每波收口回填契约**：本 ADR 只授权额度；`contract.toml` 的**数值变更随每波收口由 lead 落**
   （`baseline_update_policy = 仅架构波收口评审由 lead 执行`）⇒ ⇒ **本 ADR 落库时契约数值不动**，
   避免「先抬额度、后补能力」造成棘轮虚高。

### 2.3 本线的产品边界（**只拓新面，不动存量**）

* **做**：§3 八面地图里的**新面**（新能力 id / 新执行语义 / 新可查询对象）。
* **不做**：把已有实现接进生产根（存量接线）；改 LOCKED 5 项；改 9 哲学锚本体 / 14 键 / 3 不可变脊柱 /
  `workspace.version` / R11 baseline。
* **阶梯未到项**（Ed25519 真多签 / Noise 漫游 / 监督树 / L1-L3 总线 / T2 全流程 OTA）：
  2026-10-26 D2 已裁「T0 不做」⇒ 本 ADR **不推翻**该产品范围裁定；
  其中与「全能上线」强相关者列入 §3 的 **Wave 6（需 owner 逐项重新拍板）**。

### 2.4 治理纪律（新面沿既有 R0–R4 分级，**不放宽**）

| 档 | 语义 | 新面的典型 |
|---|---|---|
| R0 | 只读零审批 | 进程树快照、路由策略表查询、对象级授权**读取** |
| R1 | 审计留痕（写自身记忆/配置） | 技能包安装记录、授权账 |
| R2 | 白名单 + 逐次人批（可逆外部动作） | 互联网检索、HTTP 写调用、对象级授权/撤销 |
| R3 | 硬门 + 逐次人批（不可逆/破坏） | GUI 动作、浏览器提交、插件安装、设备动作 |
| R4 | 硬门 + 反思期 + 多签（系统级控制面） | OTA 灰度、跨设备漫游、端侧模型装载 |

**新增写能力一律默认关**；**族授权 = 按族一次授权、跨族仍逐次人批**（沿 `permission_preset.rs` 既有地板）。

## 6. O-6 三阶审查

- **总体最优**：**先立授权边界再动手**，而不是边做边撞棘轮。
  本线若按现行契约开工，第一批（任一新面）就会当场违规 ⇒ ⇒ 先把「破什么、破多少、谁回填、
  何时到期」写成 ADR，才可能真正造出东西。**拒的 alternatives**：
  ① **不破棘轮、只做 0 成本接线档** —— 拒：那是**存量**，与 owner「只拓新面」直接冲突，
  且 8 族全是接线 = 本线目标落空；② **owner 口头「允许破所有的」直接当无限额度** ——
  拒：那是空白支票，违反契约「新增必须 ADR + 登记」与棘轮「只减不增」精神；
  ⇒ 选**有额度、有回填、有到期**的破格。**拒理由**：无限额度 = 契约形同虚设 = 下任无法判断
  「该不该加」。

- **系统最优**：本线只动**能力面**（capabilities 层新增面 + adapters 层新增传输/端点），
  **不碰治理链、记忆语义、审批状态机、Provider 路由既有行为** ⇒ 新面一律复用既有
  `ToolCapability` / `ExtensionDescriptor` / 治理链 / 审批链。
  **拒的 alternatives**：① **在 plugin 层新增第二套能力注册表** —— 拒：ADR-0008 已定「单 ABI 家族 + 单命名」，
  第二套 = 概念重复（`duplicate` 权重 3 的棘轮项）⇒ 直接踩既有裁决；
  ② **新面自带审批/治理旁路** —— 拒：O-1 安全优先 + 既有 P0 三 hook 是硬约束，
  新面若绕过 = 造出「越权新面」；⇒ 选**复用既有治理链、只加能力面**。

- **架构最优**：31 members 单向依赖 + trait object 拓扑下，**新面按「依赖闭包隔离」而非「按功能族」分 crate**：
  端侧推理（178 包级闭包）/ 平台 UIA（COM/AX/AT-SPI 三套）**必须独立 crate**，
  否则污染主 lock 与 `deny.toml`；反之**只读快照、授权账、策略表**这类零新 dep 的面
  **必须留在既有 crate**（新文件），否则白耗 crate 额度。**拒的 alternatives**：
  ① **一个 `apeireth-capabilities` 大 crate 装下所有新面** —— 拒：平台/大闭包依赖会把主工作区拖进
  `multiple-versions=deny` 冲突（D19 前车）；
  ② **全部新面各占一个 crate** —— 拒：白耗 +4 额度且制造 10 个微型 crate 的概念噪声；
  ⇒ 选**4 个新 crate（仅大闭包/平台异构）+ 其余落既有 crate 新文件**。

## 9. 后果（Consequences）

* **正面**：新面从「**不可能**」变「**有额度可做**」；额度上限明确 ⇒ 任何一刻都能判断
  「还能不能加」；本线与存量线边界清晰 ⇒ 战场不重叠。
* **负面 / 接受的代价**：crate 上限 31→35、边 118→128、env 160→176 ⇒ 棘轮**被抬高**。
  代价必须被**每波回填 + 用不完就少抬**对冲（§4.3）；这是 owner 明知并授权的代价。
* **后续 stage**：W0 落库后开 W1（0 新外部 dep 档，6 族）；W1 收口回填契约 ⇒ 复评额度是否够 W2。
