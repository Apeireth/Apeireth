# ADR 0024: 1.0 release 12 项 checklist — v1.0.0 release gate

> **状态**: 🟢 Accepted (R20 阶段 6 主人 2026-08-05 拍板, 1.0 release 12 项收口)
> **commit 锚**: `reports/r20-v1.0.0-release-checklist-2026-08-05.md` + `commit 02d5db6c` (1.0 release 报告)
> **最后更新**: 2026-08-05

---

## 1. 背景 (Context)

Apeireth 1.0 release (v1.0.0) 计划 2026-09-30 tag。需 12 项 checklist 全 PASS 才允许 tag。

**问题**:
- 12 项中 2 项 P0 fail 阻塞 (test + perf), 估 2 周内解决
- 12 项覆盖 9 大类: doc / test / security / install / upgrade / uninstall / perf / observability / ci / i18n / license / signature
- 任何 1 P0 fail 阻塞 release tag (per 蓝图 §3.5 "9 P0 + 3 P1")

**约束**:
- 12 项必须 **全 PASS** 才允许 `git tag v1.0.0`
- 9 P0 + 3 P1 分布: 任何 1 P0 fail 阻塞, P1 可豁免 (主人拍板)
- 1.0 release 报告 (R20 阶段 6) 必须包含 12 项状态 + 全 commit 锚

---

### 2.2 9 P0 + 3 P1 分布

| 严重度 | 项 | 阻塞? |
|---|---|---|
| **🔴 P0** | 2 (test) + 7 (perf) = 2 项 | **是**, 任何 1 P0 fail 阻塞 tag |
| **🟡 P1** | 10 (i18n) + 其他 3 项 = 3 项 | 否, 主人可豁免 |
| **🟢 普通** | 1 (doc) + 3 (security) + 4 (install) + 5 (upgrade) + 6 (uninstall) + 8 (observability) + 9 (ci) + 11 (license) + 12 (signature) = 7 项 | 否 |

**当前 PASS 10/12 = 83.3%, FAIL 2/12 = 16.7% (2 P0 fail 阻塞)**。

### 2.3 2 P0 fail 修复计划

#### P0 #2 test (cargo test --workspace 0 fail + 54/54 报告齐)

- **当前**: 估 1-2 fail 阻塞 (per `reports/r20-v1.0.0-release-checklist-2026-08-05.md`)
- **修复路径**:
  1. 列出 fail 用例 (per `cargo test --workspace --no-fail-fast 2>&1 | grep FAILED`)
  2. 优先级 1: 跟 LOCKED 24 crate 相关的 fail → 必须修, 估 3-5 天
  3. 优先级 2: 跟 R20 估缺 9 skeleton 相关的 fail → 标 TODO R21, 估 1-2 天
  4. 优先级 3: flaky test → 加 retry 或放宽阈值, 估 1-2 天
- **估时**: 1-2 周
- **owner**: backend-engineer 主 + 测试 sub-agent

#### P0 #7 perf (P95 < 2s + 1000 req/s 软上限)

- **当前**: 估 baseline 已记录 (per `reports/r20-stage-6-cargo-bench-baseline-2026-08-05.md`), 部分场景 P95 > 2s
- **修复路径**:
  1. 列 P95 > 2s 的 endpoint (per `cargo bench` + JMeter 100 次 P95)
  2. 优先级 1: `/v1/tools/*/invoke` P95 > 2s → 加 connection pool / 异步化, 估 3-5 天
  3. 优先级 2: WS `/v1/ws` P95 > 2s → 流式优化, 估 1-2 天
  4. 优先级 3: 1000 req/s 不达标 → 加 lru 缓存 + 优化 SQL 索引, 估 1-2 周
- **估时**: 2-4 周
- **owner**: performance-engineer + backend-engineer

### 2.4 1.0 release tag gate 流程

```
12 项 checklist 全 PASS (或 主人豁免 P1)
   ↓
cargo deny check (license + advisory + bans + sources)
   ↓
CI 全绿 (5 守门 + 7 matrix)
   ↓
1.0 release 报告签字 (R20 阶段 6)
   ↓
git tag v1.0.0
   ↓
GitHub release + crates.io publish + Docker Hub push (8 形态)
```

## 3. 后果 (Consequences)

### 3.1 正面

- ✅ **可追踪**: 12 项 + 9 P0 + 3 P1 分布, 主人 / Mavis / 团队 1 眼可见
- ✅ **阻塞明确**: 2 P0 fail 阻塞 tag, 主人可豁免 P1, 不会"勉强 tag"
- ✅ **修复路径清晰**: 2 P0 fail 估时 1-2 周 + 2-4 周, 估 2026-09-15 ~ 2026-09-30 tag
- ✅ **不假装**: 2 P0 fail 诚实标, 不"先 tag 再修"
- ✅ **1.0 release 报告 (R20 阶段 6) 全公开**: 团队可见

### 3.2 负面

- ⚠️ **2 P0 fail 估时 2-4 周**: 1.0 release tag 延后风险 (per 蓝图 2026-09-30)
- ⚠️ **perf 优化空间**: 1000 req/s 软上限可能不够 (per 1 用户场景估够, 多用户场景估补)
- ⚠️ **i18n P1 豁免风险**: 主人可能豁免 i18n, 1.0 release 仅英文, 引发用户抱怨
- ⚠️ **CI 7 matrix 时间长**: full matrix 估 40-60 min, 阻塞 PR review

### 3.3 风险

- 2 P0 fail 修复时间超估, 1.0 release 延期到 R21 (per `docs/adr/0013-apeireth-rust-1.0.md` §3.2 风险)
- perf 优化空间不足, 1000 req/s 软上限不达标, 主人接受但留 1.0.1 patch 修复

## 4. 备选 (Alternatives Considered)

### A. 推迟 1.0 release 到 R21 之后, 12 项全 PASS 才 tag
- 优点: 0 P0 fail
- 否决: 主人 2026-08-05 拍板 "先收 1.0, 商业化走 R21", 推迟会丢 momentum

### B. 仅发 0.9.21 alpha (per 现状 v2.0.0-alpha)
- 优点: 0 P0 fail 风险
- 否决: workspace.version 已锁 v1.0.0, semver 严守; alpha 0.9 路径被主人否决

### C. 1.0 release 12 项 + 2 P0 fail 不阻塞 (本决策)
- 优点: 严格守 gate, 不"勉强 tag"
- 拍板: R20 阶段 6 主人拍

### D. 1.0 release 12 项 + 2 P0 fail 主人豁免
- 优点: 估 9 月可 tag
- 否决: "不假装"原则, 主人不会豁免 P0 (per S-2 实事求是)

### E. 1.0 release 12 项 减为 8 项
- 优点: 易达标
- 否决: 砍项 = 砍 1.0 release 价值; 主人 2026-08-05 拍板 12 项不动

### F. 1.0 release = TUI + Tauri 全接通
- 优点: 完整前端体验
- 否决: 主人 2026-08-04 拍板 "缺审美设计, Tauri 暂搁, TUI 自己干", 1.0 release 后端先收
