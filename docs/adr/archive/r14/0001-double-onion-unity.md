## 背景（Context）

Apeireth 是高自主性长程 agent 平台。系统的**核心约束** = **双层防护**：
- 原则层（哲学守门）：让系统"做正确的事"
- 权限层（审批门）：让系统"在授权内做"

**最初设计**（阶段 1 §18.7）："双洋葱正交"——两层独立，互不干扰。

**问题**：
- 两层正交 → **谁来决定哪一层先？**（执行顺序不明确）
- 正交 → **是否可以用权限通过绕过哲学守门？**（V1 独立拒绝不强制）
- 正交 → **修改洋葱结构需要两个独立流程？**（管理复杂度）

## 决策（Decision）

**采用"双洋葱统一体"**（v4 修正 #3+#4）：

> **原则洋葱 E/S/A/M/O 嵌入权限洋葱 L0-L5**，**不是**两个独立锁，是**一个统一体的两个切面**。

**核心洞察**：
- 原则"长在"权限的每一层里
- 权限"承载"原则
- 两者**互不可分**

## 后果（Consequences）

### 正面
- ✅ **执行顺序明确**：V1+V2+V3 AND 门（任何一者不通过 = 独立拒绝）
- ✅ **不可绕过**：哲学守门无法被权限通过绕过
- ✅ **结构清晰**：双洋葱 = 一个统一体，不是两个独立模块
- ✅ **演化简单**：洋葱结构演化 → 一个流程（不是两个）

### 负面
- ⚠️ **修改复杂度**：修改原则层或权限层都需要修改"统一体"
- ⚠️ **学习曲线**：新人需要理解"为什么是嵌入不是并列"
- ⚠️ **测试覆盖**：V1+V2+V3 AND 门需要完整集成测试

### 中和
- 🛡️ **Self-Disable 防护**：重组洋葱结构必须物理隔离 + MultiHuman 多签
- 🛡️ **L0 HA 永远不可变**：作为统一体的核心，例外

## 备选方案（Alternatives Considered）

### 选项 A: 双洋葱正交（原始设计）

- 两层独立，互不干扰
- **否决原因**：执行顺序不明确 + 可绕过哲学守门

### 选项 B: 三洋葱（增加中层）

- 原则洋葱 + 中间缓冲层 + 权限洋葱
- **否决原因**：过度工程 + 增加学习成本

### 选项 C: 单洋葱（合并为一层）

- 只有权限层或原则层
- **否决原因**：失去双层防护的鲁棒性
