- **Date**: 2026-10-20

- **例外关联**: —

## 1. 背景（实测）

- 代码：`crates/foundation/core/src/philosophy.rs` 现为 **14 变体** `PhilosophyKey`（PHL-01..08）；
  数组 `ALL_THIRTEEN_KEYS: [PhilosophyKey; 14]`，编译期断言 `len != 14` 即 panic（:107-128 / :159-198）。
- 来历：V3 9 键 + v4.1 新增 3 键 = 12；R125-12 加 PHL-07 = 13；**2026-10-11 PHL-08 主人特批直加**（源码 :56-61 留痕）= **14**。
- 文档：`AGENTS.md:45`、`ROADMAP.md:210`、`ENGINEER-MANIFESTO.md` 等仍写「13 键 LOCKED」；全仓现行文档约 101 处出现「13 键」。
- 后果：LOCKED 硬规则与代码不一致——任何 AI 按 AGENTS 执行都会误判"守住了 13 键"；2026-10-16 口径统一批把错误数字写死。

## 2. 决策

1. **现值为 14 键**：PHL-01..08（12 + PHL-07 NotUnoptimizable + PHL-08 NotAuthoritative）。
2. **「13 键」= 历史口径**（PHL-07 时代，2026-10-11 之前），带日期保留、不追溯改写。
3. 硬规则/现值文件更新为「**键集 LOCKED（现行 14 键：PHL-01..08）**」：`AGENTS.md`、`ROADMAP.md §13`、架构契约 `[locked]`。
4. **历史文档不追溯**：`ENGINEER-MANIFESTO` 等 2026-08 前口径文档保留原文 + 顶部复核注；其余「13 键」出现处按「现值/历史」分批清理（不一次大扫，避免误改历史卷宗）。
5. **加键流程不变**：未来增删键 = 改 LOCKED 定义，必须 owner 特批 + LOCKED 真例外流程 + 编译期断言同步；`ALL_THIRTEEN_KEYS` 等历史常量名**不改名**（30+ 调用方，命名漂移已在源码注释说明）。
6. `arch_guard` 不检查文字口径（机器无法判断"现值/历史"语境）；该口径由 ADR + 文档门禁人工纪律维护。

- **总体最优**：只改现值硬规则、不动历史卷宗——既消除"AI 按错误规则执行"的风险，又守住"历史不追溯改写"纪律。拒 ①全仓一次性替换（会误改历史/卷宗，违反 S-2）②不改（LOCKED 硬规则持续失真）。
- **系统最优**：口径修正落在 AGENTS（最高优先级指令）、ROADMAP（现值唯一出处）、契约（机器真源注记）三处，互相引用不重复。拒 ①只改 philosophy.rs 注释（代码已对，问题在文档）②新建"键数真源"文件（多一个真源）。
- **架构最优**：0 代码改动、0 LOCKED 本体触碰；常量名历史命名保留（改名成本 30+ 调用方，收益低）。拒 ①重命名 `ALL_THIRTEEN_KEYS`（纯噪音 diff）②把键数做成运行时配置（破坏编译期 hardcode）。
