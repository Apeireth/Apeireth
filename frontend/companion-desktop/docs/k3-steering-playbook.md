# K3 施工过程控场手册 · 书面修改清单用法

> 配套 `k3-team-kickoff-prompt.md` 使用。开工提示词管"开局"，本手册管"过程"——教你在 K3 施工期间，用你那套"观察→问题→具体解法→验收点"的书面要求格式逐轮提意见。
> 模板语言规范参照你自己的提示词汇编（分镜修改清单 v091→v094 轮）：先肯定、编号问题、绰号命名现象、物理类比验证、轻重缓急排序、明确时限。

---

## 一、什么时候用什么

| 场景 | 形式 | 例 |
|---|---|---|
| 继续/催进度/确认小事 | 短指令（≤2 行） | "继续" / "那请你继续工作" / "先解决 A 再优化 B" |
| 观感有问题但说不大清 | 口头描述几句 | "消息卡的金色太重了，跟星尘卡区分不开" |
| 一轮系统性修改 | **书面修改清单**（本文档格式） | 交付后你审一轮，提 5-15 条编号意见 |
| 方向性拍板 | 直接改文档/改提示词范围 | "会话分支提前到本期" |

节奏建议：**小轮次**——K3 每完成一个子任务就交付，你每轮清单控制在 10 条以内；宁可三轮九条，不要一轮三十条。

## 二、书面修改清单模板

```markdown
# 本轮要求（v00X → v00Y）

先说一句总体观感：［哪里对了，先肯定；哪里不达标，一句话说死］

## 1. ［部件/页面名］：［现象绰号］
- 观察：［我做了什么操作/看了哪个界面，看到什么］
- 问题：［精确到部件/交互/帧；为什么不对——用物理或生理直觉讲透，禁止只下结论］
- 解法：［具体怎么做；给参照（文档条款号/别的页面/截图）；多条时编号］
- 验收点：［改好后我一眼怎么确认］

## 2. ［下一条］…
（按轻重缓急排序：先修"错"，再修"糙"，最后才提"更好"）

时限与优先级：［如"本轮先修 1、2，4 可以下轮"］
```

**五条语言规范（从你分镜清单里提炼的）：**
1. **先肯定再批评**——"看到你现在输出的结果，我觉得是非常好的，但是还有几个很关键的点"——先给方向感，再逐条压。
2. **给现象起绰号**——像"果冻""迟滞""物料镜头"那样，起一个临时名指代问题现象，K3 对齐成本低，讨论快。
3. **用物理/生理直觉讲透为什么错**——鱼摆尾那个例子是范本："现在相当于让鱼在背脊方向摆动身体，生理上做不到，因为脊椎骨没办法做到"。前端版：动效违反惯性、层级违反遮挡、文字抽搐违反"人眼对文字的敏感"。**讲得出为什么，K3 才不会只修表面。**
4. **该静止时就静止**——你的原话"比分牌上的文字不要抽动，该静止的时候就静止"是普适审美纪律：静是默认，动必须挣得理由。
5. **轻重缓急排序 + 时限**——"这个问题严重""这个问题较小就不用强调了""本轮先解决什么"。

## 三、前端审查维度速查（提意见前过一遍，像你的逐镜头表）

| 维度 | 看什么 | 常见"绰号" |
|---|---|---|
| 正确性 | 数据真假、0 装标注、API 对没对上 | "假数据""幽灵状态" |
| 流式 | 逐字是否平滑、结束是否干净、打断是否收束 | "吐字卡顿""残影" |
| 显影 | significance 分级对不对、动效是否过量 | "光污染""抽搐" |
| 调性 | 页面归没归错调性、纸面/深舱语言纯不纯 | "串味" |
| 金色 | 金色是不是只给了他 | "金滥用了" |
| 动效 | 缓动、时长（沿用 motion 令牌）、该静的是否静 | "漂""硬切" |
| 梯队 | T0 是否完整可用、降级断在哪 | "T0 破功" |
| 性能 | RAM/帧率/失焦暂停、显影耗资源 | "风扇起飞" |
| 空态 | 是否写了"当 X 发生时这里会出现 Y" | "死空态" |
| 审批 | 被等待感够不够、会不会被晾着 | "没重量" |

## 四、两个示范（教格式，不是真实任务）

### 示例 A：观感类
```markdown
## 1. 审批卡：没重量
- 观察：工具触发审批后，对话里浮起一张卡片，金色的。
- 问题：卡片是出现了，但它是"咣"一下弹出来的，停在那像个广告。我要的"被等待感"没有出现——他停下等我签字这件事，应该像有人轻轻放下一张纸，不是弹个 banner。人眼对"突然出现又静止的物体"的直觉是"可以稍后处理"，所以我会晾着它。
- 解法：① 出现用光环收束引导视线（从场景侧流光到卡片位，0.6s，缓动沿用 motion 令牌），不是 scale 弹入；② 卡面加极慢的呼吸（振幅 ≤5%，4s 周期，跟着 presence 走），等我处理完才停止；③ 超过 90s 未处理，宠物在桌面抬头看我一眼（stance 联动），不弹通知。
- 验收点：触发一次审批，把视线移开再回来，我能感到"它还在等我"，而不是"它已经躺在那了"。

## 2. 空态：死空态
- 观察：治理卷宗空 tab。
- 问题：写的是"暂无数据"。这是软件语言，我们的空态要写数据契约。
- 解法：改成"批准第一条工具调用后，这里会出现它的完整执行轨迹"（照 gap-plan §4.3 的句式）。
- 验收点：空态文案里能读到一个具体动作 + 具体会出现的东西。
```

### 示例 B：行为类
```markdown
## 1. 记忆星图：幽灵状态（严重）
- 观察：断网后打开记忆页。
- 问题：列表显示了上一次的数据，没有任何标注。这在 0 装纪律里等于"假装他记得"——缓存数据必须可识别，否则用户在断网时分不清真假，信任崩一次就完了。
- 解法：离线数据一律加"截至 HH:MM 的本地缓存"一行小字（等宽，status 行样式），在线刷新后自动消失。新数据拿不到就显示空态契约，不显示旧数据。
- 验收点：拔网线刷新记忆页，我能明确看出"这是旧的"。

时限：示例 A 两条本轮全修；示例 B 是严重问题，下条子任务之前必须修掉。
```

## 五、验收与驳回

- **验收入口**：每条意见的"验收点"就是你回看的脚本——让 K3 按你的验收点自证（附命令/截图），你抽查。
- **不合格的说法**：直接说"没改到"并引用原条编号，别重写一遍——"第 1 条没改到：呼吸还在抽搐，我说的是振幅不是频率。"
- **虚报处理**：发现虚报完成（说做了没做/假数据/假成功），升级到最高级：要求全量复核本轮所有条目 + 台账登记一次失信记录。
- **文档同步**：方向性意见（改优先级、改 scope）说完记得改对应文档（00-PHILOSOPHY / plan），别让文档和会话漂移——这条也写进给 K3 的要求里。

## 六、给你的速查卡（贴在手边）

```
改前：截图/复现步骤在手 → 起绰号 → 为什么错（物理直觉）→ 具体解法 → 验收点

节奏：每轮 ≤10 条；小轮次勤回
措辞：先肯定一句 → 编号逐条压
方向变了：改文档，不只是改对话
```
