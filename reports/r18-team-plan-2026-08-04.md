## 📋 集成规范 (sub-agent 必须遵守)

### 1. 代码风格
- 沿用 R18-01/02 已有代码: 纯 axum + format! HTML 模板
- 不引入新依赖 (除非必要, 需要 Mavis 拍板)
- 走 apeireth-* crate 的真实 API, 不 mock

### 2. 文件结构
```
crates/apeireth-web/src/
├── main.rs                (Mavis 维护, axum router 注册)
├── api.rs                 (Mavis 维护, 数据结构)
├── app.rs / council.rs / verdict.rs  (R18 stub, 暂不删)
├── memory.rs              (sub-agent #1)
├── asi.rs                 (sub-agent #2)
├── sovereignty.rs         (sub-agent #3)
├── council_history.rs     (sub-agent #4)
├── api_endpoints.rs       (sub-agent #5)
└── style/
    └── main.css           (Mavis 维护, 公共 CSS)
```

### 3. 命名
- 路由: `/{module}/{action}` (e.g. `/memory/append`, `/sovereignty/attack`)
- Handler: `async fn {action}_handler(Form/Json) -> impl IntoResponse`
- 模板函数: `fn render_{page}_page(...) -> String`
- HTML escape: 必须用 `html_escape()` (main.rs 已有)

### 4. 错误处理
- LLM 失败 → `render_error_page()`
- 不假装成功: 真跑通才返回 200
- 测试时如果 LLM 失败, 写明 "需 APEIRETH_API_KEY"

### 5. 测试
- 每个新模块加 ≥ 1 个 example: `cargo run -p apeireth-web --example {module}_demo`
- example 用 scripted LLM provider (不耗真 key), 走 R16 e2e example 模式

### 6. Commit
- sub-agent **不 commit**
- 完成时只 report 给 Mavis:
  - 改了哪些文件
  - example 跑通的输出
  - 任何 trade-off
- Mavis 集中 review + commit (按 v12 规范 `round18-NN`)
