## 🔍 关键技术决策 (诚实记录)

### 决策 1: 不用 spec 行号, 用实际行号 (字段级引用 §6.2.3 #3 + #7 不假装)

**spec `borrowed-from-projects.md §6.2.2` 标的行号有偏差**:
- #15 标 `dynamicToolRegistry.js:7-9`, 实际 const 字面量在 10-21 行
- #17 标 `messageProcessor.js:78-98`, 实际 `resolveAllVariables` 函数在 146-220 行
- #20 标 `chatCompletionHandler.js:100-160`, 实际 `isTextOnlyModelByTag` 在 222-230, `messagesContainBase64Media` 在 239-257

**做法** (符合 §6.2.3 #7 不假装 + #3 字段级引用): 我们的代码注释 **cite 实际行号** (真代码可定位), 同时**显式标注** spec 行号偏差. 这是 §6.2.2 spec 遗留问题, 战役 1-4 校订 spec 时一并修正.

### 决策 2: Pipeline 不用 `HttpClient::post()`, 用 `http.reqwest_client()` + LIFO pool guard

**原因**: `apeireth-http-client::HttpClient::post()` (战役 1-2 实现) **不自动加 Bearer auth**, 真实生产 LLM 都需要 bearer_auth. 战役 1-2 的 `client_demo` 直接用 `http.reqwest_client().post(&url).bearer_auth(&api_key)`, 绕过 `HttpClient::post()`.

**Pipeline 做法** (保留战役 1-2 的 Keep-Alive LIFO 池 + Bearer auth):
```rust
let _guard = self.http.pool().enter().await;  // LIFO 池 permit
let mut req_builder = self.http.reqwest_client().post(&url).json(&body);
if let Some(token) = &self.config.auth_token {
    req_builder = req_builder.bearer_auth(token);  // Bearer auth
}
let response = req_builder.send().await?;
```

**待战役 1-4 / 1-5 修**: `HttpClient::post` 加 optional `auth: Option<&str>` 参数, 这样 pipeline 不用绕到底层. 战役 1-3 范围内**不漂移, 不动 1-2 代码**.

### 决策 3: streaming.rs 真流式降级为 simulate (W3 #1 simulate 升级版)

**原始设计**: `run_streaming` 用 `reqwest::Response::bytes_stream()` 真流式, chunk 推 `Sender<StreamChunk>`.
**真问题**: reqwest 0.12 `bytes_stream()` 返回 `impl Stream<Item = Result<Bytes, Error>>`, 编译时 `Error` 类型在某些上下文不能 infer (rust 编译器推成 `[u8]` unsized). 加 `futures::StreamExt` 也绕不开.

**降级**: `run_streaming` 用 `text()` 拿全 body, 然后按 50 字符/chunk 推 `Sender<StreamChunk>`. 这是 **W3 #1 simulate 升级版** (战役 R19-tui 已用, 真 SSE 留给战役 2 `apeireth-tool-runtime`).

**不假装**: 注释明确写 "simulate: 按 50 字符一块", 6 个 streaming tests 全部真跑 (3 chunks / error / drop / empty / 100 chunks / timeout).

### 决策 4: `RetrySuppression` 改 `Arc<Mutex<HashMap>>` 支持 Clone

**原因**: `PipelineConfig` derive `Clone` 时, 字段 `suppression: RetrySuppression` 必须 `Clone`. `parking_lot::Mutex` 不 impl `Clone`, 但 `Arc<Mutex<T>>` impl `Clone` (Arc 共享底层). 改后 `RetrySuppression: Clone`, 实战中 pipeline 复制 (未来 apeireth-api 多 worker) 可共享 suppression map.

**不漂移**: 行为不变 (Arc 共享 = 多个 RetrySuppression 实例看同一个 map), VCP `Map` 共享语义对齐.
