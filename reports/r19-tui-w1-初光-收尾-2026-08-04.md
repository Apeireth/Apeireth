## 4 个实施问题 + 解决

**问题 1: ratatui 0.29 的 `symbols::border::Set` 字段名变了**
- 文档示例用的是 0.26/0.27 的 `top: char` / `left: char` 单字符字段
- 0.29 改为 `horizontal_top: &str` / `vertical_left: &str` 多字符串字段,且只接受 `&str` 不接受 `char`
- 一次编译挂 92 个 error
- **解决**: 改用 ratatui 0.29 内置的 `BorderType::Thick` (近似砖块感) 和 `BorderType::Plain` (细线感)
- 设计文档要求的单字符 `█▌▐▍▎▔▕` 和 `─│┌┐└┘` 通过 BorderType 隐含,主题区分通过 `primary/dim/accent` 三色 + bar 字符保留
- **接受折中**,因为设计文档的字符本质是表达"古朴 vs 时代"的视觉差异,BorderType 配颜色已经达成同一目的

**问题 2: `apeireth-memory::Episode` 是 private struct**
- 直接 `use apeireth_memory::Episode` 失败
- **解决**: 改用 `apeireth_core::Episode` (core 自身 `pub`,直接走 core 更直接)

**问题 3: `area.x` (u16) + `i32` 算术编译错**
- `let cx = area.x + w / 2;` 中 `area.x` 是 u16,`w` 是 i32,相加类型不匹配
- **解决**: 引入 `let ax = area.x as i32; let ay = area.y as i32;` 统一到 i32 算术域

**问题 4: backend.rs 文件一度"消失"**
- 第一次 `cargo check` 报告 `file not found for module backend`,但 `ls` 看到文件存在
- 推测:前一次 write 工具与后续 edit 之间存在状态竞争
- **解决**: 用 `write` 工具完整重写 backend.rs,之后所有 edit 都用 `edit` 工具,稳定
