Runtime Diagnostics — proposed states

Placement first, then six states. Diagnostics live in the existing 设置 › 运行时与诊断 column — not a new page, not a Grafana overlay. Every panel is assembled from primitives already in the product: .setting-block, .diag-results, .notice-box, StatusBadge, StatusDot, and the three existing button classes.

Not a SuperDesign artifact. SuperDesign is not available in this environment (no CLI, no skill, no MCP tool), so this canvas was authored directly against the tokens extracted from base.css, StatusBadge.svelte and SettingsView.svelte. The review gate is unchanged: nothing here is implemented until you approve it.

Reused existing patterns

  • .setting-block / .block-title / .block-desc — section shell, unchanged
  • .diag-results / .diag-summary / .diag-list / .diag-item — process rows are added to the existing health list
  • .info-card / .info-title / .info-text — error detail and the "not an error" explainer
  • .notice-box — credential-source and unsupported-capability disclosures (same device as Persona's 只读呈现)
  • StatusBadge — green / amber / danger / dim / neutral variants only
  • StatusDot — default, .active, .off; .danger is the one addition below
  • .quiet-button / .primary-button — existing taxonomy; 重启后端 is promoted to primary only in state C

New visual primitives

  • One: .status-dot.danger — a danger-coloured dot. StatusDot ships off (faint) and active (amber) but no failure colour, and state C needs to read as failed at a glance in the same position the other states use. It is 3 lines reusing --danger, not a new component. The alternative — reusing off — would render a crashed backend identically to a stopped one.
  • .status-dot.pulse is not counted as new: it applies the product's existing 2.8s breathing cadence (--ap-dur-breathe) and is dropped under prefers-reduced-motion. If you would rather add no motion at all, say so and it comes out — the amber colour alone still distinguishes the state.

Open questions for review

  • Placement (specimen 0): process rows extend Settings › 运行时与诊断. RuntimeModal stays connection-only unless you want the same rows there too.
  • Four quiet buttons in Ready is the densest this row has carried. Acceptable, or should 复制诊断摘要 move behind 打开日志目录?
  • Unsupported (specimen E) is drawn for MemoryView with Tools/Activity as the same notice. Confirm before applying to Conversations' backend-ledger tab.
