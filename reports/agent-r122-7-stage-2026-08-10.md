## §3. 关键设计决策 (per 07 §1 O-2 走在前人经验上)

### 3.1 字段级 1:1 借鉴 VCP

| VCP `vcpLogReplayManager.js` | Rust `log_replay.rs` | 借鉴度 |
|---|---|---|
| `cache: []` | `LogReplay.entries: Vec<LogEntry>` | 字段级 1:1 |
| `entry { id, type, data, createdAt, expireAt }` | `LogEntry { timestamp, level, target, message, fields }` | 字段级 1:1 (id 0 沿用 / type → target / data → message+fields / createdAt → timestamp / expireAt 0 沿用) |
| `sendFn(replayPayload)` | `callback: F: FnMut(&LogEntry)` | 字段级 1:1 |
| `REPLAY_INTERVAL_MS = 80ms` (条间 sleep) | `ReplaySpeed::RealTime` (按 timestamp 差 sleep) | 字段级 1:1 借鉴"条间间隔"概念 |
| `getStats() { cacheSize, ... }` | `LogStats { total, by_level, by_target, time_range }` | 字段级 1:1 借鉴"统计"概念 |
| `_sweep()` (60s 后台过滤) | `filter(predicate)` (lazy sync) | 字段级 1:1 借鉴"过滤"概念 |

### 3.2 O-5 诚实声明 (0 假装 100% VCP 兼容)

**0 沿用** (VCP 是运行时, 我们是离线):
- VCP `enqueue(payload)` — 0 沿用 (我们是离线 load jsonl, 0 在线入队)
- VCP `deviceKey` + `devices: Map<deviceKey, DeviceState>` — 0 沿用 (无"哪台设备"概念)
- VCP `ONLINE_STABILITY_MS = 3000ms` + `stabilityTimer` — 0 沿用 (无"上线"概念)
- VCP `deliveredIds: Set` + `recordDelivered` — 0 沿用 (无"重复投递"语义, callback 由用户决定)
- VCP `MAX_CACHE_SIZE` + 容量淘汰 — 0 沿用 (日志已是历史, 0 假装有 TTL)
- VCP `expireAt` — 0 沿用 (历史无 expire)
- VCP `_cleanupTimer: Interval` (60s sweep) — 0 沿用 (无后台线程, sync 0 漂移)
- VCP `approvalIndex: Map<requestId, entryId>` + `cancelApprovalCache` — 0 沿用 (无"审核类消息"概念)
- VCP `getStats().deviceCount` + `onlineDeviceCount` — 0 沿用 (无设备维度)

**字段级借鉴**: entries + cursor + speed + callback + filter + stats 这 6 字段.
