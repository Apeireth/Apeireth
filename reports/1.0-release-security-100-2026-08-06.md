### 1.5 RUSTSEC-2024-0437 实际风险评估 (per O-3 真源代码深读)

**漏洞描述** (per https://rustsec.org/advisories/RUSTSEC-2024-0437):
> Crash due to uncontrolled recursion in protobuf crate
> Affected version of this crate did not properly parse unknown fields when parsing a user-supplied input. This allows an attacker to cause a stack overflow when parsing the message on untrusted data.
> Affected Functions: `protobuf::coded_input_stream::CodedInputStream::skip_group` (version <= 3.4.0)
> Patched: `>=3.7.2`

**实际触发路径分析 (per apeireth-metrics src/ grep)**:

```bash
$ grep -n 'use prometheus\|from prometheus' crates/apeireth-metrics/src/*.rs
# (no output — 0 命中)

$ grep -n 'prometheus' crates/apeireth-metrics/src/exporter.rs
# 只命中 4 处:
#   line 7:  "1 | Prometheus | ✅ 完整" (表格注释)
#   line 33: "exporter name (e.g. "prometheus")" (doc)
#   line 50-73: `PrometheusExporter` struct (自实现, 不 import prometheus crate)
#   line 84-104: `export()` impl — 调 self-implemented encoder::encode_*, 不调 prometheus crate
```

**`PrometheusExporter::export()` 实现 (line 84-104)**:
```rust
async fn export(&self, registry: &MetricsRegistry) -> MetricsResult<String> {
    let mut out = String::with_capacity(2048);
    for metric in registry.list() {
        // ... 调 self::encoder::encode_counter / encode_gauge / encode_histogram_full / encode_summary_full
        // 全是 apeireth-metrics 自实现, 走 text exposition format
    }
    Ok(out)
}
```

**结论**: 
- `RUSTSEC-2024-0437` 触发路径 = `protobuf::CodedInputStream::skip_group` (用户输入恶意 protobuf → 解析时栈溢出)
- apeireth-metrics **0 调 prometheus crate API** (Cargo.toml line 34 引入只是为 R21 留口, 0 真用)
- 0 解析用户输入 protobuf (自实现 text exposition format 输出)
- **0 实际风险** (RUSTSEC 是 static analysis 误报; runtime 不可达)

**但 cargo audit 仍报 vulnerability** (它只扫 Cargo.lock, 不知道 runtime 不可达). 续补方案见 §6.3.
