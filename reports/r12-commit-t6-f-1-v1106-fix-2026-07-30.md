# apeireth/v1106_engineering_lift.py 第 1550-1563 行

## 3. 修复方案

**最小改动** — 加版本兼容常量列表：

```python
# 文件顶部 (line 49, import pytest 之后)
_ALLOWED_LIFT_METHODS = ("ast_grep_capabilities", "r11_ast_ownership")
```

```python
# test_handles_empty_dir (line 1087)
assert r["total"] == 0
# T24 (T6-F-1, T13 报告 §7.2 P1 残留): 兼容 'ast_grep_capabilities'
# (legacy) 与 'r11_ast_ownership' (R11 V0.4 closure, T6-A 引入)
assert r["method"] in _ALLOWED_LIFT_METHODS

# test_method_set (line 1093)
# T24 (T6-F-1, T13 报告 §7.2 P1 残留): 兼容 'ast_grep_capabilities'
# (legacy) 与 'r11_ast_ownership' (R11 V0.4 closure, T6-A 引入)
assert r["method"] in _ALLOWED_LIFT_METHODS
```

### 3.1 为什么是常量列表而不是 `or` 链

- **可读性**: `assert r["method"] in _ALLOWED_LIFT_METHODS` 比 `assert r["method"] == "ast_grep_capabilities" or r["method"] == "r11_ast_ownership"` 更清晰
- **可扩展性**: 后续若 R12+ 引入新 method (如 `v11_ast_ownership_v2`)，只需在常量列表追加
- **Ponytail 一行化原则**: 三个值两行 OR 链已超 80 字符，常量列表一行解决

### 3.2 为什么不改 apeireth/v1106.py

按 §5.E 红线 + T24 硬性约束：
- `apeireth/v1106_engineering_lift.py` 是主人真生产模块 (`v1106_engineering_lift`)
- T6-A 引入的工作变化是 **预期升级** (AST-based ownership > legacy filename grep)
- 改测试期望（兼容新旧 method）是单向正确做法，不是回滚工程
