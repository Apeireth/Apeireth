# R114-R118 Batch Final — Dynamic Operations Layer

## Scope

This batch continues the dynamic operations layer after R78-R113. It converts existing eval, council, cognition, protocol, and skills capabilities into MCP-, CLI-, and runtime-consumable surfaces without changing the workspace semver (`1.1.0`) or embedding credentials.

## Delivered

| R | Delivery | Engineering result |
|---|---|---|
| R114 | Eval MCP bridge | `EvalToolServer` lists and dispatches smoke, real-LLM, and cross-model eval tools; callers can inject a real handler. |
| R115 | Council MCP bridge | Prompt and resource servers share council member and verdict state, exposing member lists, last verdict, and risk hints. |
| R116 | CLI command families | Skills, eval, and council arguments are parsed into typed commands and dispatched to existing crate capabilities. |
| R117 | TUI cognition live | Summary signatures detect first-seen/update/clear transitions; the TUI runtime polls every 500ms and requests refresh on change. |
| R118 | Protocol transport bridges | Stream chunks are assembled with UTF-8 validation, queue hand-off is bounded FIFO with backpressure errors, and pass-through preserves payload identity. |

## No-fake audit

- Eval MCP metadata mode explicitly reports that live execution requires a configured handler/environment; it does not claim an LLM call occurred.
- The failed R117 global-state test was replaced with a pure state-transition test that truly exercises `Some -> None -> Cleared`.
- R117 is registered in the binary and consumed by `run_app`; it is not an unused source file.
- R118 performs actual chunk assembly and bounded queue operations; no fabricated latency metric or network claim is exposed.
