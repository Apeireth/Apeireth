### 3.4 Google Gemini GenerateContent (战役 1-4 新增)

**Endpoint**: `POST /v1/gemini/v1beta/models/{model}:generateContent` (minimaxi 端点)

**跑法**:

$env:APEIRETH_API_KEY = "<主人 key>"
cargo run -p apeireth-api --example gemini

**实测** (URL 路径 + minimaxi 服务端限制):
- latency: 400ms (比 3 协议快 10x, 因为 minimaxi Gemini 端点对 MiniMax-M3 直接返回 "model not supported" 错误)
- 返回: `{"base_resp":{"status_code":2013,"status_msg":"invalid params, model MiniMax-M3 not supported"}}`
- 错误处理: 正确解析 minimaxi 错误格式, 返回 `protocol decode: missing required field: responseId`

**代码路径** (全过):
- ✅ URL 构造: `https://api.minimaxi.com/v1/gemini/v1beta/models/{MODEL}:generateContent` (minimaxi 路径)
- ✅ 请求体: `contents[]` + 顶层 `systemInstruction` + `generationConfig` (VCP 借鉴 `gemini adapter.adapt_request:64-82`)
- ✅ Pipeline 5 步: placeholder / token_budget / force_translate / 协议归一化 / HTTP
- ✅ Keep-Alive LIFO 5 字段
- ✅ 错误处理: 4xx 响应正确反归一化 + 错误信息透传

**minimaxi Gemini 服务端限制**:
- minimaxi 暴露 Gemini 端点 (`/v1/gemini/v1beta/...`) 但暂无可用模型 (gemini-1.5-pro / gemini-2.0-flash / abab6.5s-chat / MiniMax-Text-01 都返回 "not supported")
- 这是 minimaxi 服务端限制, 不是 apeireth-api 代码 bug
- 后续 minimaxi 上线 Gemini 模型时, 改 MODEL 即可 (代码无需改动)

**Gemini URL 特例** (战役 1-4 显式处理):

- 解决: `is_minimaxi_gemini_quirk()` 检测 minimaxi 域名, 自动加 `/v1/gemini/` 前缀
