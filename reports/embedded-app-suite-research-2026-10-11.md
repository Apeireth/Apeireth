## 一、结论速览

1. 上游是「中枢服务 + 桌面壳」双仓形态：中枢管模型接入/记忆/插件/工具审批，桌面壳管交互面。其最新桌面端的核心卖点是一套**内置应用面**：内置浏览器、富文档工作台（类办公文档+演示）、文本/源码编辑器、协同画板、内置终端、图表等 27+ 内置子应用。
2. 「内置」的实现不是各自为政的独立软件，而是**统一宿主 + 贡献点注册表 + 多标签壳**，每个子应用只实现 `mount(container, context)` 协议即可挂载。
3. 三大内置件中，**富文档工作台的技术含金量最高**：一条「源码保持型」渲染编辑管线（编译时产出字符区间索引 → 渲染态直改 → 偏移映射回源码 → 带原文校验的区间事务写回），值得我们独立重建。
4. 我们的基地（Tauri + Svelte 桌面壳 + Rust 引擎工作区）具备做同样事情的全部底座，且 Rust 侧可把上游放在 JS 里的重活（编译器、语义树）做成更强的引擎件。
5. 安全面必须先想清楚：终端、浏览器桥、可编程脚本岛都是「权限爆炸面」，必须走我们既有的审批分级与安全纵深（00-backlog E），默认拒绝、人工审批兜底。

## 三、三大内置件逐件拆解

### 3.1 内置浏览器面（四层结构）

```
[托管浏览器运行时]   spawn 系统浏览器二进制 + 独立托管配置目录 + 调试端口 + 一次性令牌
       │             （有头/无_headless 开关、空闲自动回收、残留进程清理、启动参数留痕）
       ▼
[浏览器桥扩展]       浏览器侧扩展，把页面事件/指令桥回中枢（WebSocket + 令牌鉴权）
       ▼
[语义化网页操控内核]  页面 → 去噪语义树（可读的结构化文本）→ 语义句柄点击/输入/连续操作
       │             适配器契约化：桌面壳适配器 / 浏览器扩展适配器 同一协议
       ▼
[侧栏共享浏览器]     人机共用的内嵌浏览面：仅允许 HTTP/HTTPS、白名单宿主、
                    标签上限（12）、只接受受信渲染进程注册的目标
```

要点：
- **语义树而非 DOM 树**：给模型看的是去噪后的语义结构，操作走「语义句柄」，模型不必解析原始 DOM；
- **适配器契约**：同一套操控协议跑在不同宿主（内嵌 webview / 外部浏览器）上；
- **托管即隔离**：浏览器有独立配置目录、独立生命周期、令牌鉴权、空闲回收，不与用户日常浏览器混用；
- **技能录制**：连续操作可录制成可复用操作序列（含校验强度分级），用自然语言回放。

### 3.2 富文档工作台（类办公文档 + 演示，技术含金量最高）

核心命题：**人类编辑渲染后的文档，智能体编辑同一文档的源码，两者必须汇入同一份唯一真源。**

```
Markdown 主导的混合唯一真源（Markdown / HTML / CSS / 公式 / 图表 / 可编程岛）
        │
        ▼
混合源码扫描与受保护区识别（围栏代码、公式、图表、脚本岛不被编译器改写）
        │
        ▼
编译产物 = 阅读用 HTML + 编辑索引（每编辑区：源码字符起止、内容哈希、token 类型、岛 ID）
        │
        ▼
静态渲染树（默认）／点击后局部临时编辑树（编辑树文本 ≡ 原源码片段，不满足即拒绝进入编辑）
        │
        ▼
光标与选区映射回源码字符偏移
        │
        ▼
区间事务写回（expected 原文校验，只替换真正变化的源码片段）
        │
        ▼
重新编译 + 局部修补渲染区
```

配套机制：
- **三态解耦**：输入态 / 渲染态 / 源码事件态分离 + 事务队列仲裁，专治输入法合成与高频并发编辑竞态；
- **可编程岛**：文档内嵌脚本/图形/计算小岛，稳定语义 ID + 可释放生命周期（切页/重渲清理定时器与动画帧）；
- **文脉版本面**：每份文档自带署名历史与版本分支，智能体写操作走**提案-审核-幂等合入**协议（差异可同时看源码差异与隔离渲染差异）；
- **双工程模型**：长文流式文档（自有排版分页引擎，导出独立可读）与演示场景（HTML 场景模型）分开建模；
- **导出解耦**：导出产物不需要原编辑器即可打开阅读。

## 四、可复用的通用宿主模式（与具体产品无关的抽象）

1. **贡献点注册表（数据优先）**：子应用/命令以纯数据定义注册（`id / title / kind / mount()`），注册表校验字段白名单，**显式禁止注入 HTML/URL/通道字段**，防止注册面成为注入面；注册/注销有 owner 生命周期（owner 失活即拒绝注册）。
2. **mount/unmount 协议**：子应用只拿容器与上下文，销毁时必须释放；浮层走 acquire/release 会话配对。
3. **多标签壳**：内建应用与嵌入应用统一进标签体系，可拖出为独立物理窗口；快照与「安定回调」方便测试断言。
4. **流式渲染纪律**：消息流式渲染采用会话 ID + 代次序号 + 消息身份三维校验，防旧任务串写；预览/终稿双阶段提交。
5. **配置中心化 + 热更新监控**：插件配置变更可被监控并即时生效。
6. **工具审批分级**：高危工具调用走审批配置；工具结果出站前过隐私过滤。

### 5.4 技术路线要点（独立重建，非抄写）

- **文档管线**：编译器放 Rust（crates 新引擎件），输出「渲染产物 + 编辑索引」两份；前端只做映射与事务提交。索引含字符区间与内容哈希，写回用 expected 原文校验——这是防并发写坏的关键，必须上测试钉住；
- **编辑树不变量**：临时编辑文本 ≡ 原源码片段，不满足拒绝编辑。这条要上性质测试；
- **浏览面**：Tauri 多 webview 与独立窗口都可行，建议先「标签内嵌 + 可拖出」；语义树操控内核用 Rust + 平台无关键树遍历，别把重活放前端；
- **可编程岛**：脚本岛默认关闭、逐文档授权、生命周期强制释放（防定时器泄漏），运行走我们的沙箱件；
- **依赖策略**：文本编辑选用成熟开源编辑组件（许可证兼容优先 MIT/Apache-2.0），不自造文本编辑底层；上游用的组件生态我们只当「选型参照」，不跟风。

### 5.5 风险与债预警

1. **许可证**：上游 CC BY-NC-SA 4.0（非商业 + 相同方式共享）→ 代码级复制会污染我们的授权面。**硬规矩：零代码复制、零文件搬运、零符号照抄；只按行为规格独立实现**。本报告的引注豁免表只登记来源事实；
2. **权限爆炸面**：终端/浏览器/脚本岛/本地执行四个都是高危面，全部走默认拒绝 + 审批链 + 审计；先有 E 的对象级判定再放行 I-5/I-7；
3. **体积与冷启动**：内置应用面按需加载（贡献点注册 + 懒挂载），不进首屏关键路径（B 性能红线）；
4. **输入法/并发编辑竞态**：文档面三态解耦与事务队列从第一天就要，后补必留债；
5. **口径纪律**：新增 crate/测试数/接口口径随批同步文档，`check-neutral-terms.ps1` 零命中。
