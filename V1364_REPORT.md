## What V1364 ships

### 1. V1357 CLI flag (`apeireth/v1357_vcp_observability_snapshot.py`)

Two new arguments on the existing `snapshot` subcommand:

```
v1357-snapshot snapshot [--json] [--pretty] [--record] [--tag TAG]
                          ↑ already existed         ↑ V1364 new
```

- `--record` — opt-in flag (default OFF). When set, the snapshot
  is also appended to V1362 history via `append_snapshot_with_dict`.
- `--tag TAG` — optional label passed to V1362 (default: no tag).
- Stderr confirmation: `[v1364] recorded to history: tag='X' measured_at=...`
- Guard rails: `_record_to_history()` returns `None` and prints to

### 3. V1362 helper (`apeireth/v1362_pole_star_history.py`)

`append_snapshot()` is now a thin wrapper that calls

## Known unknowns / honest disclosure

- **History grows on every `--record` call.** This is intentional (append-only ledger).
  If a human runs `--record` 1000 times in a script, the file gains 1000 entries.
  V1362 has no auto-rotation; the file is rotated manually if it grows beyond a
  threshold (existing V1362 contract).
- **Recording adds ~10-50 ms latency** to `snapshot --record` (file I/O).
  Acceptable for interactive use; not for tight loops.
- **`--record` is a flag, not a subcommand.** V1363's wording said "subcommand `record`"
  but the actual usage model is cleaner as a flag on the existing `snapshot` subcommand:
  same command produces JSON + writes ledger. A separate `record` subcommand would
  require duplicating snapshot-building logic. We chose the flag.
- **V1357 imports V1362 lazily** (inside `_record_to_history`) to avoid module-level
  circular imports. Cost: first `--record` call pays the import (~5 ms).
- **If V1362 cannot be imported**, `--record` prints to stderr but does NOT fail the
  command — the JSON output still succeeds. This is intentional graceful degradation.
